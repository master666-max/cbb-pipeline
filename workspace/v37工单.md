## 第 0 章 总评

前六轮把「语义正确」做完，本轮抓到的主题是**「单一事实源被旁路」**：overrides 永久压制 REGISTRY 本体（L-002）、--redeliver 的重写逻辑与 _deliver 分叉导致试点文件被按旧语义重写（L-001）——两处都是「旁路权威源」型缺陷。另有渲染化收尾与三条测试债。

## 第 1 章 新发现

### L-001（P1）--redeliver 与 _deliver 逻辑分叉（已在回归场实证）
- 【证据】redeliver 的重写代码（v3.5 写）只有 ADAPTER 注入分支，**不认识 v3.6 的试点渲染化**——对 PILOT 文件按 v2.x 原文重写，与 install 渲染版不一致 → 回归场「漂移 1」复现。两份注入/渲染逻辑并存且已分叉。
- 【修复】抽 `_write_body(rel, meta, b, level, target)` 单文件落盘函数（内聚：removed 过滤、适配页、试点渲染化），_deliver 与 redeliver 共用。
- 【回归】install → redeliver → 校验漂移 0（含 PILOT 文件）。

### L-002（P1）overrides 永久旁路 REGISTRY——单一事实源被架空
- 【证据】J-003 闭环后，overrides 一旦写入就永远参与对账：即使后来人工把正确标题改回 REGISTRY 本体，override 仍以旧值压制（via=override 永远 match），**REGISTRY 作为单一事实源被旁路**，且无任何提示。
- 【修复】①verify 输出提示「override 与 REGISTRY 不一致 N 条——本体应回写」；②新增 `verify --absorb-overrides`：把 overrides 值写回 REGISTRY 源码语义层（生成对账报告供确认+清空 overrides 文件），恢复单一事实源权威。
- 【回归】override 存在 → --absorb-overrides → REGISTRY 更新建议输出 + overrides 清空 + verify 纯净对账。

### L-003（P2）账本覆盖缺口：guard/absorb-md 无汇总动作
- 【证据】guard snapshot/anchor、absorb-md 迁移无 changes.jsonl 汇总行（absorb-md 仅逐条 append 间接入账）——公理 C「全动作记账」有漏。
- 【修复】三处补 `_ledger_append` 汇总行（guard-snapshot/guard-anchor/absorb-md）。

### L-004（P2）eval 基线无劣化检测
- 【证据】baseline.json 每次覆盖，宪章级纪律「劣化超 5% 不得合入」无执法——参数改坏静默通过。
- 【修复】eval 读旧 baseline（存在时），recall@5 或 MRR 劣化 >5% 输出 [宪章警告] 并退出码 2；基线更新仍写入（警告在案）。
- 【回归】劣化场景警告触发。

### L-005（P3）跨月链测试债：t_chain_and_cross_month 名不副实
- 【证据】测试同月跑两次，跨月分支（新月首行引用上月尾）从未被真测——X-018 根治形态的核心路径零覆盖。
- 【修复】monkeypatch time.strftime 模拟跨月（首月 1 行→次月 1 行），断言次月首行 prev=上月尾哈希。

### L-006（P3）entry_normalize 类型不设防
- 【证据】links 传字符串时 `" ".join(e["keywords"])`/迭代崩溃；keywords 同理。schema 校验只查存在不查类型。
- 【修复】entry_normalize 强转 list（str→[str]，None→[]）。

### L-007（P2·文档同步）_index/SKILL.md 的 v2.x 描述冻结核对
- 【证据】根库 knowledge/skills/library-bootstrap/SKILL.md 等描述停留在 v2.x 口径（legacy 化已在 DEPRECATED 声明）——核对无遗漏即可，不改。
