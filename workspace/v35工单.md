## 第 0 章 总评

v3.4 的命令面（eval/reflect/doctor/absorb-md/guard 锚定）已齐；本轮审查抓到的最有价值问题是一个**架构级自相矛盾**：engine append 自己在静默覆盖同 id 条目（J-001）——「永不覆盖」的铁律被体系自己的写入路径违反。其余为对账闭环的小断点。

## 第 1 章 本轮审查新发现

### J-001（P0）engine append 静默覆盖同 id 条目
- 【证据】cmd_engine append：`(dest / f"{e['id']}.json").write_text(...)` 无存在性检查——同 id 二次 append 直接覆盖旧条目，铁律 1「永不覆盖」被写入路径自己违反；schema 校验也不查 id 已存在。触发场景：absorb-md 对多源迁移（两个 v4 库的 TRAJ-1 互覆）、用户重复写入。
- 【修复】dest 已存在 → sys.exit 列出既有条目 created_at 与新条目差异提示（更新走显式 update 语义或换 id）；absorb-md 遇重复跳过并计数（不中断迁移）。
- 【回归】同 id append 两次第二次必须拒绝；absorb-md 双源同 id 跳过计数。

### J-002（P1）_deliver 会把 bodies["removed"] 槽的已删除文件重新交付
- 【证据】_deliver 遍历 `b.items()` 不排除 removed 槽——absorb 镜像移入 removed 的文件，下次 install 按前缀匹配重新落盘（删除复活）。
- 【修复】_deliver 跳过 "removed" 槽；回归：构造 bodies 含 removed → install 交付清单不含该文件。

### J-003（P1）verify --fix 的 overrides 写而不读（对账闭环断裂）
- 【证据】cmd_verify --fix 把 mismatch 写 registry_overrides.json，但 REGISTRY 判定从不加载 overrides——人工裁决结果永远不进账，下次 verify 仍报同一 mismatch。
- 【修复】verify 启动加载 overrides（存在则覆盖 title 参与对账），match 条目标注 via=override；报告显示 overrides 应用数。
- 【回归】mock mismatch → --fix → 二次 verify（带 overrides）该条转 match(override)。

### J-004（P2）build-docs --lib 的 out 默认错位
- 【证据】`build-docs --lib <库>` 不带 --out 时 spec/速查/citations 落 ./dist 而 AGENTS/README 落库——一套渲染两个去处。
- 【修复】--lib 给定时 out 默认取 lib（显式 --out 可覆盖）。

### J-005（P2）build-docs --lib 顺带刷新 state 的 version/package_sha256
- 【证据】包升级后 state.version 停留安装时版本，根对账语义之外还有账面陈旧。
- 【修复】--lib 模式写根时同步 version/package_sha256。

### J-006（P2）render_entrypoint 命令清单过期
- 【证据】AGENTS.md「常用命令」仍是 v3.2 五条，缺 eval/reflect/doctor/absorb-md/guard snapshot——渲染件内容滞后于命令面（H-001 通道已通，内容本身要跟）。
- 【修复】渲染清单补全六条+快捷说明；回归：渲染内容含 "engine eval"。

### J-007（P2）migrate 输出接 eval parity 门
- 【证据】migrate 打印「parity 门=recall@5 ≥ 基线−0.03」但无下一步指引；eval 现已存在。
- 【修复】migrate 尾部提示「下一步：engine eval --lib <库> 对账 parity 门」。
