> 来源：用 v3.2.0（锚点 c247f37b…）在 `库调试v3.2/` 建库 L9 + 迁移 v4 内容 42 条的全过程（2026-09-06，规划 workspace/v3库迁移规划.md 的现场变体：根工作区不动，新目录复制制）。

### W1（P1）cmd_engine 函数层 Path 契约不一致
- 现场：迁移器直接调 `cmd_engine("append", LIB=str, …)` → `chain_append(lib / "audit")` TypeError 崩溃（retrieve 分支有 `Path(lib)`，append 没有）。
- 根因：CLI 入口传 `Path(a.lib)` 掩盖了函数层对入参类型的隐含假设；API 契约不统一。
- 已当场修（两个副本同步 `lib = Path(lib)`）；v3.3 应全函数扫描同类假设 + 回归断言（直接以 str 调 engine append 不崩）。

### W2（P1）C-001 检查顺序 bug：已安装库上重跑 install 被空 bodies 拦截，校验模式不可达
- 现场：在 `库调试v3.2/`（cwd）重跑 `install L9 --yes --target .` → 报「bodies 为空，先跑 absorb」——但该库 state.json 已在，本应进入校验模式；C-001 的 bodies 检查写在了幂等校验**之前**。
- 影响：C-004 的漂移/未在册/根对账（发布门语义）在非发布 cwd 下不可达。
- 修复：把 bodies 空检查移到幂等分支**之后**（已安装 → 校验模式不需要 bodies）；回归断言：在无 bootstrap_data 的 cwd 对已装库重跑 install 必须走校验模式。

### W3（P2）DATA_DIR 相对 cwd 的设计债
- 现场：同一命令在发布目录可跑、在库目录即报 bodies 空（被 W2 掩盖成另一个错误）。bootstrap_data/manifest 全部相对 cwd，长命令链对 cwd 敏感。
- 修复方向：--data 参数或「state.json 同目录寻 bootstrap_data」回退；与 W2 一并做。

### W4（P1）manifest「未在册」口径误报运行时文件
- 现场：校验模式报 `[未在册] memory/intermediate/PT-004.json`——记忆条目本来就不在交付 manifest 范围（manifest=交付内容体；运行时面归 audit/ledger 管）。
- 修复：校验模式的未在册检查排除 `memory/`、`audit/`、`ledger/`、`evals/`、`state.json`、`skills/`（渲染产物另议）；「未在册」只对内容体目录（modules/packs/presets/references/experimental-*/docs）有意义。

### W5（P1）根只在 wrapup 刷新，任意写操作后根对账必然漂移
- 现场：wrapup 后根=38077b92（入 state）；随后 retire 追加审计行 → 现算根 7f84ee2b ≠ state——校验模式「根不一致」对**合法操作序列**必然报警，语义失效。
- 修复：append/retire（写操作）后重算并写回 state.merkle_root（shadow 不写）；或根口径改为「交付+内容体面，不含运行时面」二选一定稿。倾向前者（根=库当前态，公理 E 的本意）。
