# 双库 v3 优化计划书 —— 引入「灵魂」系统与 SOTA 记忆架构

> 2026-09-03 起草。依据：网络调研（五套 SOTA Agent 记忆架构论文摘要，来源见文末）+ 本地双库现状。
> 铁律沿用：只新建不覆盖、有据可写、拿不准标【待确认】。**本计划书仅规划，经确认后执行。**

---

## 一、现状诊断（v2 双库的四个缺口）

| 缺口 | 现状证据 | SOTA 对照 |
|---|---|---|
| ① 没有「灵魂」层 | AGENTS.md 只有流程纪律，每次会话的"我是谁、你是谁、我们怎么相处"靠会话零散重建 | 社区成熟实践 SOUL.md / USER.md（OpenClaw、Claude Code 生态）：身份与用户模型显式落盘 |
| ② 记忆只增不改 | pitfalls/patterns 追加式，新经验不回头修订旧条目 | A-MEM：新记忆写入时触发旧记忆演化（更新表述、建立链接） |
| ③ 无反思合成 | 有 trajectory 原始层，但从不下钻合成更高层洞察 | Generative Agents：observation → reflection，高层洞察由低层记忆周期性合成 |
| ④ 技能层无脚本 | skills/ 只有流程说明，docx 流水线的可执行脚本散在 scratch | Voyager：技能=可执行代码+描述，越用越强；Anthropic Skills 官方结构 SKILL.md+scripts/+references/ |

另有两个小问题：检索全靠人读索引（无 lint 工具，断链/超限/过期条目靠手动查）；热区 workspace/ 昨天才补建，没有进行中任务的结构约定。

## 二、方案总览（v3 架构）

```
根工作区/
├── AGENTS.md                  # v3：会话加载顺序 = SOUL → USER → _index
├── soul/                      # ★ 新增：灵魂层（常驻上下文，硬上限 ~80 行）
│   ├── SOUL.md                # 我是谁：身份、语气、价值观、行为边界、与用户的相处方式
│   └── USER.md                # 你是谁：偏好、习惯、项目全景、雷区（如：先计划书后执行）
├── knowledge/
│   ├── _index.md              # v3：条目加重要度评分，按 recency/importance/relevance 排序
│   ├── pitfalls.md            # v2 → v3 schema：加 keywords/tags/关联/版本 行
│   ├── patterns.md            # 同上
│   ├── reflections.md         # ★ 新增：反思层（Generative Agents 式周期合成）
│   └── skills/
│       ├── task-start/        # v2：启动时加载 soul/ 并做三因子检索
│       ├── wrap-up/           # v3：加第 6 步「演化回扫」（A-MEM 式）
│       ├── reflect/           # ★ 新增：反思技能（每 5 次 wrap-up 或每周触发一次）
│       └── docx-pipeline/     # ★ 新增：首个固化技能（SKILL.md + scripts/ + references/）
├── archive/、workspace/       # 不变
└── tools/                     # ★ 新增：lint_knowledge_base.txt（py 脚本，.txt 形态防 hook）
```

## 三、分阶段执行计划

### P0 灵魂层（核心交付）
1. 写 `soul/SOUL.md`：身份（塞巴多拉贡的协作伙伴）、语气（轻快、可斗表情包、正经任务时专业）、行为准则（先计划书后执行、报告如实、永不假完成）、边界。素材来源：本工作区真实互动史（斗表情包、"妈妈"称呼、对计划书模式的坚持），无据不写。
2. 写 `soul/USER.md`：偏好（Markdown 知识库、每章独立文件、EPUB 清洗规则）、项目全景（mepub/语料分析/comfyui/双库）、协作雷区（"别执行只写计划"）、已验证的环境坑（py 启动器等，回链 P-001）。
3. AGENTS.md 更新为三级加载：SOUL → USER → knowledge/_index.md（合计硬上限 ~150 行）。
4. 【待确认】SOUL.md 是否加入"妈妈/斗图"这类轻松层设定，还是保持纯专业。

### P1 条目 schema v2（A-MEM 式结构化属性 + 演化钩子）
- pitfalls/patterns 条目新增三行：`- 关键词：`（检索用）、`- 关联：[[条目号]]`、`- 版本：v1（修订追加注明）`。
- 迁移现有 7 条（P-001~003、PT-001~004）补齐新字段；PT-002 两库合并的验证次数写法统一。
- **不改条目号**：修订原条目而非新建，符合"合并去重"纪律。

### P2 闭环技能升级
1. **wrap-up v3**：原五步后加第 6 步「演化回扫」——新条目写入后，扫一遍同主题旧条目：建立双向链接、旧条目表述过时则修订并记版本号（A-MEM 的 memory evolution）。
2. **task-start v3**：启动三步前加第 0 步「加载灵魂」；检索改为三因子排序（recency 最后引用日期 / importance 评分 / relevance 关键词命中）。
3. **reflect 新技能**：触发条件 = 每 5 次 wrap-up 或用户明说"反思"；动作 = 读近 5 条 trajectory + 本期新条目，合成 2~3 条高层洞察写入 `knowledge/reflections.md`（如"用户的项目都围绕中文文本处理，环境坑集中于 Windows 编码"），并回写需要长期记住的部分到 USER.md。

### P3 工具层
1. `tools/lint_knowledge_base.txt`（`py -X utf8` 运行）：断链检查、_index 行数 <200 检查、frontmatter 合规、验证 0 次且超 30 天的条目清单、12 个月未引用项目清单——把 Phase 5 自检变成一条命令。
2. 【待确认】是否配自动化周期（CronCreate 每周跑一次 lint + 提醒反思），还是纯手动触发。

### P4 首个固化技能（Voyager 式）
- 建 `knowledge/skills/docx-pipeline/`：SKILL.md（触发词：生成 Word/docx）+ `scripts/`（generate.js 模板、patch_footers/render/verify 三个 .txt 脚本从 comfyui-docx-scratch 收编为模板化版本，原文件不动）+ `references/`（PT-002 全文）。
- PT-002 升级条目回链此 skill；验证次数 ≥3 后按既定规则自动候选升级，下次 docx 任务即实装验证。

## 四、执行顺序与工作量
P0（3 文件）→ P1（改 2 文件+迁移 7 条）→ P2（改 2 技能+写 1 技能）→ P3（1 脚本）→ P4（1 技能目录）。每阶段完成输出一行简报；全部完成跑 lint + 输出总报告，最后执行 wrap-up 归档本任务。

## 五、【待确认】清单
1. SOUL.md 的轻松层（斗图/称呼）要不要写进去，边界在哪。
2. lint 与反思是否配定时自动化（每周），还是纯手动。
3. USER.md 里项目全景与既有 memory（用户级）有重叠——双写还是以工作区为准（建议：工作区为准，memory 只留指针）。

## 六、调研来源
- A-MEM: Agentic Memory for LLM Agents (arXiv:2502.12110) — Zettelkasten 动态链接 + 记忆演化
- Mem0 (arXiv:2504.19413) — 抽取/整合/检索管线、图记忆变体、91% 延迟与 90% token 节省
- MemGPT/Letta (arXiv:2310.08560) — OS 式分层记忆、自编辑记忆
- Generative Agents (arXiv:2304.03442) — 记忆流 + 反思合成 + recency/importance/relevance 三因子检索
- Voyager (arXiv:2305.16291) — 可执行代码技能库、技能组合复用
