## 第 1 章 P0

### H-001 渲染件版本升级通道（v3.3 现场发现 #1）
- 【问题】build-docs 只刷 spec/速查/citations；AGENTS.md/README.md 仅 install 时渲染。包升级后（VERSION 变→渲染内容变）校验模式必报「渲染件被改」，且无合法更新路径——v3.3 当场只能用渲染函数手工重写过渡。
- 【修复】build-docs 增 `--lib <库>` 模式：读 state.json 的 level，重渲染并落盘 AGENTS.md/README.md（渲染产物由包生成=合法，公理 B）；校验模式配合不变。
- 【回归】install → 模拟版本差异 → build-docs --lib → 校验模式渲染件清零。

### H-002 宿主痕迹豁免策略（v3.3 现场发现 #2）
- 【问题】ZCode 宿主跑命令时往库目录写 `.v2c/plugin_root`，校验模式按外来文件报「未在册」——技术上正确（该报），但宿主痕迹会随每次会话出现，成为常驻噪音。
- 【裁决点 D1】a（推荐）隐藏目录/`.v2c` 类已知宿主目录从「未在册」剔除，但**单独输出 [环境痕迹] 行计数**（如实呈现，不当噪音）；b 全报维持现状；c 直接忽略不报（违背如实纪律，不推荐）。
- 【回归】构造 .v2c → 校验模式显示 [环境痕迹] 且不进未在册计数。

### H-003 反思合成的承载（L5 语义补全）
- 【问题】importance_accum 触发反思提示后（库调试v3.2 已两次触发），「反思合成」在 v3 引擎无任何承载——触发有机器、合成靠默契，L5 档名不副实。
- 【修复】`engine reflect --lib .`：**取材打包器**（单文件边界的诚实形态，同 referee 模式）——收集触发原因、importance_accum 值、近期 append 清单、高 importance 条目全文 → 产出 `memory/reflect/materials-{ts}.md`；LLM 合成由 harness 执行（提示词内嵌），合成结果走 `engine append`（id=R-xxx）入账。不做引擎内 LLM 合成（CLI 无法 spawn 模型——骨架诚实声明②同源）。
- 【回归】设 accum 越线 → reflect 产出素材文件，含触发原因与 ≥N 条素材。

## 第 2 章 P1

### H-004 迁移器收编（裁决点 D2，推荐收编）
- 【背景】migration_v4_to_v3.txt 是一次性工具（M6 裁决），但「真实存量库 migrate」迟早要跑（v4 根工作区、其他 v4 库），每次手改路径易错且无守恒保证。
- 【修复】收编为 `absorb-md` 子命令：`absorb-md --src <v4根> --lib <v3库>`——v4 Markdown 条目解析器（P/PT/R/D 四格式+soul 指针+轨迹索引）内置，守恒断言+监测报告随行（v3.3-2 验证的配方固化）。一次性工具退役入 legacy。
- 【回归】对根工作区跑 absorb-md --dry-run：解析条目数=22+模板跳过 2（与库调试v3.2 迁移对账一致）。

- 【问题】golden_queries.json 还在 workspace/v21-rev/，install 不落 evals/；eval 的 misses 无诊断信息；无 v2.x 基线参照（recall@5=0.455）。
