## 二、L8 设计原则（从 DGM 提炼的三条铁护栏 + 一条逃生舱）

1. **变体档案制**：一切自改只写 `mutations/candidates/`，永不直接改 live 模板；晋升=用户明示批准后复制（旧版进 attic）。
2. **实证基准制**：每个变异候选必须跑 `run_tests.txt`（13 断言基准）+ lint，分数写进台账；破坏基准的变异自动否决。
3. **人类令牌制**：任何 candidate→live 的晋升、任何条目降级，都走用户裁决，agent 不得自批。
4. **逃生舱**：删除 `experimental-l8/` 与 `mutations/` 即回退 L6/L7，主库无损。

## 三、六个 L8 模块（exp8-*）

### 1. exp8-constitution（L8 宪章 + 卫兵脚本）★ 必装基座
- **做什么**：`L8-CONSTITUTION.md`（上述三护栏+逃生舱的正式条文）+ `l8_guard.txt` 脚本：①校验 mutations/ 台账与 live 树哈希分离 ②校验每个 candidate 附带基准分 ③校验 lifelog 哈希链完整 ④拦截对 live 模板的未授权就地修改（检测到即报告）。
- **依据**：DGM「sandboxing + human oversight」；本库 manifest 哈希体系扩展。
- **验收**：T11/T12。

### 2. exp8-mutation-engine（变异引擎 · DGM 移植 · L8 旗舰）
- **做什么**：月度睡眠任务中，agent 依据**使用遥测**（哪些模板被抄最多/哪个 install 步骤反复被问）提出**一个**机器变异：改某模板措辞/加某 install 子步骤/简化某 SKILL 段落。变异以 diff 形式写入 `mutations/candidates/{MUT-001}/`（含动机、遥测证据、基准分），跑基准后进台账等裁决。被否决的候选永久归档（DGM 垫脚石：今天的废案可能是明天的垫脚石）。
- **护栏**：单次一个变异；必须有遥测证据不得凭空变异；未批准永不生效。
- **依据**：DGM 变体档案+实证验证；Self-Evolving survey「进化工具/架构」列。
- **验收**：T8（故意提交破坏基准的变异 → 自动否决，live 树哈希不变）。

### 3. exp8-council（心智议会 · society of minds）
- **做什么**：reflect 升级为四席位辩论——**档案官**（证据说了什么）、**批评家**（哪里夸大/无据）、**梦想家**（跨域狂想，承接 dream-fusion）、**用户代言人**（miza 会怎么反应，读 soul/USER.md）。两轮：各席位首轮独立写 → 互读修订 → 综合报告 + **少数派异议保留**（不许被综合吞掉）。
- **护栏**：默认同一 agent 分饰（便宜模式，token 预算 2 轮封顶）；强 harness 可选真子代理模式。
- **依据**：Multiagent Debate（多实例辩论提升事实性）。
- **验收**：T9（产出四席位+综合+少数派三件套，格式齐全）。

### 4. exp8-lifelog（全息轨迹 · 哈希链）
- **做什么**：每次 task-start/关键决策/wrap-up 追加一行到 `knowledge/lifelog/{YYYY-MM}.mdl`，每行含前一行的 sha1 —— **防篡改记忆链**。月度 lint 校验链条完整性。这是 L8 自改的信任锚：机器变异的台账同样入链。
- **护栏**：append-only；lifelog 永不进常驻上下文（仅审计与反思取材）。
- **依据**：MemOS「记忆是一等资源」的完整性面；Zep 双时态（有效时间）简化实现。
- **验收**：T11（篡改任意一行 → l8_guard 报断链位置）。

### 5. exp8-tournament（知识锦标赛 · 达尔文选择压）
- **做什么**：检索工具每次命中时追加 `usage.log`（条目号+日期）；季度睡眠任务跑锦标赛：按命中率排序，末位四分之一的 pattern 被「合并挑战」（agent 起草合并案）或「冷置提案」（移 archive 标 superseded）——**用选择压防库腐化**，替代纯人工清理。
- **护栏**：只降级不删除；降级必须用户批准；新条目 30 天豁免（防新条目被饿死）。
- **依据**：MemoryBank 遗忘曲线的主动版；DGM 选择压思想。
- **验收**：T10（伪造 usage.log → 末位识别正确、降级仅为提案、零删除）。

### 6. exp8-twin（用户数字孪生 · 预演 oracle）
- **做什么**：soul/USER.md 之上建 `soul/TWIN.md`（决策偏好模型，从 USER+相处记录提炼）；**每次提交计划书前，agent 先用 TWIN 预演「miza 的三个最可能反应」并在计划书末尾列【孪生预演】节**——把用户常拍的那种「再加点激进的/额度要用满」提前自己拍。每次预演后记录命中/落空，TWIN 自校准。
- **护栏**：仅咨询不代行——TWIN 永不替代真实用户确认；预演必须显式标注，不许冒充用户意见。
- **依据**：Generative Agents 的 agent modeling 面；本库 5 轮互动史可作初始语料。
- **验收**：本计划书末尾就带第一个【孪生预演】（ dogfood ）。
