## 第 1 章 P0（建库能力与诚实性）

### V-001 install 不落地内容体（功能头号缺口）
- 现状：install 只建目录骨架 + state.json + audit 链 + 渲染 spec/速查；**bodies 里 131 个内容体一个都没复制到 target**——mods 只是名字清单。engine 能跑是因为脚本自包含，但「建库」产物不含任何模板/工具/SKILL，建库语义不成立。
- 修复：install 按 MODULE_MAPPING 从 bodies 复制模块文件到 target（保持 v2.x 相对路径结构）；附 {{SLOT}} 填槽清单输出；复制后重算 Merkle 根写回 state.json。
- 验收：T 号新增——install L2 后 target 下存在 modules/m-tools 的 lint/search 脚本与 m-core 骨架文件，且与 bodies 的 sha256 一致。
- 回归锚点：t_install_delivers_bodies（常驻）。

### V-002 特色包名映射缺失
- 现状：PACKAGES 语义名（x-roleplay/x-writing）与 v2.x 目录名（packs/x-rp、packs/x-writer）无映射；--packages x-roleplay 时包内容体无法定位。
- 修复：增补 PACKAGE_MAPPING（x-roleplay←packs/x-rp、x-writing←packs/x-writer、其余同名）；absorb 校验双侧路径存在。
- 验收：install L2 --packages x-roleplay 后 target 含 x-rp 内容体；t_absorb_mapping 扩展双侧。

### V-003 verify 离线 error 被静默吞掉（诚实性）
- 现状：urllib 异常时 report[aid]={"error":…}，既不算 mismatch 也不提示——离线跑 verify 输出「对账 14 条，不一致 0」，看起来像全部核验通过，实际一条都没对上。
- 修复：报告三态分离（match/mismatch/error=未对账）；汇总行分别计数并显式打印「未对账 N 条（离线？）」；error 不许计入「通过」。
- 验收：断言——mock 网络异常时 verify 输出含「未对账」且退出码/汇总不显示零不一致的误导表述。

### V-004 retrieve 对坏时间戳全库崩溃
- 现状：`time.strptime(e["created_at"][:10], "%Y-%m-%d")` 无容错——一条 created_at 格式坏的条目让整个 retrieve 抛 ValueError。
- 修复：单条解析失败降级 age=0 并在输出行标注 [bad-ts]； retrieve 顶部累计坏条目数汇报。
- 验收：注入坏时间戳条目后 retrieve 正常返回其余条目且含 bad-ts 标注。
