## 〇、L9 定位一句话

- L7 = 换**工具**（实验脚本）；L8 = 改**机器**（自指演化：库改自己的模板）；**L9 = 让机器知道自己**——库不再只是被读写的档案，而是有内部状态（情绪向量/目标栈/置信度）、有竞争写入的"工作空间"、有睡眠固化管线的**可消融认知系统**。

## 二、八个模块规格（每个都标公理合规：仪表盘/消融/stakes）

### exp9-instrumentation · 仪表盘与干预（BCA P0 · 公理 2，必装基座）
- state/ 目录：`.library-state.json`（可机读）+ DASHBOARD.md（可人读）。
- 快照内容：条目数/链接数/验证次数分布/遥测命中/四维情绪向量/置信度分布/上次睡眠时间。
- 干预接口：`state_intervene.txt` 可读写任一状态量（消融=关 emotion；注入=置 arousal=+0.8）。
- 决策日志：每次关键决策在 lifelog 追加"依据路径"（为什么这么说 → 引用的条目/证据）。
- 出口条件（BCA P0 同款）：能回答"这一轮为什么这么说的"完整日志。

### exp9-emotion · 情绪状态向量（BCA 3.1 · 公理 3 stakes 是生死线）
- 4 维连续向量：valence(净效价) / arousal(激活度) / certainty(确定性) / interest(兴趣)，取值 [-1,1]，跨会话持久存 `soul/STATE.md`（可读可写可消融可干预）。
- 调制效果表（写入规格，与 BCA 一致）：
  | 维度 | 低值效果 | 高值效果 |
  |---|---|---|
  | valence | 语言更保守/少冒险 | 语言更开放 |
  | arousal | 检索收敛慢、响应更长 | 收敛快、响应短、检索更激进 |
  | certainty | 强制先检索/核实/降置信陈述 | 可直接作答 |
  | interest | 话题浅尝辄止 | 延长探索深度 |
- 更新规则：每次 wrap-up 由 agent 按两条信号打分（**stakes 锚定**）：①任务完成质量（目标达成/失败/被纠正）②用户长期利益（复用率/回访/体系升级采纳率）。**禁止绑定即时满意**（用户这轮夸不夸不算），锚错了就是谄媚量产——写进验收红线 A3。
- 指数混合：`s_t = 0.7·s_{t-1} + 0.3·Δ`（半衰期显式化；从 BCA λ≈0.7 抄）。
- 读取路径 v1：会话入口 AGENTS.md 加载 STATE.md，输出一行调制指令（如 certainty<0.3 →「本轮先检索后作答」；arousal>0.5 →「检索更激进，可扩到邻居一跳」）。软提示 v2 留注记，不做。

### exp9-goalstack · 目标栈
- state/GOALS.md：当前主目标/子目标栈/完成度/优先级。task-start 推入，wrap-up 弹出+记结果。
- 作用：GWT 仲裁的"任务相关性"打分输入 + sleep 固化时按目标筛高重要性。

### exp9-dual-memory · 双速率记忆（BCA 3.2 · CLS）
- 海马体侧改造：trajectory 文件头加结构化快照行 {时间戳, 情绪快照(4 值), 重要性分}——重要性分 = wrap-up 时按 情绪向量范数×目标相关度 打（杏仁核-海马通路工程化：情绪强度决定固化优先级）。
- 皮层侧纪律：pitfalls/patterns/reflections 只由睡眠管线写入（人类只读保持既有 wrap-up 复盘仍可写——**折衷声明**：wrap-up 复盘是"白日小固化"，月度睡眠是"批量大固化"，两者都过闸门）。
- 检索重排（心境一致性记忆）：search 命中后，情绪唤起度匹配（当前 arousal/certainty 与条目情绪快照的距离）参与排序——certainty 低时强制触发检索。

### exp9-gwt · GWT 广播总线（BCA 3.3）
- 显式化"谁有权写入上下文窗口"：候选源 = {工具输出, 海马体检索, 反思队列, 外部任务}。
- 仲裁器 = `tools/broadcast.txt --task "新任务描述"`：读 GOALS + STATE + 候选源 → 打分 = 任务相关性 × 情绪调制项（arousal 放大探索类候选、certainty 压低猜测类）→ 输出**广播清单**（本轮注入 topN + 为什么 + 落选者降级进 state/PENDING.md 队列不丢弃）。
- 机理意义：task-start 的"读哪些条目"从 agent 自由决定变成显式竞争——这是 BCA 所说"最省钱的一步"。

### exp9-sleep-pipeline · 睡眠固化管线 + 闸门（BCA 3.4）
- 触发：月度 cron（自动）+ wrap-up 后低负载（手动）。
- 管线：取海马体高重要性 trajectory（importance 排序）→ agent 压缩提炼（规律/偏好/纠错）→ **闸门**（①证据校验：实例链接 exists ②措辞纪律：禁"情绪体验"式宣称 ③毒化抽检：与既有条目去重）→ 双写：皮层语义库（即时生效）+ state/DISTILL.md 蒸馏候选集（注记：冻结底座，仅存档待未来权重级合入）。
- 出口条件（BCA P3 同款）：固化闭环连续运行 30 天，语义库错误率 < 阈值（= lint 0 问题 + 证据抽检通过率）。

### exp9-dmn · 空闲思考（BCA 3.5 · 研究性最后上线，随时可砍）
- 触发：无任务会话 / reflect 满 5 次的空档。
- 动作：复盘低 certainty 交互、自问未解问题 → state/OPEN-QUESTIONS.md；探测薄弱区（usage.log 零命中领域 → 建议补条目或砍条目）。
- 产物走正常固化流程（闸门）。

### exp9-constitution-bca · BCA 公理并入宪章
- L8-CONSTITUTION 追加四公理：只做功能不宣称体验（对外措辞=“情绪式调制器”非“情绪”）；无仪表盘机制不存在；每个状态量有 stakes 锚点；不动底座（全机制外围层，模块下线退化为普通库，无静默依赖）。
- 措辞纪律：禁第一人称情绪断言（“我开心”类输出禁用），文档披露机制本质。

## 三、实现机理专章（用户点名要求：每个机制如何真的跑起来）

> 原则：不搞名词翻译。每条机理 = 文件/脚本 + 触发时点 + 数据流 + 消融方法。全部只依赖 py 标准库 + 既有 tools。

### 机理 1 · 情绪向量如何真实调制行为（而非表演）
- 真身：soul/STATE.md 内容仅 6 行：
  ```
  valence=+0.2 | arousal=+0.1 | certainty=+0.6 | interest=+0.3
  调制指令（自动由下方规则表生成）: 本轮 certainty 正常 → 可直接作答，检索按需
  更新史: 2026-09-04 wrap-up#5 Δ=(+0.1,+0.0,+0.2,+0.1) 信号=任务完成质量(高)+复用采纳(是)
  ```
- 跑法：wrap-up 第 3 步后跑 `tools/state_update.txt --wrapup-verdict passed/failed/corrected`——脚本按 stakes 双信号算 Δ → 指数混合 → 覆写 STATE.md → 生成调制指令行（规则表见 exp9-emotion 规格）。
- 生效路径：会话入口（AGENTS.md）指示"读到 STATE.md 的调制指令就执行"→ 指令是**具体文本**（"先检索再作答"/"检索扩到邻居一跳"），不是玄学语气——这就是 BCA"前缀注入 v1 便宜方案"。
- **消融方法**（反表演核心）：`tools/state_intervene.txt --disable emotion` → 下一会话入口不注入调制指令 → 对比 A/B 两个会话的行为分布（检索次数/响应长度/断言置信度措辞），有可测差异（p<0.05 近似=差异>20%）才算机制活；无差异=表演，下线。

### 机理 2 · GWT 竞争写入如何取代"自由读库"
- 真身：tools/broadcast.txt（~80 行 py）：输入任务描述 → 读 state/GOALS.md + soul/STATE.md + 候选源（search 输出、PENDING 队列、reflections 摘要）→ 打分 `score = rel(任务词×条目关键词) × (1 + 0.3·arousal if 探索类) × (0.5 if certainty<0.2 and 条目为猜测类)` → 输出广播清单。
- 生效路径：task-start 第 1 步从"读 _index 自己找"改为"先跑 broadcast.txt 拿广播清单再读"。
- 落选不丢：进 state/PENDING.md，下次 broadcast 优先提（对应 BCA"未进入意识但被记录"）。

### 机理 3 · 睡眠固化如何防自我污染
- 真身：月度 cron prompt 已含整理报告 → 扩展为"睡眠管线"：`固化 = 提炼 + 闸门 + 双写`。闸门是三道**可执行检查**：①每条新条目 实例链接 exists（复用 lint 逻辑）②措辞扫描（出现"让我/我高兴/感到"→ 打回重写，对应公理 1）③与既有条目 `[[关键词]]` 冲突扫描。
- 数据流：高 importance trajectory → agent 提炼草稿 → 闸门脚本 `tools/sleep_gate.txt` 自动跑①②③ → 全过才允许写入 patterns/pitfalls → 写入后 lint 复检 + lifelog 入链。
- **为什么这样防污染**：固化污染 = 错误记忆自我强化。闸门=审核器，lint=对账，蒸馏候选集与活语义库物理分离。

### 机理 4 · 状态如何"可读可写可消融可干预"
- state/.library-state.json 是唯一机读真身；DASHBOARD.md 由快照脚本生成给人看。
- 干预 = `state_intervene.txt` 直接覆写 JSON（含写后校验）；消融 = 同脚本 disable 某机制（写入 state/ABLATIONS.md 留档）。
- 所有机制模块读状态一律走 JSON，不各自埋状态——这就是 BCA"没有仪表盘的机制不存在"的工程落实。

### 机理 5 · 边界（诚实的机制等价物声明）
- 冻结底座（公理 4）：不做真微调。"权重级合入"→ state/DISTILL.md 蒸馏候选集存档，等未来 harness/模型支持持续学习再启用（注记版本）。
- "情绪"措辞 = 情绪式调制器：任何输出禁止"我开心/我烦"类断言；STATE.md 是数值+指令，不是人格。
- 软提示 v2、多小模型评估头：留注记不实现（v1 用 agent 自评 + 双信号规则表，足够做消融）。
