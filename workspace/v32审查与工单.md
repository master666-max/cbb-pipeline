## 第 1 章 方向性裁决（最重要，先拍板）

### C-000 双语义并存：交付的库是「v2.x 文件堆放处 + v3 引擎」，还不是真正的 v3 库
- 【证据】install 交付的 131 个内容体全部是 v2.x 语境写的：install.md 指南教的是「复制 template/ 到 state/、跑 tools/lifelog_append.txt」这类 v2.x 路径；而 v3 库结构是 memory/audit/ledger。落地后两套路径互不认识。同时 v3 没有自己的会话入口（AGENTS.md 三级加载）、没有 task-start/wrap-up 技能接线——库建好了，harness 不知道怎么用它。
- 【三个方向】
  - **a（推荐）v3 原生内容体渲染**：由 SOURCES（LAWS/CHARTER/LEVELS/PACKAGES/SCHEMA）渲染出 AGENTS.md 入口、wrap-up/task-start 技能、README——公理 B「文档即产物」的自然延伸，内容体也应是产物；v2.x 内容体降级为 references/legacy 参考（不再作为运行时交付）。
  - b 双轨兼容：保持 v2.x 内容体交付 + 附 v3 引擎接线说明（快，但语义含混永久化）。
  - c v3 轻库形态：承认 v3 是极简「引擎优先」库，砍内容体交付，只留 memory/audit/ledger + 渲染文档。
- 【影响面】决定了 C-016 入口文件、C-015 技能接线、以及 v3.2 工作量的大头。

## 第 2 章 代码级缺陷（P0/P1）

### C-001 install 空库静默成功（P0）
- 【证据】`_deliver` 在 bodies 缺失/未 absorb 时交付 0 个文件，install 照常 exit 0 打「交付内容体 0 个」——新用户不跑 absorb 直接 install，得到空库且看起来成功。
- 【修复】交付数=0 → sys.exit「bodies 为空：先跑 absorb（用法见 docstring）」；测试：无 bodies 时 install 必须拒绝。

### C-002 Merkle 根口径不一致（P0）
- 【证据】install 的根算在 cmd_build **之前**（不含 spec/速查渲染件），也不含 state.json（当时还没写）；wrapup 的根含渲染件与 state.json——同一库两个时点的根口径不同，人侧对账必然误报漂移。
- 【修复】定稿口径（建议：根 = 内容体 + 审计链 + 渲染件 + manifest，state.json 排除——它是根的持有者不能自含）；install 重排：deliver → build → 写 state（无根）→ 算根 → 回写 state → 打印。测试：install 后立即用抄录根重算比对一致。

### C-003 manifest 漏账 referee（P1）
- 【证据】`_deliver` 中 referee 写盘后只改了内存 manifest dict，**没有回写 .library-manifest.json**（SOP 守卫段那段有回写，referee 段漏了）→ 在册清单缺 references/referee.md。
- 【修复】referee 写盘后回写 manifest；测试断言 manifest 含 referee 条目。

### C-004 幂等校验不查未在册文件（P1）
- 【证据】install 校验模式只遍历 manifest 在册文件查漂移；往库里塞新文件不报——防篡改语义有缺口（Merkle 根能兜住但校验模式没对根）。
- 【修复】校验模式加两步：重算 Merkle 根对 state.json 的 root；列出未在册新文件清单。测试：构造塞入文件 → 校验模式必报。

### C-005 公理 C 落地缺口：ledger/changes.jsonl 无人写（P1）
- 【证据】公理 C 说「每库唯一 ledger/changes.jsonl；延期不填目标版本=不合法」，但 install 不建、engine 不写——账本只有 audit 面，changes.jsonl 是纯概念。
- 【修复】install 建空账本；engine append/wrapup/retire/shadow 与 install 变更全部追加一行（时间/动作/对象/来源事件）；「延期登记」字段随行。

### C-006 L8 变异守卫运行时缺位（P1）
- 【证据】宪章三守卫目前只有文本 + SOP 关键词断言（t_l8_guards），没有机械执行者——v2.x l8_guard 的 v3 对应物不存在：没有任何命令去检查「变异 diff 是否触碰基准文件」「锚定表是否对得上」。
- 【修复】新增 `guard` 子命令：输入候选 diff（目录/文件），机械检查①触及基准黑名单即否决 ②基准文件哈希对锚定表 ③SOP 守卫段在位。测试：触碰 run_tests 的 diff 必被否决（X-010/T49 的 v3 真正落地）。

### C-007 importance 阈值未定义，累计器空转（P1）
- 【证据】V-015 的 importance_accum 只累计不判定；TUNABLES.reflect_trigger 主轨写「importance累加超阈值(主)」但阈值无数值。
- 【修复】TUNABLES 定阈值常量（建议 importance_accum ≥ 50 触发反思提示，来源标「拍脑袋，待校准」）；wrapup 时检查并输出触发提示。测试：累计越线 → wrapup 输出反思触发。

### C-008 unverified_ttl 语义半落地（P1）
- 【证据】TUNABLES 的 unverified_ttl_days=90 名义管「未验证」，但 SCHEMA_V3 没有「已验证/未验证」状态，retire 只实现 t_invalid 出仓一半。
- 【修复】二选一：a) validity 扩 unverified 时间戳语义；b) 改名 invalid_ttl_days 如实收窄。推荐 b（最小真相）。

## 第 3 章 架构与质量项（P2）

### C-009 检索零评测：evals/ 空置（P2）
- 【证据】install 建 evals/ 目录但无任何评测脚本；v2.x 的 golden 33 条与 eval_retrieval 未吸收；migrate 承诺的「parity 门 recall@5 ≥ 基线−0.03」无执行者。
- 【修复】吸收 v2.x 评测集（workspace/v21-rev/golden_queries.json 33 条在案）做 v3 retrieve 基线评测，parity 门可执行化。

### C-010 检索质量回退：无关键词加权、无 [[扩散]]（P2，与 C-000 联动）
- 【证据】v3 retrieve = content 子串 ×2 + importance − 时间衰减；v2.x 的关键词 ×3/标题 ×2/正文 ×1 + [[双链]]一跳扩散全部丢失，而 v3 的 SCHEMA_V3 八字段**没有 keywords/links 字段**——检索质量天花板被 schema 锁死。
- 【修复】随 C-000 裁决：a 方向则 SCHEMA_V3 扩 keywords/links（十字段，migrate 兼容旧条目回填空值）。

### C-011 L5 反思在 v3 无承载（P2）
- 【证据】referee 提示词随包了，但 reflect 流程（计数→合成→落盘 R 条目）在 v3 引擎无操作、无声明——L5 档语义弱化成「只有情绪衰减」。
- 【修复】随 C-000：a 方向则渲染 reflect 技能文件 + engine 反思计数（已有 importance_accum 可作触发源，接 C-007）。

### C-012 absorb 非镜像语义（P2）
- 【证据】重跑 absorb 是 merge：源树删掉的文件在 bodies 里残留旧条目（含已删除内容），抽取数只增不减。
- 【修复】absorb 改镜像：本轮未命中的旧 key 移入 bodies 的 "removed" 区并报告（不静默消失，符合铁律 1）。

### C-013 absorb-pending 题录回填无数据源（P2）
- 【证据】13 条 pending 题录的回填靠手工改 REGISTRY——v2.x 的完整题录在说明书 content2.js 里，不在源树，absorb 抽不到。
- 【修复】把 v2.x 终版题录（A1-A33）作为常量或数据文件进包（v3 原生内容，对齐 C-000 a 方向），absorb 后自动回填 pending，再 verify 对账。

### C-014 六个新增包无模板（P2，task-014 候选）
- 【证据】x-game/x-learn/x-lab/x-life/x-term/x-sec 只有语义声明，install 提示「模板待建」。
- 【修复】每包最小模板三件（README+账本头+一个示例条目），由渲染生成（对齐公理 B）。

### C-015 错误路径风格不统一（P2）
- 【证据】migrate/append 的 assert 与 json.loads 异常会裸 traceback，与其他命令的 sys.exit 友好信息不一致。
- 【修复】统一 sys.exit 中文可读信息 + 退出码约定（0 成功/1 断言失败/2 依赖与网络）。

### C-016 v3 库会话入口缺位（随 C-000 裁决，列此备忘）
- v3 库建好后 harness 的入口文件（AGENTS.md/CLAUDE.md）、三级加载、技能路由均不存在——C-000 a 方向的第一交付物。
