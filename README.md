# cbb-pipeline · 把百万字长篇小说，整成一部"查得到出处"的正典资料库

> 一句话：**让 AI 一章一章读完整本书，把设定、人物、伏笔全记下来，每条都带原文出处，拿不准的绝不混进正式库。**

## 它治什么病

用 AI 提取小说设定有个死结：书太长（百万字级），AI 一次读不完；读完后面的，忘了前面的——于是：

- 同一个人换了个名字就当成两个人（别名对不上）；
- 第 50 章埋的伏笔，第 400 章忘了回收，没人发现；
- 前后设定矛盾（人明明死了又出场），谁都不知道。

任何"一口气读全书"的方案都会栽在这上面。这个工具换了个思路。

## 它怎么治（四句话）

1. **一章一章读**：AI 每次只读一章 + 一页自动生成的"前情提要"（谁是谁、还有哪些伏笔没结）。不靠记性，靠账本。
2. **每句话都要出处**：所有记录都附原文引用（第几卷、第几章、第几行、原文那句）。任何时候能翻回去对质。
3. **拿不准的不入库**：每一条信息分三种状态——**确认 / 暂定 / 待人工裁定**。相互矛盾的、证据不足的，一律进"待审区"列清单等人看，宁可多问、绝不混进正式库。
4. **全书画完自动对账**：自动扫一遍全书——谁死了又出现、哪些伏笔埋了没收、哪些引用翻不到原文，一次性列清楚。

## 产出是什么

一部可随时查询的正典资料库：**人物、关系、事件、伏笔**，全部带原文出处。适合：

- 连载小说的世界观管理（写作时查"这个设定在哪章写的"）
- 续写/同人的一致性检查
- 角色卡、世界书、年表等下游产品制作

## 怎么用（三步）

```bash
# 1. 安装（放进 AI 助手的技能目录，或直接在项目里用）
cp -r . ~/.zcode/skills/cbb-pipeline

# 2. 配置：复制模板，填书名和正文文件路径
cp assets/project.template.yaml project.yaml

# 3. 开跑：生成"书房"骨架，然后按 SKILL.md 的流程一章章推进
py -X utf8 scripts/init_project.py project.yaml
```

## 里面有什么

| 位置 | 是什么 |
|---|---|
| `SKILL.md` | 使用说明（流程 + 注意事项）——AI 助手会自动读它 |
| `scripts/cbb/` | 六个核心程序：切章标号 → 时间轴整理 → 逐章提取 → 入库前检查 → 待审区分流 → 入库 |
| `scripts/cbb/tools/` | 辅助工具：前情提要生成、相似条目查重、图数据库导出、防篡改记账、矛盾预筛等（各带测试） |
| `references/` | 详细规则：提取规范、检查清单、争议裁决办法 |
| `assets/` | 配置模板 |

## 靠谱吗

- 所有程序带自动化测试；已在一部 **517 章连载小说**上完整跑通
- 每条记录可追溯原文；矛盾或证据不足的**不会静默进入正式库**
- 不要求你信任工具——每条结论你都能翻原文自己验证

## 关于名字

内部资料里会看到一些简称，对照表在此：

| 简称 | 人话 |
|---|---|
| 证据四元组 | 卷 / 章 / 行 / 原文引句 这四样必填 |
| 三态 | 确认 / 暂定 / 待人工裁定 三种状态 |
| 待审区（隔离区） | 拿不准的信息的"待办清单"，等人裁决 |
| 门 1（gate1） | 入库前的自动检查（格式、引用、时间、前后一致性） |
| cbb-coordinate / cbb-anchor / cbb-extract / cbb-gate1 / cbb-quarantine / cbb-store | 上面那六个核心程序各自的代号 |
