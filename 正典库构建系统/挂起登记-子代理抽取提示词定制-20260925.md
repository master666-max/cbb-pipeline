## 现状备忘（挂起时的机制基线）

现行抽取提示词是**静态三层、无 LLM 定制**：
1. **共享规范**（`references/抽取规范.md`）：R6 四面防御 / 契约 / 别名四分类 / 引文预检 / 封套纪律——每子代理必读，全单元同一份；
2. **每单元差异只来自上下文包**（`context_pack.py`）：库内相关既有事实 + 判例 + 原文切片——材料随单元变，提示词措辞不变；
3. **代码内嵌闸**（`cbb_extract` 四面 + gate1）：确定性代码，不依赖提示词。
另：Graphiti 摄入提示词 v2（quote 逐字锚点/禁跨事件补名/事件独立）为同类静态件，版本号走 git。

## 重开条件（任一满足即可提请）

1. 某类文本对象的抽取质量**持续不达标**，且证据指向提示词不适配（而非模型能力/原文本身问题）——例如同一类场景连续两个批次在 gate1 的拒收率显著高于其他类；
2. 语料中出现成规模的新文本形态（如整卷系统面板文/诗歌体章节），静态规范覆盖失效；
3. 用户显式重开。

## 已知代价（重开时先答）

LLM 定制提示词 = 用一次 LLM 调用生成另一次调用的提示词——**成本乘法线进"每单元"档**，且定制过程本身需要被对样（谁校准定制器？），否则提示词漂移不可复算。与判定权分离纪律的相容性需先论证。

## 补充（2026-09-25 · 用户提出粒度阶梯，重开后的建议形态）

用户提议以粒度分层化解"每单元定制成本太高"：

| 档 | 定制什么 | 成本 | 效果 |
|---|---|---|---|
| L0 整书一版 | 静态提示词（现状） | 0 | 对典型章节够用，特殊章节盲 |
| L1 类型模板 | 按章节类型（战斗/设定/对话/过场/面板…约5~10类）定制模板，每类只做一次 | ≈0 边际 | 抓住大类差异的80% |
| L2 章级小差量 | 类型模板+本章结构化差量（场景标签+关键实体+注意事项） | ×章数但很小 | 补齐章间差异 |
| L3 每章全定制 | LLM 整体重写提示词 | ×517+517次对样 | 最准但不可复算（挂起主因）|

**切分原则**：模板改内容过人（LLM起草→人工定稿→对样一次→版本化）；章级差量必须是结构化字段（拼接进模板槽位），禁止 LLM 自由改写提示词文本——否则不可复算。

**落地顺序**：①先机械打场景类型标签（词表+规则，存章收口summary，零成本）→ ②负载复核证明某类章节拒收率系统性偏高 → ③只对该类做模板（LLM起草→人工定稿→对样20条→进版本）→ L0 永远兜底（无模板类型自动回落+口径注明）。
