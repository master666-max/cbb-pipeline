# 补强方案 · 精细度选择与总架构（2026-09-22）

> 配套件：《关系演化补强-工单-20260922.md》（v1.2，U-D01~U-D18 + T-1~T-10）。
> **本件用途**：①给一个可选的精细度菜单（选一档即等于裁定该档范围内的单位生效）；②画出总架构与流程图，标清每个补强件**挂在哪、被乘几次**。
> **判定权在审核线/用户**；本件不生效任何东西。

---

## §1 成本的第一性原理（先看这一条，再看菜单）

> **凡是加进"每章子代理必读包"的东西，成本 ×287（剩余章数）；凡是主代理每段收口跑一次的脚本 ×6；凡是全库动作 ×1 但动 6172 条。**

实测现状（不是估计）：

| 项 | 实测 |
|---|---|
| 每章子代理必读包 | 42KB = 抽取规范 5.6 + 判例 1.2 + 上下文包 6.5 + 本章切片 30.4 |
| 剩余主队列输入量 | 287 章 × 42KB ≈ **11MB** |
| 读一遍整份补强工单 | 29.7KB ≈ **读一章原文**；占主队列总量 **≈0.03%** |
| 抽取值 | **¥0**（代理算力免费）；DeepSeek 仅抽检，累计 ¥0.79／¥7 |

**结论**：文档不贵、脚本不贵；**贵只发生在两个地方**——①上了"每章必读"这条乘法线的改动；②对全库 6172 条做一遍的动作。菜单按这两条划线。

| 挂点 | 乘数 | 例 |
|---|---|---|
| 每章子代理必读 | **×287** | 词表分片（**唯一**踩线项，必须做成枚举清单+按章分片，禁写散文） |
| 每章候选字段 | ×287（但每章只多几十 byte，可忽略） | 规范版本字段 |
| 段收口脚本 | ×6 | 分流回放、因果谓词回放、约束扫描、校准 |
| 一次性脚本 | ×1 | 覆盖复算、并发域校验、隔离账回写、（待主线完成后）全库补齐 |

## §2 精细度菜单（三档 + 自选）

### 档位 A · 保命档（"信息不再丢、没漏能自证"）
| 项 | 内容 |

| 成本画像 | **全部脚本或字段级**；新增每章必读 = **0**；新增每章候选字段 ≈+40 byte |
| 对主线 | 不抢额度（无模型调用）；可在任一班车开场做 |
| 守的条款 | T-2 判定面非空 · T-3 正对照 · T-5 标签与量对账（**只守三条**） |

| 建议投入 | 2~3 个工作窗 |

## §4 选择方式

- **选一档**：A／B／C —— 该档范围内的单位即视为获批施工（档 C 的"全库三件"仍各自须单次批准）。
- **自选**：按 §3.2 的乘数线挑（建议原则：**先做 ×1 的，再做 ×6 的，最后才碰 ×287 的**）。
- **不选**：默认停在"草案"，只做 U-D01（在途半批定性）——它是唯一"不做就会丢东西"的一项。

**建议**：先 A 后 B；C 排到主线跑完之后。理由已在 §1／§2 写明。
