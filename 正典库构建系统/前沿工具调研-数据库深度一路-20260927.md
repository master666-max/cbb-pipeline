# 前沿工具调研 · 数据库技术深度一路（2026-09-27）

> 深度档：Git-for-data 谱系/嵌入式分析引擎/图数据库谱系/溯源存储/向量库/jsonl 天花板。WebSearch 全程限流，改为 GitHub API+官方文档直查；16 候选仓库元数据实测；【推断】处已标注。

## A. 逐题深度发现

**A1 时间旅行/版本化数据系统（Git-for-data 谱系收敛为 Dolt 一家独活）**
- **Dolt**（Apache-2.0，24.5k★，2026-09-25 日活级）：Windows 一等公民（winget/choco/msi 实测）；存储三层=Commit DAG+Prolly Trees+Block Store——**"append-only+哈希链+按哈希回溯"在 Dolt 是存储基底不是特性，语义上是 jsonl 哈希链的超集**。可无服务 CLI 操作 .dolt 目录。Noms 已死（2021 归档，Prolly Tree 发明者），Dolt 是唯一活体后代。
- lakeFS（BSL 1.1+云对象存储定位）排除；TerminusDB（语义贴合度全场最高，但 Docker 服务端+2026 维护权易主）单机纪律不符。
- **加分发现 XTDB**（MPL-2.0，不可变+双时态 SQL:2011+`!Local` 单机拓扑实测）=唯一可能整体吞掉"账本+审计"语义的单机选项，代价是 JVM 进程+放弃 jsonl 直读。

**A2 DuckDB=性价比最高的换现成件，且零迁移**
- MIT，41.7k★；json 扩展自带，`read_ndjson` 直读现有 jsonl（compression zstd 自动识别、ignore_errors 撕裂尾行容错、filename 虚拟列=分段文件 glob 自带路径语义）——**只读挂现有数据即可，不替换任何东西**。
- Parquet 格式级事实：footer 后写制 → 不重写 footer 的追加不可见 → **Parquet 是快照格式不是追加格式**；账本不能是 Parquet，"账本只读分析快照"可以（DuckLake：catalog=DuckDB/SQLite 文件+Parquet 分片+快照时间旅行，MIT，v1.0 已 production-ready）。

**A3 图数据库谱系：Kùzu 停摆改变答案**
- **Kùzu 2025-10-10 归档（团队被苹果收购）**——MIT 冻结可用但安全修复/Cypher 演进双停；现有部署冻结，**新依赖排除**。
- FalkorDB（SSPL+Redis 服务）/Memgraph（BSL+内存态服务）排除；TerminusDB 同 A1。
- **DuckPGQ**（MIT，DuckDB 官方 community extension，SQL/PGQ 标准，进程内零服务）=嵌入式图查询现役选项——万节点量级是其舒适区，代价=Cypher→SQL/PGQ 一次性改写。

**A4 溯源感知存储与事件溯源**
- why-provenance 学术谱系（Buneman 2001→PASS 2006→GProM）20 年无通用工程化新品；2024-2026 工程能量在 OpenLineage/W3C PROV（作业级血缘，非陈述级 why-provenance）→ **我们手搓的哈希链+sidecar 记账就是 why-provenance 的事件级实现，无现成件可整体替换**（置信中高，有限检索声明）。
- EventStoreDB→Kurrent（源可用许可+独立服务）语义对口但主权外包，负资产。XTDB 双时态模型语义更贴（再提）。

**A5 向量库（4096 维、1万-10万级）**
- LanceDB 主力维持（Apache-2.0，0.39，日活；向量+全文+SQL+过滤+版本化三全；Lance 格式移交独立组织=治理加分）。
- sqlite-vec（Apache-2.0 纯 C）=降复杂度备选：int8 量化（16KB→4KB/向量）+元数据列+分区剪枝；⚠️ pre-v1+2026-05 后放缓。usearch（索引内核强）**无元数据存储，排除出存储选型**（作纯索引另议）。
- 内存算术：4096 维 fp32 单向量 16KB，10 万条 1.6GB；int8→400MB。

**A6 jsonl 天花板（事实+推断分离）**
- 写侧追加 O(1) 无天花板；三处真瓶颈：哈希链线性校验成本（千万行=分钟级全扫）、崩溃撕裂尾行、文本压缩比。
- 业界稳妥路径=**分段 jsonl+manifest（段头携带前段尾哈希，可并行可增量校验）**——与 Kafka 分段日志/我们的投影检查点同构；ndjson+zstd 是合规中间态（DuckDB 自动识别，消费方零破坏）；Parquet 追加路线格式上不成立。
- **我们 4,488 行距所有天花板都很远。**

## B. 对数据面的建议

**保留手搓（无现成件可替，且已是资产）**：①jsonl 哈希链账本（三态+sidecar 记账语义全谱系无对口——"三态门禁无现成件"结论的存储层重演；重估触发器=50 万行或全链校验超 1 分钟）②本体目录树+小 JSON（版本化已被 git 覆盖，文件可读性+审计是刚需）③sidecar 家族与投影检查点（差异化本体）。

**换现成件（低风险增量）**：①**DuckDB 立即引入**——只读挂现有 jsonl，投影重建/抽查/统计升级为 SQL 视图，与 Neo4j 并存；②图投影双轨试点——DuckPGQ 平行投影对照跑，达标则 Neo4j 服务依赖退役、正典库回到"纯文件+单 DuckDB 库文件"零服务形态；③向量层维持 LanceDB，万级以下评估 sqlite-vec。

**观察项（不迁，留触发器）**：XTDB（SQL 级双时态审计需求真出现时）；Dolt（多写者合并语义出现时）。总原则=账本层永远最后动，先派生层换现成件跑对照（PT-021 纪律）。

## C. 排除项（均实测）

lakeFS（BSL 1.1+云定位）、FalkorDB（SSPL+Redis 服务）、Memgraph（BSL+内存态服务）、EventStoreDB/Kurrent（源可用许可+独立服务）、Noms（archived）、Kùzu 新依赖（归档+收购）、TerminusDB（Docker+易主）、GProM（12 星学术件）、usearch 作存储（无元数据）、Kùzu 社区分叉（存续未验证）。
