## §0 一句话结论

CBB 缺的不是"更聪明的模型"，是**几件结构性的记账与判定机制**：谁依赖谁、什么时候失效、谁在什么时刻知道什么、谁该先被裁决。调研中最值钱的三条是：**①失效要能向前传播（改一章只重跑下游）②伏笔回收要变成可执行的谓词而不是"隔三章就算超期"③哈希链证不了"没漏"，必须补覆盖矩阵**。全部落地成本都在脚本与字段级，不需要新硬件。

## §1 A 档 · 立刻可做（低成本、纯脚本或小改）

| # | 机制 | 出处 | 改哪里 / 价值 |
|---|------|------|--------------|
| A1 | **规范版本写进每条记录** | 12-Factor Agents（factor-02 自有 prompt / factor-12 无状态 reducer）https://raw.githubusercontent.com/humanlayer/12-factor-agents/main/content/factor-02-own-your-prompts.md | 现有 `verified_against` 只锚**语料**（路径+sha+日期），不锚**抽取规范版本**。规范已迭代十余版，历史记录的"当时规范"不可辨。加一个字段即可，是防漂移的根。**（本次新发现，不在补强工单里）** |
| A2 | **账本补"完整性"证明** | HN 讨论 https://news.ycombinator.com/item?id=48818098 | 自持哈希链只能证"未被篡改/重排"，**不能证"没有遗漏"**（可删坏日志再重封）。补两样：条目计数 + **章节覆盖矩阵**（哪章有记录、哪章确实空）。**新发现** |
| A3 | **引文质量双指标** | ALCE arXiv:2305.14627；LongCite arXiv:2409.02897 | 现只验"引文能否逐字回落"（召回侧），缺**精确侧**：去掉这条引文，断言还成立吗？补上可剔冗余引文、并消化一批假冲突。现基线：117185 条引文 99.83% 可回落。**新发现** |
| A4 | **中文归一化与分词** | Unicode UAX #15；OpenCC https://github.com/BYVoid/OpenCC；jieba https://github.com/fxsjy/jieba | NFKC + 繁简/异体折叠后做 UNIQUE 规范化键；触发匹配先分词再比对。**坑**：世界书的"全词匹配"对中日文有害（不空格语言），必须关。**新发现** |
| A5 | **积压按"不确定度"排序，而不是只按 urgency** | Dataset Cartography arXiv:2009.10795；BADGE arXiv:1906.03671；BALD arXiv:1112.5745 | 现 1222 件积压按伏笔层级排 urgency；改成"模型分歧 + urgency"混合，人力打 5–10% 就能覆盖最高错率区。**警告**：主动学习只能找错、不能估总体错误率。**新发现** |
| A6 | **裁决账区分"改写"与"作废"两种 retcon 语义** | TVTropes Retcon / CanonDiscontinuity https://tvtropes.org/pmwiki/pmwiki.php/Main/Retcon | 社区把 retcon 分两类：**追溯改写**（"当作一直都在"）vs **官方作废**。裁决账现在只有 confirmed/rejected 两态，再加一个动作标签即可，直接服务失效宣告。**新发现，可与 U-D06 合并** |
| A7 | **世界书的条目级状态机** | SillyTavern 世界书文档 https://docs.sillytavern.app/usage/core-concepts/worldinfo/ | Sticky（命中后 N 章内持续有效）/ Cooldown / Delay（第 X 章后才允许出现）/ Inclusion Group（同组只进一条）。**"活跃伏笔清单"可直接用 Sticky 语义**，Delay 可表达"某设定第 X 章才允许登场"。**新发现** |
| A8 | **token 硬预算裁掉的条目必须进审计日志** | 同上（SillyTavern 文档自承：预算耗尽后再命中也不插入，**且静默发生**） | 上下文包是 ≤2K 硬预算，现在被裁掉什么无人知晓；补一行"本包因预算裁掉 N 条 + 名单"。成本近零。**新发现** |
| A9 | **judge/判分器校准用 κ + 分层抽样 25–50 条** | Hamel evals https://hamel.dev/blog/posts/evals/；Eugene Yan https://eugeneyan.com/writing/llm-evaluators/ | W1 判分器补考用了"分离度≥70%"单门槛；可加 Cohen's κ 区间与 TPR/FPR 分列（类别不平衡时 raw agreement 会骗人）。**新发现，改判据即可** |

## §2 B 档 · 中期结构（要新字段或新模块，但仍是脚本级）

| # | 机制 | 出处 | 改哪里 / 价值 |
|---|------|------|--------------|
| B1 | **失效前向传播（改一章只重跑下游）** | Narrative World Model arXiv:2607.05577（原文："republishing an edited chapter invalidates the downstream edges that depended on the superseded state, so a correction propagates forward"） | 需先建"依赖来源章"字段；改动某章 → 只重跑其下游闭包。配合 U-D06 的失效宣告构成完整闭环。**解决"返工式修订"的最大成本项** |
| B2 | **伏笔回收 = 可执行因果谓词** | CFPG arXiv:2601.07033（Foreshadow-Trigger-Payoff 三元组；作者指出 LLM 常留"未开火的契诃夫枪"） | 把现"契诃夫枪 ≥3 章算超期"升级为：伏笔挂**触发条件**，回收时查谓词而非语义相似。边际成本≈0（逐章顺带产出）。**建议优先做** |
| B3 | **角色认知状态（谁知道什么、何时知道）** | STAGE arXiv:2601.08510；Zep/Graphiti arXiv:2501.13956 | 上下文包人物册升级为"每章状态快照（位置/关系/知识边界）"，并支撑"戏剧反讽/知识边界"检查。CBB 现有 `knowledge` 观察类目但未结构化 |
| B4 | **时态约束挖掘 + 全库扫描违反** | PaTeCon arXiv:2304.09015 / arXiv:2312.11053（从 KG 自身挖约束、含按度量的类限制，明确针对 granularity issues） | 补"门只查同批"＝ 一次挖约束、跨全库复用。**只把违反项送隔离区，不自动改状态** |
| B5 | **不一致四分类（替 U-D05 的三档）** | Kontrast arXiv:2607.25959（granularity / direct conflict / temporal change / KG incompleteness） | 比 U-D05 草案多一档"知识库不完整"（=本章没写≠冲突），直接降假阳性。可叠 survey arXiv:2403.08319 的 context-memory / inter-context / intra-memory 作二级标签 |
| B6 | **动作序 vs 揭示序分列** | Narrative World Model arXiv:2607.05577（每场景/事件同时存 event order 与 reveal order） | 现 CBB 的时间轴只有"故事时间（instant）+ 摄入序（tick）"，**缺"揭示顺序"**——网文大量倒叙与身份揭示正需要它 |
| B7 | **互索引（结论同时回指 chunk 与图边）** | KAG arXiv:2409.13731 | CBB 的证据四元组已是现成基础；补图侧双向索引，用于"从图边一键回原文"，与 U-D08 章节节点同批做 |
| B8 | **同义边 + 个性化 PageRank 多跳** | HippoRAG arXiv:2405.14831 / HippoRAG 2 arXiv:2502.14802 | 用"相似度超阈即连"的同义边近似异名/称谓连通；PPR 是确定性脚本，可离线。**阈值须按中文称谓重标**，否则误连 |
| B9 | **按需社区摘要（低成本版全书归纳）** | LazyGraphRAG https://www.microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/（索引期不写摘要，查询时按需生成；博客称索引成本 0.1%、查询成本低 700×） | 哨兵 A（全局归纳）一直未启用的正解＝**不预生成、问的时候才建**。非同行评审，须先小样验证 |
| B10 | **摘要树（章→卷→全书）** | RAPTOR arXiv:2401.18059；GraphRAG arXiv:2404.16130 | 现"最近 30 章平铺摘要"可升级为递归树，查询按抽象层命中。成本≈2× 基线（本系统成本=夜间吞吐，不是钱） |
| B11 | **按需实体消解（避免全量比对）** | FastER arXiv:2504.01557；Splink（Fellegi-Sunter）https://moj-analytical-services.github.io/splink/；姓名变体建模 aclanthology.org/P14-1035 | "改名/身份揭示"应写成**称呼增量事件**（同一实体的称呼随时间增加），而不是两条字符串实体打架——这正对 CBB 头号难题 |
| B12 | **采样一致性（把"第三方抽检"扩成 N 抽 + 跨模型 1 抽）** | SelfCheckGPT arXiv:2303.08896；Semantic Entropy arXiv:2302.09664 | 低一致自动入隔离区。**警告**：系统性错误会一致地重复，一致性≠正确，必须与原文核验并用。与现有 DeepSeek 抽检预算条款兼容 |

## §4 明确不适用（照抄会踩雷）

1. **一切要训练/微调的**：CrossAug 的 GNN（arXiv:2605.28004）、HippoRAG 2 检索编码器、Ditto 领域微调、LongCite 的 45k 微调——违反零预算/不训练。
2. **白盒探针/激活干预**：ContextFocus、IRCAN、COIECD 一类需权重访问；本系统只有不透明 API，且不可审计。
3. **把过期事实藏在向量里**（连续相位旋转类 arXiv:2604.11544）：语义上等价于失效，但**无法回原文核验**，与"证据可核验"硬约束冲突。
4. **纯 TKG 补全/链路预测**：方向相反——CBB 要的是历史断言的可核验管理，不是预测未来事实。
5. **世界书的两件诱人做法**：递归/链式插入（官方文档自承可无限循环，且让"为什么抽到这条"不可预测）；概率触发/随机择一（破坏可复现性，与审计冲突）。
6. **向量化条目做正典召回**：SillyTavern 官方文档原话"retrieval quality is unpredictable"——不可核验的召回不该进正典库，改用显式别名表。
7. **外部见证/第三方时间戳让账本自证完整**：无机构会替私人项目托管 witness，零预算下不可行；本地链 + 覆盖矩阵 + 人工抽检足够。
8. **托管式幂等网关/ledger 服务**：与纯本地约束冲突。
