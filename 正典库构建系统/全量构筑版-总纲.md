## §V 版本宣言
- **全量构筑版**（本文件起）：以极致时间换质量——开工前先对 16 仓外部源码做**全量三层分析**（每仓一份独立详报），吸收已验证设计后再构筑 CBB 本体。
- **实验版**（冻结 · 对比参考）：`cbb-skills/`（P1-M1 产物，U0-U8 全 done，73 单测绿，冒烟 20/20 双跑，交接文书在案）。冻结声明见 `cbb-skills/FROZEN-实验版声明.md`。**冻结 = 只读保全**：全量构筑版不修改、不删改其实验版文件；同名概念重设计时并排对比、引用其实测结论（P-017 幂等教训、gate1→隔离映射暂定等 6 条待确认），不覆盖。
- 两版关系：实验版证明"契约+三态+断点协议"可跑通；全量构筑版在此基础上先补"外部情报全量化"，再重构本体。实验版的实测数据（73 单测/冒烟计数/P-017）是全量构筑版的回归基线。

## §T 时间换质量方法论
- 计价依据：`现成技能侦察/源码全量分析·工作量预设.md`（task-036 实测 8800 文件/8.3 万行 py/70 万行 js；全量三层 ≈ 170-200 轮）。
- 通道双开：①**闲时任务**（免费排队，一句话提示词，见 §G）；②**交互式 /goal**（用户侧设目标，未达自动继续）。两通道共用同一 BUILD-STATE 与同一套判据，可混用、可并行多会话（先读后写，R-015）。
- 时间不设限：每仓分析做到"三层见底"为止——结构层（目录/入口/依赖图）→模块层（逐文件职能）→机制层（核心算法与数据流追查），不以轮数封顶。

## §S 执行协议（执行代理必读，三通道通用）
1. 开场自举：读 `全量构筑版-BUILD-STATE.md` → **对账**（STATE=缓存，磁盘+git=事实；done 单位证据不在即改回 todo 并记勘误）→ 从第一个 todo 继续。
2. 单位=一仓详报（或 U-A17 汇总）。收口两件事：更新 STATE + git commit（**只 add 本单报告与 STATE，禁 `git add -A/.`**）。
3. 铁律与服务纪律：照《P1执行区/闲时任务提示词模板.md》⑦（D-004/append-only/py -X utf8/前台子代理/编号先查重）与⑧（Neo4j/LM Studio/云 API 探活+注册表兜底）执行，本总纲不重复。
4. 与审核线接口：无权自宣"验收通过"；报告即证据；与总纲冲突写 `全量构筑版-分析报告/issues/`。

## §R 每仓报告判据（六节，缺一不验收）
落盘 `全量构筑版-分析报告/<仓名>.md`，全部关键断言带 `文件:行号` 证据：
1. **§1 架构与数据流**——目录结构、入口、依赖图、端到端数据流追查；
2. **§2 数据模型与接口**——schema/存储格式/对外 API 或 CLI 契约逐项列出；
3. **§3 可借鉴 / 不可借鉴清单**——逐项给理由；涉及代码级借鉴的注明许可后果；
4. **§4 许可与红旗**——LICENSE 判定（GPL/AGPL 红旗一票否决代码借鉴）、维护状态、硬编码/密钥/可疑代码；
5. **§5 与 CBB 对照**——该仓如何处理 Step 0 三条件同类问题（元文本防御/时间归一/去重）、与四契约（Record/Issue/Verdict/Case）及三态写入的异同；
6. **§6 处置建议**——四选一：借鉴设计（只学思路）/ 装外挂（进运行时）/ 只读参考 / 无关弃用，附理由。

## §G 发令格式（审核线制作，执行者照抄）
