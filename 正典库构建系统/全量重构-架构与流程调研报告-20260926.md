### 3.2 契约的弱核心（D-23 的根）

- `record.schema.json:12` 对 canonical 只有一行：`{"type": "object"}`——**schema 层零约束**，子字段全靠 profile 自觉。
- 实测 6,172 件枚举出 canonical 子字段 23 个，天然混着两类：
  - **断言位**（受控）：`entity_type`/`rel_type`/`kind`/`tier`（走词表）
  - **陈述位**（自由文本）：`claim`(relation)/`fact`(setting)/`note`(foreshadow)/`time_verbatim`(event)/`label`(timeline)
- 身份键（`cbb_store.py:80-88`）：entity=library+`name`、relation=三元组。`name` 兼身份键意味着任何写法变体都变成"另一条"或"矛盾"——65 悬挂端点（43 变体）就是下游代价。
- 冲突比对域（`cbb_store.py:91-98`）：**canonical 全部同键**。断言位与陈述位不分 → D-23。

### 3.3 D-23 爆炸半径实测（我们的数据 vs 采用者的数据）

- 主库隔离区 1,373 件中双轨字段矛盾 416 件，**涉自由文本位仅 2 件**——我们的 canonical 恰好没把叙事文本当高频比对位，且 604 件矛盾的成因主体是 entity_type 词表混沌（SKILL Common Mistakes #3 的"604 件假矛盾"正是它，词表.py 已裁为解法）。
- 同一代码在 qoder 的书上：小队列五单元 14 件隔离件 9 件假矛盾 + incoming 整条不写库，**逼到整库作废重建**（`本体库-作废-20260926-R000R001`，276 文件留证）。
- 结论：D-23 是**schema 依赖的地雷**——对当前数据低危，对任何把 statement/claim 类字段放进 canonical 高频比对位的使用者是 P0。发布件级缺陷，不是理论风险。

## 六、病理诊断：山是怎么长成的

1. **拷贝繁殖无正源**——五份部署实例、零机械同步哨。修复落点靠人记（已漏：qoder 安装位）；发布包≠构建产物而是手工快照（import 漂移实证）。P-020（手工修订不进生成链=再生成即回退）在**仓库级**重演。
2. **契约弱核心**——schema 对 canonical 零约束（一行放行），断言/陈述混比（D-23），name 兼身份键（变体风暴）。门再硬，门前的地基是软的。
3. **载体耦合进代码**——容器名/端口/凭据回退写死在 8+ 文件（D-21/D-15/`图库隔离.py:152` taken 集）；46 处 sys.path 手术（重构已测）。换机即坏，多书必串。
4. **纪律纸面化**——③④ 两步无编排工具（每个消费者自造一遍）；G5 判卷无独立考官；17 条 mistakes 4 条无机检；"覆盖复算"只有配方文档。
5. **能力接线无判据**——D-26/28/29 三连：embedding_scan 记"已补"实未接线、NLI 十三批 0 调用恒 READY、重排端点 READY 但入口不传参。"批准了"和"用上了"之间没有机器。
6. **判定器输入档缺失**——门对畸形输入崩而不码（D-1/D-25）、CLI 未 smoke（D-27）、零 docker 分支零断言（D-11）。判定器自身的健壮性没有判定器。
7. **时间与状态纪律不闭合**——dual_track 漏 at（D-24）、confirmed 从未发生（晋升无机制无样本）、债务只增不清（D-14）。设计宣称的三态/时序/债务，实战各缺一角。

## 七、目标架构提案（重构蓝图）

### 7.0 六条设计原则

1. **单一正源**：一份源码仓；发布包/技能/安装位全部是**构建产物**（单命令构建 + hash manifest 对账哨），禁手改禁手同步。
2. **契约先行**：canonical 强类型化（v3），断言位/陈述位二分声明在 profile，身份键与比对域进 profile。
3. **判定器健壮**：任何输入先出码后判定，永不崩；CLI 全量 smoke；判据分支全覆盖。
4. **载体外置**：端点/容器/凭据/命名空间全部走 config 单源（cbb2/config.py 已 PROVEN，扩权即可）；guard hook 加静态禁令（源码出现硬编码端点/容器名/实例名即拦）。
5. **纪律机械化**：纸面纪律要么变成工具+判据，要么显式降格为"建议"不许写"必须"。
6. **数据兼容承诺**：`libraries/{lib}/{status}/{rid}.json` + `quarantine-zone/items.jsonl` + 哈希链账本布局不变——6,172+1,373 件真库零迁移。

### 7.1 核心包：以 cbb2 为基长成 monolith-core

cbb2（899 行，五面指纹 PROVEN）扩为九+N 模块：

| 模块 | 动作 | 吸收的缺陷 |
|---|---|---|
| `contract` v3 | canonical 二分：`assertion_fields`/`statement_fields`；`compare_fields` 参数化；identity_key 进 profile；**互补陈述 → 内容哈希 event 记录**（吸收 qoder 互补陈述分流设计，含"真冲突不得洗白"反例测试） | D-23、变体风暴 |
| `store` | dual_track 全写路径 `at` 强制透传；矛盾轨 incoming 全文留存（sidecar 拦截件全文） | D-2/D-24/D-6 |
| `gate` | 候选态输入档（null id→哈希占位、canonical 畸形→G1-SCHEMA 码不崩） | D-1/D-25 |
| `runner` | ③④ 编排工具化（试车/小队列/脏单元接种进包），批次收口十查内嵌 | 纸面纪律 |
| `derive` | 图/嵌入/派生对账适配器：**归属单键 ns 读写同名常量**；导出债务 repay 语义 | D-13/D-14 |
| `ops`（新） | 运行契约闸：端点在位+消费件存在+已接线+本批回执，四缺一 BLOCKED 焊进入库 | D-26/D-28/D-29 |
| `config` | 扩权收编全部端点/容器/taken 集/凭据引用 | D-21/D-15 |
| 检索面 | 检索层+重排器机械面入包（**reranker 必填化**，D-29） | D-29 |
