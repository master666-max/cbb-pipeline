## 一、数据模型（正典记录 canonical）

每条正典记录是一个 JSON 对象，描述小说世界中的一条**结构化断言**。

### 记录顶层字段

```json
{
  "record_id": "cand-entity-0013930c15ba",
  "library": "character",
  "status": "provisional",
  "canonical": { "...按 library 类型不同的 schema，见下..." },
  "evidence": [
    {"vol": 1, "chapter": 3, "line": 237, "quote": "原文逐字引文"}
  ],
  "_aliases": ["别名1", "别名2"],
  "observations": [
    {"category": "summary", "text": "总结性观察"}
  ],
  "supersedes": null,
  "version": 1
}
```

| 字段 | 类型 | 必有 | 语义 |
|---|---|---|---|
| record_id | string | ✅ | 唯一标识：`cand-<类型>-<内容哈希12位>`（`-m`/`-m-m` 后缀=重抽版本） |
| library | string | ✅ | 所属库分区：`character` / `event` / `relation` / `foreshadow` / `setting` / `timeline` |
| status | string | ✅ | 文件态（恒为 `provisional`——R13 设计）；**真值用 effective_status（见 §三）** |
| canonical | object | ✅ | 结构化断言（schema 按 library 类型不同，见下） |
| evidence | array | ✅ | 逐字引文列表，每条含 vol/chapter/line/quote |
| _aliases | array | ✗ | 已知别名（string 列表） |
| observations | array | ✗ | 观察（category + text） |
| supersedes | string | ✗ | 被此记录取代的旧 record_id |
| version | int | ✗ | 版本号 |

### canonical schema 按 library 类型

**character**（人物）：
```json
{"name": "相川涡波", "entity_type": "人物", "fact": "转生者，原为地球人"}
```

**event**（事件）：
```json
{"title": "_diá·西斯召唤仪式", "tick": 188, "time_verbatim": "同日练习室（吞噬实验中）", "description": "..."}
```

**relation**（关系）：
```json
{"subject": "相川涡波", "rel_type": "家人定位(视为妹妹)", "object": "玛利亚", "claim": false}
```
- `claim: false` = 反推记录（原文否定此关系），**不是判定此关系为假**
- `claim: true` 或无 claim = 正向记录

**foreshadow**（伏笔）：
```json
{"title": "...,", "plant_or_payoff": "伏笔", "tick": 3, "chapter": 3, "status": "planted"}
```

**setting**（场景/设定）：
```json
{"name": "异世界迷宫", "description": "...", "category": "location"}
```

**timeline**（时间线锚）：
```json
{"name": "...", "tick": 0, "chapter": 1}
```

## 二、三态标注体系（质量分级）

每条记录有一个 **effective_status**（真值），由文件 status + transitions.jsonl 旁车叠加计算：

| 状态 | 含义 | 判卷来源 | 可信度 |
|---|---|---|---|
| **confirmed ✅** | 人审物料化正典 | 批次 5（v2.2 五十件验证轮植株 8/8 门 PASS） | **最高——放心用** |
| **provisional ◐** | 双票参考值 | 放量判卷 v2.2 契约（门 FAIL→全卷参考值） | 中——参考但不作为正典 |
| **quarantine ⚠** | 隔离区待处理 | NLI 分歧/低置信路由 | 最低——待人工 |

**当前计数**（截至批次 5 物料化后）：

| 状态 | 主库 | 隔离区 | 合计 |
|---|---|---|---|
| confirmed | **29** | 743 | 772 |
| provisional | 6,249 | 442 pending | 6,691 |
| 合计 | 6,278 | — | — |

> **重要**：lens 三态快照显示 confirmed=29（批次 5 物料化后），而非批次 3 时代的 0。记录文件 status 字段仍写 `provisional`（R13 文件不动设计）——**真值在 transitions.jsonl 叠加层**。

## 三、交付格式

### 3.1 SillyTavern World Info JSON（`lorebook/sillytavern-v1.json`）

**格式**：ST World Info 标准格式，可直接导入 SillyTavern。

```json
{
  "entries": {
    "1": {
      "uid": 1,
      "key": ["相川涡波", "涡波", "小麦"],
      "keysecondary": [],
      "comment": "相川涡波",
      "content": "【相川涡波】聚合档案（159 条断言，三态随行）\n- [卷1章3] 姓名：相川涡波...\n- [卷1章6] ...",
      "constant": false,
      "selective": true,
      "order": 99,
      "position": 0,
      "disable": false,
      "excludeRecursion": false,
      "probability": 100,
      "useProbability": true
    }
  },
  "name": "迷深实战-正典-lorebook",
  "description": "...",
  "protocol": "https://github.com/SillyTavern/SillyTavern"
}
```

| 字段 | 类型 | 语义 |
|---|---|---|
| uid | int | 条目序号 |
| key | string[] | 触发词列表 = 正名 + 全部已知别名 |
| comment | string | 条目注释 = 主名 |
| content | string | 聚合正文 = 该实体/关系全部断言按章排序 + 逐条源回链 + 三态徽章 |
| order | int | 注入优先序（簇成员数降序） |
| constant | bool | 常驻注入（本导出全 false = 关键词触发制） |
| probability | int | 触发概率（100 = 每次必触发） |

**规模**：4,740 条（保守两源聚合：L1 精确名簇 ∪ L2 aliases.jsonl 539 行证据面 ∪ L3 四分类过滤）

### 3.2 RAG 分块（`lorebook/rag-chunks.md`）

Markdown 格式，每聚合簇一块。每块含 front-matter 元数据（name/aliases）+ 逐条断言（record_id + effective status + canonical JSON + 逐字引文）。可直接被 LangChain/LlamaIndex 切割 ingestion。

### 3.3 LLM Wiki（`wiki/records/<type>/<rid>.md` + `wiki/aggregates/<name>.md`）

Markdown 格式，每记录一页（1:1 忠实渲染）+ 每聚合簇一页（时间线）。每页头部 YAML front-matter 含 record_id/status/aliases/快照锚。

### 3.4 正典记录 JSON API（活体服务）

`canon_server.py --port 8420` 启动后：

```
GET /api/records           → {"total": 6278, "records": [{record_id, library, status, canonical, evidence_count}]}
GET /api/record/<rid>      → 单记录完整 JSON（含 effective_status + transitions 审计）
GET /api/stats             → {"records": N, "tri_state": {...}, "ledger": {...}, "quarantine": N}
```

**活体语义**：每次请求现读 store 文件——判卷写入/物料化/新章摄入，刷新即最新。

## 四、消费指引（角色卡 skill 怎么用这些数据）

### 取正典级数据
```
筛选 status == "confirmed" 的记录（当前 29 件，来自批次 5 验证轮双 support）
每件含 canonical（结构化断言）+ evidence（逐字引文）→ 直接作为角色卡的"正典事实"字段
```

### 取参考级数据
```
status == "provisional" 的记录——可用但须标注"机器参考，未经人审"
建议在角色卡中以"参考信息"分区呈现，与 confirmed 分开
```

### 取聚合页
```
wiki/aggregates/<name>.md —— 同角色全部断言按章时间线排列
适合作为"角色完整档案"整页注入 LLM 上下文
```

### 取 lorebook
```
lorebook/sillytavern-v1.json —— ST World Info JSON
直接 import，或解析 entries[].content 作为每条的正典速写文本
```

### 质量分级引用规范（建议）
```
✅ confirmed  → "正典事实"
◐ provisional → "机器参考（双票一致，未经人审）"
⚠ quarantine → "存疑待处理"
无三态标注    → "原始抽取（未经判卷）"
```
