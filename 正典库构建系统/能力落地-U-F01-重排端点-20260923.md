## 三、调试链（可复用知识，别重踩）

1. **LM Studio 无 rerank 端点**（实测 `POST /v1/rerank` 与 `/rerank` 均返回 "Unexpected endpoint"；其模型列表把 qwen3-reranker-4b 标为 `llm` 类型）。
2. **LM Studio 自带的后端 `llama-server.exe` 不能独立跑**（`--version` 零输出、需其宿主引擎）。
3. → 采用官方 llama.cpp release（`b11125` 的 `llama-b11125-bin-win-cpu-x64.zip`，18.5MB），丢到 `D:/tools/llama.cpp/`；`--reranking` 与 `--pooling rank` 均在。
4. **LM Studio 转的 GGUF 三缺**（这是真正的坑；缺了照样"能返回"，但分数是噪声）：
   - 缺**具名** rerank 模板（llama.cpp 只查 `llama_model_chat_template(model,"rerank")`，命令行传模板无效）
   - 缺 `qwen3.classifier.output_labels`（键名是 `{arch}.classifier.output_labels`，**不是** `classifier_output_labels`）
   - 缺 `cls.output.weight` 张量（**不是** `cls.weight`；形状 ne=[2560,2]，即 yes/no 两行）
5. **三件套规格来源**：llama.cpp 官方转换器 `conversion/qwen.py` 的 `Qwen3Model.set_gguf_parameters()`（模板原文含 `<think>` 段）与 `_get_cls_out_tensor()`（从输出头取 yes/no 两行，顺序 [yes; no]）。
6. **补丁脚本**：`D:/tools/patch_rerank_gguf_v2.py`（原件不动，产出 `*-rerank.gguf` 副本）。踩过的四个小坑记录在脚本注释：
   - `add_chat_template` 传**字符串**会写进默认模板键；必须传 **list** 才写具名键 `tokenizer.chat_template.rerank`
   - 行切片：`token_embd.weight` 按**词表行**存（data[tid] 即该 token 的整行块）；`dequantize` 要一维字节流
   - `write_tensor_data` 无 `tensor_type` 参数（按数组原样写）
   - Windows 下服务正映射着文件时不能覆盖写入（先停服务再打补丁）
7. 自检还发现**我自己的检查器有竞态**：字符串包含判断把 `cls.output.weight` 也算作 `cls.weight` 在场——已修（T-3/T-5 的老病，机器判据要精确）。
