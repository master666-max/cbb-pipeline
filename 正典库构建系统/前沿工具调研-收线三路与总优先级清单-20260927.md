# 一、知识图谱表示学习路

**框架与选型**：PyKEEN（MIT，2039★，当天活跃）=首选，30+ 模型+`predict_target/predict_all` top-k API；**官方警告：KGE 分数无统计含义、不能跨模型比较、只能作排序优先级**——决定人审闭环设计。万节点级=FB15k-237/WN18RR 标准量级，RotatE/ComplEx-N3 最优；**小图上训练策略与超参的影响大于模型类别**（LibKGE ICLR 2020）。**AnyBURL（BSD，笔记本级）=规则+confidence 可解释输出，比 KGE 分数更适合缺口提议人审**。

**共现图算法**：networkx 链接预测六件套（Adamic-Adar/RA/Jaccard/共同邻居中心性）+Leiden 社团；通行实践=共现边权≥2-3 剪噪、AA/RA top-k 且**硬性要求共同邻居数≥2**、多分数共识才提报。

**时序知识图谱**：离散时间步线（RE-GCN/TiRGN）与区间型双时序**错配**且均无 license 休眠；区间型 TKBC（TimePlex/Time2Box/NeuSTIP）均研究级无码——**"失效感知链接预测"无生产级现成件**。工程替代三层：validity 掩码训练＋**过期边当天然负例**（"曾经真现在假"的免费监督，静态 KG 没有的信号）＋时间特征（活跃度/共存窗口）。

**Neo4j GDS Community**：LP 基线（Alpha）/Leiden/Louvain/Node Similarity（Production）/LP Pipeline（Beta）全覆盖，万节点毫秒-秒级；GPL-3 传染边界=内部用无碍。

**LLM+KGE 混合**：OMNIA（嵌入粗滤→LLM 精验）；**PERSEUS（2025）实测 generate-then-verify 比直接 LLM 抽取精度 +11%、假阳性 −54.6%**；KICGPT/KoPA/RoG（均 MIT）。

**冷启动**：1719 三元组落在经典小数据集区间（Nations/UMLS/Kinships 级）——**可训，但要按小图套路**：KvsAll/1-N 打分显著优于负采样（稀疏图伪负例）、dim 压 32-64、epoch 加大；**低于 ~500 三元组 KGE 基本不可用**（转 AnyBURL 规则或共现统计）。

**接入**：链接预测→缺口队列的三通道人审闭环——①共现结构（networkx AA/RA+社团过滤）②KGE/AnyBURL 排序（规则文本直接给审阅者）③LLM 语义校验；队列字段=候选+各通道分数（**分开列不融合**——KGE 分数不可跨模型比较）+规则解释+矛盾标记+建议 valid_at；人审接受/拒绝回流→自建 PR 曲线。**双时序进特征**：validity 掩码训练+过期边负例+活跃度特征。

**排除**：DGL-KE（2020 停+亿级设计）、RE-GCN/TiRGN 线（错配+无 license）、Time2Box 集成（研究码）、ConvE/TuckER 重模型（小图过拟合）、NSCaching/AnyBURL 大图配置。

# 二、资产化管道编排路

**核心判断：引"薄编排层"，不引"平台型编排器"。** 痛点本质=缺一层声明式依赖图，不是缺调度平台——失效语义已由哈希链免费提供，买编排器是把免费的东西再实现一遍。

- **Dagster 1.13.24**（Apache-2.0，16.2k★，2026-09-25 push，极活跃）：SDA+`AutomationCondition.eager()`=**"上游变更自动传播下游物化"与我们的痛点一一对应**；SQLite 本地持久化零云零容器；**Windows 无官方 CI（shell 集成雷区 #15202）+学习曲线数天**。升级触发器：投影 4→8+、两跳以上传递失效、需 UI 级重跑/回填。
- **Prefect 3.8.6**（极活跃，Windows 一等公民+官方专页最硬）：`cache_key_fn` 返回账本 offset=检查点语义等价实现；但**常驻 server 架构与"单机零常驻"纪律冲突**；2.x 已是维护线。
- **doit 0.37（MIT）=首选薄层**：`file_dep` 用 **MD5 内容哈希（不是 mtime）**——"账本内容哈希变化才重建"天然等价投影检查点；`calc_dep` 动态决定失效范围；单文件 dodo.py 即用。0.x 版本号 API 偶有破坏（需跟 changelog）。
- **DVC 不引**：已易主 Treeverse+6 个月无 release+官方自认小文件开销（#8895 find 慢）；与 offset 检查点语义重叠且更弱。git 已覆盖版本化需求。
- **OpenLineage 可选最小形态**：openlineage-python+file transport 零服务器 JSONL 血缘事件（信息增量当前小，留接口）。Marquez（release 停 2024-10+Java/PG/Docker 三重栈）排除。
- **文件监听**：watchdog/ReadDirectoryChangesW **存在"缓冲溢出静默丢事件"的官方设计语义**（MS Learn 原文：溢出时返回 true 但内容全弃）+watchdog 2026 年仍在修 Windows 边缘 bug（#1234/#1286/#1156）——**结论：现有 mtime 轮询哨+哈希校验兜底比纯事件驱动更符合可靠性需求；watchdog 最优用法是"低延迟唤醒轮询器"的 hybrid**。

**排除**：Marquez（停滞近 2 年）、Prefect 2.x（维护线）、Airflow（无 Windows+重量级）、K8s/Docker 部署路径、lakeFS/Kafka/云 transport、GNU Make 原生 Windows、Invoke（无依赖图+活跃度下滑）。

# 三、检索内部与学习排序路

**金标构造（LLM-as-judge 可靠性）**：UMBRELA（SIGIR 2025）——LLM judge **判档位不可靠**（Cohen κ 0.308-0.373；"highly relevant"判准仅 ~30%）但**排系统高度可靠**（Kendall τ 0.87-0.94）；Thomas/Bing：选最优系统一致 0.86-0.97、识别最难 query 弱（RBO 0.40-0.48）。**合成 query 循环的关键负面结果**（SIGIR 2024）：合成 query+人工判断 τ=0.82 可用；**合成 query+稀疏判断（只把生成来源当正例）τ=0.157 完全不可用**——正例池必须池化。RAGElo=工业样板闭环。

**LTR 小数据**：LambdaMART 最低标注量**无公开系统对照**（明说）；最硬实证=**Bruch 融合函数分析（CIKM 2023）**：单参数凸组合（CC）用一小撮标注即收敛、α∈[0.6,0.8] 跨域稳定、**理论上优于 RRF**；RankVicuna/RankZephyr 证明 LLM listwise 判序可当教师标签（无需人工）。**门槛判断：<100 人工锚定 query 不上 LambdaMART；≥500（每 query top20≈1 万对）才上 LightGBM lambdarank**；query 多样性是瓶颈不是行数。

**查询扩展**：query2doc（BM25 MRR@10 +3.0）；DMQR-RAG：多改写策略各自有益但**"全开"引噪——必须按 query 自适应**；HyDE 依赖 LLM 对领域熟悉度（小说世界观不熟→伪文档偏移）；RM3 中文有 NeuCLIR 先例（k1=0.9/b=0.4）；CoT 式 LLM-QE 比 PRF 更不被第一阶段拖累。

**中文索引**：Lucene CJK 默认**字 bigram**（生造词免疫）；NeuCLIR 中文：细粒度切分 BM25=0.290 强基线、BGE-M3 sparse=0.307 最强；jieba 冻结（2024-08）但 MIT 可内嵌自定义人名/别名词典。**小说生造专名占比高→字 bigram 路在别名类 query 上可能反超词级**（对照实验收益预期高）。

**拒答校准**：Sufficient Context（ICLR 2025）——充分性分类器 1-shot F1=0.935；**"标准答案字符串出现在 context"这个平凡基线 F1=0.810 意外地强（我们的逐字门正是其强化版）**；RAG 悖论（有材料在手模型更倾向强行作答）；自建门槛=几百人工标注（Google 自己用 500）；2000 条 LoRA 微调**没有**可靠提升拒答——别指望微调。

**RRF 科学**：Bruch（CIKM 2023）证明 RRF 对参数敏感、归一化凸组合（CC/TM2C2）理论+实证均优于 RRF；Elasticsearch 官方：k=60 手工设定、**rank_window_size 是独立旋钮**——两个旋钮都要实测。
