## §0 为什么"轮"这个量纲是错的

1. **轮次是过程指标，不是判据。** "跑满十轮"无法区分"第三轮就干净了"与"第十轮还在同一个病上打转"；它奖励的是**时间投入**，不是**覆盖与证伪**。
2. **重复同一层，边际收益是零。** 第二次通读全文查引文，不会比第一次多查出任何东西——因为判据没变、对象没变。真正的收益只来自**未被覆盖的层**和**未被证伪的假设**，而这两件事与"轮"无关。
3. **它与 T-4 直接冲突。** 有限测试只能证相交、不能证不相交；十轮是有限测试的十次重复，**不构成"已穷尽"的证明**。
4. **本项目已有前科。** "闲时任务 2.5 小时上限"就是"把无法证伪的过程指标写进指令"的同族错误（见 task-056 勘误）。十轮到全库层是同一件事：**一个量纲不对的量，被当成了判据。**

**一句话**：审查的强度不该由"跑几轮"决定，该由**每一层的失效模式该用什么检查才能被证伪**决定——而这个，能从架构直接读出来。

## §1 从架构读出审查面（五条写入路径）

CBB 的写入路径只有五条，每条路的失效模式是**有限且可穷举**的。审查方法＝对每条路的每个失效模式，选一种**能证伪它**的检查：

| 层 | 写入路径 | 失效模式（穷举） | 能证伪它的检查 | 覆盖方式 | 机器/人 |
|---|---|---|---|---|---|
| **L1 语料** | 原文 → 章边界表 → 切片 | 章号错序／漏切／重切／编码与繁简混入／缺号章未登记 | 与原文逐字比对 + 章号序列断言 | **全量** | 机器 |
| **L2 抽取** | 切片 → 子代理 → 候选 | 引文对不上（幻觉）／元文本混入／先验污染／漏抽（空记录其实不空）／**口径漂移**（不同班车用不同规范版本） | ①引文逐字回落（机器可全量）②空章理由可核查 ③**分层抽样人看机器查不了的**（内容是否真支撑断言、是否漏抽）④规范版本可辨 | 机器全量 + **人看分层抽样** | 混合 |
| **L3 入库** | 候选 → 门1 → store → 库 | 门放行坏件／双轨误合并／矛盾静默／取代链断／账本断链／约束失效 | **成对可执行反例**（每条规则一条"必须被拒" + 一条"必须放行"） | **规则数有限 ⇒ 全枚举** | 机器 |
| **L4 派生** | 库 → Neo4j 视图 | 派生与真源不一致（**差集静默** T-8）／时序字段未回填／节点缺失 | **真源↔派生对账**（数、字段非空率、抽样三元组回查） | **全量** | 机器 |
| **L5 结论** | 库 → 报告/判定 | 宣称越界（说过头）／数字不可复算／**判定面为空读成通过**（T-2） | 标签与量对账 + 口径上界检查 + 空判定面检查 | 逐句（报告有限） | 机器 + 人核 |

**两条由架构推出的原则**：

- **P1：机器能全量查的层，不要用人抽。** 引文回落、章号序列、账本链、对账——这些都能全量跑脚本，人抽只能降低样本量、不提高确定性。
- **P2：人只抽机器查不了的层，且抽样量要算，不要拍。** 人力的靶子是"内容是否真支撑断言""是否漏抽"这类语义判断——它们的错误率上界可以由抽样算出（§3）。

## §2 替代方案：五层证据门（每条门都带正对照）

> 出口不再是"跑满 N 轮"，而是**五条门全部可复算通过 + 每门有正负对照 + 全部数字可复算 + 没有空判定面被读成通过**。

| 门 | 判据（可复算） | 正对照（必须成对） |
|---|---|---|
| **G1 覆盖门** | 相对语料章清单的覆盖完备（应−实=未覆盖集，逐条有理由） | 抽掉一章 → 必 FAIL；补回 → 必 PASS（U-D10 已立） |
| **G2 证据门** | 引文回落率 + 不可回落项逐条定性（是缺陷还是口径）；分层抽样给出坏率**上界** | 故意改坏一条引文 → 必被抓；原样 → 必过（U-D11 已立） |
| **G3 规则门** | 门1 每条规则与每个约束族：成对反例通过 | 拒对了 + 放过了，成对出现（T-3） |
| **G4 对账门** | 真源↔派生：记录数／边数／字段非空率／抽样三元组回查 | 派生层人为少导一条 → 必被对账抓出 |
| **G5 结论门** | 终报每个数字可复算（给"这个数怎么数出来的"）+ 每条宣称有口径上界 + 判定面非空的显式标注 | 把某判据的判定面清空 → 报告必须显式标"不适用（非通过）" |

**五门与旧 R1~R10 的关系**：R1/R2/R8（对账、孤悬、重放）≈ G1+G4；R3/R4（时间轴、别名）≈ G3 的规则枚举；R5/R7（矛盾、隔离区）≈ G5；R6（confirmed 抽检）≈ G2 的抽样；R9/R10（许可、红队）＝ G5 的专门项。**十项镜头没有丢，丢的是"跑十轮"这个外壳。**

## §3 抽样量要算，不要拍（现在"30 条"的真实含义）

**公式**：想以把握度 `1−α` 发现"坏率 ≥ p"，最少抽 `n = ln(α) / ln(1−p)` 条。

以 95% 把握（α=0.05）：

| 想证明的坏率上界 | 需要的样本量 |
|---|---|
| < 20% | 14 条 |
| < 10% | **29 条** |
| < 5% | **59 条** |
| < 3% | 99 条 |
| < 1% | 298 条 |

**这解释了现口径的真实强度**：主工单写"随机 30 条对原文核证据"——它实际证明的是"**坏率 < 10%（95% 把握）**"，而不是"质量 ≥95%"。两个说法常被混用（R-010 口径病）。**要么把样本加到 59 条以证 <5%，要么把宣称改成"<10%"**——只能选一个，不许两全。

**分层**：按批（班车）分层抽，而不是全库均匀抽——因为错误往往按班车聚集（同一班车同一规范版本同一上下文包）。每层抽 8~10 条即可发现"某一班车整体劣化"这类聚集性缺陷。

## §4 出口条件（替代"十轮"）

一次审查被判定为完成，当且仅当：

1. **五门全部可复算通过**（脚本 + 原始输出在案），且
2. **每门都有正负对照**（T-3），且
3. **报告里每个数字给出复算方式**（T-5），且
4. **任何"判定面为空/未执行"被显式标为"不适用（非通过）"**（T-2），且
5. **每条宣称写明口径上界**（T-4）。

不满足其中任一条 ⇒ 该次审查**未完成**，与"跑了几轮"无关。

| 方案 | 人工 | 机器 | 说明 |
|---|---|---|---|
| 终审十轮（现口径） | 十次全库过读 | 重复跑同一批脚本 | 人工量 ∈ O(轮数 × 全库) |

## §9 抽样量的科学计算（按架构工作量，非按总体大小）

> **一句话原理**：抽样量不是从"库有多大"算出来的，是从**"哪一层该抽" + "错误怎么分布"**算出来的。
> 出处：均经检索核验（NIST e-Handbook；Clopper-Pearson 1934 DOI 10.1093/biomet/26.4.404；Wilson 1927；Wald 1945 DOI 10.1214/aoms/1177731118；Chapman/闭总体模型见 R `Rcapture` 文档；Briand 2000 IEEE TSE DOI 10.1109/32.852741；Petersson 2004 JSS DOI 10.1016/S0164-1212(03)00090-6；Neyman 1934 DOI 10.2307/2342192；设计效应公式见 PLOS ONE 2021 DOI 10.1371/journal.pone.0254330）。

### S9.1 第一刀：分出"根本不该抽样的层"
机器能全量查的层，抽样就是**降级**：

| 层 | 查法 | 为什么不用抽 |
|---|---|---|
| 引文回落（117185 条） | 全量核验 | 现状 99.83% ⇒ 约 199 条失败，**全量列清单人看**即可 |
| 结构完整性（必填/ID 唯一/关系两端存在/时间轴单调/伏笔闭合/章覆盖） | 全量脚本 | 规则确定 |
| 口径一致性（同班车同规范版本同上下文包哈希） | 按班车**分组统计** | 直接暴露成簇 |
| 真源↔派生对账 | 全量脚本 | 数得出来 |

→ **人只抽一层：语义正确性**（证据是否真的支撑断言、指代消解、事件边界、伏笔判定）。

### S9.2 公式：以置信度 C 证明"坏率 ≤ p"（零缺陷）
```
n ≥ ln(1−C) / ln(1−p)
```
| p | C=95% | C=99% |
|---|---|---|
| 10% | 29 | 44 |
| 5% | **59** | 90 |
| 3% | 99 | 152 |
| 1% | 299 | 459 |

**有限总体修正（FPC）可忽略**：本规模抽样比 n/N < 5%，超几何只比二项省 0~4%（N=6172 时 1%/95% 从 299 降到 290）——不要在这里纠缠。

**现口径的真实强度**：主工单的"随机 30 条"零缺陷时只证得 **≤9.50%**，不是"质量 ≥95%"。两个口径曾被混用，现已随换壳一并改判。

### S9.3 抽到缺陷不许"口头承诺合格"
- `k=0` → 报 **U = 1 − α^(1/n)**：n=30→9.50%；59→4.95%；100→2.95%
- `k≥1` → 报 **Clopper-Pearson 单侧精确上界 U = BetaInv(1−α; k+1, n−k)**：n=59 时 k=1→7.79%、k=2→10.29%
- 结论：**一旦出现 1 个缺陷，"证 ≤1%"必然失败**——口径要么定 ≤5%，要么承认要几百条。如实报上界，不做合格/不合格的口头结论。

### S9.4 成簇修正（★ 最关键，公式决定"按架构工作量"的确切含义）
```
deff = 1 + (m−1)·ρ          n_eff = n / deff
```
- CBB 的"群"= **班车**（同一班车 = 同一规范版本 + 同一上下文包 + 同一执行会话）：`m ≈ 每班车记录数`
- 若 ρ=0.02、m≈200 → `deff ≈ 4.98` ⇒ 名义 59 条的有效样本量只剩约 12 条，**真实置信度远低于 95%**
- **解法不是把 n 涨到 300，而是改抽样设计**：**按班车分层、每层固定抽 8~10 条**——分层抽样消除簇内相关的惩罚（挨 deff 打击的是整群抽样）
- 于是：**抽样量 = 层数 × 每层条数**，其中"层数"正是**架构工作量**（段数 × 每段班车数）。这就是"按架构工作量科学计算"的确切含义。
- `ρ` 不许拍：用 S9.5 的双复查一致率**现场估**。

### S9.5 残余缺陷：捕获-再捕获（回答"还有多少没被发现"）
- 两名**独立**复查者看同一批（n₁=n₂=40~60 条）；**Chapman 估计量**：
```
N̂ = (n₁+1)(n₂+1)/(m+1) − 1        （m = 双方共同查出的缺陷数）
```
- 算例（各 40 条）：共同 m=16 → N̂≈98（残余 ~34）；m=10 → N̂≈152（残余 ~82）
- **独立性是命门**：两人若共用同一份规范/上下文包，正相关会让 N̂ **严重低估** ⇒ 必须做一致性检查（错误类型分布是否雷同），雷同则换第三人或换模型。
- **这条正是"第三方抽检"该升级成的东西**：现在 DeepSeek 抽检是"抽 1~2 章重抽对比"，连一个估计量都不是；改成双复查对，就能直接报"还剩多少"。

### S9.6 停止规则：序贯（SPRT）
先抽 30 条，质量明显好/坏即停、卡在中间继续 → 平均省 30~50%（Wald 1945）。适配夜间窗口"边抽边停"。

### S9.7 落地表（按层定量，非按总数定量）
| 层 | 方式 | 量 |
|---|---|---|
| 语料／结构／口径／对账 | 全量机器 | — |
| 规则（门 1／约束族） | 成对可执行反例，**全枚举** | = 规则数 |
| **语义正确性** | 人；**按班车分层** | **每班车 8~10 条**；需整体陈述时 n≥59（≤5%，95%） |
| **残余缺陷** | 双独立复查者 + Chapman | 每轮 40~60 条 |
| 报告结论 | 逐句对账（标签与量／口径上界／判定面非空） | = 报告句数 |

**成本**：一轮全库复核 ≈ 班车数×10 条 + 40~60 条双复查 ≈ 一个夜间窗口量级；比"十次全库通读"低一个数量级，且结论强度**可计算**。

### S9.8 明确不用：ISO 2859-1／Z1.4／MIL-STD-105E 的 AQL 表
那套是**供方↔需方的逐批验收决策**工具：AQL ≠"我证明的坏率上界"（AQL 处仍约 5% 拒收风险），且它假设**批内独立同分布**——与"错误按班车聚集"直接冲突；用于内部还会莫名"误废"。若非要引用字码，必须先用 R 包 `AQLSchemes` 复算 OC 曲线核对（标准原文本次网络不可达，【未核实】）。**改用 S9.2／S9.3 的公式口径：不依赖任何被墙原文，且直接产出"坏率上界"。**

## §10 "单位级十轮"与"每批十查"到底是什么

### S10.1 单位级十轮自审（《本体构筑-工单》§3 原文操作化）
**是什么**：阶段二**每完成一个工作单位**（一个模块/一件交付），在标 done 之前**按十个不同镜头各查一遍**，日志逐轮追加：
`R<n> <镜头> | 检查了<文件×方法> | 发现=<逐条或零> | 处置=<修复/记录/零>`；**零发现也必须写明实际检查的文件与方法（空话零发现无效）**。

**十镜头**：R1 契约符合性（四 schema 校验器跑本单位产物）／R2 证据链（每项设计决策可回溯 U-A17 §3 或 Step 0 结论）／R3 幂等与断点（重跑零副作用、STATE/commit 纪律）／R4 边界与异常（空输入、坏编码 GBK、超长、符号链接、越界章号）／R5 Windows 纪律（`py -X utf8`、路径分隔、注册表兜底）／R6 许可红旗（零 GPL/AGPL 代码接触、CC BY-NC-SA 零文本复制）／R7 Step 0 三条件对照／R8 吸收项对照（U-A17 清单逐条落实或记录不落实理由）／R9 测试覆盖（新行为有测试 + 至少一反例；总用例数不降）／R10 红队终局（假设自己是审核线找打回理由）。

**出口门**：10 轮全部有留痕 + **最后两轮零新发现**（或发现已当场修复并复验）；未过门不得标 done、不得 commit。

**架构定性**：它**不是"同一件事重复十遍"，是"十种不同视角各查一遍"**——这正是它有效的原因（每轮换镜头 ⇒ 覆盖不同失效面）。适用尺度是"**单位小到一轮能通读**"。
**短板**：①"十"没有统计依据（凑十个视角）；②**它是写者自审**（自己查自己），无独立性；③到全库尺度"一轮"＝一次全量扫描，重复无新增信息 ⇒ **故只保留在单位级**。

### S10.2 每批十查（《迷深实战-工单》§3 原文十项）
**是什么**：**每批收口前**逐项留痕的十个机械项：①工作区健康（git 干净/STATE 对账）②边界表切片正确（章题与首行对质）③R6 生效（规范含 R6 全文 + 候选零元文本抽检）④reference_time=伪锚点无墙钟 ⑤抽取量合理区间（空记录须记原因）⑥quarantine 分流正常（矛盾/低置信/超期各归其位）⑦去重与双轨命中入账（别名四分类 + UNIQUE 拦截 + 嵌入相似度，不静默）⑧**证据四元组抽检 2 条**对原文（judge 锚定评分辅助）⑨verified_against 真实三件套（脏工作树不作锚）⑩STATE 游标 + scoped commit（含 Neo4j 增量导出）。

**架构定性**：**它是清单（每批必答十项），不是轮次**——"十"是清单长度，不是重复次数，**形状本来就对**。
**短板**：第⑧项"抽检 **2 条**"在统计上等于**零强度**（2 条只可能撞见极端问题）。按 §9 改为"**按班车分层抽 8~10 条**"，并注明它只对语义层有效。

### S10.3 三者的架构位置（"从架构决定方法论"的结论）
| 机制 | 尺度 | 性质 | 查谁 | 处置 |
|---|---|---|---|---|
| 单位级十轮 | 一个单位（小） | **写者自审**，十视角 | 变更本身 | **保留**（尺度合适） |
| 每批十查 | 一个批次 | **写者自审**，机械清单 | 批次产出 | **保留**；第⑧项重算强度 |
| 五层证据门 G1~G5 | 全库 | **独立复核**（新增） | 全库产物 | 新增（替代全库十轮） |

**架构上唯一真缺的那一层是"独立性"**：前两者都是自己查自己；而"还剩多少没发现"这件事，软件检查领域十年的实证（Briand 2000；Petersson 2004；Thelin 2002）指向同一个结论——**必须两个独立复查者 + 捕获-再捕获**才能估。故本方案把"第三方抽检（现为抽 1~2 章重抽）"升级为**正式的双复查对**。

## §11 批次层与单位层的替代推导（裁定 2：**两个十轮全部去除**）

> **效力声明**：本节依用户裁定（2026-09-22"去除这两个 10 轮"）推导，**推翻 §5 与 §10.3 中"保留单位级十轮／每批十查"的结论**；§5／§10 原文保留留痕，以本节为准。
> 落点自陈：本节是 L5 文档；强制力来自《迷深实战-工单》《本体构筑-工单》的追加裁定段。

### S11.0 三条推导原则（与终审五门同源）

1. **检查面 = 该层失效模式的穷举**——与层绑定，与"轮"无关；
2. **执行载体 = 能机械判定的必须机器判定**（判定面非空，T-2）；人只查机器判不了的；
3. **出口 = 证据**（可复算 + 正对照 + 逐条锚点），**不是过程量**（轮数、时长、"零新发现"的口头声明）。

### S11.2 批次层：十查 → **批次机械自检**

**关键发现**：十查的十个检查面本身没错——它们恰好就是批次产出的失效模式穷举；**错的是执行载体**：十项全是人工逐项留痕，而这十项**全部机械可判**。所以不是删检查，是把清单从人脑搬进机器：

| 十查原项 | 失效模式 | 机械断言（脚本逐项判） |
|---|---|---|
| ①工作区健康 | 库/STATE/commit 不同步 | 三方对账断言（游标=账本头=commit 内容） |
| ②边界表切片正确 | 章号错/跳章 | 候选章号 vs 边界表一致；缺号章必有登记 |
| ③R6 生效 | 元文本混入 | 候选文本禁词/元文本**全量扫描** |
| ④无墙钟 | 真实时钟入档 | reference_time 字段伪锚点断言 |
| ⑤抽取量合理 | 空章无因 | 零候选章必须有原因登记（纯对话/过渡章合法） |
| ⑥分流正常 | 该隔离的入库 | 状态字段断言（隔离/入库各归其位） |
| ⑦去重入账 | 去重静默 | 嵌入扫描"已执行且有输出"断言（**判定面非空**） |
| ⑧抽检 2 条对原文 | 引文悬空 | **改为全量回落**（每章候选量小，机器可全量；旧"抽 2 条"零强度） |
| ⑨verified_against | 占位三件套 | 字段存在性+非占位值断言 |
| ⑩游标+commit+导出 | 断点丢失/导出债务 | commit 存在性 + 导出文件存在性 |

**交付**：`批次自检` 脚本（一次性开发，之后**每批零人工**）；人只处理 **FAIL 与合法例外**；**留痕＝脚本输出本身**（自动留痕，天然可复算）。
**过渡条款**：脚本就绪前，十查暂按原样执行——**不得因换壳停止检查**。

### S11.3 单位层：十轮 → **单位收口三件套**

十轮的十个镜头**拆散归位**（镜头思想保留，轮次废除）：

| 镜头 | 去向 | 载体 |
|---|---|---|
| R1 契约符合性 | **机械门** | schema 校验器跑本单位产物 |
| R3 幂等与断点 | **机械门** | 集成双跑断言（U-B08 实证：双跑抓过两个真缺陷） |
| R4 边界与异常 / R5 Windows 纪律 | **机械门** | 单测反例 + `py -X utf8` 全量跑 |
| R6 许可红旗 | **机械门** | 红线词表 grep（GPL/AGPL 零接触、CC BY-NC-SA 零复制） |
| R9 测试覆盖 | **机械门** | "新行为必有反例"断言 + 总用例数不降 |
| R2 证据链可回溯 | **人工增量清单①** | 逐条锚 `文件:行号`（只查增量，不重读全库） |
| R7 Step0 / R8 吸收项对照 | **人工增量清单②** | 对照表逐条勾选 |
| R10 红队终局 | **人工增量清单③** | 写打回理由清单——每条要么修复、要么登记【待确认】 |

**出口条件（替代"十轮留痕+最后两轮零新发现"）**：机械门全绿 ＋ 清单三条逐条有锚 ＋ scoped commit。**零轮次，只看证据。**
**历史不追溯**：U-B00~B09 的十轮日志是既成事实，保留原样。

### S11.4 为什么这不是"少查了"

| | 旧协议 | 新协议 |
|---|---|---|
| 十查的十个面 | 人工留痕 | **全在**（机器化），且⑧从抽 2 条升为全量 |
| 十轮的十个镜头 | 人工十轮 | **全在**（6 个进机械门、3 个进清单、红队照旧） |
| 新增覆盖 | — | 批次三方对账自动化 · 判定面非空断言 · 全量证据回落 |
| 人工成本 | 每批 10 项留痕 + 每单位 10 轮文档 | 每批 0（只看 FAIL）+ 每单位 3 条带锚 |

**减少的是重复劳动，不是覆盖。**
