## 0. 记号与状态集

```
CONSTANTS Records, PseudoDate   \* PseudoDate = "YYYY-MM-DD" ∪ "chNNNN"（contract.PSEUDO_RE）
VARIABLES
  lib,          \* libraries/<library>/<status>/<rid>.json 的记录集，status ∈ {"confirmed","provisional"}
  quarantine,   \* quarantine-zone/items.jsonl 的隔离件集，item.status ∈ {"pending","confirmed","rejected"}
  sidecars,     \* supersede-index / invalidations / complementary-statements / 拦截件全文 / transitions（全部 append-only）
  ledger        \* ledger.jsonl 哈希链（规格见 账本链完整性.alloy.md）
```

三态的物理承载（store.py `Store` 类注释，B1：**库里只有两态**）：

| 态 | 物理位置 | 进入动作 |
|---|---|---|
| provisional | `libraries/<lib>/provisional/<rid>.json` | `write_decision` 分支①④⑤-neutral 落盘 |
| confirmed | `libraries/<lib>/confirmed/<rid>.json` | 仅 G5 票门晋升（见 §3） |
| quarantine | `quarantine-zone/items.jsonl`（独立第三态，不占库内目录） | 分支⑤ 闸1 定 contradicts → `_gate_to_quarantine`，或隔离区显式 `register` |

## 1. 输入校验族（先于一切分支；违反即抛已知 ValueError，不落任何轨）

对应 `write_decision` 开头的四道校验 + `_append` 的序列化防线：

```
Guard(incoming, at) ≜
  ∧ at ≠ "" ∧ at ∈ PseudoDate        ── "at 必须为伪锚点日历取值…禁墙钟"（D-2/D-24；
                                        test_v3_store.py::test_at_required_without_at_rejected）
  ∧ incoming.record_type = "entity"  ⇒ incoming.canonical.name ≠ ""
  ∧ incoming.record_type = "relation" ⇒ subject/rel_type/object 全非空
                                       ── 身份键无法建立即拒绝（红队 P1-6；
                                        test_entity_without_name_rejected / test_relation_identity_includes_library）
  ∧ incoming.t_valid ≠ NULL ⇒ incoming.t_valid ∈ PseudoDate
                                       ── 自报时间位格式校验（红队 P1-1；
                                        test_t_valid_format_rejected）
  ∧ profile(library) 存在            ── contract.load_profile，缺 profile 抛 KeyError（非 ValueError，校验族同收）

序列化防线（Store._append）：对象不可 JSON 序列化 / 含不可 UTF-8 编码字符（未配对代理）⇒ ValueError
——"拒绝写而非半行崩溃"（属怋试策略 PRINTABLE/evidence.quote 以 Cs/Cc 考题钉住该面）
```

闸回调合法性：`nli_gate` 返回值 ∉ {contradicts, neutral} ⇒ ValueError"NLI 闸返回非法值"。

## 2. 五分支决策树（`write_decision` 主体）

```
RECURSIVE WriteDecision
WriteDecision(incoming, at) ≜
  LET existing ≜ FindByIdentity(incoming)      \* 身份键：entity=(lib,name)；relation=(lib,S,rel,O)；其余=record_id
      conflicts ≜ ClassifyConflicts(profile, incoming, existing)
                  \* 比对域=双方 canonical 同键 − {name}；kind ∈ {statement, mutable, immutable, unclassified}
                  \* 声明为断言但未定可变性 → 保守按 immutable（contract.field_kind）
  IN
  IF existing = NIL THEN
    Branch1_OnCreate                            \* ①新建
  ELSE IF conflicts = ∅ THEN
    Branch2_ConsistentDuplicate                 \* ②一致重复（可选闸2 NLI 复核）
  ELSE IF ∀c ∈ conflicts: c.kind = "statement" THEN
    Branch3_ComplementaryStatement              \* ③互补陈述（仅陈述位差）
  ELSE IF (∀ assertC: mutable) ∧ ProvableOrder(old_tv, new_tv) THEN
    Branch4_InvalidationUpdate                  \* ④失效记账
  ELSE
    Branch5_TrueContradiction                   \* ⑤真矛盾（闸1 三分/保守回落）
```

各分支动作（`track` 返回名与源码逐一对应）：

```
Branch1_OnCreate:   status' = "provisional"（强制；红队 P1-5）、version'=1（强制；红队 P0-2）、
                    剥 supersedes、t_valid 缺则由证据章推导（_derive_t_valid）、
                    rid 撞名 ⇒ 改派 "-x{n}" 后缀重写绝不静默吞（_admit_unique，红队 P0-1）
                    → track = "on-create"

Branch2_ConsistentDuplicate: 证据子集 ⊆ 库内证据 ⇒ 幂等守卫 repeated=True 不写（P-017）；
                    否则合并证据 + 置信 max+BUMP(=2.0)、新 id = "<base>-m{version+1}"、
                    走 supersede 原子对（supersede-index.jsonl 追加 old_id→new_id）
                    → track = "consistent-duplicate"
                    （闸2 nli_merge_gate 判 contradicts ⇒ 改走 _gate_to_quarantine，track="contradiction"）

Branch3_ComplementaryStatement: incoming 不落库，逐陈述位落 sidecar 事件
                    （event_id = ce-sha256(about|field|value|at|证据)[:12]——哈希域含 about/field/at/证据，
                    不同记录/时点不碰撞；红队 P1-3）
                    → track = "complementary-statement"
                    （混合冲突时：陈述位先落 sidecar，断言位继续走④/⑤——B7 修复，陈述位不丢）

Branch4_InvalidationUpdate: 前提 = 冲突全为 mutable ∧ 时序**严格可证** old_tv < new_tv
                    （_tv_lt：只信证据章推导/ch 格式可比；缺位或格式不可比 ⇒ False，"保守，不洗白"）
                    动作 = invalidations.jsonl 追加 {record_id, t_invalid, fields, at, key=rid|new_tv|at}
                          （幂等键含时序——第二笔失效不被吞；红队 P1-9/B3）
                    + 新件 provisional 入库（旧件字节不动，历史全保留）
                    → track = "invalidation-update"

Branch5_TrueContradiction: verdict ≜ IF nli_gate = NIL THEN "contradicts"   \* 无闸保守回落=v1 行为
                                     ELSE nli_gate(incoming, existing, assertC)
                    verdict = "neutral"    ⇒ 新件 provisional + _meta.uncertain 标注
                                              → track = "uncertain-coexist"（⑤的闸1三分中立叉）
                    verdict = "contradicts" ⇒ register_conflict = TRUE：
                                              隔离区登记（entity_unalignable/contradiction_pending）
                                              + 拦截件全文.jsonl 留全文可重放（D-6）
                                              → track = "contradiction"
                                              register_conflict = FALSE（重分流场景）：
                                              → track = "contradiction"（quarantine_item=NULL，交调用方处置）
```

## 3. 三态迁移

```
Promote(rid) ≜ 票门通过才可执行（promote.vote，B13 语义）：
    need      = ⌈2 × full_size / 3⌉      \* 需票按满编制算——缩员不得自动降门槛
    against   = 0                        \* 任何异构反对 ⇒ human（真分歧信号，人工裁决）
    support ≥ need ∧ n ≥ 2               \* 双考官下限——单考官无异构性不得单独晋升
    ∧ gate1 零违例 ∧ tenure_ok（由调用方传入 promotion_check）
  ⇒ 库内 provisional → confirmed（G5 晋升）

WritePathNeverConfirms: WriteDecision 任何分支产出的新件 status 恒 = "provisional"
  （源码注释"红队 P1-5：confirmed 仅能由 G5 晋升产生"；test_version_and_status_forgery_stripped
    钉住 caller 伪造 status/version/supersedes 一律剥除）

HumanTransition(rid, to) ≜ status_transition（R13 旁车日志，文件不动）：
    to ∈ {"confirmed","provisional"}，by ∈ {"human","shadow","promotion"}
    效果 = transitions.jsonl 追加一行（append-only）；库件 JSON 本体永不改写（_write_immutable）
  【在案注释】代码层允许 human 将 confirmed 迁回 provisional（每次必留痕）——故本规格把
  "confirmed 是 sink"建为**写入面+自动面**的 sink（WritePathNeverConfirms + Promote 门），
  人工回退是显式留痕事件而非非法状态。若需把人工回退也封死，属设计决策，登记待裁【待确认】。

Adjudicate(iid, verdict) ≜ verdict ∈ {"confirmed","rejected"}（隔离区，quarantine.adjudicate）：
    pending → confirmed | rejected；同 (iid|verdict) 幂等跳过（LedgedStore.zadjudicate 账本幂等键）；
    改判（换 verdict）会再次执行并追加 adjudications.jsonl 留痕（append-only 日志可回溯）。
    裁决为 confirmed 的语义=该矛盾件"坐实"，处置回到人工/重分流通道，不等于库内 confirmed 记录。
```

## 4. 不变式

```
PromotionMono ≜   \* 晋升单向性
  ∀ r ∈ lib: r.status = "confirmed" ⇒
      ∃ 票门通过事件（vote ⇒ "promote"）或 HumanTransition(by ∈ {"human","promotion"}) 留痕
  ∧ 无任何 WriteDecision 分支直接产出 confirmed
  ∧ 无自动动作使 confirmed → provisional（唯一回退通道=显式留痕的 HumanTransition）

TriStateDisjoint ≜   \* 三态互斥
  ∀ rid: 计恰一次于 {provisional, quarantine, confirmed}
  ∧ provisional ∧ confirmed ⇒ rid 分别在 libraries/*/provisional 与 libraries/*/confirmed，无同件双态
  ∧ quarantine 件永不直接落库目录（admit 显式拒收 quarantine 决定，"quarantine 走 register_quarantine"）

Totality ≜   \* 任意输入必落五轨之一或抛已知 ValueError
  ∀ incoming ∈ 合法 Unicode 域, at ∈ PseudoDate:
      Guard(incoming, at) 违反 ⇒ 抛 §1 已知 ValueError/KeyError 族（不崩、不静默）
      否则 ⇒ track ∈ {"on-create","consistent-duplicate","complementary-statement",
                       "invalidation-update","uncertain-coexist","contradiction"}
  （六 track 名=五分支+⑤的中立叉；与 test_v3_properties.py 的 TRACKS 集合逐字一致）

IdempotentReplay ≜   \* 幂等守卫（属怋试第二条）
  同 (incoming, at) 二次 WriteDecision 不产生新库件（P-017 证据子集守卫 + sidecar 账本幂等键）
```

## 6. 已知 ValueError 族总表（Totality 的"已知"边界）

| 错误 | 触发 | 源码锚 |
|---|---|---|
| at 缺失/非伪锚点 | `write_decision(incoming)` 无 at 或 at ∉ PseudoDate | store.py 首行校验（D-2/D-24，禁墙钟） |
| 身份键无法建立 | entity 缺 canonical.name；relation 三元组不全 | 红队 P1-6 |
| t_valid 非伪锚点格式 | caller 自报非法 t_valid | 红队 P1-1 |
| NLI 闸返回非法值 | nli_gate 返回 contradicts/neutral 之外的值 | write_decision 闸回调校验 |
| 非法入库决定 / 缺 record_id / 直调 quarantine | `admit` 校验（write_decision 不直调 admit 的 quarantine 路径） | store.py admit |
| 不可序列化/不可编码 | sidecar 对象含非 JSON 类型或未配对代理 | Store._append（拒绝写而非半行崩溃） |
| （KeyError）缺 profile | library 无 profiles/<lib>.json | contract.load_profile |
