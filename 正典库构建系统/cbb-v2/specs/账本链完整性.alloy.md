## 0. 签名（sig）

```
abstract sig Sha {}
one sig EmptySha extends Sha {}          \* "0"×64 = 创世 prev_hash（ledger.py EMPTY_SHA）

sig Entry {
  seq:      Int,                          \* 从 1 起连续
  op:       Op,                           \* append / genesis / rebaseline（verify 口径）
  target:   Target,                       \* 侧车相对路径，如 "complementary-statements.jsonl"
  key:      Key,                          \* 幂等键（key|item_id|record_id，缺席取整对象哈希前 16 位）
  shaBefore, shaAfter: Sha,
  prevHash: Sha,
  hash:     Sha,                          \* line_hash(payload) = sha256(canonicalJSON(payload − hash))
  corrupt:  lone RawLine                  \* 仅坏行占位件持有——"行损坏"标记（P-028 语义）
}

fact LineHashDeterministic {
  all e: Entry | e.hash = lineHash[e]     \* lineHash 只依赖除 hash 外的载荷（canonical JSON：sort_keys + UTF-8）
}

fact ChainShape {                        \* Genesis 锚 + 逐行自洽
  no e: Entry | e.seq = 0
  all e: Entry | (e.seq = 1 implies e.prevHash = EmptySha)
              and (e.seq > 1 implies some p: Entry | p.seq = e.seq − 1
                                     and e.prevHash = p.hash)
  all e: Entry | e.seq − (#{p: Entry | p.seq < e.seq}) = 1    \* 序号连续：seq = 行位次 i+1
}
```

## 1. 断言（assert）——篡改检测性

verify（读盘不信任缓存：`_rows_fresh` 先置空 `_cache` 再重读文件）逐行做三查 + 可选对账：

```
assert ChainIntegrity {
  良构账本（由 record_append 逐行产生）⇒ verify 返回 ok=true, errors=∅
  ——运行时对应 test_ledger_chain_recompute：任意 (target,key,sha_before,sha_after) 序列（Hypothesis 30 例）
    构链后 verify 必 ok
}

assert TamperDetection {
  对账本文件任一字节取反（blob[pos] ^= 0x01）⇒ 新实例 verify 必 ok=false，且 error ∈ {
    "行哈希不匹配（被篡改？）",       \* hash ≠ lineHash(e)
    "prev_hash 断链"                  \* e.prevHash ≠ 前行 hash（或坏行后置 prevHash=∅ 传导）
  }
  ——运行时对应 test_tamper_detection：随机翻转一字节，断言"要么哈希不匹配要么 prev 断链"
}

assert SeqContinuityDetected {
  任一行 seq ≠ 行位次 ⇒ verify 追加 "seq{N}: 序号不连续"
  ——对应 verify 第三查（r.get("seq") != i + 1）
}

assert ExternalDriftDetected {
  给定 store_root 时：逐 target 取账本最后一条 sha_after 与磁盘现值比对，
  不符 ⇒ 追加 "{target}: 当前 sha 与账本不符（账本外改动）"；文件缺席按 EmptySha 对账
}
```

## 2. 坏行语义：corrupt 标记不崩溃（P-028，本批刚修语义）

```
fact ReadSplitOnlyOnLF {
  行界 = 字节 0x0A 一个；JSON 字符串内合法的 U+0085 / U+2028 等 Unicode 行分隔符**不是**行界
  ——str.splitlines() 会把它们当行界撕碎 JSON（P-028 病灶）；实现为 raw.split(b"\n")
}

assert CorruptLineMarkedNotCrash {
  任何字节串输入 ⇒ 解析产生 Entry 集 ∪ corrupt 占位件集，**不抛异常**
  ∧ all c: corrupt 件 | c.corrupt = 该行前 32 字符（utf-8/replace 解码）
  ∧ verify 对 corrupt 件追加 "line{i}: 行损坏无法解析（'…'）" 并将 prevHash 置空
    ——后续行 prev_hash 必不一致，让断链误差**显式暴露**而非静默吞
  ∧ 审计工具对任意输入必须给判定，不许抛异常（ledger.py 注释原文口径）
}
```

## 3. append-only 与幂等入账（LedgedStore 层）

```
assert AppendOnly {
  时间步序列中不存在对既有 Entry 载荷的赋值；唯一变更 = 末尾追加新行
  ——实现侧：_append_row 只 open("a") 追加；库件本体写入不入账（与 v1 A3 口径一致），
    侧车 _append 经 LedgedStore._wrap_appends 全量自动入账（U-A02 起 write_decision 的
    complementary-statements / invalidations / 拦截件全文 无需逐名注册）
}

assert IdempotentAppend {
  has_key(target, key) = true ⇒ 再 append 同键被跳过且**不产生新账行**
  ——幂等键取 obj 的 key|item_id|record_id，全缺则整对象 canonical JSON sha256 前 16 位
  ——运行时对应 test_sidecar_idempotent_under_ledger：同件重放 rows=1 且 verify(Path(td))["ok"]
}

assert AdjudicateDoubleRow {
  隔离区裁决入账为双行（items 的 sha 与 adjudications 的 sha 各记对目标）——彩排抓 bug #2 修复后语义
}
```

## 5. 边界

- 账本只对**侧车 append 面**记账（库件 JSON、隔离区 items 的裁决改写除外——裁决经 zadjudicate 双行入账）；"账本证明不了没有漏"的残余由前置/后置门与投影检查点分管（见 `CBB全流程说明书-20260925.md` 纪律速查第 12 条）。
- `verify` 的对账分支（store_root 给定时）读磁盘现值，属"读盘不信任缓存"同族设计。
