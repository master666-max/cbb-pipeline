## 二、批次 6：聚合人物页 + lorebook 转换器

### 语义核心（判卷级，须谨慎）
别名合并=同指判定。证据面三层：
1. **精确名簇**（canonical.name 相等）——零风险聚合；
2. **aliases.jsonl 证据面**（539 行 alias→entity_id 映射，抽取期已判）——低风险聚合；
3. **四分类策略**（cbb-extract SKILL：proper_name 可合并／nickname 须同指证据且置信≥0.85／descriptor·title 永不合并／存疑分开建）——中风险，按类施策；
4. LLM 同指判定——判卷成本，**本批不做**（留人工窗/后续）。

### lorebook 转换器
- 目标格式：SillyTavern World Info JSON（entries: uid/key[]/keysecondary/comment/content/constant/selective/order/probability）【待确认：ST 版本字段差异】；
- 内容源：**29 件 confirmed 优先**（批次 5 物料化的干净正典）→ 全量 wiki 页可扩展；
- key=name+aliases；content=聚合渲染正文（断言+引文回链）。

### 单元
- **A1 聚合引擎**：名字精确簇 ∪ aliases.jsonl entity_id 映射（连通分量）→ 聚合簇清单+统计（385 簇实测基线）
- **A2 聚合页渲染**：每簇一页——实体头（名/别名/类型/状态徽章）+ 断言时间线（按 chapter 排序，逐条带源记录回链+三态徽章）+ 冲突断言并列不仲裁（判卷语义留人工窗）
- **A3 lorebook 转换器**：聚合页/记录页 → ST World Info JSON；confirmed 优先级排序
- **判据**：聚合簇统计与手工抽验 5 簇一致；lorebook JSON 结构校验+可导入【待确认：ST 实测环境】；全链零 API

## 三、批次 7：巡检自动化 + 增量摄入调度化

### 现役组件盘点
| 组件 | 状态 | 缺口 |
|---|---|---|
| g17_patrol_queue / execute | 首圈 903 卡基线在案 | 调度化（定时/事件触发） |

| ingest.py 增量摄入 | 手动扣扳机形态 | 调度化三档（见下） |

### 调度化三档
- a) 手动命令（现状，ingest.py --dry-run→实跑）
- b) **watchdog 文件监控**（推荐）：监控 corpus 目录变更 → 自动 ingest_diff → 有增量自动摄入 → 完成自动重导快照；书架页显示增量状态
- c) 计划任务定时（Windows 计划程序每日/每周）

### 批次 7 单元
- **B1 G17 二圈自动调度**：巡检队列→执行→CUSUM 读数，一键化
- **B2 增量摄入调度**：watchdog 监控 + 自动 ingest + 快照重导（全链 done-set 幂等，断点安全）
- **B3 CUSUM 激活**：改判率序列入监控（生命周期条款：3 圈无告警降频）
