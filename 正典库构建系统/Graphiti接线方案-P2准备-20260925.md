## Spike 实测（`graphiti_spike.py`）

- 输入：真章节切片（ch0003 前 600 字）+ 伪锚点 reference_time（第 3 章 → 2000-01-03，禁墙钟纪律同 neo4j_export）；
- 输出：**Entity 8 / RELATES_TO 6** 落入 graphiti 实例——管道全通；
- **成本：988.7 秒/集**（600 字！graphiti 每集多轮 LLM 调用：实体抽取→消歧→边抽取→摘要，14B CoT 模型慢）。
- 坑记三笔：①cross_encoder 缺省会找 OPENAI_API_KEY（须显式 `OpenAIRerankerClient(config=…)`）；②episode 节点标签是 `Episodic` 不是 `Episode`（清点查询注意）；③neo4j AsyncSession/AsyncResult 全异步（`async with` / `await result.single()`）。

## 架构决定（接线形态）

1. **双图并存**：正典图（neo4j-step0，neo4j_export 派生，检索单真源）不动；Graphiti 图在独立实例积累双时序层——两图不做 MERGE；
2. **episode 摄入挂章收口**（与 lightrag delta sync 同批 aux）：每章一章文本一集；reference_time=伪锚点；
3. **时序语义收益**：graphiti 自动做实体消歧与旧事实 invalidation（t_valid/t_invalid + t'created/t'expired），取代手工维护——这正是"作者吃设定"的终态解；
4. **消费方式**：graphiti 实例只读检索（search/syntax 邻域），结果作为链构造器的第二来源，不直接写正典。

## 铺开前的成本裁决（待审）

- 判据（铺开前）：单集抽取 ≤180s 且实体/边质量抽检通过（与亲抽记录对样 20 条）。


## DeepSeek 实验记录（2026-09-25 补 · 用户供 key 实测）

| 项 | 本地 14B（基线） | DeepSeek（graphiti 抽取管线） | DeepSeek（自管抽取） |
|---|---|---|---|
| 耗时/600字集 | 988.7s | **36.0s（27.5×）** | 秒级（抽取 1 次调用） |
| 图产出 | +8 实体/+6 关系 | **≈空（+1 实体/+0 关系）** | +5 实体/+4 关系（4/4 全落） |
| token | 不可计量 | 3 调用 4937+271 | 抽取 483+229/次 |
| canon 命中 | 1/8 | 无法评估 | 探针 6 实体全部合理 |

**结论**：
1. DeepSeek 原始抽取能力**优秀**（裸调用 json_object：同文本 6 实体/4 关系、合法 JSON、秒级、~700 tokens）；
2. **graphiti 0.30.2 的 json_object 抽取管线有缺陷**：schema 虽注入 prompt 但产出被静默过滤（+1 实体/+0 关系）——graphiti 侧不修不能用；
3. **架构裁定：抽取自管 + graphiti 只当双时序存储**。`fact_triple` 模式实测 4/4 三元组全落图（episode/实体/关系/valid_at 齐备）——绕开缺陷管线，两端都用已验证的件；
4. 三坑新增记档：DeepSeek 不支持 json_schema response_format（须 SPIKE_STRUCTURED=json_object）；嵌入器 base_url 不得随 LLM 路线走（钉死本地）；episode 标签=Episodic。
5. DeepSeek 路线形态定稿：`graphiti_spike.py` env 开关（SPIKE_LLM_MODEL/SPIKE_LLM_BASE/SPIKE_STRUCTURED/SPIKE_GROUP）+ key 注册表注入（D-004）。

**成本外推**（牌价口径按 2025-09 公开价量级，铺开前以当期牌价复核）：抽取 ~700 tokens/600 字 → 全章 ~1.2 万 tokens ≈ 分厘级；517 章全量抽取成本为**个位数人民币量级**——两路线中 DeepSeek 在成本与时延上均占优，质量对样（20 条判据）过即铺开。
