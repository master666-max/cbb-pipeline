description: 状态报告（薄壳）——库量/游标/哨兵/副本对账一页汇总
---

生成**状态报告**（只读，零写入）。路径一律从参数或 env 取，**本文不写任何机器专属值**
（v0.1.3 之前这里放着某台开发机的绝对路径与上一个项目的实例名，换机即不可复跑——
那正是"副本对账"要防的漂移形态之一）。

需要你先给的几个量（缺哪个就报哪个，不许拿猜的顶上）：

| 量 | 取法 | 说明 |
|---|---|---|
| `<版本源>` | env `CBB_SKILL_SRC`，或 `CBB_GUARD_ROOT/cbb-pipeline/` | 本地版本源目录（三副本的基准） |
| `<安装位>` | env `CBB_SKILL_INSTALL` | 宿主插件位（Qoder：`<宿主配置目录>/plugins/cache/<source>/cbb-pipeline/<version>/`，**目录末段须等于 version**；ZCode：其 skills 位）。无用户级技能目录的宿主，技能只能随插件壳装 |
| `<项目根>` | env `CBB_GUARD_ROOT`（缺省＝cwd 向上找 CBB 标记） | 下面三类读数的定位根 |

1. **副本对账**（T-8 副本多义律）：三处逐文件 sha256 对照——`<版本源>` ↔ `<安装位>` ↔
   GitHub `master666-max/cbb-pipeline` 最新 commit（`gh api repos/master666-max/cbb-pipeline/commits/main --jq .sha`，
   或 `git ls-remote`）。差异文件逐个列出，**差集不许静默**；三处互不知情是常态，
   只有从 clone 里 commit＋push 的那份才算"那边知道"。
2. **游标与库量三方**：`<项目根>/*-本体库/ledger.jsonl` 行数与末条 seq ↔ `BUILD-STATE.md` 的游标行 ↔
   `git status --porcelain -- <本体库>` 干净度。**STATE 两种文件名都要读**：带项目前缀的
   `*-BUILD-STATE.md` 与 `init_project.py` 默认产出的裸名 `BUILD-STATE.md`——只认前者会读到空，
   而"读到空"不等于"三方一致"（批次自检 v0.1.3 前就栽在这上面）。
   库量快照：六库各计 JSON 数、`quarantine-zone/` 的 items 与 adjudications 行数。
3. **哨兵读数**：读 `<项目根>/*-工作区/logs/` 下的计数件（全局归纳型查询数、按章回溯数、
   隔离积压与裁决滞后），按 `graphiti_ready.py --sentinel` 的 GREEN/AMBER/RED 口径原样转录；
   **计数件不在就写"无面可判"**，不许把缺席写成 GREEN。
4. **导出债务**：`<本体库>/导出债务.jsonl` 逐条列（含 `infra-degraded` 那类带债通行的），给笔数。

输出成一页；每个数字后面带口径（怎么数的、从哪个文件数的）。只读工具：本命令不写任何文件。

参数：$ARGUMENTS
