description: 批次机械自检（薄壳）——运行既有检查脚本并汇总；脚本缺席时报明确错误（不静默）
---

执行 **批次机械自检**（U-F02 交付件），把结果汇总成一份带口径的报告。按顺序运行并汇总：

1. **先读步骤⓪ 的回执定载体**：`工作区/环境自检.json` 里的 `carrier` 字段决定这一发用哪个后端——
   `py -X utf8 cbb/tools/批次自检.py --store <本体库> --workspace <工作区>`（十项机械门）
   `py -X utf8 cbb/tools/连续性巡检.py --store <本体库> --backend <file|graph>`（连续性规则巡检）

   **不许写 `--backend auto`**（v0.1.3 前本命令的模板就是这么写的）。自动选择会先摸图，
   机器上只要留着别的项目的图库，它就会摸进去并产出"零孤悬/零矛盾"的假干净——
   那与"这本书真没问题"同形。归属未判 ⇒ 只许 `--backend file`，并在报告里保留"不含一跳邻域"的声明。
2. `git status --porcelain` 与 `git log --oneline -1` —— 工作区健康与游标对账的 git 侧。
   注意：**目录不是 git 仓时 `git status` 报错但 stdout 为空**，据此判"干净"是假阳性（批次自检 0.1.3 起记 `None`）。
3. 若 `<工作区>/logs/批次自检*.json` 存在则读取最新一份（**工作区目录按惯例名 `*-工作区/` 找，不写死实例名**）；
   不存在则明确报告"批次自检器脚本未落地（U-F 线），当前为部分覆盖"。
4. 若第 1 步的十项里出现 `SKIP`，逐条抄进报告——SKIP＝检查器自身失灵或无面可判，与 PASS 不是一回事。

汇总格式：每项一行 `PASS/FAIL/SKIP + 一句话`；FAIL 项给出精确命令与原因。**禁止**把"没跑"报成"通过"（判定面非空纪律）。

参数：$ARGUMENTS（可覆盖 --store / --workspace / --backend）
