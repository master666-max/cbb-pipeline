## §0 起因与三问

**起因**：本项目跨多会话推进，说明书自 v1.0 迭代到 v1.9.5（十余轮）。会话记忆已被用户判定"涣散"，**记忆不可再作为事实来源**。本次不看记忆、只看磁盘与 git。

**三问**（本次摸底要回答的全部）：

1. **构成**——现在到底哪些文件构成"现行说明书"？各件的职能、效力（现行/历史/冻结/影子）、读序分别是什么？
2. **自洽**——件与件、件与自身之间是否矛盾（版本号、指针、数字、口径、日期）？
3. **对账**——说明书**宣称**的状态与磁盘数据 + git 史实是否一致？

**非目标**（明确不做，防越权）：

- 不做内容质量/方法学复审（属审核线职责）；
- 不修改、不重命名、不删除任何在案文件（发现矛盾**只登记**）；
- 不重跑验收、不重跑单测、不触碰闲时任务与 DeepSeek 预算（纯本地纯读）。

## §3 执行步骤（S1~S5，每步一件产物，全部新增）

### S1 机械清单（零解释）
对 L0~L6 每件生成一行：`层|路径|字节|行数|mtime|sha256_12|正文抽取的版本串(v[0-9.]+)|自称日期`。
命令草案（分母=find 实测，覆盖率必须 100%）：

```bash
find <各层根> -type f -not -path '*/.git/*' -printf '%s\t%TY-%Tm-%Td %TH:%TM\t%p\n'
wc -l <每个 .md>
grep -m3 -o 'v[0-9][0-9.]*' <每个 .md>
sha256sum <每件>
```
