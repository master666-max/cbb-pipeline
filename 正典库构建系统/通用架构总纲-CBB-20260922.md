# 通用架构总纲 · CBB（正典库构建系统 · 项目无关版 v2.0 · 2026-09-22）

> **定位**：把**任意长文本语料**（长篇小说／多卷本文档／维基集群／法规汇编／代码库演化史……）变成**证据可核验、三态可审计的正典知识库**的通用工程。
> **真源声明**：本件是 CBB 的**通用件真源**。迷深实战线为第一个实例，已于同日冻结为资料档（见《冻结声明-迷深实战-20260922.md》）；其方法论与代码全部解耦继承于本纲，其专名与参数全部降为 profile 样例。
> **判定权**：在审核线/用户。构建线无权自宣验收通过。

---

## §0 一句话架构

**"记"不发生在模型脑子里，发生在账本上。** 任何一条事实要进正典，必须：带原文证据（可逐字回落）→ 过机械门 → 与既有事实对撞（重复/矛盾分开）→ 三态落位（确认/暂定/隔离）→ 全程 append-only 可回放。模型负责读和判，**系统负责记、对、废**。

## §1 术语映射（迷深术语 → 通用术语）

| 迷深用语 | 通用用语 | 说明 |
|---|---|---|
| 章（chapter） | **单元（unit）** | 切分单位：章/节/页/文档/条目，由语料适配器定义 |

## §2 六层架构（层与不变式）

```
L0 语料层   外部真值＋单元边界表＋锚点（单元伪锚点，禁墙钟）
            不变式：边界表来自语料自身标记，不来自抽取产物（声明面≠观测面）
L1 抽取层   单元 → 全新上下文执行者 → 候选（写盘不过主上下文，回执≤200tok）
            不变式：四件套输入＝规范＋判例(≤30)＋上下文包(≤2K)＋本单元切片
                    并发只写互不相交路径＋单元认领登记（防重复派工）
L2 校验层   门（结构／引用／连续性／词表域）→ 隔离分流 → 双轨入库
            不变式：能机械判定的必须机器判定；判定面为空≠通过
L3 存储层   账本（append-only 哈希链）＋记录库（三态）＋取代链＋出场/别名＋隔离区
            不变式：旧件字节不动；矛盾不静默合并；不可回退分配单一写者
L4 参考层   图/索引/摘要视图（照真源重建）——**地位=强制参考面，不是可选装饰（用户裁定 2026-09-23）**
            不变式：**入库不依赖它（坏了先记账、照常干活），终审必须依赖它（债务清零才许进终审）**；
                    欠账记导出债务台账；真源↔参考 对账必须全量
            **深融条款（2026-09-23 用户令"必须深度融入到过程中"）**——图是流水线的日常工具层，不是终审才拿出来的档案：
              ① **每批同步**：每批收口把本批新增节点/边 MERGE 进图（必做项；做不了→记账）
              ② **日常巡检走图**：孤悬引用/死人走路/逆类型对称/跨章身份 默认图查询；图缺席→**文件兜底跑同一套规则**
                 （**规则一份、两个执行载体**：图快查、文件慢兜底——规则不许因载体不同而两版）
              ③ **抽取前接图**：上下文包的实体册附"一跳关系邻域＋最近出场"（确定性脚本从图查询生成）
              ④ **终审/抽检**：G4 对账门＝真源↔参考全量对账；孤悬引用优先 Cypher 全扫
              ⑤ **增值层挂点**：全局归纳/多版本对齐/按单元回溯三个解锁哨都挂在图上
            成本注：图查询不烧 token（数据库查询），不吃"×单元数"乘法线

**本地模型深融条款 · 嵌入模型（q4_k_m 常驻）**——Qwen3-Embedding 类，**六岗位**：
  ① **去重扫描**（已有：区段收口跑，≥0.95 疑重走双轨、0.85~0.95 存疑入隔离）；② **别名/称谓连通提示**（已有，半实现）；
  ③ **检索层向量路**（混合检索四路之③）；④ **候选匹配粗筛**（为重排器备候选）；⑤ **同义边**（相似度超阈的实体在图里连边，供图扩展路用）；⑥ **重复记录审计**（审查侧找冗余）。
  检索是**两段式接力**：**嵌入粗筛（全库、便宜、可离线建索引）→ 重排精排（只在候选内、准）**——不是二选一。
  **新增件：持久向量索引**（`工作区/索引/`；全量建一次、每批增量、可随时重建；单条记录 4096 维 ≈ 16KB，全库万条量级 ≈ 百兆内）。
  纪律照旧：**向量只做召回、绝不裁决**——检索结果必须过引文核验才算数（不可核验的召回不进正典）。

**本地模型深融条款 · 重排器（2026-09-23 用户令"反正本地的，深度融入"）**——重排模型（Qwen3-Reranker 类）是本地资产、不烧 token，从"仅终审抽检用一次"升级为**四岗位常客**：
  ① **上下文包生成**：以本章切片为 query，对"候选人物/活跃伏笔/判例"重排——2K 预算花在最相关的条目上（先验质量↑）
  ② **审查抽样**：抽样前把候选按"证据最弱/最可疑"排序，人先看最值得看的那批（G2 证据门辅助）
  ③ **候选匹配建议**：入库/隔离处置时，对"最可能对应的既有记录"排序——**仅建议位**（存疑分开建、0.85 门槛、判定权全部不变）
  ④ **检索层重排（查询侧）**：混合检索四路候选的融合后重排
铁律：**重排只影响"先看谁"，不影响"算不算对"**——红区一律不进。调度（同日改判）：**嵌入改 q4_k_m（≈4.7GB）＋重排器（≈2.5GB）常驻同卡、免换装**；只在引入大模型（判分器等）时按批边界抽换（每批封顶 2 次）。档位纪律：**一项目内嵌入档位固定、禁混用，换档＝重算全部嵌入**，且换档前先跑 q8↔q4 距离对照确认阈值不漂。重排器不可用时退回**机械排序**（频次/时间/urgency），产出同形（规则一份、两载体照旧）。
            不变式：派生≠真源；真源↔派生对账必须全量
L5 结论层   报告/判定（每个数字可复算；每条宣称有口径上界；落点自陈）
```

**失效宣告（事实演化）**：记录带 `version＋supersedes`；证据带 `valid_at/invalid_at`；**裁决判定"新说法推翻旧说法"时写失效章＝新说法最早证据章，旧事实永久保留**；修订传播＝依赖闭包（改一个单元只重跑下游）。历史是资产，不是垃圾。

## §4 通用方法论（已沉淀，项目无关）

**4.1 审查＝五层证据门**（替代一切"N 轮"）：
每条写入路径的失效模式有限可穷举；检查类型由"能否机械判定"决定；**出口＝证据（可复算＋正负对照＋锚点），不是过程量**。
G1 覆盖门（应−实=未覆盖集，登记件缺失必非零）／G2 证据门（回落全量机器＋语义分层抽人）／G3 规则门（成对可执行反例全枚举）／G4 对账门（真源↔派生全量）／G5 结论门（数字可复算＋口径上界＋判定面非空）。

**4.2 抽样公式**（按架构工作量，不按总体大小）：
- 机器能全量的层**不抽样**；人只抽语义正确性层
- `n ≥ ln(1−C)/ln(1−p)`：95% 把握证 ≤5% 需 59 条；≤1% 需 299 条
- **按执行批次分层、每层固定 8~10 条**（缺陷按批次聚集，deff=1+(m−1)ρ 会吃掉均匀抽样的置信度）
- **双独立复查者＋Chapman** `(n₁+1)(n₂+1)/(m+1)−1` 估"还有多少没发现"；独立性是命门
- SPRT 序贯停止（平均省 30~50%）；抽到缺陷报 Clopper-Pearson 上界，不做合格口头承诺
- 不用 ISO 2859/Z1.4 的 AQL 表（那是供需验收工具，且假设批内独立）

**4.3 十条纪律（T-1~T-10，源自田·声明式审计）**：声明面/观测面分离｜判定面为空必非零｜正对照必带｜有界宣称＋绑内容哈希｜标签与量对账｜判据侧先自证能报错｜单向稀缺分配｜副本多义律（差集静默）｜落点自陈｜双向平衡核验。

**4.4 成本乘法线**：加进"每单元必读包"的东西 ×剩余单元数；每单元字段 ×N（字节级可忽略）；区段脚本 ×段数；一次性 ×1。**选址规则：先做 ×1，再 ×段数，最后才碰 ×N；×N 线上只准放枚举清单，禁放散文。**
**4.4-附 成本不是 0（2026-09-23 修正）**：实测折算——单章约 3 万–4.5 万 token（输入 49KB＋输出 47KB），全书 517 章约 **1600 万–2400 万 token**（已跑 230 章 ≈ 700 万–1000 万）。"跑免费额度"省的是**现金**，不是 token、额度与时间；另有人工裁决、本地算力（嵌入/图库）与夜间窗口时长四项真实消耗。一切"零成本"表述作废。

**4.5 数据工程**：幂等键＝单元号＋规范版本；**顺序敏感的抽取不配死信队列**；哈希链只证未篡改不证无遗漏 ⇒ 必须补"条目计数＋单元覆盖矩阵"；每条记录带**规范版本**字段（防口径漂移）。

## §5 从迷深实例固化的四类病（通用预防设计）

| 病（实测） | 通用预防 |
|---|---|
| **假矛盾**：604 件"矛盾待裁决"多为类型粒度不一致（"人物"vs"人物(迷宫生物)"），人工 128/129 判 rejected 都是返工 | 本体 profile 必含**受控词表**；门加词表域，词表外→隔离＋理由码，不静默丢 |
| **失效空转**：invalid_at 326 条边 0 条写入——"曾为真、已失效"无法表达 | 失效宣告写入路径＋允许/禁止情形判据＋裁决双语义（改写 vs 作废） |
| **裁决不回写**：129 件已裁，status 仍全 pending；裁决无日期字段致"滞后"不可算 | 裁决终态必须可读回；裁决件强制带日期位 |
| **读数不可复现**：同一"矛盾积压"六种读数（76/183/172/155/32/604） | 每个数字自带口径（怎么数的、何时数的、绑什么哈希） |

## §6 审查强度档位（通用）

- **A 保命**：覆盖复算＋裁决回写＋规范版本字段＋并发域校验＋报告体例——全脚本，零新增每单元必读
- **B 治理**：A＋受控词表＋词表域＋矛盾分流＋失效宣告＋章节节点＋引文双指标＋裁剪留痕＋伏笔谓词＋四分类
- **C 演化**：B＋属性补齐＋认知状态与揭示序＋失效前向传播——全库类，**主线跑完后做**（否则做一半还得重做）
- 乘法红线：全库类动作 ×记录总数；必读包动作 ×剩余单元数——两者都须单独批准

## §7 新项目最小启动路径

1. 装 skill（`cbb-pipeline`，已发布）→ `init_project.py` 生成骨架（`assets/project.template.yaml`）
2. 填 §3 八项参数（本体 profile 是核心，词表从基准样例试车归纳，不从零拍脑袋）
3. **基准试车**：单单元端到端（切分→锚→候选→门→隔离→入库→评分），对照基准样例，门槛未达→停单写 Issue
4. **小队列**：3~5 单元连跑（含 1 个"脏单元"试防御）
5. **主队列**：执行批次＋游标续跑；每 N 单元轻收口；区段收口跑五门中 G1~G4
6. **收尾**：G5 结论门＋交接文书→审核线验收
