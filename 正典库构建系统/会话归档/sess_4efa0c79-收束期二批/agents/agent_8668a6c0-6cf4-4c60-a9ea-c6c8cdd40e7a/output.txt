# 长篇/书籍级知识抽取与叙事理解：可搬机制调研（2024–2026）

**方法与核验**：本报告全部条目经 arXiv 官方检索页/API 逐条核对 arXiv ID 与标题；成本数字来自原文摘要、论文 HTML 或官方博客原文。**成本基线**：517 章各 1 次抽取调用（约 1 万输入 / 2 千输出 token，全书约 500 万输入 token）记为 **1×**；下述"调用量"均以它为倍数估算。

**1. GraphRAG 社区报告 map-reduce**｜arXiv:2404.16130｜Leiden 层次社区划分 → 每社区生成报告 → 全局问题按社区层级 map-reduce 归纳；论文另含 **gleaning**：把已抽实体回灌给模型，提示补抽遗漏实体。｜落地：无训练，纯 LLM；≈0.5–1× 基线（额外一次聚合）。｜适配：直接补 CBB 痛点①，在六库上叠"卷级/全书级社区报告"。｜风险：社区随章更新漂移，须固定种子+报告版本化；全局查询成本最高。

**2. LazyGraphRAG（惰性社区）**｜https://www.microsoft.com/en-us/research/blog/lazygraphrag-setting-a-new-standard-for-quality-and-cost/｜索引期只建轻量共现图不写摘要；社区报告推迟到**查询时按需生成**。｜落地：博客实测索引成本为 full GraphRAG 的 **0.1%**、查询成本低 **700 倍以上**，质量接近 Global Search；可离线跑。｜适配：CBB 可"不预生成社区报告、只在提问时重建"，把全局归纳变成按需付费。｜风险：非同行评审；查询时刻一次性开销大。

**3. RAPTOR 递归摘要树**｜arXiv:2401.18059｜chunk 嵌入降维后做**高斯混合软聚类** → LLM 摘要 → 自下而上递归成树，查询可命中不同抽象层。｜落地：无训练；≈2× 基线（章摘要+卷摘要）。｜适配：替换/增强现在"30 章滚动摘要"，并给上下文包喂"上一层摘要"作先验。｜风险：摘要压缩有损，必须保留证据回指；中文嵌入聚类稳定性未验证。

**4. HippoRAG 1/2 个性化 PageRank 检索**｜arXiv:2405.14831、arXiv:2502.14802｜开放 IE 建 KG，**同义边**（向量相似度超阈值即连）互连短语节点；查询概念作种子跑 **PPR** 跨段落整合证据。｜落地：PPR 是确定性脚本，零 GPU 常驻；建图≈1× 基线。｜适配：多跳检索层 + 用"同义边"近似异名/称谓连通（痛点②）。｜风险：阈值需按中文称谓重标，否则误连；PPR 结果难解释，仍需回原文。

**5. LightRAG 双层检索 + 增量更新**｜arXiv:2410.05779｜低层实体/关键词与高层主题双层检索；图+向量混合；**增量更新算法**把新数据并入而不重建全图。｜落地：无训练，增量写入天然贴合逐章推进。｜适配：照搬作 CBB 增量层（痛点④）。｜风险：摘要只称"及时整合"，长期质量衰减未论证（未核实）。

**6. PathRAG 关系路径**｜arXiv:2502.14902｜检索单位从节点/社区改为**带资源流的路径**并剪枝（题名可核验，机制细节未逐句核验）。｜落地：图算法+LLM 选路，低于全图遍历。｜适配：长程因果链 A→B→C 用"路径+章序"表达（痛点④）。｜风险：路径爆炸需阈值；中文动词关系抽取噪声大。

**7. KAG 互索引 + 逻辑形式推理**｜arXiv:2409.13731｜KG 节点与原文 chunk **双向互索引**，逻辑形式引导图/向量混合推理（2wiki F1 +19.6%）。｜落地：无需训练；互索引可脚本实现。｜适配：让每条结论同时回指 chunk 与 KG 边，正好服务"证据四元组"。｜风险：需先定网文关系 schema。

**8. StructRAG 推理时结构路由**｜arXiv:2410.08815｜按问题选最优结构类型，现场把文档重构为该结构再推理。｜落地：每题一次额外 LLM 结构重建。｜适配：查询侧分流——"成长弧光"与"伏笔是否回收"走不同结构化视图。｜风险：每题成本翻倍，结构选错放大错误。

**9. LiteRAG 查询期去 LLM 化**｜arXiv:2609.10239｜用查询条件化的算法探索+推理链上下文构建取代 LLM 控制检索；相对 GraphRAG Global/DRIFT **成本降 99%、延迟降 100×**，另一基准上 token 少约 14×。｜落地：脚本为主，零 GPU。｜适配：CBB 成本安全阀。｜风险：2026 新文，复现证据少；阈值须重调。

**10. CrossAug 跨块补链**｜arXiv:2605.28004｜指出现有框架只在单 chunk 内抽边，跨块关系系统性缺失；用自监督图扰动训练 **GNN** 打分定位缺失区域，只对高分区做 LLM 补抽，规避组合爆炸。｜落地：**需训练 GNN，违反 CBB 零训练约束**；只能用"可疑区优先补抽"的纯 LLM 近似。｜适配：正对跨章关系与伏笔回收（痛点②③）。｜风险：无训练预算则收益缩水。

**11. 时间/状态演化层**｜TG-RAG arXiv:2510.13590（时间戳关系+层级时间索引，显式评估更新成本与检索稳定性）、Zep/Graphiti arXiv:2501.13956（时序图保留历史关系；LongMemEval 提升最多 18.5%、延迟降 90%）、EvoWiki arXiv:2608.23265（BUILD/READ 分离，状态被覆盖/推翻可追溯）、EvoKG arXiv:2509.15464（增量 KG 演化+时间接地打分）、iText2KG arXiv:2409.03284、FastER arXiv:2504.01557（按需实体消解，避免全量）。｜原理：事实带有效区间，新章让旧事实**失效而非删除**。｜落地：纯 LLM+脚本；每章写入 O(本章实体数)。｜适配：治"死人走路"与身份维护弱（痛点②），角色状态改为"双时间轴"。｜风险：覆盖判定需人工闸门；原论文多为对话场景，小说迁移未验证。

**12. 伏笔-触发-回收形式化 CFPG**｜arXiv:2601.07033｜从 BookSum 挖 **Foreshadow-Trigger-Payoff 三元组**，把回收判定变成可执行**因果谓词**；作者指出 LLM 常留"未开火的契诃夫枪"。｜落地：纯 LLM+规则，逐章顺带产出≈0 边际成本。｜适配：直接替换 CBB 粗判的回收逻辑（痛点③）——伏笔挂"触发条件"，回收查谓词而非语义相似。｜风险：谓词库需人工定义；网文拖沓，时间窗应按卷而非固定章数。

**13. STAGE 角色状态+认知状态追踪**｜arXiv:2601.08510｜151 部中英剧本上构建**来源可追溯的叙事骨架**，恢复每个角色在时间轴每点的状态与"知道什么"，含角色发展追踪任务。｜落地：数据集+任务定义，可直接借用标注规范。｜适配：角色册升级为"每章状态快照（位置/关系/知识边界）"，是痛点②④的最小表示。｜风险：剧本≠小说叙述；无中文网文版。

**14. 中文文学与网文侧**｜NS-ST-GraphRAG arXiv:2609.05139（本体引导抽取+**确定性约束检查**+**双时间坐标**+空间场景属性+按查询时空范围取"当时有效"子图，证据可追溯；配套 Red-Chamber-QA 古典中文多跳基准）；WebNovelBench arXiv:2505.14818（4000+ 中文网文，8 个叙事质量维度+LLM-as-Judge+PCA）；中文小说 NER 语料 arXiv:2311.15509（260 部网络中文小说、13 体裁、263,135 实体；实证：体裁差异显著影响 NER）。｜落地：与常规 GraphRAG 同阶成本。｜适配：最接近"可原样参考"的架构，"时间坐标+约束检查+证据 span"三件套可直接抄。｜风险：效果方向正面但不显著（0.733 vs 0.675，p=0.092）；语料为古典名著，网文需重验。

**15. 长文聚合与切段**｜ReadAgent arXiv:2402.09727（要点记忆压缩+按需回读原文）、LongRAG arXiv:2406.15319（长检索单元+长上下文）、LitSeg arXiv:2605.27156（叙事理论指导切段：抽事件→识别结构→定位转折点→定边界，避免情节断裂与指代不清）。｜落地：无训练；LitSeg 多阶段提示会抬高每章调用。｜适配：为 CBB 的"章切片"做二级切段与摘要层级。｜风险：转折点判定稳定性未验证（未核实）。

## 明确不适用

- **需训练组件**：CrossAug 的 GNN（arXiv:2605.28004）、HippoRAG 2 检索编码器（arXiv:2502.14802）、KAG 的模型能力增强项（arXiv:2409.13731）——违反"零预算/不能训练"。
- **对话记忆系统的原样套用**：Mem0 arXiv:2504.19413（LOCOMO 上比 OpenAI 相对提升 26%，图记忆再高约 2%）、Zep arXiv:2501.13956 面向会话流，不是 517 章叙事结构，须重写事件粒度。
- **长上下文基准不能当机制**：RULER arXiv:2404.06654、NoLiMa arXiv:2502.05167、Lost in the Middle arXiv:2307.03172、LongMemEval arXiv:2410.10813——它们只证明"整本塞进上下文"不可靠，是选型证据而非方案。叙事 QA 基准 NarrativeQA arXiv:1712.07040、NarrativeXL arXiv:2305.13877 同理，可用于回归测试。
- **未检索到现成机制**：中文"称谓随关系变化/敬语层级/异名"的专用数据集或方法——多轮检索（appellation / honorific / address terms / alias linking 等）均无命中，此部分在 CBB 只能自建，可用 arXiv:2311.15509 语料打底。标【未核实/空缺】。
