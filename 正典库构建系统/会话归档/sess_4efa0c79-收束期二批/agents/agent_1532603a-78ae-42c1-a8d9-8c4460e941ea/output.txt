## 3. 契约 record.schema.json

文件（三份同源）：`<ROOT>\cbb\contracts\record.schema.json`、`<ROOT>\cbb-pipeline-skill\cbb-pipeline\scripts\cbb\contracts\record.schema.json`、冻结版 `<ROOT>\cbb-skills\contracts\`（v1.0 判据不回改，见 schema L4 标题）。

### 顶层必填（L6）
`record_id, record_type, library, status, canonical, evidence, provenance, version, supersedes, verified_against`（10 项）。

### 断言位（枚举/数值/pattern/受控词表）
- `record_type` enum：event/entity/relation/foreshadow/setting/anchor（L9）
- `library` enum：event/character/timeline/relation/setting/foreshadow（L10）
- `status` enum：**confirmed/provisional 二态**（L11；L97 $comment：不设第四态，quarantine 走隔离区）
- `evidence[]`：必含 vol/chapter/line（integer≥0）+ quote（minLength 1），可选 file、graph_edge{edge_id, valid_at, invalid_at}（L13-36）
- `observations[].category`：19 类受控词表枚举（L44）
- `verified_against`：path+sha（`^[0-9a-f]{7,64}$`）+verified_at（ISO 日期起头 pattern）三件套必填（L50-59）
- `version` integer≥1（L93）；`supersedes` string|null（L94）；`spec_version` 可选 string（L95）
- `provenance.gate_trace[].gate` enum ["1","2a","2b","3"]（L70）；`status_history[].by` enum ["human","shadow","promotion"]（L86）

### canonical 子字段全集
Schema 本身对 canonical **只有一行**：`"canonical": { "type": "object", "description": "按库类型的本体字段" }`（L12）——**schema 层不约束子字段**；子字段由 profile 的 `required_fields`/`type_vocab` 配置（`assets/project.template.yaml` L20-22）与抽取规范约束（`references/抽取规范.md:44`：“canonical 必须是对象”，写歪属 G1-SCHEMA 拦截项）。实测 6172 条在库记录枚举出的子字段全集（23 个）：

| 库 | canonical 子字段 |
|---|---|
| character | name, entity_type |
| event | name, kind, tick, instant, time_verbatim, entities |
| relation | subject, rel_type, object, claim |
| setting | name, entity_type, chapter, tick, fact |
| foreshadow | name, note, tier, setup_chapter, payoff_chapter, entities, chapter |
| timeline | label, kind, instant, day_offset, chapter_ref, parent_anchor, precision, pseudo_date, tick |

### 明确回答：canonical 里有没有自由文本字段？
**有。** 陈述位（自由文本，schema 与词表均不约束内容）：`claim`（relation 的关系断言）、`fact`（setting 的设定陈述）、`note`（foreshadow 备注）、`time_verbatim`（event 时间原文转写，实测长文本）、`label`（timeline 标签）、`name`（命名串，兼作身份键 `cbb_store.py:81`）。其中受控的断言位是 `entity_type`/`rel_type`/`kind`/`tier` 等（走 `type_vocab`/`relation_vocab` 受控词表，模板 L21-22 明写“禁自由文本”）。

**断言位 vs 陈述位总结**：record 顶层除 canonical 外几乎全是断言位（枚举/整数/pattern）；`evidence[].quote` 与 `observations[].text` 是自由文本但属**可机验陈述位**（quote 受逐字回落检查，G1-EVIDENCE/批次自检 c8）；canonical 内部则是“每库少数受控分类字段 + 1~2 个自由文本陈述字段（claim/fact/note/time_verbatim/label）”的混合结构。
