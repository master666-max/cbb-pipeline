# 批次 3 工单 · 交付形态层：LLM Wiki 导出器 + 静态前端（v1.0 · 2026-09-29）

> **动机**：判卷门 PASS 的东西，必须走到"人和 LLM 都能用"才算产出。当前全部产出（jsonl 库/台账/报告）是机器可消费的中间态——**独立不可查看**：web_console 已退役、F1 U2 图谱视图未实施、LLM wiki 零规划零实现。本批补上最后一公里。
> **设计公理（快照范式，用户裁决）**：
> 1. **store=活体**（唯一事实源，受产线纪律维护）；**导出=不可变快照**（生成即冻结，永不手改——手改=P-020 拷贝漂移病，自校验必抓）。
> 2. **快照只读，反馈走产线写入面**（人工窗/判例窗/supersede）——人在 wiki 页发现的错误不回写快照。
> 3. **快照自锚定**：头部强制携带「账本检查点 rows+chain_head+导出器版本+记录数对账」——离线、可分发、可独立验真。
> 4. 修 bug=修导出器+重新导出新快照；旧快照归档保留（迷深永不删除铁律）或滚动覆盖（config 可选）。

## 一、快照目录结构（不可变快照的标准形）

```
快照-迷深实战-<检查点rows>-<ts>/
  SNAPSHOT.json            # 锚：检查点 rows+chain_head、store 记录数、页数/边数对账结果、导出器版本、生成时间
  wiki/
    _index.md              # 全局索引：三态计数、类型分布、导航
    records/<type>/<record_id>.md   # 记录页（1:1）：YAML front-matter + 断言 + 引文块引 + 观察 + 失效/隔离标注
    quarantine/<record_id>.md       # 隔离区专区（显式隔离标记）
    indexes/by-type/<type>.md       # 类型索引页
    indexes/superseded.md           # 失效链索引
    indexes/complementary.md        # 互补陈述索引
  graph/
    nodes.jsonl            # 实体节点投影（id/name/aliases/type/status）
    edges.jsonl            # 关系边投影（relation 记录：source/target/断言/状态）
  site/                    # W2 静态前端（双击 index.html 离线可开，零网络依赖）
    index.html  browse/*.html  graph.html  search.json  assets/
```

记录页 front-matter（LLM 消费契约）：`record_id / type / status / aliases / chapters / evidence_count / supersedes / 快照锚`；正文=断言（canonical 摘要）+ 逐条引文块引（原文逐字）+ 观察列表。**一页=一自然 RAG 块**。

## 二、单元划分

- **X1 锚与对账引擎**：`cbb-v2/cbb2/export.py`——SNAPSHOT 锚构造（notary.ledger_head 对接）、记录页渲染器、对账函数（页数≡store 记录数、边数≡relation 数、随机 N 页引文逐字回链抽查、三态标注核对）。对账失败 ⇒ 快照头标记 FAIL，**不发布**。
- **X2 wiki 导出器 runner**：`wiki_export.py --config extraction.config.json --store 迷深实战-本体库 --out 快照目录`——全量渲染 + SNAPSHOT 写入。
- **X3 图谱投影**：nodes/edges 投影器（relation 断言→边；entity+别名→节点；三态字段随行）——X2 内步骤，产出 graph/。
- **X4 静态前端生成器**：`site_build.py`——stdlib HTML 渲染（零依赖、离线内联 JS）：库况首页、类型浏览（分页）、客户端搜索（别名+名称预建索引）、**egocentric 图谱视图**（点节点看一度关系，三态着色——F1 U2 规划落地）。
- **X5 双书实测**：迷深全量快照（6,278 页）对账全绿 + 终末库快照（跨实现复验）对账绿 + 双击离线可开实测。
- **X6 自审与交付**：发布类四镜头自审（PT-027 裁剪版：契约符合/证据链/幂等/红队+抽查）→ 交付声明。

## 三、对账判据（W3，全为机械复算）

1. 页数对账：记录页集合 == store 记录集合（逐 record_id，含隔离区分离核对）
2. 边数对账：graph 边数 == relation 记录数
3. 引文回链抽查：随机 ≥30 页，页内引文 == store evidence quote 逐字一致
4. 锚核对：SNAPSHOT 检查点字段 == notary.ledger_head 现值
5. 三态核对：每页 status 标注 == store status
6. 离线性：site/ 断网双击可用（无外链资源）

## 四、边界（本批不做，如实）

- 聚合人物页（同名/别名合并渲染）——合并是判卷级语义，本批只做 1:1 忠实渲染，聚合列后续
- lorebook/SillyTavern 格式转换器——列后续（wiki 结构已为其留好 front-matter）
- 在线服务/服务端编辑——违反快照只读公理，永不做
- LLM 语义质检——wiki 忠实渲染 store，**内容质量由判卷战役负责**；导出器的责任是忠实性=对账纪律
- 增量导出（只渲染变化页）——先全量，性能不够再优化
