## §2 单位清单

### U-G01 plugin 骨架与打包
- 内容：把现有 skill 收进 plugin 包（manifest＋版本号＋安装/卸载脚本）；**skill 保持独立可装**（现有安装位 `~/.zcode/skills/…` 与发布仓照旧可用）；版本号与 skill 版本联动。
- 判据：①装/卸可复现（两次装卸后目录逐字节一致）②卸载后 skill 独立路径仍可触发③发布仓 URL 与既有安装说明不破坏。

### U-G02 hook 强制力四项（本单核心）
> 取舍原则：**能拦的才叫纪律**。四项按"拦 vs 警告"分级——起步建议：①②直接拦，③④先警告（阈值内可放行），一周复盘后再收紧。
- **①冻结库只读**：任何写入冻结路径（`迷深实战-本体库/` 等冻结线）的动作 → **拦截**。
- **②红区写门禁**：对红区六项（验收/晋升、契约文件、失效宣告绕道、权限表、量尺配置、规范正文改写）的直改 → **拦截**；合法路径（追加段/确认件制）放行。
- **③决策账先写后动**：绿区动作执行前必须已有决策账行（先写账后执行的可测顺序）→ 越序警告并补账。
- **④副本漂移告警**：四处副本（版本源/安装位/发布仓/本地暂存）哈希比对，**差集非静默**（T-8）；差异 → 告警并列出清单。
- 判据：**每项一对正负对照**（必须被拦的样例＋必须放行的样例，照 T-3）＋每项可单独开关＋钩子自身故障时**放行且留痕**（不得因钩子坏而阻断主线——fail-open 留痕，例外见 D1）。

### U-G03 斜杠命令入口（三条薄壳）
- 内容：`/批次自检`、`/状态报告`、`/覆盖复算`——只做参数转发到既有脚本，零业务逻辑。
- 判据：命令输出与直跑脚本逐字节一致；脚本缺席时命令报明确错误（不静默）。

### U-G04 版本化分发与副本收敛
- 内容：以 plugin 版本号为准；副本比对脚本化（取代今天的手动 `cp`）；发布流程固化（现 REST 推送脚本升格为正式发布工具，带版本与变更记录）。
- 判据：比对脚本跑出任一差异即非零（含发布仓）；一次完整发布走通全流程并留痕。

### U-G05 MCP 触发条件与预留（**本单不实施**）
- 内容：写明 MCP 的启用条件（**U-F07 检索层落地且查询需求成立**）与降级纪律（**MCP 缺席退回脚本直跑**——同"模型缺席不影响主链"）；本单只留条款。
- 判据：条款在册；待 U-F07 完成后由审核线评审是否启用。

## §3 纪律（本单特有）

| # | 条款 |
|---|---|
| D1 | **强制力分级**：冻结库与红区直改＝**拦**（fail-closed）；决策账越序与副本漂移＝先**警告**；一周复盘后按数据收紧 |
