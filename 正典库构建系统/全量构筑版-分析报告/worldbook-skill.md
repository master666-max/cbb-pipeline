## §1 架构与数据流

**定位**："SillyTavern 角色卡/世界书管理助手——一句话让 AI 读轻小说/设定集，自动生成结构化世界书 JSON 与角色卡"（README.md:3-5；echo-xianyu，198★）。README 诚实声明"本项目基本由 AI 生成……作者并不很懂编程"；方法论致谢 sanmingyue 写卡教程（README 致谢节）。

**构成**：单技能（world-book-skill/）=SKILL.md 入口（251 行，**铁律 8 条+任务路由**）+13 references（6,017 行）+3 py CLI（world-book-create.py 517/card-generator.py 1,435/query.py 234——纯本地 argparse+json，零外部 API）。

**数据流**（二创主线，SKILL.md 分支一）：源材料判定（本地文件/网络搜索/询问）→ **行号索引全文标注**（"第1章: L1-L350"）+首轮通读四类标记（`[W]`世界观/`[C]`角色/`[I]`物品/`[★]`重要章节，information-extraction-guide.md:45-66）+角色出场速览 → 阶段二角色八维度提取 → 阶段三世界观 A/B/C 类型判定+分维提取+**去小说化** → 阶段四输出 outline.txt（思维链分析/章节行号索引/人物总纲/世界观要素总纲/重要章节标注/条目规划表）→ 编写条目前**重读对应章节**（"编写各条目之前，再次阅读源材料中对应的章节"，SKILL.md Step 4）→ CLI 生成 SillyTavern JSON → **SubAgent 禁词扫描自检通过后才输出**（README 功能表）。

**铁律 8 条**（SKILL.md:24-44）：非商业红线/原创二创分流/**description 空置（全部信息入世界书条目）**/世界观设计先于条目化/先设定再角色卡/不主动建议 MVU-EJS-HTML/禁词红线贯穿/物品写作分类规范（服装写外观材质不写优缺点）/**先读 reference 再动手**。

## §2 数据模型与接口

**角色八维度提取**（guide :78-213）：基本信息与首次出场/外貌特征/身份定位/性格线索/关键事件/关系网络/能力与物品/出场章节总览——每维度强制输出格式（:361-371）。

**世界观 A/B/C 类型判定+分维**（:217-258）：按地理/历史/势力/规则/社会结构分维。

**去小说化操作表**（:259-270）：原文写法→提取写法转化（"人族与妖族争斗了数千年"→"人族与妖族长期对立"；"充满机遇与挑战的世界"→**删除**；"由...组成/存在着"→冒号或列表）。

**禁词剔除八类**（:373-387）——本仓最高价值：意象比喻→特征白描（"眸如星辰"→"天青色瞳"）/万能修饰直接删（"精致的/美丽的"放任何角色都成立）/**默认特征删（"中国人写黑发黑眼、18 岁写年轻、精灵写尖耳——AI 数据库已有"）**/叙事禁词（一丝、一缕、弧度、弯起嘴角）/性格标签→原文具体行为依据/主观评价删/解释性描写删（"这个动作体现了他的紧张"→只留动作）/语气修饰删。

**不能确定的信息四规则**（:388-394）：原文没写→**不补全，标 `// 原文未提及`**；信息不足→只提取已有不推断；**前后矛盾→以首次出场为准，变化在条目中说明"第X章后发生改变"**；**从行为反推性格→标注"反推"区分于原文直接陈述**。

**信息合并规则**（:395-402）：多章出现合并、**首个出场章节为基准**、后续为"补充/变化"**不创建重复条目**、不一致时**优先保留更详细、更晚出场的版本+说明变化过程**。

**常见错误 9 例**（:450-561，带原文/错误提取/正确示范三段式）：1 搬运原文比喻/2 万能美人描写/3 性格写成标签/4 关系写成抽象形容/**5 提取 AI 已知信息**（黑发是日本人默认→"无特殊外貌特征，不写入"）/**6 补全原文没有的信息**（家庭背景→"`// 原文未提及`"）/**7 世界观提取保留小说叙述**（意象描写→"背景：后末日废土"事实化）/8 条目规划遗漏禁词/9 复读环节被跳过。

**MVU ZOD 变量系统**（mvu-guide.md 921 行，十节）：SillyTavern 变量框架（变量结构脚本→世界书条目→正则配置→多开局初始值→状态栏界面）；EJS 依赖 MVU（"MVU 不需要 EJS，但 EJS 需要 MVU"，:7）——RP 运行时状态层的完整教程。

**py CLI 三件**：world-book-create（世界书条目 CRUD+导出 ST JSON）/card-generator（1,435 行角色卡生成：XML 包裹 YAML 格式+MVU+HTML 美化模板）/query（查询）——零依赖零 API。

## §3 可借鉴 / 不可借鉴清单

**可借鉴（设计层；CC BY-NC-SA 下 CBB 非商用成立，但 ShareAlike 使提示词文本不可复制——全部转述重写）**：
1. **禁词剔除八类表**——**16 仓中最接近 R6 元文本防御的机制**：明确处理"提取物中的非事实成分"（比喻/修饰/默认/叙事腔/标签/评价/解释/语气八类各有处置：转白描/删/转行为依据）——cbb-extract 的 R6 规则表可直接按此八类框架扩充（我们已有 R6 元文本防御，此表是**输出侧清洗**的领域词典）。
2. **错误 5"提取 AI 已知信息"**——**防模型先验污染**（默认特征="AI 数据库已有"不该入正典）：与 Step 0 的元文本抽取双败教训同族，且给出了操作判据（默认值不入档）——**16 仓首见该问题被显式命名**。
3. **不确定信息四规则**——`// 原文未提及` 显式占位（不补全）+**"反推"标注（区分直接陈述与推断）**≈EXTRACTED/INFERRED 分层（graphify-novel）的提取侧版本；首次出场为基准+变化说明。
4. **信息合并两派对照**：本仓"首次出场为基准+变化说明"vs claude-book"事实后书优先"——**两种正典裁决流派**，CBB 可并陈（首次定义 vs 最新事实，按字段类型分派）。
5. **行号索引+四类标记首轮通读**——L1-L350 章界索引+[W][C][I][★]内联标记：CBB 抽取预处理的人类可读中间层（与 grep 式溯源兼容）。
6. **编写前重读对应章节**（Step 4+错误 9）——"复读环节"显式纪律（防凭缓存写条目）——对账先行的操作化。
7. **outline.txt 中间产物**——条目规划表先于生成：抽取与生成分离的中间检查点。
8. **SubAgent 禁词扫描自检门**——生成 JSON 前独立子代理逐字扫描（与主流程分离的质检）。
9. **铁律 8 条的"先读 reference 再动手"**——不凭记忆编写（与 oh-story"重读磁盘"同族）。
10. **错误示例三段式**（原文/错误/正确）——反例教材格式（story-skills 可执行反例的文档版）。

**不可借鉴**：
1. **提示词文本本身**（CC BY-NC-SA ShareAlike 传染）——全部转述重写，不引用原文措辞。
2. 面向 SillyTavern 生态的输出格式（世界书 JSON/角色卡 XML 包 YAML/MVU/EJS/HTML 美化）——X-RP 下游已有 PT-013 自建流水线，无需此层。
3. 工程质量弱（AI 生成自述+无测试+无 CI）——仅方法论层借鉴。
4. 无时间归一（出场章节总览是章列表非时间轴）；无实体级去重（合并规则是提示词级）。

## §5 与 CBB 对照（Step 0 三条件 + 四契约/三态）

**三条件对照**：
1. **元文本防御：最近亲（输出侧）**——R6 防"作者旁白混入抽取"（读入侧），本仓禁词八类+去小说化防"小说腔混入正典输出"（**输出侧清洗**）+错误 5 防"AI 先验混入"（模型侧）——**三层防御的另两层**：CBB 应三层并配（R6 读入侧已有/输出侧按八类表扩充/模型侧加"默认值不入档"规则）。
2. **时间归一：无**（章列表非时间轴）——cbb-anchor 仍独有。
3. **实体/事件去重：提示词级合并规则**（首次出场基准+不建重复条目+变化说明）——与 oh-story 四分类互补（它有裁决规则无类型学）。

**四契约/三态对照**：
- **Record ≈ 世界书条目**（行号溯源+`// 原文未提及` 占位+"反推"标注——**claim 置信标记三态雏形：直接陈述/反推/未提及**）；
- **Issue ≈ 自查清单四阶段+禁词自查**；
- **Verdict ≈ SubAgent 扫描门**（通过才输出）+矛盾裁决规则（首次出场为基准）；
- **Case ≈ 常见错误 9 例**（三段式反例教材——Case 契约"失败也是资产"的最佳文档形态）；
- **三态映射**：`// 原文未提及`≈空值语义（非 quarantine）、"反推"≈推测标记（quarantine 的字段级）、禁词命中→剔除（rejected 的输出侧）——**字段级三态先例**。

**金标方法学（§K2）**：无评测件；错误 9 例是人工金标的雏形（错误模式目录）——不适用。

**PT-013 直系对照**（索引清单§7 原话）：PT-013（2026-09-09 X-RP 实战：角色卡/世界书对照原著全量核对）与本仓同题——PT-013 做了"内容对照原著核对"（正史分层/别名矩阵/同源传染），本仓提供了"提取时的净化规则"——**实战经验与领域方法论的互补**；CBB 吸收两者。
