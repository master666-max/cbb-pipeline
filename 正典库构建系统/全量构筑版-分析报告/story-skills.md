## §1 架构与数据流

**定位**："Story Skills — Agent Skills for planning, tracking, and drafting fiction in markdown"（README.md:1-21，Daniel Dewhurst，MIT）——**CLI 把 story bible 当"可校验契约"，"treats contradictions like a compiler treats type errors"**——16 仓中唯一以编译器哲学做小说一致性的仓。

**构成**：src/ 核心 5 js + bin/story.js 入口 + skills/ 7 技能 + schemas/（JSON Schema draft 2020-12）+ docs/schema-v2.md + **examples/ 3 个样例故事 76 md（其中 the-unraveled-thread 是故意写崩的可执行反例）** + scripts/ CI 六件 + test/ 8 件（986 行）。

**数据流**：md 实体文件（人写+agent 写）→ `validate/links/continuity` 三域检查（确定性，零 NLP）→ errors/warnings 文本报告（error→stderr+退出码 1，warning→stdout）→ `reindex` 全量重建 8 张 _index.md 注册表（人工段落保留）→ `next/doctor` 输出 **P0-P3 修复行动清单**（每条附精确命令）。

## §2 数据模型与接口

**16 命令**（cli.js:26-44）：init/import/validate/reindex/wordcount/links/continuity/report/next/doctor/migrate/add/rename/remove/export/build。

**story bible schema（三处定义、JS 为准）**：JS 强制（枚举 story.js:44-58）+ schemas/story.schema.json（draft 2020-12，schema-version const:2，$defs kebab id pattern）+ docs/schema-v2.md 散文规范。组织：story.md + characters/ + worldbuilding/{locations,systems,factions,artifacts} + plot/{arcs,timeline.md} + chapters/chapter-{NN}.md + scenes/ + **continuity/{state.md,questions,promises}** + glossary/。**continuity/state.md = current-chapter + character-state[]/object-state[]/knowledge-state[] 三张持久状态表**（生成器 story.js:1039-1071，校验 :2409-2427）——knowledge-state 第三次出现（author-toolkit→claude-book→本仓），且本仓**机器可校验**。

**validate 三层**（story.js:263-328）：①结构：19 个 REQUIRED_PATHS（:10-30）；②frontmatter schema 逐类校验（:2196-2470）：必填/类型/枚举/文件名 kebab-case（:2472）；**chapter 专规则：文件名必须 chapter-{NN}.md 且 frontmatter number 必须等于文件名编号**（:2360-2363）+**章号重复报错**（:2371-2375，seenNumbers Map）；schema-version 必须=2（:2208-2210）；③完整性 warning：_index 缺链接/声明 word-count 与实际不符（:317-320）/章无 scene 记录。

**links 全量交叉引用**（:330-481）：**人物关系双向回链+逆类型校验**（RELATIONSHIP_INVERSES 12 对 :60-73 + SYMMETRIC_RELATIONSHIPS 12 项 :75-88——"parent"必须被"child"回指，sibling 类要求对称）；人物↔地点互指；chapter 的 pov/characters/mentions/locations/arcs；faction 成员/地点；artifact owner/location；scene/question/promise 各引用。

**continuity 八项检查**（src/continuity.js 259 行，纯整数比较零 NLP）：**死人走路**（died-in 章存在性+status 一致性+更晚章 cast 含死者即 error 并提示"移到 mentions"，:29-59）；**伏笔时序**（payoff<planted→error；paid-off 无 payoff 矛盾；**契诃夫枪：planted 后距最新章 ≥3 章（CHEKHOV_CHAPTER_GAP=3，:3,:130）未回收→warning**）；问题时序（resolved<introduced→error）；cast 一致性；章号跳号；完稿仍挂 open promise/question；state.md 引用存在性+current-chapter 领先/落后；object-state 与 artifact 文件 status 冲突。

**reindex 幂等**（:643-687）：从实体文件全量重建 8 张 _index.md；人工段落（Relationship Map/Family Trees）经 extractSection 保留（:662-679）；**writeChanged 内容不变不写**（:2060-2065）——确定性输出。

**修复行动生成器**（projectActions :1118-1191）：三类检查结果→**P0-P3 优先级行动**，每条附精确命令（"P0 Fix validation errors — Run story validate . and repair N errors"，:1121-1127；P1 审阅 warning/刷新字数；P2 追踪 open questions/promises）——经 next/doctor 输出。

## §3 可借鉴 / 不可借鉴清单

**可借鉴（MIT；设计层为主——CBB 校验器直接对标件）**：
1. **三域分离**：validate（结构/schema）/links（引用完整性）/continuity（语义契约），统一返回 `{ok,errors,warnings}`——CBB gate 链的分域蓝本（我们 gate1 四校验+审核线验收单可按此三分）。
2. **关系逆类型表+对称关系表**——双向回链校验的具体实现（逆类型 12 对+对称 12 项成表）——CBB store 关系写入的完整性检查直接采用此设计（basic-memory 的"双向关系抽查"在此被自动化）。
3. **契诃夫枪阈值检查**——开环超期 warning 的自动化（与 danghuangshang 🔴遗漏同题，此处是**可执行算法**：latestChapter−planted≥3）。
4. **修复行动生成器（P0-P3+精确命令）**——错误不止报告还**给出下一步命令**：CBB Issue 文书应带"修复动作"字段。
5. **章号=文件名=frontmatter 三处一致强制**——实体键的三处一致性校验（防漂移）。
6. **writeChanged 内容不变不写 + 打包产物逐字节一致检查**——确定性输出三保障（幂等重跑不留 diff 噪声）——P-017 的正面实现。
7. **写入安全**（符号链接拒绝+词法根目录围栏 prepareWriteTarget :2089-2105）——三态写入防越界。
8. **可执行反例**（故意写崩的 example 作为 checker 活体测试）+**100% 行+函数覆盖门禁**（check-coverage.js:23-30）——CBB 校验器的测试纪律（反例驱动）。
9. **error/warning 两级+退出码语义**（error 改退出码/warning 不改；ok=errors.length===0）——CI 可集成。
10. **continuity/state.md 三张状态表机器可校验**——character-state/object-state/**knowledge-state** 的 schema 化。

**不可借鉴**：
1. **输出纯人类可读文本，无 JSON/机器可读模式**（grep 无 --json）——R-020 反面：CBB 校验报告必须双轨（机器可读+人读）。
2. **无日历时间**：章号=全序替代时间戳（scene 排序=(chapter,scene)，story.js:230）——**无时间归一能力**（对小说够用，对 CBB 的故事内时间轴不够）。
3. 无别名/模糊去重（实体 id=文件名天然唯一，aliases 字段存在但不参与去重）；import 有 Map 计数+阈值去重（import.js:68-88）但非实体级。
4. 英文语料设计（kebab-case/关系词表全英文）——中文需重建词表（亲戚关系词表汉化是好起点）。

## §5 与 CBB 对照（Step 0 三条件 + 四契约/三态）

**三条件对照**：
1. **元文本防御：有、形态不同**——"Frontmatter is machine-owned 不改不重写"（schema-v2.md Core Rules）+reindex 保留人工段落+export 注入生成标记（`<!-- Generated by story export. -->` story.js:729）——**机器区/人工区隔离**（防 agent 覆写人写内容）是元文本问题的**写入侧镜像**（R6 防读入污染，它防写出污染）；无 prose 注入扫描。
2. **时间归一：无**——章号全序替代时间（对章节叙事够用）；无时间戳格式/排序规则——cbb-anchor 仍独有。
3. **去重：结构性免疫**——id=文件名唯一+add/rename 拒绝重名+章号重复报错——**用文件系统语义消灭去重问题**（无别名归一，但结构性保证无重复实体）——CBB 主键设计可采此哲学（主键不可变+位置即身份）。

**四契约/三态对照**：
- **Record ≈ 实体文件+注册表**（frontmatter schema+三处一致）；
- **Issue ≈ errors/warnings+修复行动 P0-P3**——**Issue 带修复动作的完整先例**；
- **Verdict ≈ 退出码+ok 语义**（ok=无 error；warning 不阻塞）——裁决的机器化最小实现；
- **Case ≈ 可执行反例 example**（故意写崩样本=失败案例库的活体形态）；
- **三态映射**：error/warning 两级+契诃夫枪超期 warning≈quarantine 的超时态——**"确定性裁决器"的完整实现是 CBB gate 的直接同类**（我们的 gate1 四校验原因码+它的三域八检查可互为补充）。

**金标方法学（§K2）**：不适用（无评测件）；但其 100% 覆盖+反例测试是校验器自身的质量纪律——CBB 校验器开发应采用。

## §6 处置建议

**四选一：借鉴设计（只学思路）**——理由：
1. **本仓是 CBB 确定性校验器的第一对标件**（编译器哲学+三域分离+八项检查+修复行动生成全链），MIT 干净、工程纪律最强——设计层吸收密度与 graphify-novel/oh-story 并列第一梯队。
2. 它是通用 CLI（非 agent skill 形态优先），装外挂价值有限（CBB 校验器自建 stdlib 路线已定，实验版四契约校验器在案）——**学其规则集与分级哲学，不引入其运行时**。
3. 其缺陷（无机器可读输出/无时间归一/英文词表）恰好是 CBB 差异化方向。

移交 U-A17 吸收项：①三域分离（validate/links/continuity）②关系逆类型+对称关系双表 ③契诃夫枪超期检查（≥3 章算法）④修复行动生成器（P0-P3+精确命令→Issue 带修复动作字段）⑤章号三处一致强制 ⑥writeChanged+逐字节一致（确定性输出）⑦写入安全围栏 ⑧可执行反例+100% 覆盖门禁 ⑨error/warning+退出码语义 ⑩机器区/人工区隔离（frontmatter machine-owned）⑪state.md 三张状态表 schema。
