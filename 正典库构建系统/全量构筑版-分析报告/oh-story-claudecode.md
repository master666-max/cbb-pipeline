## §1 架构与数据流

**定位**：中文网文全流程 skill 包（13 技能，MIT），"扫榜→拆文→写作→去AI味→封面"（README.md:7）——**由 agent 宿主（Claude Code/ZCode/Codex）解释执行**，LLM 即宿主本身，py/js 只做确定性校验与事务。

**构成**：skills/ 13 件 + scripts/（仓库自检 CI：check-current-skill-contracts.py 1,437 行+static-check.py 681）+ **demo/（真实拆文样例：盘龙/曾将爱意私藏/长篇连载工程——含 62 md 的长篇 demo 与 55 md 拆文库）** + docs/。md 448 聚合：story-setup 116（部署器模板）/story-long-write 81/demo 长篇 62/拆文库 55。

**代码分布**：py 51 个/23,262 行=**技能配套事务提交器**（story_codex_hook.py 1,570 行 Codex 宿主 hook 适配+tracking_commit.py 1,228 行×3 副本+author_memory_commit.py 871 行×5——**多副本部署器模式**，每技能目录带一份）；js 57 个/27,860 行（46 js+11 mjs/cjs）=确定性校验器（check-ai-patterns.js 1,439×4 副本/story_hook_core.js 1,219）+**爬虫**（scrapers/qidian 592 行等）+UI。

**拆文主流程**（skills/story-long-analyze/SKILL.md 330 行）：输入=用户小说文件/贴文（:27,:35）→ **Stage 0-6 七阶段**（:115-123）：概要+章节边界→黄金三章深拆→逐章摘要（每章 10-40 情节点）→聚合分析→设定+关系（4a/4b/4c）→汇总报告→文风档案 → 输出纯 Markdown 拆文库树 `拆文库/{书名}/`（原文//章节//角色//剧情//设定/世界观|势力/文风.md/_progress.md，:71-104）。

**长篇三件套**（对 CBB 迷深 517 章直接对口）：
1. **章节边界表单一切片真值**：Stage 0 一次生成写入 _progress.md，全管道共用（:125-137）——防各阶段 regex 各自漂移；
2. **逐章子代理**：Stage 2 每章 spawn chapter-extractor，5-8 个/批（:224-227），**haiku 失败升 sonnet 重试 1 次，仍败标"跳过"不阻断**（:239-263）；
3. **>500 章降维聚合**（material-decomposition.md:481-489）：实测中文章节摘要 ~15KB/章≈5-7K tokens（大奉打更人 57 章样本 869,663 字节）；>500 章切 10-20 章/批（≤15 万 tokens/批）子代理并行，**子代理只回传 ≤8K tokens 中间聚合**（禁止回传原始摘要），主线程只合并聚合；批数过多再做**两两分组合并（N→√N）**直到装下；每批更新 _progress.md 按批续跑。

**人工确认**：Stage 1 后强制停靠产出快速预览二选一询问（:139-149）；导入场景自动续跑不停靠（story-import/SKILL.md:138-145）。

## §2 数据模型与接口

**拆文库文件树 schema**（SKILL.md:71-104）：`剧情/README.md` 为权威分工索引（:106）；**节奏.md/情绪模块.md 为权威、报告只是摘要**（material-decomposition.md:230）——权威投影与摘要视图分离。

**情节点格式**：`P{n} 类型|白描|涉及|地点|物品|时间`+主题标签行（SKILL.md:217）；时间字段=**相对时间标记（次日/半月后/同时）**（material-decomposition.md:36-48）。

**角色档案**：frontmatter archetype/出场率+档案 200-500 字+character_arc+关键情节时序+**别名表（别名|类型|置信度）**（demo/拆文库/盘龙/角色/林雷.md 实例）。

**别名四分类（实体去重核心规则）**（material-decomposition.md:256-274）：proper_name（专名，可合并）/nickname（绰号，**须同指证据+置信度≥0.85** 可合并）/descriptor（描述性称谓"红发壮汉"，**永不合并**）/title（头衔"族长"，**永不合并**）；**"绝对禁止将不同人物的信息合并到同一实体；无法确定两称呼同指必须分开建实体"**——宁可分裂不可误合。

**导入侧结构化单源**（story-import/references/tracking-transaction.md）：`追踪/_tracking-state.json` 单源+派生只读 Markdown 视图（:9-13）；**timeline_events 双视图**——作者真相 vs 读者已知，**"未揭示的 reveal_chapter 必须为 null；部分/完全揭示只能填实际已发生章节"**（:126）——信息揭示态管理；**mode=append vs mode=revision 事务分离**（:124-125：退役只能 append 提交，"revision 的逐章记录属于被改写的旧章，落在那里会谎报退役发生的章节"）。

**质量阈值体系**（material-decomposition.md:399-405,507-517）：置信度≥0.85/剧情覆盖率 85-95%/重叠率≤35%/跨块边界合并四准则。

**py 事务提交器机制**（tracking_commit.py:1-6）：模型产出语义 JSON→校验合并→**原子写 _tracking-state.json 并重渲染全部派生视图**——"LLM 判断、脚本提交"的职责切分。

## §3 可借鉴 / 不可借鉴清单

**可借鉴（MIT；设计层为主，规则文本可参照）**：
1. **别名四分类+合并门槛**——**16 仓实体去重的规则层最强设计**：类型学（四类）+证据要求（同指证据）+数值门槛（0.85）+保守缺省（存疑分开建）；与 neo4j-skills 的算法层（Resolver 三档）互补成完整方案：**四分类定"能不能合"，Resolver 定"怎么合"**。
2. **机械硬检查**（SKILL.md:241-245）——"主线程落盘后直接 grep，命中即判质量失败，**不依赖 agent 自报**"：情节点数==基调行数/白描非空/枚举值域校验（基调词表封闭集）——CBB gate 的确定性校验清单直接参照（我们 stdlib 校验器同思想，此处提供了**落盘后 grep 式终检**的具体形态）。
3. **事实溯源自检**（SKILL.md:202）——合成阶段硬事实必须 grep 回原文，"原文未明确"禁推断填空——Step 0"应抽样本非穷尽+claim=true"的执行层兄弟。
4. **降维聚合预算**——15KB/章实测→≤8K 聚合回传→N→√N 两两合并：迷深 517 章全量抽取的**施工级参数**。
5. **章节边界表单一切片真值**——一次生成全管道复用，防 regex 漂移。
6. **模型升级重试+跳过不阻断**——haiku→sonnet→标"跳过"：分级降级链。
7. **timeline_events 双视图+reveal_chapter 纪律**——"作者知道 vs 读者知道"的机器化（与 claude-book dramatic irony、nb-memory as-of 同族，但以"揭示章"字段落地最具体）。
8. **append/revision 事务分离+退役只能在 append**——"谎报退役发生的章节"的防御：P-017 幂等的时间维兄弟。
9. **权威投影与摘要视图分离**——单源 JSON+派生只读视图（R-020 机器可读的完整实践：_tracking-state.json 单源，md 是渲染产物）。
10. **demo 即证据**——拆文库带真实样例（盘龙），技能附带可验产物——CBB 技能交付可学（冒烟样本随技能走）。

**不可借鉴**：
1. **元文本防御缺口**：拆文侧零命中"作者的话/求月票/感言"过滤（仅导入迁移"去除文件头尾无关信息（如广告、声明等）"一处近邻 structure-mapping-long.md:65）——**中文网文特有的章末求月票穿插无过滤规则**，CBB R6 仍需自建（且此仓证明该缺口在同类中文工具中普遍存在）。
2. 无时间归一（相对时间标记仅记录不换算；无双时间轴意识）。
3. 爬虫件（scrapers/起点等）法律与合规风险，CBB 不碰。
4. py/js 多副本部署器模式（×3/×4/×5 副本）是分发设计非代码复用——维护成本高，CBB 单源+装机即可。

## §5 与 CBB 对照（Step 0 三条件 + 四契约/三态）

**三条件对照**：
1. **元文本防御：无专门机制**（检索：作者的话|求月票|感言|本章说 于拆文三技能零命中）——**反面样本+1**（同类中文工具普遍缺位，R6 的必要性再证）。
2. **时间归一：无**——情节点记相对时间（次日/半月后）不换算；导入侧 timeline 双视图是**信息揭示态**不是时间归一——cbb-anchor 仍独有。
3. **实体/事件去重：规则层最强**——别名四分类+置信门槛+存疑分开+"一人一实体"；剧情侧覆盖率/重叠率阈值+跨块合并准则——**与 neo4j-skills（算法层）拼成 CBB 去重完整参照**。

**四契约/三态对照**：
- **Record ≈ 拆文库+追踪单源**（情节点带原文引用白描=证据；别名带置信度；_tracking-state.json 单源）；
- **Issue ≈ 质量阈值体系**（覆盖率不足/重叠超限/置信不足各有处置）；
- **Verdict ≈ 人工确认停靠**（Stage 1 二选一）+reveal_chapter 揭示裁决；
- **Case ≈ demo 拆文库**（真实样本可验）；
- **三态映射**：**"存疑必须分开建实体"≈quarantine 的实体版**（宁可分裂不可误合=宁可隔离不可误 confirmed）；跳过不阻断≈第三态（skipped）；未揭示 null≈信息隔离态——三态语义在实体/信息/进度三个维度均有先例。

**金标方法学（§K2）**：机械硬检查（grep 计数不依赖自报）是 R-018（评测器先过对账）的落地形态；无精度宣称数字——不适用。
