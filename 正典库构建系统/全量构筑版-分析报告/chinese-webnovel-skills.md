## §1 架构与数据流

**仓库形态**：「网文工坊 WebNovel Studio」——中文网文全流程 Claude Code 插件（tance-mang，MIT，v0.29.1 语义化版本），33 技能（skills/ 目录 33 个）+ 31 篇 references/ 知识库 + 3 模板 + 独立终端版 CLI。双形态分发：Claude 插件（.claude-plugin/）与**零依赖终端版**（cli/webnovel.py 485 行，接任意 OpenAI 兼容 API，README.md:56-62）+ 多模型导出包（exports/，供 ChatGPT/DeepSeek/Gemini/Kimi 用，README.md:44）。

**数据流**：`start` 模式化入口四门（新建/继续/优化/投稿，CHANGELOG v0.29.0）调度技能 → 技能读写**书的档案文件夹**（八档案单一事实来源，见 §2）→ 正文落 `正文/第NNN章.md` → memory 技能负责回写档案（"不回写就会'下一章继续漂'——这是防失忆的闭环"，skills/memory/SKILL.md update 节）→ continuity 技能按七条逻辑链逐章核对（references/continuity-check.md）。

**长篇失忆三临界点模型**（continuity-check.md 三节表格）：~50 章偶漏（查资源/伤势）、~100 章开始崩（配角名混/设定微漂移，查人物状态/战力/知情人）、~300 章彻底失忆（伏笔全忘/时间线乱，需卷末全量核对）——**对 CBB 分级审查频率设计有直接参考价值**（对应我们 16 仓分析的分层深度同理）。

## §2 数据模型与接口

**八档案模型**（references/project-memory.md 一节，skills/memory/SKILL.md 同步定义）：
| 档案 | 内容 | CBB 对应物 |
|---|---|---|
| 00_设定.md | 立项卡+金手指+世界观+势力库+**战力体系**（境界链+战力对照表） | world 设定 Record |
| 01_人物.md | 人设卡+当前状态+**语言指纹**（口癖/句长/常用词/不会说）+**情绪轨迹数值**（悲伤90/希望20/对X敌意70 随章变）+弧线 | character Record+状态演进 |
| 02_大纲.md | 卷纲/章纲 | 大纲 Record |
| 03_伏笔追踪.md | **编号台账**：F001\|伏笔\|埋点章\|计划回收章\|重要度(主线/支线/细节)\|状态(待回收/✅已回收) | **开环 open-loops 台账** |
| 05_进度.md | 当前章/字数/卷/上章结尾钩/下一步/日期 | 断点状态（≈BUILD-STATE） |
| 06_投稿记录.md | 每次投稿：平台/结果/拒因/我的判断/改动/**复盘标签**（#开篇慢 #爽点晚） | 失败案例库（≈Case） |
| 07_时间线.md | **主时间线（Day1/第N月绝对锚点）+倒计时+知情人名单+世界状态逐章量化**（北城损毁=20%→60%→沦陷） | 时间轴+knowledge states+世界状态 |

**七条逻辑链**（continuity-check.md 一节，逐章必查）：①人物行为合理性 ②剧情因果链（防"突然冒出"/"挖了不填"）③资源变化（钱/灵石/道具只能按剧情增减）④身份暴露状态（**知情人名单：每个秘密谁知道**）⑤伤势/状态延续（期限到点必兑现）⑥战力/等级一致 ⑦情绪/关系连续性（跳变要有过渡事件，"压抑也是一种连续，凭空翻篇不是"）。

**检查输出格式**（continuity-check.md 四节）：结构化体检报告=时间线行+七条 ✓/✗+**矛盾清单**（第_段 与 第_章/档案 冲突→改法）+**待兑现**（到期未兑现期限/伏笔）+**档案待更新**清单——矛盾定位到段/章、每个矛盾给改法（改本章/回改前文/补一句交代）、查完写回档案。

**CLI 接口**（cli/webnovel.py）：三选一配置（环境变量 WN_API_KEY/WN_BASE_URL/WN_MODEL 优先 → config.json →交互输入，:14-17）；`PREF_KEYS` 偏好白名单"绝不写 api_key"（:32-33）；默认 DeepSeek（:50-52）；stream+temperature=0.8（:123）。**注意**：api_key 允许存进 config.json（:51 cfg.get、:71"保留其它字段含 api_key 原样"）——key 落盘由用户自担，非硬编码。

**引号规范史**（CHANGELOG v0.29.1）：全仓示例直角引号「」『』→弯引号""''，"规则已禁用「」，示例也统一，模型照着学就不会输出「」"——中文清洗口径的版本化治理实例（与 P-003 清洗陷阱同题）。

## §3 可借鉴 / 不可借鉴清单

**可借鉴（MIT 无障碍；仍零代码复制）**：
1. **伏笔台账 schema**（编号+埋点章+计划回收章+重要度+状态）——CBB open-loops/开环记录的直接参照；"编号即占位"与我们 R-015 同思路；接近计划回收章未回收则 review/continuity 提醒=**到期触发器**。
2. **时间线绝对锚点纪律**（"用 Day/第N月/第N年 绝对锚点，别只记'几天后'"+倒计时到点兑现+"**所有'X 时间后'都要能换算成时间线上的一个点。换不了，就是要出事的地方**"，continuity-check.md 二节）——cbb-anchor 时间归一在中文网文域的先验表述。
3. **知情人名单**（每个秘密谁知道、何时起知道"师父(第12章起)"）——knowledge states 的成熟台账式。
4. **世界状态量化演进**（损毁=20%→60%、粮道断=是/否、势力更替随章更新）——实体状态字段+变更日志的合并式。
5. **情绪轨迹数值化+允许/不允许行为约束**（"当前：低落但不认输｜允许：哭、嘴硬｜不允许：突然恋爱脑"）——角色 OOC 防护的可校验表达。
6. **七条逻辑链**作为抽取后核查清单——CBB gate/audit 的领域检查表素材。
7. **三临界点分级审查**（50/100/300 章）——审查频率随长度升级的量化判据。
8. **投稿复盘标签**（结构化失败经验+标签归纳高频拒因）——Case 契约"失败也是资产"的实践。
9. **memory 的 resume 一句话汇报**格式——跨会话恢复的低成本接口。
10. **git 即版本快照**（推荐书文件夹 git init 定稿即 commit，project-memory.md 九节）——与 CBB 逐单位 commit 同构。

**不可借鉴**：
1. 全部档案是**人工/AI 维护的自由文本**，无 schema 校验、无机器可读保证（R-020 协调账本必须机器可读的反面）——台账格式靠约定不靠校验器。
2. 伏笔只有两态（待回收/已回收），无隔离/争议态；矛盾清单不留裁决记录（给了改法就散）。
3. 战力对照、情绪数值等字段无单位与量表规范（悲伤90 是什么量表未定义）——直接照抄会引入不可比数据。
4. 面向**写作生成**侧（帮作者写书），不是**正典抽取**侧（从既有文本抽事实）——方向相反，档案模型可借鉴、技能正文不可移植。

## §5 与 CBB 对照（Step 0 三条件 + 四契约/三态）

**三条件对照**：
1. **元文本防御：无**。写作侧工具无抽取环节；deslop/aidetect 处理 AI 味、annotate 做修辞标注，均非"防作者旁白混入设定"。R6 仍独有。
2. **时间归一：强意识、写作侧实现**。绝对锚点+倒计时兑现+并行线对账（"A 线过了一个月、B 线只过了三天，汇合时矛盾吗"）+季节/年龄/节日核对——**域内最接近 cbb-anchor 的先验**；但它靠人/AI 逐章维护时间线，无抽取时的 reference_time 污染问题域（写作侧不存在该问题），故是"纪律参照"而非"机制移植"。
3. **去重：编号防重**。伏笔编号 F001 防重复登记（编号即占位）；实体级/事件级去重无（人物档案一名一卡天然去重，但别名/化名场景仅靠知情人名单+马甲字段人工维护，无别名归一机制）。

**四契约/三态对照**：
- **Record ≈ 八档案**（"档案是单一事实来源：写正文前先读档案，写完后必更新"，skills/memory 原则节）；
- **Issue ≈ 矛盾清单**（定位到段/章+指明冲突对象+给改法）；
- **Verdict：无对应物**（矛盾处置不留裁决文书）；
- **Case ≈ 投稿记录**（失败结构化+复盘标签）——四契约中 Case 的最佳域内形状；
- **三态 ≈ 伏笔两态+待兑现**（待回收/已回收/到期未兑现）——无隔离态；"待兑现"概念≈超时未闭环的警报态，值得 CBB 开环记录借鉴；
- **状态演进三件**：世界状态量化/情绪轨迹/知情人名单——实体状态随章演进的三个可复用维度。

**金标方法学（§K2）**：无评测件、无精度宣称——不适用。

## §6 处置建议

**四选一：借鉴设计（只学思路）**——理由：
1. 这是**至今最贴近 CBB 域内需求的一仓**（中文网文+连续性台账+时间线锚点+开环追踪），其档案 schema 与七条逻辑链是 CBB Record/Issue 设计的一级参照；但它是写作生成侧纯提示词，无运行时件可装。
2. MIT 最干净+维护最活跃，借鉴设计零风险。
3. 它的短板（自由文本无校验/两态无隔离/无机器可读）恰是 CBB 四契约+三态+stdlib 校验器的差异化所在——**"它管记、CBB 管证"**：它的台账格式可作 CBB 人类可读视图层，机器层由 CBB 契约承担。

移交 U-A17 吸收项：①伏笔台账 schema（编号/重要度/状态/到期提醒）②时间线绝对锚点+倒计时兑现纪律 ③知情人名单字段式 ④世界状态量化演进 ⑤情绪轨迹数值+允许/不允许约束 ⑥七条逻辑链核查表 ⑦三临界点分级审查频率 ⑧投稿复盘标签（Case 形状）⑨resume 一句话汇报格式。
