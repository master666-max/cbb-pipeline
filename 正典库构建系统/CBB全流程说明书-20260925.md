# CBB 全流程说明书 · 每个环节做什么、为什么、失效会怎样

- 版本：2026-09-25（对本日全量代码与实测状态负责）
- 读法：每个环节四段式——【做什么】【为什么这么做】【作用】【失效会怎样】。
- 一句话总纲：**逻辑不活在模型上下文里，活在库的账本上**——抽取无状态，记忆在库；每个环节都是往"可被不在场者复核"这个目标上加一层保障。

## 总图

```
⓪环境自检 → ①初始化 → ②边界坐标 → ③试车 → ④小队列 → ⑤主队列(每单元循环) → ⑥收口 → ⑦终审
                │            │                        │              │
                │            │                        │              ├─ 嵌入扫描（向量库）
                │            │                        │              ├─ Neo4j 导出（正典图）
                │            │                        │              ├─ LightRAG 同步（live哨 1s + 章收口兜底）
                │            │                        │              └─ Graphiti 摄入（双时序）
                │            │                        │
                │            │                        └─ 实时同步哨 / 账本前置后置门
                │            └─ 守卫钩子（cbb-guard，全程在岗）
                └─ 决策账（所有裁定的唯一出口）
```

---

## ⓪ 环境自检（开工前；工具 `环境自检.py`）

【做什么】逐项探测基础设施并出 READY/BLOCKED 清单：M1 解释器 / M2 依赖 / M3 工作区可写 / M4 账本可追加；G1-G4 图载体（Neo4j HTTP/bolt/凭证/归属归属判）；E1 嵌入端点；R1 重排端点；L1 推理端点（观察项，不闸门）；P1 graphiti 包+路由探测（json_schema 支持→native 原生抽取，否则→fact_triple 自管管线）；J1 判定者身份声明。

【为什么】这套流程最大的隐性风险是**静默降级**：嵌入端点不在、向量路就悄悄消失，你以为查到了全库其实只查到一半。先探明、写清"缺哪一项、怎么补"，把环境错配从运行时事故提前到开工前告知。图/嵌入/重排三件定为**不可抛弃闸门**（缺失即阻断，降级必记欠账），是 2026-09-24 的显式裁定——它们参与每一章的产物，中途缺失等于产物质量前后不一致。

【作用】①开工前环境清单可交给不在场者复核；②graphiti 路由探测决定抽取架构走哪条管线（实测：DeepSeek 400 → fact_triple；本地 14B → native）；③J1 判定者声明落实"量尺机械化"（判定者是谁、prompt 版本几号，必须先说）。

【失效会怎样】未探=未检=BLOCKED，不许写 N/A 蒙过。跳过自检直接跑 → 环境错配会在第 N 章才暴露，返工成本×N。

## ① 初始化（`init_project.py`）

【做什么】按 project.yaml（八项参数+本体 profile）生成工作区骨架与 BUILD-STATE。

【为什么】参数先行禁散文——八项参数（单元划分/粒度/置信阈值/别名策略/精细度档位…）写进配置而不是写在某个会话的记忆里，任何 Agent 重启都能从同一份参数出发。本体 profile（受控词表写法/术语映射）让"这部小说里骑士团算组织还是概念"这类领域判断有案可查。

【作用】工作区布局从此可预测——后续所有工具按相对布局找文件，跨机不用改代码。

【失效会怎样】书名键位漏收 `name|book_name` 曾让 README 三步走第 3 步必 KeyError（已修）；BUILD-STATE 先开文件后写内容曾留 0 字节残留（已修+自愈）。初始化坏了，后面每一步都在流沙上。

## ② 边界与坐标（`cbb_coordinate`）

【做什么】解析语料自带的章节标记（`<<<CHAPTER 0003 | …>>>`）切成单元；每段文字落**坐标四元组**（卷, 章, 行, 引文）+ block_id；配伪锚点日历（`pseudo_anchor`：第 N 章=2000-01-N，从不用真时钟）。

【为什么】①**语料自身标记=声明面真值**：章节边界不从"我觉得"出发，从文件里实际存在的标记出发；②**引文四元组是全系统可信度的锚**——后面每条事实、每个图边、每个检索结果都能逐字回落到原文，靠的就是它；③**禁墙钟**：小说内部时间与现实中你哪天跑的无关，墙钟入档会让两次合规运行产出不同的库（不可复算），所以用伪锚点日历。

【作用】"这条事实出自第几卷第几章第几行"永远可机查——这是 G2 证据门能机器化的前提。

【失效会怎样】不剥 BOM 会让首章标记失配→全库坐标偏移（已修，实测复现）；第一人称/转写导致的定位失败正是对样要人工看的部分。

## ③ 试车（单单元端到端）

【做什么】拿一个单元从抽取到入库完整跑一遍，输出与预注册门槛对照。

【为什么】全流程十余个环节，第一次串联必然暴露衔接问题；在 1 个单元上暴露，成本是 1 个单元。

【作用】产出第一份真实 pipeline-summary，作为后续所有章的"形状基准"。

## ④ 小队列（3~5 单元连跑，含 1 个脏单元）

【做什么】连续跑 3~5 个单元，其中故意混入一个"脏单元"（带元文本/注入/坏引文）。

【为什么】单点跑通≠连跑稳定；脏单元是**主动接种**——防御机制（元文本闸/注入闸/禁词闸）必须被真实触发过一次，才证明它们不是纸面条款。这与疫苗同构：没有见过病毒的防线不算防线。

【作用】隔离区从此有真实住客，分流状态可查。

## ⑤ 主队列（核心循环，每单元执行）

### 5.1 派工与上下文包（`context_pack.py`）

【做什么】调度员为每个子代理打包：抽取规范+判例+**库内相关既有事实**+原文切片。

【为什么】"执行者无状态，记忆在库"——子代理每次新上下文，它对这个世界的前情全部来自上下文包；库喂抽取的闭环在此形成：已入库事实成为抽下一章的先验。注意纪律：**先验非事实源**——上下文包喂的是"库里现在怎么记"，原文才是对错裁判。

【作用】跨章一致性（人名写法/译名/前情）不靠模型记忆靠库。

### 5.2 抽取与四面防御（`cbb_extract`）

【做什么】从原文抽实体/关系/事件候选，过四面防御：
- ①读入侧：元文本章整章跳过（"本章说"/"翻译："/"转载请注明"…）；
- ④安全侧：内嵌指令样文本整块拒抽（"忽略之前…"——untrusted narrative text 条款）；
- ②输出侧：禁词八类扫描（值表/数值/情绪词等模型最爱编的东西）；
- ③模型侧：无先验填充（canonical 里没有的字段一律 `// 原文未提及`，禁脑补）。

【为什么】LLM 抽取的失效模式就这四类：把排版垃圾当正文、把作者的话当指令、编数值、脑补设定。四面各堵一类，**每面都有成对测试**（正例过/反例必拦）。

【作用】候选质量前置把控——后面所有环节都默认"候选是干净的"，防线必须在这里。

【失效会怎样】元文本漏一章 → "本章说"内容进正典；注入漏一条 → 正文里的"忽略上述设定"被当真执行。全量扫描闸（批次自检 c3）兜底。

### 5.3 gate1 证据门

【做什么】逐条候选机检：证据四元组齐全？引文逐字回落原文？无前验填充？契约合规？

【为什么】**幻觉的机械可检形态就是"引文落不回原文"**——LLM 编造事实时引用的卷章行经常不存在或引文对不上。这条门把"幻觉"从抽象风险变成一次字符串比对。

【作用】过门候选才进置信路由；被拒候选进隔离区留档（不静默丢）。

### 5.4 三态写入与双轨分流（`cbb_store`）

【做什么】置信度 ≥τ → provisional；高置信一致重复 → 合并升级（版本+1）；矛盾 → 隔离区+裁决文书（不静默合并）。所有 jsonl 侧车经 `_append` 汇聚点 → 哈希链账本。supersede 版本链：旧文件字节不动。

【为什么】**三态是"错误可以产生，confirmed 的库里进不来"的机制化**——承认抽取会犯错，用状态门替代完美抽取的幻想。双轨分流承认"一致重复"与"矛盾"是两种事：前者上调置信，后者必须人裁。append-only + 旧件字节不动，让任何时刻都可以从账本重放全库。

【作用】库的每一字节变化都有账本行（sha_before/after+幂等键），防篡改可机验。

【失效会怎样】撕裂 JSON 曾让全链崩（A2 修：原子写+披露）；账本被旁路直写污染曾到 P0（前置/后置门修：跑前跑后各验一次）。

### 5.5 隔离区

【做什么】矛盾/低置信/超期未决条目分流登记（group+subclass+日期位），状态机 pending→裁决。

【为什么】**隔离区是一等公民**——处理不了的东西显式放隔离区出报告，绝不静默丢弃（B6）。它是"不确定"的合法存放处，让主库保持"每条都是已决事实"的简洁。

【作用】裁决工作队列；也是"库不知道什么"的透明清单。

### 5.6 实时同步哨（`lightrag_live.py`，1s 颗粒度）

【做什么】每 1 秒扫库文件 mtime（scandir，只 stat 不读），变更记录即时构建三元组喂 LightRAG 副本；喂入失败保持重试位（毒批不静默丢）；心跳独立任务（长喂入期间不假死）；与章收口同步通过心跳让位（防双写）。

【为什么】LightRAG 的核心卖点就是增量更新——每章才同步一次，等于花了几十秒 embedding 却让副本滞后整章。颗粒度拉到顶（1s）后，"写入→可检索"延迟 ≤1 个轮询周期。

【作用】查询侧（第五路）永远基于最近写入；写、存、查三环节全在线。

【失效会怎样】端点挂→重试位不前进，恢复后自动补喂（实测故障注入通过）；哨死→章收口 delta 同步兜底。

## ⑥ 收口（每章/每段）

### 6.1 aux 四件自动事（`run_chapter.py` 收尾段，全部探活降级不阻塞）

1. **嵌入扫描**（向量库，4096 维富文本）
2. **Neo4j 导出**（正典图，零 LLM 纯机械翻译）
3. **LightRAG delta 同步**（live 哨在岗时自动让位）
4. **Graphiti 全章摄入**（自管抽取→fact_triple，伪锚点 reference_time）

【为什么是这四件】它们共同维护**三个派生视图**（正典图/向量库/LightRAG 副本）+一个时序层——全是库的只读投影，真源永远只有正典库。派生件可随时全量重建，这是"索引坏了不用慌"的底气。

【失效会怎样】任一件 blocked 只记状态不阻塞主链——派生件可以之后补建，正典进度不能等它。

### 6.2 账本前置/后置门（BUG-0 门）

【做什么】run_chapter 跑前/跑后各验一次账本哈希链（磁盘 sha vs 账本）。

【为什么】哈希链只证明"已入账的没被改"，证明不了"没有漏"——旁路直写（绕过 _append 的写）在两个方向漏：上一轮留下的（前置门拦）、本轮内部的（后置门拦）。**没有这个门，账本对账就是事后审计；有了它，变成运行时拦截**。

【失效会怎样】实测：干净库放行；注入 `ok:false` 必 SystemExit——产数据之前先挡住。

### 6.3 批次机械自检（`批次自检.py`，十项失效模式）

【做什么】区段收口时十项全机器断言：①库/STATE/commit 三方对账 ②章号边界一致 ③元文本混入全量扫描 ④墙钟入档 ⑤空单元登记 ⑥隔离分流状态 ⑦去重提示入账 ⑧证据引文回落全量 ⑨verified_against 真实三件套 ⑩断点与导出存在性。

【为什么】这十条是**该层失效模式的穷举清单**——每条对应一种真实发生过/可推演的坏账形态。出口=证据不是轮数：机器能查的不耗人眼，人只处理 FAIL 和合法例外。

【作用】批次质量的可复算证明（脚本输出即留痕）。

### 6.4 图对账与悬挂端点处置（`graph_audit`，段收口常态）

【做什么】四断言面：①节点集双侧 ②边集双侧 ③时序字段一致性 ④D2 侧车 edge_id 对账。差异只报告不改写。

【为什么】派生图与库的同步是增量 MERGE，任何环节出错都体现为两侧差集。**悬挂端点两分法**（变体归一 vs 真缺候选）来自 65 例实战：全删会扔掉有价值名字，全收会让变体名泛滥——先分类再处置，禁自动 DELETE（带边即活）。

【作用】首轮 65 例→归一 43+隔离 22，边 1645/1645 零不一致。

### 6.5 派生层对账（`派生层对账.py`）

【做什么】图节点数==实体向量库记录数、边数==关系向量数、每节点带来源位——三方计数对账，任一不过退出码 1。

【为什么】LightRAG 直灌是**非事务**的：嵌入端点中途挂，节点已进图、向量没写——图查得到、向量召回不到，与"真没有"完全同形。所以灌完必须双查，"跑成功了"不算对账。

## ⑦ 终审（五层证据门 G1~G5）

| 门 | 查什么 | 为什么 |
|---|---|---|
| G1 覆盖 | 单元切错/漏/缺号 | 应−实=未覆盖集，语料自身清单为应然 |
| G2 证据 | 幻觉引文/元文本/漏抽 | 回落全量机器查，人只抽语义层 |
| G3 规则 | 门放行坏件/误合并 | 成对可执行反例全枚举 |
| G4 对账 | 派生视图 vs 真源 | 数/字段/抽样三元组回查 |
| G5 结论 | 宣称越界/数字不可复算 | 标签与量对账，判定面非空 |

【为什么是五层】按**失效模式穷举**不按轮数：覆盖缺失、证据造假、规则误放、派生漂移、结论越界——终审要拦的坏账形态就这五类，每类一道门，每门必须带正负对照（改坏一条必被抓、抽掉一单元必 FAIL）。**出口=可复算的证据，与跑了多少轮无关。**

【抽样】机器能全量的层不抽样；人只抽语义正确层。零缺陷公式 n≥ln(1−C)/ln(1−p)（95% 把握压到 5% → 59 条），按执行批次分层（缺陷按批次聚集，均匀抽样被设计效应虚标），双独立复查+Chapman 估计残余缺陷。

【对样实例】ch0003 全章抽取 20 条对样走完四轮（判定表→扩上下文→精准定位→终判），抓出：张冠李戴（翠色结晶被贴十位魔法石之名）、动作强度放大（持有/评价被写成"使用了"）——**机械判读建议两次被用户纠正**（报出魔法名即发动），判定权在人的活证明。

## 检索层 L6（读取侧；`检索层.py`）

```
查询 → 路由（机械优先：别名→单跳；关系词→多跳；全局语式→哨兵A门控）
  → 五路召回：
     ①别名/专名精确（机械，恒可用）
     ②关键词（FTS/bigram 降级）
     ③向量（LanceDB 4096 维富文本）
     ④图扩展（Neo4j 1-hop，或 graph_chain 深度链）
     ⑤LightRAG 图游走（默认并入，CBB_FIFTH=0 关）
  → RRF 融合（纯公式可复算）
  → 重排精排（qwen3-reranker，打分对象=富文本；缺席退 RRF 序）
  → 证据链组装 + 引文核验（逐字回落，落不回=拒答/标未核实）
  → 网络补充层（web_supplement，admissible=False 硬标记，单列低置信区）
```

【为什么五路】问题类型分布决定：单点事实走①③、多跳走④⑤、全局走哨兵 A 门控的摘要层——**任何单路都有结构性盲区**（向量连不上散点、图不懂语义概括），融合是对盲区的对冲。

【为什么重排】RRF 是投票不懂语义；reranker 逐条深读候选富文本打相关分（0.988 vs 0.0001 实测分辨力）。缺席退 RRF 序，不阻塞。

【为什么引文核验在最后】**答案的可信度不由生成模型说了算**——每个交付条目必须能逐字回落库内证据，落不回就拒。这是"上下文污染/幻觉"的最后一道闸。

## 守卫层（cbb-guard v0.1.2，全程在岗）

【做什么】PreToolUse 钩子：拦 A 冻结线覆盖（原位保全：新建放行、覆盖拦截）、拦 B 红区 Write（契约/工单/决策账）；旁通唯一合法通道=绑定式 `CBB_HOOK_BYPASS='<目标前缀>=<裁定引用>'`，且**无留痕不越权**（决策账写不进去就拒绝放行）。

【为什么】Agent 的所有破坏都是"写"——在写之前拦，比写之后审计便宜一个数量级。根解析四级（env > cwd 向上找 CBB 标记 > 回落 cwd）+ 保护面=命名惯例谓词（与根解耦，全局按名判定）——同机多项目各保各的，不硬编码任何实例路径（0.1.2 修的正是"自动保了迷深"这个缺陷）。

## 三图一册分工（谁存什么、为什么不能合并）

| 件 | 存什么 | 为什么独立 |
|---|---|---|

5. **隔离区一等公民**——不确定有合法存放处：主库保持"条条已决"

7. **断点纪律**——游标+scoped commit：STATE=缓存，磁盘+git=事实
8. **量尺机械化**——禁自抽自评：自评必然虚高（对样中机械建议两次被人纠正的实证）
9. **成本乘法线**——×剩余单元数的东西三思：token 经济学的护城河
10. **判定权分离**——执行无权自宣验收：出口=证据
11. **派生图带边即活**——悬挂端点两分法禁自动删：派生件上的"库外"≠垃圾
12. **账本前置/后置门**——哈希链证明不了"没有漏"：把漏变成运行时可见
13. **无留痕不越权**——旁通写不进账就拒绝：唯一越权通道必须有痕迹
