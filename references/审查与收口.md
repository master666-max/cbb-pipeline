# 审查与收口（v2.0 · 现行审查体制 · 出口=证据，不是轮数）

> 三条推导原则：①检查面=该层失效模式的穷举，与"轮"无关；②能机械判定的必须机器判定，判定面为空≠通过；③出口=证据（可复算＋正负对照＋锚点），不是过程量。
> 历史注：v1.x 的"每批十查/单位十轮/终审十轮"已废止（检查面被本件继承，执行载体从人脑换成机器/清单）。原文留痕见各实例档案。

## 一、单位收口三件套（一个模块/一件交付完成时）

1. **机械门**（全绿才许收口）：契约校验器跑本单位产物 ＋ 全量单测 ＋ 集成双跑（幂等断言）＋ 许可红线扫描（GPL/AGPL 零接触、CC BY-NC-SA 零复制）
2. **人工增量清单**（仅三项，逐条带 `文件:行号` 锚点，只查增量不重读全库）：
   ①证据链可回溯——每项设计决策能指到来源条目
   ②吸收项对照——对照表逐条勾选
   ③红队打回理由——假设自己是审核线找打回理由；每条要么修复、要么登记【待确认】
3. **scoped commit**（只 add 本单位路径，禁 `add -A`）

**出口**＝机械门全绿 ＋ 清单三条逐条有锚 ＋ commit。零轮次。

## 二、批次机械自检（区段/批次收口时）

十个失效模式逐项**机器断言**（一次性写成脚本，之后每批零人工；人只处理 FAIL 与合法例外；**留痕＝脚本输出本身**）：

| # | 失效模式 | 断言 |
|---|---|---|
| 1 | 库/STATE/commit 不同步 | 游标=账本头=commit 内容 三方对账 |
| 2 | 单元号错/跳单元 | 候选单元号 vs 边界表一致；缺号单元必有登记 |
| 3 | 元文本混入 | 候选文本禁词/元文本**全量扫描** |
| 4 | 墙钟入档 | reference_time 伪锚点断言 |
| 5 | 空单元无因 | 零候选必须有原因登记 |
| 6 | 分流错 | 状态字段断言（隔离/入库各归其位） |
| 7 | 去重静默 | 嵌入扫描"已执行且有输出"断言 |
| 8 | 引文悬空 | **全量回落**（不做抽样——机器扫得起） |
| 9 | 占位三件套 | verified_against 存在性＋非占位值；脏工作树不作锚 |
| 10 | 断点/导出丢失 | commit 存在性＋导出债务台账 |

**过渡条款**：自检脚本就绪前，按 v1.x 十查人工执行——**不得因换壳停止检查**。

## 三、全库终审＝五层证据门 G1~G5

| 门 | 查什么 | 怎么查 | 正对照（必须成对） |
|---|---|---|---|
| **G1 覆盖** | 单元切错/漏/缺号未登记 | 应−实=未覆盖集（应=语料自身单元清单）；逐条理由可核查 | 抽掉一单元→FAIL；补回→PASS |
| **G2 证据** | 幻觉引文/元文本/漏抽 | 回落全量机器＋语义层分层抽人 | 改坏一条引文→必被抓 |
| **G3 规则** | 门放行坏件/误合并/链断 | 成对可执行反例，全枚举 | 拒对了＋放过了 成对出现 |
| **G4 对账** | 派生视图与真源不一致 | 真源↔派生：数/字段非空率/抽样三元组回查 | 派生少导一条→必被对账抓出 |
| **G5 结论** | 宣称越界/数字不可复算 | 标签与量对账＋口径上界＋判定面非空 | 判定面清空→必须显式标"不适用（非通过）" |

**出口条件**：五门全部可复算通过＋每门有正负对照＋每个数字给复算方式＋空判定面显式标"不适用"。任一不满足＝**未完成**，与跑了多少轮无关。

## 四、抽样（按架构工作量，不按总体大小）

**第一刀**：机器能全量查的层不抽样（引文回落/结构/口径一致性/对账）。**人只抽语义正确性层**（证据是否真支撑断言、指代消解、事件边界）。

- 零缺陷公式：`n ≥ ln(1−C)/ln(1−p)`。95% 把握：≤10%→29 条，**≤5%→59 条**，≤3%→99，≤1%→299
- **按执行批次分层、每层固定 8~10 条**——缺陷按批次聚集（同一批次=同一规范版本=同一上下文包），均匀随机抽样的置信度被设计效应 `deff=1+(m−1)ρ` 虚标
- **残余缺陷**：双**独立**复查者各看 40~60 条，Chapman 估计 `N̂=(n₁+1)(n₂+1)/(m+1)−1`；独立性是命门（共用规范/上下文包会严重低估）
- 停止规则：SPRT 先抽 30 条，明显好/坏即停（平均省 30~50%）
- 报数：k=0 报 `1−α^(1/n)`；k≥1 报 Clopper-Pearson 上界。**抽到缺陷不许口头承诺合格**
- **抽样前重排（本地重排器，深融条款②）**：候选按"证据最弱/最可疑"排序，人先看最值得看的；重排器不可用→退回机械排序。重排只定顺序，不定结论
- 不用 ISO 2859/Z1.4 的 AQL 表（供需验收工具；假设批内独立，与本场景冲突）

## 五、十条纪律（T-1~T-10，源自田·声明式审计）

| # | 纪律 | 违反时你会看到什么 |
|---|---|---|
| T-1 | 声明面与观测面分离："应该有什么"来自语料自身标记，不由抽取产物自报 | 覆盖矩阵变恒真，任何单元都能自证已处理 |
| T-2 | 判定缺席/为空/通过三者在输出上同形——空必须非零 | 哨兵写 UNKNOWN 仍是一份"可读报告" |
| T-3 | 正对照必带：判据价值在"拒对了一个、放过了一个" | 只有负例 ⇒ 分不清检查器对什么都报错还是真在工作 |
| T-4 | 有界宣称＋实测对象绑内容哈希 | "没漏"与"没被篡改"混成一句；换语料后矩阵没有指称 |
| T-5 | 标签与量对账：每个数字给"怎么数出来的" | 同一指标出现六种读数（实例实证） |
| T-6 | 判据侧的错与被测的错同形——新脚本先跑空/坏输入自证能报错 | 检查器坏了，你看到的是同一个"没问题" |
| T-7 | 不可回退分配（编号/状态晋升/裁决终态/单元认领）单一写者＋撞号即占位 | 双写者撞号，事后无法判谁有效 |
| T-8 | 副本多义律：≥2 副本时差集静默——必须锚哈希＋机械比对 | 两份指令互相矛盾却无任何报警（实例实证） |
| T-9 | 落点自陈：每份文书写"有无强制力/谁读/删了会怎样" | "写了"被读成"做了" |
| T-10 | 双向平衡核验：每条判据在自家账面找同构实例，找不到=未完成 | 只给别人定标准，判据不可判 |
