# 检索增强与图谱对账（v2.0 · 2026-09-25 实战沉淀）

> 本册收录第五路检索/图对账/网络补充三项实战经验。判例式写法：每条=场景+纪律+反例。

## 一、多路检索的路间纪律（第五路 = 图游走供应商）

- **检索器可以是外脑，裁决必须是本库**：第五路（LightRAG 图游走）只产出名次列表并入 RRF，引文核验、重排精排、三态库全部保留为终审。外部引擎的 schema 鸿沟（多值 `<SEP>`、边 keywords/weight）在导出层补齐，不让其格式渗透进正典。
- **零查询期 LLM 是硬判据**：图游走引擎默认查询期调 LLM 抽关键词——必须用 `hl/ll_keywords` 外部传入绕过，且以桩计数断言 `llm_calls=0`。**注意空关键词表会让引擎回退调 LLM**（实测）：关键词生成必须"词表准入 + 非空兜底"双态。
- **自造词准入门**：查询关键词只收 canon 词表（全库实体名∪别名，跨库）；记录号形态、查询套语碎句一律丢弃并计数披露；词表全空时才降级准许碎句。反面教训：全收噪音词在合成测试集上反而涨分——**纪律判据优先于分数**。
- **实测锚点**：词表准入制下第五路给"关系对查"类带来 +40pp（46.7%→93.3%/86.7%），全合成 45 查询、B-A Δ≥5pp 预注册判定。

## 二、图对账（图谱↔正典库常态交叉印证）

- **对账四断言面**：①节点集双侧（图 vs 库实体名）②边集双侧（三元组）③时序字段一致性（valid_at/invalid_at 与库内重算值）④证据回填侧车 edge_id 对账。出口=差异报告，不改写任何一侧。
- **悬挂端点两分法**（2026-09-25 首轮 65 例，工序化见《审查与收口》一·补2）：关系记录引用了但无实体记录的名字——导出件 MERGE 边端点所致，是主线引用完整性缺口，不是图之过。处置全程：
  - **弯路即教训**：首轮误判为"历史遗留陈旧孤岛"准备清理，写了零度防护（只删无边节点），实测 65 个全部带边（157 条引用边，最多 8/中位 2）→ 立即停手转人裁。**派生件上的"库外"≠垃圾，带边即活**。
  - **两刀分类**：形态刀（括号限定/引号/裸名，只看分布）+ **裁决刀**——按"能否机械归一到现役实体"分：43 变体可归一（『史诗探索者』→史诗探索者、《持有物品》→持有物品）vs 22 真缺实体记录（FlameAccel、『狂王』、『天上的七骑士』……恰好是候选设定物，证据在引用它的关系记录里）。
  - **两条通道**：变体→导出层归一映射（确定性零裁量最长优先、计数披露 40 条边、同三元组合并、库文件字节不动）→ 65 旧名节点清理 + 全量重导 → 复测图外 65→22；真缺→隔离区候选（走账本合法通道，verify 精确闭合 4488=4466+22），按正常准入裁决。
  - **连锁**：端点归一改 edge_id 并合并同三元组边 → 增量副本的 source 集记账自动看到 delta（37 关系+34 chunks，重放安全）——设计使然非漂移。
  - **一句话**：库外名字先两分（变体归一 vs 缺口候选），归一机械放导出层、缺口走准入通道，全程账本闭合、每步披露。
- **归一的副作用要跟着走**：端点归一会合并同三元组边（去重）+ 端点名变化 → 依赖 source 集记账的增量系统（如 LightRAG 副本）会自动看到 delta——这是设计使然，不是漂移。

## 三、网络搜索补充层（低置信度材料）

- **硬标记 + 三闸**：产物 `admissible=False`/`confidence=low`；①准入闸（试图入正典直接拒绝）②引文核验面（网络句必然落不回库内证据池→unverified）③呈现闸（必须单列"低置信度补充"区，不与正典结果混排）。
- 依据：Wikipedia 2025 实证——AI 生成内容 >2/3 "failed verification"（引用真实来源但来源不支撑句子），失效点在归属错配而非伪造来源。

## 四、增量同步（派生索引副本与章收口挂钩）

- **sidecar 按 source 集记账**：副本喂入件记录每个实体/三元组已喂的 source 集；delta=当前-已喂；无变化=零嵌入调用（幂等，可反复跑）。
- **bootstrap 语义**：副本已含全量时，先 `--bootstrap` 只播种记账不重喂（防首次同步全量重嵌）。
- **喂入函数契约（LightRAG 1.5.7 四坑）**：①custom-KG 路径不自动初始化存储（须显式 `initialize_storages()`，否则 flush 崩 `NoneType async CM`）；②嵌入/LLM 函数必须是**协程**且返回 **numpy 数组**（`result.size` 校验）；③`aquery_data` 外层是 `{status,message,data}` 信封需解包；④内部队列绑定事件循环——跨 `asyncio.run` 复用必炸，生产形态=常驻线程常驻循环。

## 五、运行器挂钩（与流程深度同步）

- 增量同步/图导出/嵌入扫描同为 aux 段探活降级件：blocked 不阻塞主链，状态进 summary；
- **共享单模型本地端点的并发防线**：多路同时敲嵌入端点会 400（实测 LM Studio）——全局锁串行化（`EMB_LOCK`），锁在调用侧不在服务侧；
- 查询日志默认开（`CBB_QUERY_LOG=0` 显式关）：四路+第五路双写 jsonl，是负载复核与后端降级率统计的数据底座。

## 六、三元组抽取提示词通用纪律（v2 · 2026-09-25 对样沉淀）

LLM 直抽"实体-关系-三元组"（供图/时序层喂入）时，提示词必须内含四条硬性要求（领域无关，源自 ch0003 对样 19✓/1✗ 实测）：

1. **quote 逐字锚点**：每条 relation 必须附原文逐字支撑句（含第一人称原样），无逐字句支撑的关系不许输出——错也无从机械回查的反面教训：转写型 fact 两次掉落张冠李戴（『翠色结晶』被贴上后文另一次掉落的『十位魔法石』之名）。
2. **禁跨事件补名**：事件产出的对象名称以**本次事件原文**为准，未确认就写描述形态；禁止把其他事件的对象名补到本事件上。
3. **事件独立**：每次独立事件独立成关系，禁合并同类项。
4. **宁缺勿滥** + 实体名用原文写法。

纪律注：机械判读建议≠判定——对样中"报出魔法名即发动"这类本作特有的使用形态，只有人能确认；判定权在人。
