# 编排与并发（v1.9.4 条款通用化 · 子代理运行手册）

## 一、调度员-子代理编排（百万字唯一可扩展架构）

- **主代理=调度员，不亲自抽章**（单上下文不可扩展；亲抽仅为引擎故障兜底）。
- 每章派**前台子代理**（新上下文），提示词=四行指针：
  ①读《抽取规范》（连同《判例》）②读**上下文包**+本章切片 ③按 Record 契约产出候选 JSON 自行写入工作区 candidates/ ④回传一行回执 ≤200 tokens（路径+计数+引文预检结果）。
- **候选全文走磁盘不过主代理上下文**；调度员收执后核文件存在与行数 → gate1 → quarantine → store → commit。

## 二、上下文包（库喂抽取的闭环）

派工前由**确定性脚本**（禁代理裁量）从库生成，≤2K 封顶，四件套：
1. 主要人物册（canonical+别名，出场频次排序）
2. 活跃伏笔/开环清单（status=open）
3. 滚动摘要（最近 30 章，每个子代理追加"本段新增要点/新角色/新设定"）
4. 判例指针（封顶 30 条，淘汰最旧留痕）

**先验非事实源**：与原文冲突以原文为准+存疑分开建（防先验污染）。种子期可并入既有角色语料库/异名统合表作深度先验。

## 三、并发两段式（v1.9.4）

```
开工（第一笔 commit 起计时）
├─ 0 ~ 2h：并发 9 猛开（抢窗口红利；限流则回落 7→5 探稳定档）
├─ 2h ~ 掐停：并发 4 巡航
└─ 唯一合法停止=服务端掐停；禁止自我停止/滑行收尾/时间表降档
```
- **限流协议**：并发限制→全批等待 60~120s 重试一次→仍失败降档并**记录稳定并发数**（入 STATE，后续班次直用起步）。
- **挂死诊断**：子代理疑似挂死查 metadata（status/更新秒数/工具计数全空=首次请求即挂死）→ 等 1~3 分钟无动静放弃重拉（幂等零污染）。
- **并行前置四条件**：对象文件互不重叠／断言式幂等／失败零写入／提示词固化+验收脚本独立。

## 四、收口与断点

- **每 8 章轻收口**（秒级）：游标+scoped commit（只 add 本批路径/STATE/日志，禁 add -A）——commit 频率=断点密度，批界不是停止点。
- **每段重收口**：十查重项（嵌入扫描/召回探针/judge/图导出/校准报告）+十查留痕。
- **STATE=缓存，磁盘+git=事实**：done 单位证据不在即改回 todo 记勘误；开工程序=读 STATE→对账→从游标续跑。

## 五、NLI 矛盾预筛（矛盾积压>50 时上岗）

- 矛盾对生成器导出（新候选 claim vs 既有记录 claim，含双方证据）→ 三分判定（entails/neutral/contradicts，temp=0）。
- **只分流不裁决**：contradicts→人工队列置顶；neutral→挂起；entails→转双轨 confidence 流程；全程留痕。
- **上岗小考**：已裁案件 ≥10 对+注入伪矛盾 ≥10 对，分离度 ≥0.70 才启用；不达标继续人工。
