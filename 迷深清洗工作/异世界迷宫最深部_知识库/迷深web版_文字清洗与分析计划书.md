## 一、总原则（两份文档的原句级要求）

1. 针对《迷宫深部》这类"高密度心理刻画 + 多层反转 + 千年时间线"的群像作品，语料清洗的核心思路是：**以"分层清洗 + 结构化提取"为总原则**，前期尽量保留原文的语言风格与心理独白，通过标签化、降噪、维度拆解，把线性叙事转化为可供 LLM 稳定检索的角色卡与世界观知识库。这部作品的精髓恰恰藏在涡波的"演技假面"、玛利亚的病娇独白、诺斯菲的千年执念这些细腻的心理描写里，**粗暴清洗会把这些灵魂细节一起抹掉**。
2. **清洗不是压缩，而是重构**——把叙事流变成结构化知识，同时把涡波那句"我绝对要救你"的灵魂原句原封不动地留在卡里。
3. **咏唱语料是全库唯一要"原文原样保留"的板块**：咏唱段落不压缩、不合并、不做同义改写，只做"分类打标 + 按层级抽取"；清洗的全部工作量都应放在"分类、打标、建元数据"上，而不是动文本本身的一个字。咏唱是这部作品的世界观指纹与角色灵魂台词，一旦改写就不再是涡波、不再是诺斯菲。
4. 普通"爽文式清洗"（只留打斗和结论）会把这部作品洗成废纸，必须执行第五节的五项特殊处理。

## 二、Phase 0：原文来源、底本与边界确认

1. **两套语源**：web 版（成为小说家吧，2012–2021，已完结）与文库版（OVERLAP 文库，16 卷），两者在伪名、剧情细节上存在差异，清洗前必须确认底本。指导文档指出"web 版前几章涡波化名'基督·欧亚'，文库版则改为'齐格弗里德·维吉托'"——**实测校正**：本合集语料中未出现"齐格弗里德·维吉托"，web 正文全程用"基督"（全名 相川涡波・基督・欧亚・瓦尔德弗茨亚茨・冯·沃克），凡指导文档与实测语料冲突处以实测为准（详见附录B）。
2. **本计划的底本**：`04_web版` 第一章～第十章。其中第一～三章为文库版第一～六卷转写补全（标记 `web_reconstructed`），第 129 话 Epilogue 与第四～十章为合集内实际存在的 web 原文（标记 `web_original`）；web 版第 8 章起的"超越于爱，更胜生命"高潮段、第 9–10 章新篇章为 web 专属剧情（标记 `web_only`）。
3. **web/文库差异的处理模式（两选一，Phase 0 决策）**：
   - 模式A：做完整知识库 → web 版与文库版**两版并行清洗**，用 `edition: web / 文库` 标注；
   - 模式B：只做一版 → 优先文库版（更完整、更精修），但要标注 web 独有设定以供补充。
   - 本计划默认从模式A'起步：先做全 web 版（含补全的三章），文库版已在本知识库 `02_文库` 中保留原文，后续按需并行。
4. **化名锚点（web版专属要点，原句纳入）**：所有 web 版语料中"基督·欧亚/克里斯托"指向涡波本人，但角色卡上必须作为**独立别名保留**并标注 `alias_type: web_pseudonym`，**不能在抽取时直接替换成"涡波"——这会破坏前期"身份隐藏"剧情的检索逻辑**。
5. **别名表（统一译名，Phase 1 建立）**：相川涡波 / アイカワ・カナミ / カナミ / 基督·欧亚（キリスト・ユーラシア）／齐格弗里德·维吉托（仅文库版语境条目）均指向同一角色，但**不同伪名必须作为独立条目保留，并标注使用的时间线**（千年前后、web/文库差异），这是本作剧情反转的关键锚点。此外本语料实有别名还需收录：使徒西斯、始祖涡波、罗德（Lord）、次元之理的盗窃者等。


## 三、Phase 1：预处理（切分与去噪）

### 3.1 三级切分（动作清单第1条，原句纳入）
按卷、章、场景三级切分，章内再按"场景切换"（空行、章节小标题、地点变动）切为段落块，**每块 300–1500 字**为宜，这是后续向量化与 LLM 抽取的最小单元。
本语料落地：卷/章=10 个 md（已有）；话/节=现有 `## / ###` 标题（第一～三章内为文库章节，四～十章内为"第N话"）；场景切分信号=`◆◆◆` 分隔线、话标题、地点/时间词突变。每块携带元数据 `{chapter, episode, block_id, edition, timeline, translator, cast[]}`。

### 3.2 去噪清单（动作清单第2条，原句纳入 + 本语料适配）
| # | 去噪项（指导原文） | 本语料适配 |
|---|---|---|
| 1 | 剔除作者吐槽、更新公告、感想页、感谢语 | 对应各话开头"翻译君:"署名与交流截图说明行→移入块元数据 `translator`；`后记`/`特典`不在 web 正文处理范围 |
| 2 | 剔除重复的技能/状态栏长模板（系统面板反复出现，保留首次完整版，后续用 `[面板略]` 占位） | ⚠️ 压缩前先跑咏唱/伏笔正则，命中块跳过压缩；状态栏中的拉丁技能名清单（如 `Freeze1.04`）可与面板一同压缩 |
| 3 | 剔除重复的迷宫地图描述 | 同规则：保留首次，后续 `[地图略：同第X话]` |
| 4 | （本语料追加）外部图片链接行 `![图片](论坛url)` | 译者论坛互动截图，移入附录"插图引用清单"，正文移除 |
| 5 | （本语料追加，**保留而非去噪**）`（PS：…）（译注：…）` | 不删，转 `[注]` 标签保留——含译者对伏笔的提示，属分析性语料。故指导正则 `re.sub(r'(作者的话\|あとがき\|※.*?※)', '', text)` 中 `※.*?※` 一项**不采用** |

### 3.3 指导文档的正则清洗示例（原样纳入，括号内为本语料适配注记）
```python
import re
text = re.sub(r'(作者的话|あとがき|※.*?※)', '', text)      # 去作者吐槽（※规则不采用，见3.2-5）
text = re.sub(r'={3,}|-{3,}', '\n—— 场景切换 ——\n', text)   # 分隔符转场景切换（本语料分隔线为◆◆◆，追加该模式）
text = re.sub(r'(第.{1,3}卷|第.{1,3}话|第.{1,3}章)', r'\n\1\n', text)  # 章话标题独立成行（本语料已是独立标题行）
text = re.sub(r'\n{3,}', '\n\n', text)                      # 压缩空行
# 对话行标注（日文引号「」与中文""都要兼容）
text = re.sub(r'^「(.*?)」$', r'[对白]\1', text, flags=re.M)
```

### 3.4 保留原味（动作清单第4条，原句纳入）
不要在中途改写措辞。涡波的内心独白（"我一定会帮你的，如果是为了这个，我会——！"）就是角色卡的灵魂语料，直接保留原文摘录。

### 3.5 不可去噪红线（本语料实测追加）
咏唱全部层级、心理独白、守护者开场白的间隔点号、辞世诗、**`[ ]` 半角方括号行（本作的心灵通讯/内心自白，如 `[胃好痛……]`，不得当作噪声删除，须归独白/通讯类打标）**、伏笔句、`──`/`——` 破折号。

## 四、Phase 2：对话行标注体系

## 五、Phase 3：咏唱分库（最高优先级板块，文档②全量纳入）

### 5.1 分层依据（原句）
本作咏唱在语料中的呈现密度极高，清洗逻辑与普通对话、心理独白完全不同——咏唱段落**不压缩、不合并、不做同义改写**，只做"分类打标 + 按层级抽取"。原作中熟练者可省略普通咏唱，而支付"代价"强化效果的代价咏唱、以及守护者觉醒时才解禁的真正魔法咏唱，**三者必须分库存储**。

### 5.2 七分类分层表（原表全量）
| 层级 | 文本特征 | 保留策略 | 提取字段 |
|---|---|---|---|
| 普通魔法咏唱 | 短句+魔法名，如"《烈焰箭矢》！""魔法《维度·多重展开》" | 保留原句，可按魔法名去重合并 | caster, magic_name, incantation_text, effect_brief |
| 代价咏唱 | 含"作为『代替』""燃烧记忆""支付代价"等显式代价描述 | 原样保留，单独标注 cost 字段（魔力量/记忆/寿命/器官等） | cost_type, cost_desc, trigger_condition |
| 真正魔法/固有技咏唱 | "——『xxx』——"三段式对仗+魔法名，如"——『我眼中的世界(你)是如此惹人怜爱』——魔法《我的世界的物语》" | **一字不改，连同"——"与『』全保留** | true_magic_name, final_incantation, scene_chapter, power_level |
| 守护者开场白 | "这·里·，这·xxx·便是·x·十·层"的带点断字宣告 | 原样保留，这是身份宣誓，**不可删点号** | guardian_rank, opening_declaration |
| 辞世诗 | 汉诗体四六骈文，如"『所谓人者，非唯躯骸。倘此胸鼓动尚在，则心中灯火不灭』" | 原样保留，单独归档 | death_poem, character, layer |
| 共鸣魔法咏唱 | 双人合唱型（如缇缇&艾德的《樱童乐土》） | 按说话人分行保留 | participants, combined_incantation |

**保留优先级：真正魔法咏唱 > 代价咏唱 > 固有技 > 普通魔法 > 技能名列表。原则上魔法名列表可以压缩成条目，但咏唱正句绝对不压缩。**

本语料追加两处形态注记：
- 辞世诗在本语料有**两种载体**：话标题本身（如"218话 天狱五十，孤臣堕坠。唯愿奏此、幼王终曲。""178话 牢狱二十，少年暗秽。伊人之光，降注于兹。"）与正文内『』『』连排骈文，两者都要归档。
- web 原文破折号为 `──`（U+2500），文库转写章亦为 `──`，三段式正则按 `[—─]{2,}` 适配。

### 5.3 Web版专属处理要点（原句纳入）
1. 化名锚点：见第二节第4条（`alias_type: web_pseudonym`，不替换为"涡波"）。
2. Web 版专属剧情：web 版结局与文库版在 16 卷之后差异较大，web 版第 8 章起的"超越于爱，更胜生命"高潮段、第 9–10 章新篇章均为 web 专属，抽取时加 `edition: web_only` 标签。
3. **涡波咏唱的关键演进节点**：从初期《维度·多重展开》索敌，到中期的《次元之冬》系列，再到最终战的《次元决战演算『先谭』/『前日谭』/『再谭』》三连——这条咏唱升级链就是角色卡的"成长轴"，**单独建一条 `incantation_evolution` 时间线条目**。（指导文档另一表述"《Ice Arrow》→《Di·Winter》→《Dimension·Gradient》系列"与本语料实际拼写对应关系在 Phase 3 建链时逐条核对。）

### 5.5 提取正则（原样纳入 + 本语料适配）
```python
import re
# 真正魔法/最终咏唱：『——』包裹的对仗句 + 魔法名
# 【适配】破折号类改 [—─]{2,}；魔法名括号同时覆盖《》与『』
TRUE_MAGIC = re.compile(
    r'[「「]?[—─]{2,}\s*『.+?』\s*[—─]{2,}\s*」?\s*'
    r'(?:[「「]?[—─]{2,}\s*『.+?』\s*[—─]{2,}\s*」?\s*)*'
    r'[「「]?[—─]*\s*(?:魔法|技能|魔弹|咒术|共鸣魔法|真·真正魔法|最终咏唱)?\s*[《『](.+?)[》』]'
)
# 守护者开场白："这·里·，这·xxx·便·是·x·十·层"带间隔点号
GUARDIAN_DECL = re.compile(
    r'这·里·[，,]?这·.+?·便·是·[一二三四五六七八九十百零]+·层'
)
# 普通魔法咏唱：《魔法名》形式（短促，无对仗句）；【适配】追加『』变体
NORMAL_MAGIC = re.compile(r'[《『]([A-Za-z\u4e00-\u9fff\u30a0-\u30ff・\s·\-]+?)[》』]')
# 辞世诗：『xxx』『xxx』连续骈文结构，通常以">"引导或独立段落
DEATH_POEM = re.compile(
    r'『[^』]{4,}』(?:『[^』]{4,}』){2,}'
)
# 代价咏唱标志词
COST_SIGNAL = re.compile(
    r'(作为『代替』|燃烧.{0,6}记忆|支付.{0,8}代价|以.{1,8}为代价|献予|献上)'
)
# 对话行清洗（用于预处理阶段剥离非咏唱内容）
def extract_incantation_blocks(text):
    """从段落块中切出疑似咏唱区段，供人工复核"""
    blocks = []
    for para in text.split('\n'):
        if TRUE_MAGIC.search(para) or GUARDIAN_DECL.search(para) \
           or COST_SIGNAL.search(para) or DEATH_POEM.search(para):
            blocks.append(('incantation_candidate', para))
        elif NORMAL_MAGIC.search(para):
            blocks.append(('normal_magic', para))
    return blocks
```
上线流程：正则只做"候选标记"→**召回抽样**（每章随机抽 3 话人工数咏唱句数对比命中率，目标 ≥95%，未命中样本回填规则）→全部命中块进**人工复核队列**（预计数百条）→落库。

### 5.6 咏唱质检清单（原六项全量，逐项过）
1. **三段式结构完整性**：真正魔法咏唱是否保留了"——『上句』——""——『下句』——""——魔法《名》"的完整三段？"——"破折号与『』方头括号是否原样存在，有没有被正则误吞。
2. **对仗逻辑未被破坏**：守护者最终咏唱的固定语法是"『我眼中的世界(你)是……』"或"『世界(你)……于我……』"的世界/我对照结构，抽取时**不可拆成两句独立存档，必须作为一个 incantation_unit 整体落库**。
3. **间隔点号保留**：守护者开场白"这·里·，这·烈·火·灼·烧·的·山·丘·便·是·第·十·层"中的中点"·"是节奏标记，是守护者身份宣告的仪式感来源，**任何去噪规则都不能删它**。
4. **魔法名双语一致性**：web 版译文中魔法名多为"日文汉字（英文注音）"双语结构，如《冬之异世界（Wintry・Dimension）》，两套名都要入库，`magic_name_jp` 与 `magic_name_en` 分字段存，供 LLM 双向检索。
5. **成长链连贯性**：涡波的咏唱演进是否形成连续时间线，抽卡时能否按"施术者 + 章节序号"串成完整成长轨迹。
6. **代价字段的因果闭环**：每条代价咏唱的 cost 与 effect 是否成对存在、是否与上下文描述一致，防止"只留效果丢了代价"的残缺卡片。

**底层原则（原句）**：咏唱语料清洗不是做减法，而是做分层归档。普通对话可以压缩、场景可以摘要，但咏唱是这部作品的世界观指纹与角色灵魂台词，一旦改写就不再是涡波、不再是诺斯菲。

## 八、Phase 6：本作特殊处理五要点（原句全量纳入）

1. **时间线循环必须分层**。涡波既是"千年前的迷宫创造者"，又是"当下的攻略者"，还与妹妹阳滝、诺斯菲存在跨千年身份重叠。清洗时给所有相关段落打上 `timeline: 千年前 / 千年后 / 千年前后交错` 标签，抽取时**按时间线分别入库**，再在角色卡 `secret_layers` 字段中关联——**切不可在一张卡里把三层真相混为一谈**。
2. **心理独白优先级最高**。本作的精髓是"高强度反转叙事 + 人物心理刻画"。玛利亚从奴隶到圣母玛利亚隐喻、斯诺的"害怕变得认真"、诺斯菲的千年求爱而不得，这些全部依赖心理独白承载。清洗规则上，**独白段落即便再长也不要压缩**，只需标注所属角色与情绪层级。
3. **反转伏笔要单独抽取**。所有"读者当时以为是 A，后期揭示是 B"的段落，用 `[伏笔:角色X]` 标注，抽取时归入该角色的 `plot_hooks`。例如涡波前期的"游戏系统恩惠，理由不明"，后期揭示为千年前的自我布局。
4. **web 版与文库版差异处理**。伪名、部分剧情细节不同。如果做完整知识库，两版并行清洗，用 `edition: web / 文库` 标注；如果只做一版，优先文库版（更完整、更精修），但要标注 web 独有设定以供补充。（本计划现状见第二节第3条。）
5. **群像关系网**。本作人物关系是"千年羁绊网"，不是简单的好友/敌人二元关系。建议用**关系图而非线性列表**存储：涡波—妹妹→阳滝—千年镜像→诺斯菲—名义婚姻→涡波，这种循环结构用图数据库（如 Neo4j）或嵌套 YAML 表达最清晰。

## 九、清洗流程总览（原流程图全量 + 本语料管线）

```

    ↓

    ↓

    ↓

    ↓

    ↓

    ↓

```

## 十、质检与验收标准（原句全量）

1. **质检标准很直接**：随机抽 3 段原文，看清洗后的语料能否完整还原该场景的人物心理与剧情功能；随机挑 1 个角色，看角色卡能否准确回答"这个角色在千年前后分别是谁、对主角意味着什么"。能，清洗就合格；不能，回头补维度。
2. 咏唱六项清单（5.6）逐项过。
3. 术语回归：一～三章抽检《文库转web_字词转换对照表》一致性（维度/连接/次元魔术/──/⋯⋯零回退）。
4. 红线 diff 审计：咏唱正句、独白、`·`间隔点与原文逐字一致性校验。
5. 伏笔完备性抽查：每位核心角色至少核对一条已回收伏笔入 `plot_hooks`。
