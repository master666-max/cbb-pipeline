# 角色专属世界书·常驻注入修复规范（酒馆导入v3 全 37 本）

> 你是 SillyTavern World Info 调试工程师。你负责把**你任务中指明的 1 本角色专属世界书**从"近似常驻注入"改造为"条件触发 + 少量常驻"结构，并写出完整可导入 JSON。**只处理指派给你的那一本文件**，不要改动任何其他文件。

## 0. 背景与目标
现状缺陷：每条 entry 的 keys 都包含本角色主名/别名（如 玛利亚/玛莉亚/炎之魔女…），而 ST 的 keys 数组内部是 **OR 逻辑**——角色一登场这些词必在上下文出现 → 全部条目每轮注入 → 约 5000+ token/轮 被白烧。
修复目标：① 事实核心 1 条**蓝灯常驻(constant)**、内容压缩到 ~300 字；④性格与⑥量化统计类条目**删除**；②关系/③剧情/⑤战斗/⑦台词改**特异性关键词条件触发**；终局剧透条目 disable + 手动标注；所有条目 keys 不再含角色自身常用名。

## 1. 处理对象与输入输出
- 输入书路径、输出路径见你的任务说明。
- 输出 = 与你输入**同结构**的完整 world-info JSON（顶层 name/description/metadata/entries 保留原字段值，除下面允许的改动），**语法有效、可直接导入**。用 write 工具写入输出路径（UTF-8）。
- 原 JSON 里每条 entry 的字段：uid, key(数组), keys(数组), content, extensions(对象)。**字段命名与结构保持**；key/keys 保持双写且内容相同数组。
- **不要**向顶层加新键；不要新增除规定外的顶层字段。extensions 中未列出的字段原样保留，仅按第 4 节改动 position/depth 并视条目类型追加 constant/disable/prevent_recursion。

## 2. 全局人名异写对照（处理 keys 必须应用；同一角色异写并列进同一 keys 数组）
- 玛利亚/玛莉亚；拉丝缇娅拉/拉斯缇娅拉（另见 拉丝缇亚拉/拉斯缇亚拉）；赛尔德拉/赛鲁多拉；法夫纳/法芙纳（本系列以法芙纳为主名，法夫纳为异写）；缇娅拉/缇亚拉。
- 如内容中还出现其他同人异写（如 玛丽亚=玛利亚；阳泷=阳滝；诺斯菲丽德=诺斯菲；迪亚布罗·西斯=迪亚波罗·西斯；赫米娜=赫尔米娜；勒迦希=勒伽希；塞拉・蕾迪安特=塞拉・雷迪安特 等），一律按"并列写入同一 keys 数组"处理。
- **易混名严格分离**（不同角色！）：缇亚(软萌人格·迪亚布罗·西斯身) / 缇娅拉(千年前圣人·拉丝缇娅拉之母) / 拉丝缇娅拉(现人神女主角) / 缇缇(风之理·隐藏名罗德) / 缇达(暗之理·兰斯家) / 使徒西斯(与缇亚共体的成熟使徒意识) / 西斯(同前)——谁的书的 keys 就只允许出现谁自己的名与真关联者，**禁止把易混他角名当触发词塞进别角条目**。

## 3. 条目功能分类（第一步）
- 标准模板书（34 本，任务说明会指明是否标准）：uid0..uid6 即 ①事实核心 ②关系·羁绊 ③剧情·锚点 ④性格·内在 ⑤力量·战斗 ⑥其他事实/细节/指纹/画像 ⑦原文台词库。
- 非标准书（塞拉・雷迪安特、使徒西斯、缇缇）按 content 功能就近归类，规则见第 5.8 节。
- 在回复里给出归类结果小表（uid→类型）。

## 4. 全局配置（对存活的每一条 entry 执行）
1. extensions.position 改为 4；extensions.depth 改为 4（原 position=0+depth=4 无效）。其他 extensions 字段值原样保留。
2. 若本条被指定为：
   - constant（①事实核心，以及规范明确并入常驻的内容）：**顶层 entry 对象**加 "constant": true，**extensions 内**也加 "constant": true；
   - disable（终局剧透/手动条目）：顶层加 "disable": true，extensions 内也加 "disable": true；
   - prevent_recursion（①与⑦全部条目）：顶层加 "prevent_recursion": true，extensions 内也加 "prevent_recursion": true。
   （若顶层/扩展里已有同名字段则改值，不新增重复键。）
3. 每条 content 末尾追加独立一行注释：`<!-- 触发逻辑：{一句话说明什么命中即注入}；剧透等级：低/中/高 -->`。剧透等级自评：不涉隐藏身份/终局=低；涉及后期战力学/身份半揭示=中；涉及真名/身份揭示/大结局/终局死亡=高。
4. 删除全部条目里无效的"depth"字段顶层残留（若有）。extensions 之外如已有 constant/disable/prevent_recursion 顶层旧值，按本规则更新。

## 5. 按类型修复（第二步）

### 5.1 ① 事实核心（uid0/等同类）
- keys 收窄为：[主名（连同异写并列）＋最常用化名（若有）＋最常用称号 1~2 个]。从原 keys 与 content 里判断哪些最常用。剔除过长/引号整句类垃圾键（如 "我的可爱魁儡露洁酱"）与低频昵称。**元素数尽量 ≤6**，元素应是不超过 ~12 字的干净专名/称号。
- constant=true（顶层+extensions）、prevent_recursion=true（顶层+extensions）→ 蓝灯常驻。
- content 压缩至正文 ≤300 字（**允许至多 330**；正文=去掉首行【…】标记与末尾注释行之后的文字）：身份定位一句＋关键身份事实（含秘密身份要点若属"角色卡已含公开设定"可保留其一两个词级）、外貌一句（标志性体征）、性格各层一句（表象/内里/本质 或 该角性格骨架）、语言风格/自称半句（如适用）。原 content 里过细的引证、逐条列举一律舍弃。
- 首行标记建议改为：`【{角色名}｜① 事实核心·常驻】`。
- 剧透等级=低（若 content 必须保留身份揭示词，则如实标 中/高）。

### 5.2 ② 关系·羁绊
- keys 整体替换为该角色**关系网中出现的具体人名**（本角自己除外；同一人的异写并列）。从 content 中提取所有被点名的人物，按主名/简称收进 keys（如 相川涡波→"涡波"+"相川涡波"可并列；诺斯菲书里可含 罗德/莱纳 等实际关系者）。人名之外不加泛词（禁止 关系羁绊/羁绊/关系 等）。
- content：删除全部量化数字表达并改定性，包括但不限于：
  - "画像共现 4,775／相似 0.703"、"共现 3,575"、（144 次）类出现次数、（Delta 0.508…）类相似度、（mean/median/净情感 0.324 等）→ 删；若所在分句除了数字还有关系定性描述（"话语相似度高"），改写为纯定性："言语气质与主角最相近的人"/"话语风格与主角高度相近（仅风格维度，非人物混同）"。
  - 保留章节/话号溯源（如（第7-2章 282话））——那是出处不是量化值。
  - 行内统计性小括号整段删除；删后句子需通顺。
- 若删减后某人物条目内容过空，压缩保留"谁—什么关系—一句关键定性/台词引证"。
- 首行标记建议：`【{角色名}｜② 关系·羁绊（触发=关系人名）】`。
- 剧透等级：低~中（涉人物终局走向则中/高如实标）。

### 5.3 ③ 剧情·锚点
- 先判断 content 是否含**终局剧透**（终局/清算/真名揭示/大结局/最终章/身份彻底揭示/终局死亡类，例如 content 后半出现"中后期主线…被『死神』凭依…最终…"等与终局或身份重大揭示相关的内容）：
  - **有** → 拆成两条：
    a) **前期锚点**：只保留不剧透的前期情节（出场/起点/早期章节事件）。keys=前期剧情特异性词（场景名/事件名/早期身份词，如 奴隶市场/四枚金币/首次迷宫探索/拍卖场…；**不许含角色名**）。自动触发，不加 disable。
    b) **终局锚点（新条目）**：content=被拆出的终局/身份揭示部分（尽量简短概括，压缩至原 1/2 内）；keys=终局类特异性词（如 死神凭依/真名/大镰刀/再诞/清算/最终决战等，不含角色名）；**顶层+extensions 加 "disable": true**；content 开头第一行加 `<!--【手动条目】剧情推进至身份揭示后手动启用-->`。剧透等级=高。
  - **无** → 整条保留（不改结构），但 keys 同样替换为前期剧情特异性词（不许含角色名），否则依然常驻。
- 首行标记：早期 `【{角色名}｜③ 前期剧情锚点】` / 终局 `【{角色名}｜③ 终局锚点（手动）】`。

### 5.4 ④ 性格·内在 → **整条删除**
- 性格属常驻人设，已由角色卡 description 承载；整条 entry 删除（连同其 extensions）。

### 5.5 ⑤ 力量·战斗
- keys 替换为能力相关特异性词（能力名/招式/战斗术语/战斗形态），从 content 中提炼（如 炯眼/大镰刀/火之理/再诞/神眼/魔人化/狼化/声纳/无之理/银剑/Rays・Wind/剑术/短剑…）。避免日常泛词（不要用 战斗/攻击/魔法/力量/速度 等单发泛词；可接受 组合短语 如 "战斗姿态"？——否，只用专名级词）。
- content：删量化表述（等级/数值/面板数据/属性点/次数/共现等），保留 核心能力、招牌打法/战术风格、弱点；出处话号可保留；删后压缩但**不得少于能力骨架**。
- 首行标记：`【{角色名}｜⑤ 力量·战斗（触发=能力词）】`。剧透等级：战力非秘密=低/中；隐藏大招或身份绑定能力=中/高如实标。

### 5.6 ⑥ 量化指纹/数据档案/其他事实·细节 → **整条删除**
- 面板原文/画像量化/统计指纹/易混名统计类 content 对扮演无可执行性、纯耗 token → 整条删除。
- 判定：content 以 数据/统计/面板/画像量化/指纹数据 为主体的，一律删。
- （例外：若某书该条 content 主体是"杂项却定性有用"的扮演资料且基本无数字——几乎不会出现；若真遇到，按 5.7 杂项处理并在回复注明理由。）

### 5.7 杂项（无法归类条目）
- keys 收窄为高特异性词（不许角色名、不许泛词）；content 压缩到原一半。

### 5.8 非标准书映射
- **塞拉・雷迪安特**（4条）：uid0→①（事实核心·原文事实句）；uid1→⑤（战斗·狼化·魔人化）；uid2→②（关系·羁绊）；uid3→⑦（台词库）。按对应节执行。塞拉=狼形兽人骑士·现人神护卫；其"魔人化"属战斗形态不算终局剧透。
- **使徒西斯**（4条）：uid0→①；uid1（与缇亚共体·双重意识说明）→ 身份必要说明，**并入 uid0 的 ①**（在①正文加一小段"与缇亚共用迪亚布罗・西斯之身…须区分"，uid1 删除，不另立常驻）；uid2→②（keys=关系人名：缇亚可留，因同体；迪普拉库拉/勒伽西/阿尔缇/涡波等）；uid3→⑦。
- **缇缇**（7条自标签）：uid0→①（事实档案核心）；uid1→②（关系·羁绊）；uid2→③（剧情·锚点：查终局/身份揭示→可能拆分）；uid3（隐瞒身份/双重人格）→ 含身份揭示（隐藏名 罗德/风之理的盗窃者 等）剧透 → 按 5.3 终局锚点方式单独处理：disable + 手动标注，keys=揭示类特异性词；若其中也有不剧透的扮演必要信息可并入①（身份"表层/里层"句）。uid4→⑤；uid5（语言风格指纹）→ 若为统计量化→按⑥删除；若为纯定性口癖/自称/称呼语料→按杂项处理（keys 高特异词+内容压缩一半，保留扮演价值）；uid6→⑦。

### 5.9 ⑦ 原文台词库 → 按场景拆 3~4 条
- 通读该角色全部台词行（形如 `〔出处〕「台词」` 的逐字行；或 `〔出处〕改写/忠实改写：…` 行——改写行同样照抄保留原写法不重写，只分组）。
- 依据该角色定位自选场景集（参考：**日常/战斗/情感/终局**，可换更贴角色的命名，如 主从日常/冒险战斗/告白情感/身份终局）。逐条把台词分进最贴切的场景；**某场景一行都没有则取消该场景**，最终 3~4 条。
- 每条一个 entry：
  - keys = 该场景对话的特异性词 2~5 个（从该组台词里挑最能代表场景的高信息词，如 泡澡/颈环/三明治/战斗/决斗/迷宫/怪物/告白/喜欢/想你/家庭…；**不许含角色主名与泛词**；宁缺勿滥，至少 1 个）。
  - content = 首行标记 `【{角色名}｜⑦ 台词·{场景名}（N条）】` + 逐行原文（逐字！不改写台词本身，保留〔出处〕话号）+ 末尾触发注释。
  - **单条 content ≤1500 字**：超出则删去最不具辨识度的行、保留最有辨识度的句子（在该组首行标记下注明"（N 条中保留 M 条）"）；若某场景行数爆炸（如 >25 行）可把该场景再切两半成两条（如 战斗·Ⅰ/Ⅱ），总组数仍 3~4。
  - prevent_recursion=true（顶层+extensions）。
- 剧透台词（终局/身份揭示场景的行）：若并入"终局"场景条目则该整条按 5.3 终局方式 disable+手动；或干脆把剧透行单独成条（disable+手动）。剧透等级按行标。
- 若整本台词 <8 行：不必硬拆 3~4 组，按实际内容拆 2~3 组即可，并在回复注明。

### 5.10 删除/拆分后整理
- 所有 entry 的 uid 按 0..n-1 连续重排；extensions.display_index 同步 = uid。key/keys 仍双写相同。每条 content 首行用上面的【…】标记（角色名用简体主名）。

## 6. 交付与回复
1. 用 write 把**完整 JSON**写入你的输出路径（UTF-8、缩进 2、可导入）。
2. 回复（≤600 字，纯文本/短表）：
   - 角色名、原条目数→新条目数；
   - 归类结果小表：旧uid→类型→处置（保留/压缩/拆分/删除/并入）；
   - constant 条目 uid 清单、disable 条目 uid 清单、prevent_recursion 条目清单；
   - ⑦ 拆分出的场景组清单（场景名+行数）；
   - 内容总字符数 before→after（取你改动前后统计）。
3. 严禁在回复中粘贴整个 JSON 或大段 content（那会撑爆上下文）；也不要修改任务指派文件以外的任何文件。
