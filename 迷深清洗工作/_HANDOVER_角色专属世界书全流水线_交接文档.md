## 3. 补丁协议（后续每个新批次都必须遵守的规则）

每批用户会发一段 `你是 SillyTavern 世界书终X工程师（Bn…）` 提示词，含：
- 【通用自检】五项：
  ① root 层 position=4、depth=4、prevent_recursion=true 逐条核对；extensions 内 position 非 4 者改 4；
  ② 全书 constant:true 条目数必须为 0；
  ③ disable 条目 root 与 extensions 双层在位，content 开头有 `<!--【手动条目】…-->`；
  ④ 每条 content 末行有 `<!-- 触发逻辑：… -->`；标题括号内条数与实际引文行数一致；
  ⑤ 引号外 法芙纳/玛莉亚/拉斯缇亚拉/缇亚拉/■■■■■/P06/簇N/关系映射/语境锚/（改写示例）=0 命中。
- 执行纪律（各批次一致）：
  - 只执行与本书顶层 name 匹配的 ●项；未列条目/字段/台词一律原样保留（不重写、不润色、不删台词、不改 keys，除非清单指明）。
  - 幂等：原文已不存在或已改毕 = 已完成/跳过；重复执行不得二次改动。
  - 引号「」与“”内逐字台词一律不动（除非注明"跨书统一/纠错"，如希丝→西斯）。
  - uid 顺序不变；不新增不删除条目（除非清单明确要新建/删除）。
  - 交付：用文件写工具把修复后完整 JSON 覆写回原绝对路径（UTF-8 无 BOM、语法有效、可直接导入），回复 ≤8~12 行摘要（勿全文粘贴防截断）。
- key/keys 镜像惯例（本库特有）：entry 同时有 `key` 与 `keys` 两数组，默认要求镜像一致；凡清单只写"keys 删/补 X"而旧 `key` 未同步时，主代理应按库惯例追加同步（历史多次裁定如此）。

### 已确立的主代理裁定判例（新批次如遇同类可循）
1. 「希丝」＝「西斯」转录误写：全书（含引文）纠错；keys/key 同步删组合键（如"希丝・迪普拉库拉"整项删除）。
2. key 旧镜像与 keys 不一致 → 追加同步使 key==keys。
3. 源库可考的台词关键词（如艾尔米拉德"夺回女儿"，web版 L12097 可考）→ keys 保留并在摘要注明出处。
4. 终局/高剧透信息一律归 disable 条目（disable 双层 + constant:false + content 首行 `<!--【手动条目】…-->` + 剧透等级改高），普通条目只留"见禁用条目"指针。
5. content 中引文归属标注格式：〔说话者·章话〕前缀式（如〔涡波本人·第五章…〕/〔西斯视角·第五章〕），跨书人物姓氏/人名以"主用字书"为准统一（如 赛尔德拉·库因非里翁、诺伊·爱丽·利伯罗尔）。
6. 角色专属书文件名与顶层 name 不完全一致属正常（法芙纳文件/法夫纳 name；塞拉・雷迪安特；缇娅拉在库中既作独立角色也作为拉丝缇娅拉等的对照）。

## 7. 通用操作备忘（zcode 环境）

- 读取 JSON：先探测 BOM(U+FEFF) 再解析；正文以 \n 分隔（注意 content 内是转义 \n）。
- 校验 JSON：`ConvertFrom-Json` 或 JSON.parse。
- 关键一致性断言（写完必查）：JSON 可解析、无 BOM、uid 顺序不变、uid0 root/extensions constant=false、disable 双层、key==keys、每条末行 `<!-- 触发逻辑 -->`、全书「希丝」=0。
- 合并审查文件（幂等、逐字节）：
  - 按文件名 Sort-Object Name 取 37 本；
  - 前 19 本→第1部分，后 18 本→第2部分；
  - 每个文件前插一行 `===== 角色专属世界书_X.json =====` + 换行，文件本体 ReadAllBytes 原样拼接；
  - 写 UTF-8 无 BOM；SHA256 回验（内存重建流 == 落盘字节）。
- 输出防截断：摘要 ≤8~12 行，勿把完整 JSON 贴回对话；如需交付大文件用文件工具写盘。
