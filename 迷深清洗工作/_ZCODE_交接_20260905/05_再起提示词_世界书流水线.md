# 再起提示词 · 角色专属世界书流水线(ZCODE)

> 用于用户下发"角色专属世界书 补丁/新批次 Bn"任务时。全项目基线见 04_再起提示词_全项目.md。

## 权威资产(只读/可改边界)
- **世界书 = ②只读资产**(不得改): `知识库/分析/酒馆导入v3/世界书/角色专属世界书/角色专属世界书_<角色>.json`(37本, uid0-9 schema)
- **角色卡 = 可改(有备份)**: `知识库/分析/酒馆导入v3/角色卡/*_card.json`(36张, 文件名 v2 全名, 内部 name=canonical)
- 备份: `酒馆导入v3/_备份_角色卡精修/`(每卡覆写前)
- 审查合并文本: `酒馆导入v3/B*后_角色专属世界书_审查合并_第*部分.txt`(最新 B10后;B11后未合并)

## 执行协议(用户每下发一批 Bn 补丁就执行一次)
1. 读透用户批次消息 → 提取「通用部分」+「各书专属 ●项」。
2. 主代理组装每本提示词 = 通用部分(角色句+通用自检五项+输出交付要求) + 按顶层 name 分发的专属 ●项。
3. 小批(≤2-3本)主代理直接做;大批用子代理,**严格串行单子代理**(每次仅1个在飞,等其完成通知/结算后再启动下一个;失败先查文件是否已落盘再决定是否重跑,API 不稳可重试)。
4. 每本完成: 读JSON(去BOM)→ 只执行匹配●项 → 覆写回原绝对路径(UTF-8无BOM/语法有效/uid顺序不变)→ 五项自检 → 回复≤8行摘要(勿贴全文)。

## 五项自检(每本必过)
① JSON 合法可解析 ② UTF-8 无 BOM(首字节 0x7B) ③ uid 顺序 0..N 不变 ④ uid0 constant=false、disable 双层正确 ⑤ key==keys、条末触发逻辑注释在。
(附加: 全书「希丝」必须=0 → 用西斯)

## 子代理续接纪律
- 子代理会话可持久,中断后 **send_message 原地续接**(从断点继续,勿重做已完成部分)。
- 读大 JSON 用 pwsh(ConvertFrom-Json 或 raw),勿用 read 读单行长 JSON(会截断)。
- 子代理回复 [DONE-角色名]/[FAIL-角色名] + ≤8行;无 FAIL 则只按结算推进队列。
