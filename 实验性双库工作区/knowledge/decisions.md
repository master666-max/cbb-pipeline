### D-003 / 2026-09-03 / 已完成任务的体系文件采用「引用不搬移」归档方式

- 决策：「双库体系文档编制」任务归档时，交付物本体保留在根目录，归档目录只放 README + HANDOFF 记录其位置（manifest 方式）。
- 理由：`AGENTS.md` 与 `knowledge/_index.md` 常驻引用根目录路径，搬移会断链；提示词 Phase 2 本就允许「大文件不搬，只写 manifest 说明位置」。待用户裁决【待确认】1 后可改为实体搬移并同步改引用。
- 否决的备选：直接移入 archive/2026/09/（引用全断，除非同步更新所有引用方）。
- 实例：archive/2026/09/dual-library-docs/README.md

### D-001 / 2026-09-03 / 双库体系从纯 Markdown + 索引起步，不引入向量数据库

- 决策：知识库与工件库全部采用结构化 Markdown 存储，检索依靠 `_index.md` / `_INDEX.md` 加 description 关键词匹配。
- 理由：库规模在 500 条经验以内时，Markdown 可读可编辑、Agent 可直接修改、可用 Git 做版本管理、零运维；业界反直觉共识是千条以内结构化 Markdown 的能力传递优于向量库 RAG。
- 否决的备选：Markdown + 轻量向量索引（500–5000 条阶段再考虑）、向量库 + 元数据库（>5000 条且多 Agent 共享时再考虑）。
- 实例：`双库自进化体系·建库提示词.md`「附：存储选型速查」

### D-002 / 2026-09-03 / 本任务（建库）为工作区首个任务，跳过历史挖掘阶段

- 决策：Phase 0 侦察确认工作区仅含两份体系文件、无历史任务与对话日志，故跳过 Phase 2（挖掘历史），直接搭骨架并建立闭环。
- 理由：无历史内容可挖掘；两份体系文件是系统配置而非任务工件，保留在根目录作为常驻入口文件。
- 实例：`knowledge/trajectories/2026-09-03/task-001-建库.md`
