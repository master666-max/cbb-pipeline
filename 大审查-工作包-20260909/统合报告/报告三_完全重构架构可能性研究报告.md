## 一、核心裁决：完全重构要不要做、以什么形态

### 裁决 1：greenfield 推倒重写——**不采纳**（X）
证据链（四家产出内部即可完成论证）：
1. **豆包自家反方**：深度探索明说「v3 的设计直觉是对的（双平面/永不删除/慢车道=事件溯源与治理雏形），问题是工程实现不是设计理念」「v4 是地基不是天花板」——与其自家 greenfield 工单构成内部矛盾，反方论据更硬。
2. **Qwen 自杀条款**：「M2 不能证明 v3/v4 golden 行为等价即终止重构，回归 v3.10-AR」——greenfield 的行为等价证明在承诺期内不可控。
3. **混元第三条路实证**：事件溯源做实=数据模型层重构（18.5 人日），基于 120 行可运行原型——「关键收益可增量获取」被演示。
4. **GLM 载重墙**：80% 独特价值集中在四件事（真相源倒置/强制宪法/效用账本/MCP 面），其余可延后——「完全重构 80% 的价值不需要完全重构」。
5. **报告一实证侧写**：19 条属实缺陷全部是工程层（漏刷根/查重单目录/退出码），**没有一条指向公理 A-G 设计错误**。

### 裁决 2：真正收敛的「重构」= 数据模型与信任模型层——**四家独立趋同**
- **事件溯源做实**（审计事件携带完整 payload，memory/state/ledger/渲染件全部降为可重建投影）：GLM 真相源倒置＋Qwen RF-D1/H2＋豆包 CQRS＋混元 V4-02——**四家零沟通独立收敛，本轮全部产出中最强的一个信号**。
- 现状缺口三家同证：审计链「entry:id → dest」不含内容——「真相源里没有真相」（GLM）／「账本重放不出 memory」（Qwen）／「audit 只是指针日志」（混元实测）。
- 收敛的连锁收益（GLM 论证最全）：灾难恢复=重放、同步=日志传送、多写者=追加、双时态免费、时间旅行调试。
- **取舍已明**：GLM v3.10 D-1「不做重建」（审计面轻量优先）vs GLM v4.0-1/混元/RF「做实」——GLM 自我推翻的理由（前提变了：个人规模全量载荷几十 MB）成立；混元原型实测 300 条目 merkle 0.005s 背书。**采纳做实，增量路线（混元 18.5 人日），非 greenfield。**

### 裁决 3：信任模型升级——**双钥签名锚定采纳（分阶段）**
- 现状共识（三家同证）：`--yes` 是 agent 自加的 flag，公理 F 宣称「人类令牌」机制上零强度；THREAT_MODEL ③档「明示不防」诚实但 L8 gate 宣称未对齐。
- 路线：v3.9 采混元「中」档（一次性 token 文件+核销+level/package 绑定）→ v4.0-SEC（Qwen H3）双钥签名检查点（写入钥 agent 追加/锚定钥人侧签名）→ 终态「信任从信任进程收窄到信任一把钥匙」。
- **诚实边界必须写入不可删**（Qwen 原文）：锚定钥失守=全失守；能力是收窄信任面，非绝对免疫。

### 裁决 4：形态选择——**A（可审计内核）+B（认知 OS）甜蜜点，C（记忆协议）只留门不建设**
- GLM 三终局论证 + 豆包深度探索「本地优先」+ 混元 V4-13 不做清单——三家独立收敛于「不做托管/多租户/分布式」。
- 例外：GLM D8 MCP 面（engine 操作与 MCP tools 近 1:1）被 GLM 列为载重墙第四件、豆包深度探索列为留接口——**MCP 面作为「按可外带设计」的唯一例外保留**。

## 二、完全重构的图纸价值：REGISTRY 兑现

- **GLM「图纸兑现率」论**：REGISTRY 33 条已构成认知架构完整图纸（记忆分层/索引/时间/多 agent/整合/意识/情绪/反思/自改进治理），现有实现是沙盘模型，重构是按图施工；图纸里唯一没人做全的是治理与可证明性——恰是本体系自加的差异化。
- **豆包引用总表修订版定量**：T1 代码层落地 12 / T2 内容体层 13 / T3 参考挂账 8——量化了「引用了≠实现了」。名不副实显式改写（A1/A5/A8/A12/A14/A18/A19）。
- **GLM v4.0-3 清偿纪律**：每篇论文五字段（内核/采纳面/**拒绝面**/工程规格/验收判据），「没有拒绝面的落地是抄写」；卡 8 拒绝面最大号：「神经科学证据不能为工程方案背书——隐喻当机制是这个领域最流行的学术诈骗」。
- **裁决**：三份合流为 v4 的「论文清偿章程」——引用必须带判据，判据缺失不落地。

### 3.2 独立趋同（跨模型最强印证）
1. **双门/判据不可见**：GLM 双判据分离+隐判据哈希 ≈ Qwen 保证四+判据人侧 ≈ 混元双门+元层冻结 ≈ 豆包七维度——objective hacking 防线的四家同构。
2. **元层不可自改**：GLM「判定核不能成为自己判定的对象（塔斯基）」≈ 混元「系统无法修改评判自己的尺子」≈ Qwen H4 律法数据化+人侧签名 ≈ 豆包不可演化核心锁定——四家独立得出同一原则。
3. **演化分级**：GLM E0-E5 ≈ 豆包 E1-E5（自主性刻度而非全有全无）。

### 3.3 混元实验的独有高价值结论（方向采信，数字 C 级）
- **E81（全场最高价值）**：judge 看文本时系统学会堆表象权重（自报 +2.89 / 真实 −0.008），**锚定审计零触发**——「外部参照若经同一有缺陷观测通道获得，不构成外部性」。公理 G 的严格形式：测量通道有问题时，连「测不出差异」都测不出来——必须周期性更换测量通道（人直接判真值）。
- **E81c**：真值抽样每 2 代 = 无审计的 3.8 倍收益；真值验收（10-20 单位/次）将成为注意力开销主体——EV-16 的 150 预算门槛需上修。
- **E80 复合灾难**：≥3 危险并存时修正架构 −0.26 比 v3 −0.11 更差——诚实负结果，红线候选。
- **12 条防回退清单**：「让机制更聪明的改良全失败，测量已有可观测量的全成功」。
- **对本体系的直接映射**：锚定审计（Merkle）是密码学通道，不受 judge 污染 ✓；但**锦标赛效用信号/reflect 裁决/referee 评审是 LLM judge 通道**——E81 教训直接适用：EV-19 真值抽样/EV-20 judge 通道独立性审查必须进 v4 设计。

## 四、分歧与风险登记

1. **单文件存废**：GLM zipapp 退役 vs Qwen build.py 打包 vs 混元 zipapp——**采 Qwen/混元**（保留分发形态，开发模块化）。豆包 monorepo+pydantic 列 v5。
2. **真相源倒置的代价**：GLM v3.10 D-1 诚实列出（链膨胀/CAS 去重/投影维护）vs 收敛方（正确性优先+规模实测非瓶颈）——**接受代价**，但保留 `engine compact` 快照事件缓解（混元）。
3. **完全重构的文化风险**（GLM 风险二，全场独有）：「现有代码最珍贵的不是架构，是元纪律——每行注释对着一个历史事故编号；完全重构天然摧毁考古层。对策：事故史先提炼为 ADR 库与性质测试，让纪律以可执行形式存活」——**采纳为重构前置条件**（C-007/Y-001/J-003/N-001 等事故编号全部有对应的攻击测试在 run-tests 中存活，已部分满足）。
4. **agora 方法学警告**（豆包独立实验）：ρ=0.2 时 51 人≈4.6 独立人——**本次四家大审查若共享训练分布，独立结论数 <4**；顺序公开劣于同时封板——本次流程（背对背+主审仲裁）符合，后续保持。

## 六、一句话终局
