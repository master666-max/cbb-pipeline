## 1. 实验目标与假设

### 1.1 总目标

论证"agent 记忆库自演化引擎"这一架构在真实检索引擎上的**可行性、必要条件与代价**——不是纸面推演，而是让变异真实发生在 bootstrap_v3.8.2 的检索路径上，用留出集/审计集双尺子量出收益与风险。

### 1.2 四个能力轴（用户点名要求）

| 轴 | 含义 | 承载实验 |
|---|---|---|
| **存储** | 写入路径正确性：schema 校验、审计链、并发一致性、可重建性 | X1、X4 |
| **更新** | 法层参数（检索权重/过滤开关）能否自主变好而不作弊 | X2、X3 |
| **遗忘** | 失效条目 TTL 出仓零误伤；目标切换后旧能力保留（防灾难性遗忘） | X1、X2c |
| **重组** | 反思合成（多条→规律条目）后检索不退化、信息密度提升 | X2d |

### 1.3 可证伪假设

| # | 假设 | 证伪条件 |
|---|---|---|
| **H1 有效性** | 元层冻结（金标任务集、K=5、效用函数人侧固定）时，自演化组（G4）在**审计集**上的检索效用显著优于静态基线（G0） | 配对 8 种子差值 bootstrap 95% CI 上界 ≤ 0 |
| **H2 门控必要性** | 存在伪特征场景下，无门控组（G2）自报进步但审计集真实退化（Goodhart 复现）；两级门控组（G4）不采纳伪特征 | G2 真实退化不出现，或 G4 采纳伪特征 |
| **H3 一致性保持** | 全演化周期内，库的四平面（memory/audit/ledger/state）对账一致；事件流重放重建与原库条目集合完全等价 | doctor 报出未解释差异，或重建 Jaccard < 1.0 |
| **H4 遗忘可控** | TTL 出仓零误伤；目标切换后档案对旧能力保留 ≥ 单一最优档案，且 ≥ 起点能力 90% | 出仓误伤 > 0，或保留比劣于对照 |
| **H5 重组无损** | 反思合成入库后审计集 recall@5 保持 ≥ 98%，条目信息密度（单位条目覆盖的任务数）不降 | 保持率 < 98% 或密度下降 |
| **H6 资源可行** | 每配置 × 8 种子全程 wall time ≤ 30 分钟（本机量级，参照报告 300 条目 merkle 0.005s 的实测），昂贵评估次数 ≤ 报告同类实验的 1.5 倍 | 超限且无法通过减代数修复 |

**总可行性判据（go / no-go）**：H1 与 H2 同时成立 → "自演化引擎可行且护栏必要"成立；H1 成立但 H2 在危险场景边缘 → 结论限定为"干净环境可行，危险环境未证实"，不外推（报告 E41 方法论警告的纪律）。

## 3. 关键设计决策：法层适配器（可操作性的核心）

**问题**：豆包源码 `_rank_entries`（源码 L898–928）的打分权重是**硬编码字面量**：

```python
scored[f.stem] = (kw_hit * 3 + c_hit + e.get("importance", 0) - 0.1 * age_days, e, c)   # L919
# links 一跳扩散：被命中条目向 links 目标传播 s × 0.5                                    # L921-927
```

演化要变异的正是这些权重（`w_kw, w_content, w_imp, w_age, filter_zero`——报告 E1 让系统自己找到 `w_imp↓` 与 `filter_zero=1` 两个改进）。方案：

1. **参数化重实现**：`evocore.txt` 按源码逐行语义重实现 `_rank_entries`（含 links ×0.5 扩散、`t_invalid` 过滤、坏时间戳降级），权重改为参数。**这不是偷懒，是法层的物理形态**——真实部署时法层就是检索参数。
2. **等价性门（X0 的硬门槛）**：默认参数 `(3, 1, 1, 0.1, 0)` 下，参数化重实现与 `m._rank_entries(lib, q)` 在同一真实库上的** top-20 排序逐条一致**（允许分数因浮点次序微差，排序不得变）才算适配通过；不一致即停，修到一致才进 X2。
3. **真引擎不缺席**：库本体（写入/审计链/账本/doctor/retire/eval 基线）全部走豆包源码真实路径（`m.cmd_engine(...)`）；适配器只接管"检索打分"这一层。每代演化产出的配置写回 `sandbox/lib-*/memory/` 的真实条目与 `state.json`，使 doctor/guard/Merkle 全程参与。

## 5. 各实验详细方案

### X0 · 环境自检与适配器等价性（半天，全部后续实验的前置门）

1. 校验豆包源码 sha256 前 16 位 = `ef2c645aea64fb9e`。
2. `py -X utf8 大审查/豆包/bootstrap_v3.8.2_补丁后.py run-tests`，如实记录通过数（报告代码审查指出自测有硬编码"全绿"缺陷 P0-1，此处**预期它可能静默中止**——记录现象本身即数据，不修它）。
3. absorb：以 `knowledge/skills/library-bootstrap/` 为源树跑 `cmd_absorb`，`--data` 指向 `sandbox/pkgdata/`，产出 `bodies.json`。
4. 冒烟安装：`install L2 --target sandbox/lib-static --yes --data sandbox/pkgdata`（L2 带 golden 评测，无 L8/L9 慢车道干扰）。
5. 写入 10 条种子条目 → `engine retrieve` / `engine eval` / `engine doctor` 走通。
6. **等价性门**（第 3 节）：参数化重实现 vs `m._rank_entries`，top-20 排序逐条一致，输出 `data/x0_equivalence.json`。
7. 负对照：故意把重实现的 `w_kw` 改 3→4，断言排序**必须**改变（防"两个实现其实都没起作用"的假等价）。

**判据**：步骤 6 全绿 + 步骤 7 翻转 → X1/X2 放行；否则修适配器，禁止带病进 X2。

### X1 · 静态基线组 G0/G1（存储 + 遗忘轴，机时约 1–2 小时）

1. 8 种子各建一库（真实 `install` + `append` 80 条目）。
2. **存储一致性探针**：
   - `engine doctor` 五态对账逐项记录（memory/audit/ledger/审计链/state 根）；
   - 并发探针：8 进程并发 `engine append`（importance=5），记录 `importance_accum` 终值（预期复现丢更新，量化它）；
   - 截断探针（只读副本上做，不污染主库）：删 audit 尾部行 + 重算 Merkle 更新 state → `doctor` 是否检出（预期检不出，复现报告 2.3）。
3. **遗忘轴**：给 10% 条目写 `t_invalid`（过去日期）→ `engine retire` → 核对：应出仓尽出、不应出仓零误伤、attic 可回溯。
4. G1：手填报告 E1 的演化终态参数，跑同一任务集，得"人工调参上限"参照。
5. 全程 `engine eval` 逐代记录 recall@5 / MRR → `data/x1_static.jsonl`。

### X2 · 自演化主实验 G2/G3/G4/G5（更新 + 遗忘 + 重组轴，半天）

演化循环（`evocore.txt`，对齐报告 5.2 修正架构）：

```
每代：从档案选亲本（Pareto 前沿优先）→ 变异 1 个法层参数（×0.5/0.7/0.85/1.2/1.5/2.0 或 filter_zero 翻转）
  → 廉价筛选：训练集快速分 < 亲本 − 3×tol 直接 reject（只淘汰，不采纳——红线 7）
  → 档案准入（宽松）：Δ > −tolerance 即入档（Pareto：效用 × 档案规模 双目标）
  → 主线晋升（严格）：训练集配对 > margin 且 留出集配对 > margin 且 bootstrap(1000) 95% 下界 > max(0, margin)
  → 晋升即把新参数写入真实库 state.json（走适配器），doctor 随行
每 5 代：留出集消耗记账；G5 加锚定审计（对冻结锚定样本重测，一致率 < 0.85 → 冻结 + 报警）
跑 25 代 × 3 变异/代（报告 E1 同规模），8 种子
```

- **X2a（更新轴）**：G2/G3/G4/G5 各自终态的**审计集**效用 vs G0/G1；记录系统自报（训练集）与真实（审计集）的差——这个差本身就是 H2 的数据。
- **X2b（防作弊）**：注入贪婪变异（`w_imp=10` 堆权重），验证元层冻结下刷分不可表达（复现报告 E2）。
- **X2c（遗忘轴 · 灾难性遗忘）**：先优化目标 A（命中）20 代，切目标 B（省无关条目）20 代，测档案中 A 的最高保留（单一最优档案 vs Pareto 档案对照——复现报告 E16 的 0.547 vs 0.719）。
- **X2d（重组轴）**：批量写入 30 条 → 触发反思（`importance_accum ≥ 50`，TUNABLES 现值）→ `engine reflect` 出素材包 → 以源码 `REFLECT_SYNTHESIS` 原文提示词由 harness（我，固定提示词=控制变量）合成 2–3 条 R-xxx 规律条目（links 挂依据条目）→ `engine append` 入库 → 测审计集 recall@5 保持率 + 单条目任务覆盖密度。对照组：同样的 30 条不合成、只加 1 条拼接摘要。
- 全程每代一行 JSONL：`{gen, cfg, train, held, audit, archive_n, accepted, doctor_ok, wall_ms}` → `data/x2_evolve-{group}-{seed}.jsonl`。

### X3 · 危险场景矩阵（H2 的主战场，半天）

在 X2 的 G0/G2/G4/G5 上叠加场景开关（构造方法全部来自报告已验证配方）：

| 场景 | 构造 | 对应报告 |
|---|---|---|
| 干净 | 无注入 | E63 |
| 伪特征 | 训练集 100% 指向金标、留出集方向反转的假信号特征 | E3 |
| 评判者漂移 | 效用权重每代被系统输出锚定 `w ← (1−α)w + α·dir(feats)`，α=0.10；真实效用用冻结的初心 W0 衡量 | E14 |
| 欺骗地形 | 起点 0.50 局部最优 / 0.90 全局、间隔低谷（任何单步改进先变差） | E7 |
| 金标噪声 | 独立噪声 30% 一档；相关噪声一档（后者预期击穿双门） | E52/E57 |
| 复合灾难 | 伪特征 + 漂移 + 欺骗地形三开 | E80 |

**操纵检查先行**（报告 E41 教训，写死在脚本里）：每个危险场景先验证"危险真实存在"（如无门控组确实采纳了伪特征）才允许比较各组表现，否则该场景判"构造不成立"如实报告。

### X4 · 内核架构对比：v3 状态机 vs 事件溯源（存储轴深化，约 1 小时）

自研 Windows 版事件溯源内核（`x4_kernel.txt`，≤200 行，逻辑对照混元 bs3v4 的 V1–V4 目标，代码原创、`msvcrt` 锁）：

1. **并发**：8 进程并发 append → `importance_accum` 正确性（v3 预期丢、事件溯源预期对）；
2. **截断检出**：同 X1 探针，事件溯源内核用 `chain_tip` 比对（预期检出）；
3. **重建**：删除 memory/ 后从事件流 fold 重建，与原库条目集合 Jaccard 必须 = 1.0；
4. **性能**：300 条目全量 fold / merkle / 检索计时（对照报告 bs3v4 实测 0.005s/0.008s 量级）。

输出给"v4 重构是否值得"提供本机数据，不直接下重构结论。

## 6. 评估指标体系（全部公式化，脚本自动计算）

### 6.1 检索质量（演化收益的主尺）

| 指标 | 定义 | 采集点 |
|---|---|---|
| recall@5 | 金标出现在 top-5 的任务占比 | 每代 × 三集分别记 |
| MRR | mean(1/rank_golden) | 同上 |
| ΔU_audit | 终态审计集效用 − 起点审计集效用（效用 = 命中 − 0.15×无关数，K=5 冻结） | **主指标** |
| 自报-真实差 | ΔU_train − ΔU_audit | Goodhart 信号（H2） |

### 6.2 记忆一致性（H3）

| 指标 | 定义 | 判什么 |
|---|---|---|
| 五态一致率 | 演化全程 doctor 报"五态全一致"的代数占比 | v3 已知健康信号过载（官方操作也报根不一致），此项**如实记录差异类型**，不简单当失败 |
| 重建等价性 | 事件流 fold 重建条目集 vs 原库条目集 Jaccard | X4 |
| 并发正确率 | 并发 append 后 importance_accum 实测值 / 理论值 | X1/X4 |
| 审计链连续性 | 逐行重算 line_hash 的断链数 | 每 5 代 |

### 6.3 演化效率（H6）

| 指标 | 定义 |
|---|---|
| 收益/评估比 | ΔU_audit ÷ 总评估次数 |
| 采纳率 | 晋升次数 ÷ 候选总数（停摆监控的输入） |
| 收敛代数 | 首次达到终值 95% 的代数 |

### 6.4 遗忘与重组（H4/H5）

| 指标 | 定义 |
|---|---|
| 出仓零误伤率 | 1 − (误伤数 + 漏出仓数) ÷ 应出仓数 |
| 旧能力保留比 | 目标切换后档案内目标 A 最高效用 ÷ 切换前 A 效用 |
| 重组保持率 | 合成入库后审计集 recall@5 ÷ 合成前 |
| 压缩比 | 合成后条目数 ÷ 合成前（信息密度辅助指标） |

### 6.5 资源开销（H6）

每配置每种子记录：总 wall time、昂贵评估次数（选择压力的真实货币——报告 E64 的"注意力预算"）、磁盘峰值、每代均时。**预算红线**：单配置 × 8 种子 > 30 分钟即触发减代数/减条目的降规模重跑（记录降规模事实，不静默）。

## 7. 数据采集与分析方法

1. **原始层**：`data/*.jsonl` 一行一事件（代/操作/指标/时间戳），脚本只追加不改写（对齐被测系统自己的铁律 4）；库目录每 5 代打 zip 快照留档。
2. **统计层**：
   - 组间比较一律**配对设计**（同种子同世界，只差配置），报差值而非绝对值；
   - bootstrap 1000 次重采样出 95% CI；正/负种子计数直接报告（"8 种子中 7 正"式表述，对齐报告风格）；
   - 关键结论（H1、H2）双种子规模复核：8 → 24；
   - 多场景矩阵逐场景报告 + 均值，**不做跨场景 p 值合并**（场景间不独立）。
3. **分析层**：`reports/` 下每实验一份分报告（结论先行 + 证据表 + 复现命令），最后合入 `reports/总报告.md`，结构对齐用户读得懂的"结论 → 数据 → 边界"。
4. **实验失败登记**：照抄报告第四部分的诚实记录格式——每个实验若构造失败/数据被 bug 污染，进 `reports/失败登记.md`，注明原因与教训，**不删除不美化**。
