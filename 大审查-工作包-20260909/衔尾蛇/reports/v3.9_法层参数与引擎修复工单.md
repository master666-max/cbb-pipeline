## 修订哲学（一句话）

演化实验证明的**不是某个最优参数值**，而是「参数值应当可演化」——所以本工单的主件是把法层参数从硬编码字面量外置为可配置项，默认值只取证据最强的那一个（filter_zero=1），其余维持现状并标注证据等级。

## W-1（P1 · 主件）：`_rank_entries` 打分参数外置到 TUNABLES

**现状**：源码 L919 打分公式为硬编码字面量
```python
scored[f.stem] = (kw_hit * 3 + c_hit + e.get("importance", 0) - 0.1 * age_days, e, c)
```

**改法**：
1. `TUNABLES` 新增五键（附 `source` 字段注明证据等级，沿用 TUNABLES 现有 schema）：
```python
"law_w_kw":          {"value": 3.0, "source": "v3 沿革值；沙盒 X2a 终态众数 3.0–6.0（证据：中）"},
"law_w_content":     {"value": 1.0, "source": "v3 沿革值；X2a 未发现变更收益（证据：中）"},
"law_w_imp":         {"value": 1.0, "source": "合成世界 X2a 终态多为 0，真实库 X5 显示 1.0 无害——维持 1.0 待真实库老化后复测（证据：弱/冲突）"},
"law_w_age":         {"value": 0.1, "source": "合成世界病灶（age=400 → −40 分压制命中分）；真实库现龄 0–5 天未触发，属定时炸弹——维持 0.1 但必须可配置（证据：机制实证/现实未触发）"},
"law_filter_zero":   {"value": 1,   "source": "沙盒 24 种子全部采纳 + 真实库 20/20 run 采纳且 MRR 0.27–0.67→1.00（证据：强，双世界复现）"},
```
2. `_rank_entries` L919 改为读 TUNABLES（`TUNABLES["law_w_kw"]["value"] * kw_hit + ...`）；`filter_zero=1` 时跳过零命中条目（在 L911 循环内 `continue`，置于打分前）。
3. **行为变更先 shadow**（公理 G）：改动落地后先 `engine shadow` 记录，再跑既有 `engine eval` 基线对账——真实库验收标准：**recall@5 不得劣化、MRR 应提升**（沙盒与真实库双证据：filter_zero 只剔除与查询零交叠的条目，仅在金标本就排名 ≤5 时改变排名，方向只会向好）。

**验收**：①全部既有自测通过（注意先修 W-3，否则自测不可信）；②根双库真实迁移副本（沙盒 `sandbox/lib-real` 可复现）`engine eval`：recall@5 维持 1.0、MRR ≥ 基线；③`run_tests` 新增 T 号：filter_zero 开启后零命中条目不出现于结果。

## W-2（P1 · 随 W-1 顺路）：法层参数进 `state.json` 快照

install 时把五键当前值抄入 `state.json["law_params"]`（只抄不裁决），使每库的法层状态可审计、可回放。**不开放引擎自动修改**（自动修改属 v4 演化环议题，本工单不授权——元层/法层边界维持报告结论）。

## W-3（P0 · 前置）：`run_tests` 静默中止

**现状**：`cmd_run_tests` 用 `except Exception` 捕获不到 `sys.exit`（BaseException），71 个自测只跑 9 个即静默退出（rc=1），本沙盒 X0-S2 复现。
**改法**：测试循环改为逐用例 `try/except BaseException` 捕获计数（或子进程隔离逐个跑），结尾打印 `通过/总数` 并在非全绿时 `sys.exit(1)`。
**验收**：输出必须含 `71/71` 或列出真实失败用例名；rc 与打印一致。

## W-4（P0）：`importance_accum` 并发丢更新

**现状**：L949–954 read-modify-write `state.json`，8 进程并发实测丢 75%（12 进程报告口径 92%）；该累加器是反思触发唯一输入——并发写场景反思机制静默失效。
**改法**（两选一，推荐 a）：
- a. append 的 state 更新段套锁目录互斥（`os.mkdir` 原子创建 + 重试超时，沙盒 X4 已验证该原语在 Windows 可靠）；
- b. 彻底方案：importance 只记事件流，`importance_accum` 改为 fold 派生量（X4 内核已验证：并发 40/40 精确、截断可检出、重建 Jaccard=1.0）——工作量大，建议排入 v4 内核换血而非本版。
**验收**：8 进程并发 append 后 `importance_accum` 增量精确等于 8×5。

## W-6（P2 · 前瞻项）：反思条目 `importance>=7` 规则的启用前提

源码 `REFLECT_SYNTHESIS` 强制合成条目 `importance>=7`。沙盒 X2d 实测：在 W-1 修复前（`law_w_imp=1.0` 且零命中过滤关闭时），R 条目会挤占 top-5（真实库 kw 召回 0.2→0.15 的同机制）；W-1 落地（filter_zero=1 默认开）后实测无害。
