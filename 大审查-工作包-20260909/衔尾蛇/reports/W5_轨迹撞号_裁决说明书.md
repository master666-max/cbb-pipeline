## 一、背景：轨迹 ID 是什么

知识库按日记录任务轨迹：`knowledge/trajectories/{YYYY-MM-DD}/task-{NNN}-{标题}.md`，编号 `task-{NNN}` 由当日任务序号生成，**不含日期**。轨迹是本实验群的溯源锚点之一（如衔尾蛇 README 的入口表引用 `knowledge/trajectories/2026-09-08/task-020` 定位实验轨迹）。

## 三、实际影响（为什么这不是小事）

1. **溯源锚点歧义**：任何「见 task-020」的引用在不带日期时指向两个不同任务——衔尾蛇 README 引用的恰是 09-08 的 `task-020-自演化沙盒.md`（232 run 主实验轨迹），与 09-07 的 v36 执行记录毫无关系。知识库的公理 E 式锚点（哈希抄录、账本引用）若使用纯 ID，跨日即失效。
2. **实验被迫消歧**：X 线实验当时被迫对副本改名（工单原话「沙盒实验被迫在副本中改名消歧」），改名方案（218/320）无日期语义、不可自解释——它解决了一次冲突，但没有解决规则。
3. **铁律 1 张力**：知识库铁律 1「只新增不改动」。既有改名按严格口径是违例；但实测上改名是恢复可引用性的最小动作，且已进入冻结快照（不可逆）。故只剩**追认或登记违例**两个选项，没有「撤销重来」的合理路径。

## 四、向前修复方案（裁决项）

| 方案 | 内容 | 优点 | 代价 |
|---|---|---|---|
| a. 生成器修复 | TRAJ id 改 `TRAJ-{YYYYMMDD}-{N}`（如 TRAJ-20260908-020） | 结构性根除（与 W-7 同批解冻执行，动真引擎慢车道） | ID 变长；下游引用格式需跟随 |
| b. lint 守卫 | 保持现格式，lint 工具对「跨日已存在的 task-{NNN}」在写入时报错 | 立即可做（解冻后）、不改历史 | 治标：靠人改号，且改出的号（如 218/320）不可自解释 |
| **c. 双管（建议）** | 生成器改日期前缀 + lint 报错兜底 | 根除 + 兜底 | 两件小事 |
