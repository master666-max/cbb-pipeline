# 任务收尾六步（v3）

## 1 清场
- 列出临时文件清单，经用户确认后删除或移入 `attic/`。
- 确认唯一最终交付物，其余版本移入 `attic/`。

## 2 归档
- `workspace/{task}` → `archive/{YYYY}/{MM}/{task}/`，按《实验性双库工作区/双库自进化体系·建库提示词.md》第六节模板补写 README（含一句话/复现/数据流/关键决策/踩坑与经验/复用提示）。
- 历史项目本体被外部引用时采用「引用不搬移」manifest 方式（见 decisions.md D-001）。
- 归档后目录视为只读。废弃版本移入 `attic/`，永不删除。

## 3 复盘（写入 knowledge/）
- 失败/弯路 → `pitfalls.md` 新条目（必须含根因一句话 + 实例链接；强制根因分析，不记表面现象）。
- 成功路径 → `patterns.md` 新条目，或已有条目验证次数 +1。
- 写入前先与已有条目对比去重（含实验性双库工作区已有条目），禁止新增重复条目。
- 每条必须有工作区内真实依据，无依据不写，拿不准标【待确认】。
- **v3 schema**：新条目必须含 `关键词` / `关联`（[[]] 双链）/ `版本` 三行。

## 4 互链
- 新条目补「实例」字段（指向归档项目路径）；项目 README 补回链（指向 pitfalls/patterns 条目）。
- 抽查互链，断链当场修复（或跑 `py -X utf8 tools/lint_knowledge_base.txt`）。

## 5 索引同步
- 更新 `knowledge/_index.md` 与 `archive/_INDEX.md`：新增行、触发次数、最后引用日期、重要度评分。
- 验证 ≥3 次的 pattern，列为「建议升级为独立 skill」，不自动执行。
- 验证 0 次且超 30 天的条目移入归档区；工件项目 12 个月未引用移入 `archive/_cold/`（压缩存放，不删）。
- 更新 trajectory 轨迹文件（只追加）。

## 6 演化回扫（v3 新增 · A-MEM 式记忆演化）
- 新条目写入后，回扫同主题旧条目：能互证则补 [[双向链接]]；旧条目表述已过时则**修订原条目**并递增版本号（v1→v2），不新建重复条目。
- 反思计数：本次 wrap-up 后检查自上次 reflect 以来的累计次数，**满 5 次**则提醒用户（或直接）执行 `knowledge/skills/reflect/SKILL.md`。
- 若任务中产生了对用户偏好/相处方式的新认知，回写 `soul/USER.md`（注明日期）。
