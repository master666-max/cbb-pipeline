## 1. 实验目标与假设

### 1.1 总目标

论证"agent 记忆库自演化引擎"这一架构在真实检索引擎上的**可行性、必要条件与代价**——让变异真实发生在 bootstrap_v3.8.2 的检索路径上，用训练/留出/审计三把尺子量出收益与风险。

### 1.2 四个能力轴

| 轴 | 含义 | 承载实验 |
|---|---|---|
| **存储** | 写入路径正确性：schema 校验、审计链、并发一致性、可重建性 | X1、X4 |
| **更新** | 法层参数（检索权重/过滤开关）能否自主变好而不作弊 | X2、X3 |
| **遗忘** | 失效条目 TTL 出仓零误伤；目标切换后旧能力保留（防灾难性遗忘） | X1、X2c |
| **重组** | 反思合成（多条→规律条目）后检索不退化、信息密度提升 | X2d |

### 1.3 可证伪假设

| # | 假设 | 证伪条件 |
|---|---|---|
| **H1 有效性** | 元层冻结（金标任务集、K=5、效用函数人侧固定）时，自演化组（G4/G5）在**审计集**上的检索效用显著优于静态基线（G0），且对比同预算的 G6 人工维护组不劣 | 配对 8 种子差值 bootstrap 95% CI 上界 ≤ 0 |
| **H2 门控必要性** | 伪特征场景下，无门控组（G2）自报进步但审计集真实退化（Goodhart 复现）；两级门控组（G4）不采纳伪特征 | G2 真实退化不出现，或 G4 采纳伪特征 |
| **H3 一致性保持** | 全演化周期内库的四平面对账差异全程可解释；事件流重放重建与原库条目集合完全等价 | doctor 报出未解释差异，或重建 Jaccard < 1.0 |
| **H4 遗忘可控** | TTL 出仓零误伤；目标切换后 Pareto 档案对旧能力保留 ≥ 单一最优档案，且 ≥ 起点能力 90% | 出仓误伤 > 0，或保留比劣于对照 |
| **H5 重组无损** | 反思合成入库后审计集 recall@5 保持 ≥ 98%，条目信息密度不降 | 保持率 < 98% 或密度下降 |
| **H6 资源可行** | 每配置 × 8 种子全程 wall time ≤ 30 分钟，昂贵评估次数 ≤ 报告同类实验 1.5 倍；G6 与 G4/G5 在**同预算口径**下比较 | 超限且无法降规模修复 |

**总可行性判据**：H1 与 H2 同时成立 → "自演化引擎可行且护栏必要"成立；H1 成立但 H2 边缘 → 结论限定为"干净环境可行，危险环境未证实"，不外推（报告 E41 纪律）。

## 3. 关键设计决策：法层适配器

源码 `_rank_entries`（L898–928）打分权重为硬编码字面量：

```python
scored[f.stem] = (kw_hit * 3 + c_hit + e.get("importance", 0) - 0.1 * age_days, e, c)   # L919
# links 一跳扩散：被命中条目向 links 目标传播 s × 0.5                                    # L921–927
```

方案：`evocore.txt` 按源码逐行语义参数化重实现（`w_kw, w_content, w_imp, w_age, filter_zero`），**X0 等价性门**：默认参数 `(3,1,1,0.1,0)` 下与 `m._rank_entries` 在同一真实库上 top-20 排序逐条一致（100+ 查询）；外加**负对照**（改一个参数必须翻转排序）。库本体（写入/审计链/账本/doctor/retire/eval）全走真引擎路径，适配器只接管检索打分层。

## 4. 实验设计总览

### 4.1 对照组矩阵（G0–G6，七组）

| 组 | 配置 | 角色 |
|---|---|---|
| **G0** | v3 默认参数，静态不演化 | **静态记忆库对照** |
| **G1** | 静态 + 一次性人工调参（w_imp 0.5、filter_zero=1） | 排除"演化只是替人调参" |
| **G2** | 自演化 · 无门控（训练集提升即采纳） | Goodhart 消融 |
| **G3** | 自演化 · 单门（仅训练集配对 + 固定 margin） | 门控充分性消融 |
| **G4** | 自演化 · 两级门控 + Pareto 档案（宽松准入 Δ>−tol；严格晋升 = 双集配对 + bootstrap 95% 下界 > margin） | **修正架构核心** |
| **G5** | G4 + 锚定审计（0.85）+ 留出集轮换 + 停摆监控 | 完整架构 |
| **G6** | **无演化 · 全量人工维护**（v1.1 新增，定义见 §4.3） | 自主演化 vs 周期性人工维护的同预算对照 |

每组 × 场景（干净 / 危险，X3）× 8 种子；关键复验（H1/H2）加跑到 24 种子（对齐报告 E36 配对设计）。

### 4.2 世界模型与任务集（元层，人侧冻结）

- 80 条目 / 16 主题 / 20 关键词；`importance`、`age`（注入 `created_at`）按种子随机；30% 条目挂同主题 `[[links]]`（供 links 扩散与重组实验）——**条目经真引擎 `engine append` 写入**，`source_event_id` 取安装事件真实哈希前缀（不复刻源码 P0-2 的空锚缺陷）。
- 任务集 80 条（40 训练 / 32 留出 / 8 审计）；效用冻结：`U = 命中金标 − 0.15 × 无关条目数`，K=5。
- **三把尺子分离**：训练集供选择；留出集供晋升门控（消耗性、按预算轮换）；审计集**永不参与演化**，只对外报告。
- 元层常量（K、LAMBDA、margin、tol、种子表、bootstrap 次数）写入 `proto/meta_layer.json` 并记 sha256 入报告——运行脚本加载时校验，模拟"人侧签名"。

### 4.3 G6「无演化 · 全量人工维护」组定义（v1.1 新增）

模拟"人类定期保养记忆库"的常见形态，与 G4/G5 **同一注意力预算口径**记账：

- 每 5 代触发一次"人工维护"：在一个**固定 12 候选网格**上逐参数评估（4 个权重 × {×0.7, ×1.3} 共 8 个 + w_age→0 + w_imp→0 + filter_zero 翻转 + w_kw→1.0 复位，共 12 个），**只看训练集**，取最优且提升 > margin 者应用；
- 无档案、无留出集纪律、无锚定审计（人类凭"手感"= 训练集表现调参）；
- 每次维护消耗 12 个评估单位，与演化组的评估消耗同表记账，H6 的预算对比以此为准。

**定位**：G6 回答"既然人类定期维护也行，为什么要自演化"——若 G4/G5 在同预算下不优于 G6，自演化的价值主张就要重写；若 G6 因训练集过拟合而退化，则恰好证明"人工维护缺的正是门控纪律"。

## 5. 各实验详细方案

### X0 · 环境自检与适配器等价性（前置门）

1. 校验快照与原件 sha256 一致（`ef2c645aea64fb9e`）。
2. `run-tests` 行为观测：如实记录通过数/静默中止现象（源码 P0-1 预告自测有硬编码缺陷，记录本身即数据，不修它）。
3. absorb：`cmd_absorb("knowledge/skills/library-bootstrap")`，`--data` 指 `sandbox/pkgdata/`；若 MODULE_MAPPING 路径不全导致退出，**fallback** 为源码自测同款的最小 bodies.json（L1862 官方先例），如实记录走了哪条路。
4. `install L2 --target sandbox/lib-x0 --yes`；建库成功以 state.json + Merkle 根输出为证。
5. 世界构建：seed=1 的 80 条目真引擎 append；`engine retrieve/eval/doctor` 走通；`guard --snapshot` 出锚定快照。
6. **等价性门**：80 任务查询 + 20 随机查询，top-20 排序逐条一致 → `data/x0_equivalence.json`。
7. **负对照**：w_kw 3→4 必须翻转至少一个查询的排序（防"两个实现都没起作用"的假等价）。

**判据**：6 全绿 + 7 翻转 → 放行 X1/X2；否则修适配器，禁止带病进主实验。

### X1 · 静态基线组 G0/G1（存储 + 遗忘轴）

1. 8 种子各建一库（真实 install + append 80 条目）。
2. 存储一致性探针：doctor 五态逐项记录；8 进程并发 `engine append`（importance=5）量化 `importance_accum` 丢更新；截断探针（只读副本）删 audit 尾行 + 重算根 → 分别记录**密码学层检出**（链连续/根一致，预期检不出）与**集合层差异**（memory/audit 计数差会出现但与已知噪声同型——报告 2.4 健康信号过载的复现）。
3. 遗忘轴：10% 条目写过去日期 `t_invalid` → `engine retire` → 应出仓尽出、零误伤、attic 可回溯。
4. G1 手填调参跑同任务集 → 人工调参上限参照。
5. 全程 JSONL → `data/x1_static.jsonl`。

### X2 · 自演化主实验 G2–G6（更新 + 遗忘 + 重组轴）

演化循环（`evocore.txt`，对齐报告 5.2 修正架构）：

```
每代：Pareto 档案选亲本 → 变异 1 个法层参数（×0.5/0.7/0.85/1.2/1.5/2.0 或 filter_zero 翻转）
  → 廉价筛选：训练集快速分 < 亲本 − 3×tol 直接 reject（只淘汰不采纳——红线 7）
  → 档案准入（宽松）：Δ > −tolerance 即入档（Pareto：效用 × 档案规模双目标）
  → 主线晋升（严格）：训练集配对 > margin 且 留出集配对 > margin 且 bootstrap(1000) 95% 下界 > max(0, margin)
  → 晋升即经适配器把新参数写入真实库 state.json，doctor 随行
每 5 代：G6 触发人工维护（§4.3）；留出集消耗记账；G5 加锚定审计（< 0.85 → 冻结 + 报警）
25 代 × 3 变异/代（报告 E1 同规模），8 种子
```

- **X2a（更新轴）**：各组终态审计集效用 vs G0/G1/G6；系统自报（训练集）与真实（审计集）之差即 H2 数据。
- **X2b（防作弊）**：注入贪婪变异（w_imp=10），验证元层冻结下刷分不可表达（报告 E2）。
- **X2c（遗忘轴）**：先优化目标 A（命中）20 代再切目标 B（省无关条目）20 代，单一最优档案 vs Pareto 档案的 A 能力保留（报告 E16 的 0.547 vs 0.719 复现）。
- **X2d（重组轴 · v1.1 锁定）**：批量写入 30 条 → `importance_accum ≥ 50` 触发反思 → `engine reflect` 出素材包 → **由 harness（ZCode）按源码 L670–679 `REFLECT_SYNTHESIS` 原版提示词逐字执行合成**（提示词全文存档于 §5.1，合成产物与依据链全程留痕，可对抗复核）→ 2–3 条 R-xxx 规律条目（links 挂依据条目，importance≥7）经 `engine append` 入库 → `reflect-done` 重置累计器 → 测审计集 recall@5 保持率 + 单条目任务覆盖密度。对照组：同样 30 条不合成、只加 1 条拼接摘要。

### 5.1 X2d 合成所用提示词（源码 `REFLECT_SYNTHESIS` 逐字存档）

> # reflect-synthesis · 反思合成提示词（v3.5/J-009 渲染，随包分发）
> 用法：engine reflect 产出素材包（memory/reflect/materials-*.md）后，把素材与本提示词交给 harness 执行合成。
> 你是对本库近期写入做反思合成的 agent。规则：
> 1. 只依据素材包内的条目与依据链，提炼跨任务高层规律 2~3 条——不是复述单条经验（Generative Agents 式）。
> 2. 每条洞察必须附依据条目号；无据不写（铁律 2）；与库内既有 R 条目重复则合并升版本而非新建。
> 3. 产出格式：每条洞察一段（洞察正文 + 依据条目号列表 + 置信度），以 id=R-{下一个可用编号} 走 engine append（importance>=7）。
> 4. 合成完成入库后执行 engine reflect-done --lib <库>（重置累计器并入账本/审计链——勿手工编辑 state.json）。

### X3 · 危险场景矩阵（H2 主战场；复合灾难转观察态）

在 G0/G2/G4(/G6) 上叠加场景开关（构造全部来自报告已验证配方）：

| 场景 | 构造 | 对应报告 |
|---|---|---|
| 干净 | 无注入 | E63 |
| 伪特征 | 训练集 100% 指向金标、留出集方向反转的假信号 | E3 |
| 评判者漂移 | 效用权重每代被系统输出锚定 `w ← (1−α)w + α·dir(feats)`，α=0.10；真实效用用冻结 W0 衡量 | E14 |
| 欺骗地形 | 起点 0.50 局部最优 / 0.90 全局、间隔低谷 | E7 |
| 金标噪声 | 独立噪声 30% 一档；相关噪声一档（预期击穿双门） | E52/E57 |

## 6. 评估指标体系（公式化，脚本自动计算）

### 6.1 检索质量（主尺）

| 指标 | 定义 | 采集点 |
|---|---|---|
| recall@5 / MRR | 金标入 top-5 占比 / mean(1/rank) | 每代 × 三集 |
| ΔU_audit | 终态审计集效用 − 起点（U = 命中 − 0.15×无关数，K=5 冻结） | **主指标** |
| 自报-真实差 | ΔU_train − ΔU_audit | Goodhart 信号 |

### 6.2 记忆一致性

| 指标 | 定义 |
|---|---|
| 五态一致率 | doctor"全一致"代数占比（已知健康信号过载如实记录差异类型，不简单当失败） |
| 重建等价性 | fold 重建条目集 vs 原库 Jaccard（X4） |
| 并发正确率 | 并发后 importance_accum 实测/理论 |
| 审计链连续性 | 逐行重算 line_hash 断链数（每 5 代） |

### 6.3 演化效率

收益/评估比（ΔU_audit ÷ 总评估数，**G6 同口径记账**）· 采纳率（停摆监控输入）· 收敛代数（达终值 95% 的代数）。

### 6.4 遗忘与重组

出仓零误伤率 · 旧能力保留比（切换后档案内 A 最高效用 ÷ 切换前 A）· 重组保持率（合成后审计集 recall@5 ÷ 前）· 压缩比（合成后条目数 ÷ 前）。

### 6.5 资源开销

总 wall time · 昂贵评估次数（注意力预算真实货币，G4/G5/G6 同表记账）· 磁盘峰值 · 每代均时。**红线**：单配置 × 8 种子 > 30 分钟触发降规模重跑并声明。

## 7. 数据采集与分析方法

1. **原始层**：`data/*.jsonl` 一行一事件，只追加不改写；库目录每 5 代 zip 快照。
2. **统计层**：组间一律同种子配对，报差值；bootstrap 1000 次出 95% CI；正/负种子数直接报告；关键结论 8 → 24 种子复核；多场景逐场景报告 + 均值，不做跨场景 p 合并。
3. **分析层**：`reports/` 每实验一分报告（结论先行 + 证据表 + 复现命令），合入总报告。
4. **失败登记**：照报告第四部分格式，构造失败/数据污染进 `reports/失败登记.md`，不删不美化。
