### P-001 / 2026-09-03 / Windows 会话里别用 `python` 命令跑脚本：用 `py` 启动器；被 hook 拦截就写成 .txt 再执行
- 场景：多次任务需要执行 Python（提取 PDF/EPUB、生成后处理、程序化验收），直接调 `python` 失败或被会话 hook 拦截。
- 教训：Windows 下最短可行路径是 `py` 启动器（必要时 `py -X utf8` 强制 UTF-8）；根因是系统 `python` 命令损坏/缺失且部分会话对 `.py` 文件有 hook 拦截。`.py` 被拦时，把代码写成 `.txt` 交给 `py` 执行即可。
- 关键词：python、py 启动器、hook、.txt 脚本、UTF-8、Windows

### P-002 / 2026-09-03 / EPUB 解包文件名乱码：ZIP 非 UTF-8 标志位条目要按 cp437→utf-8 修复
- 场景：按文件名定位 EPUB 内章节时内容错乱/找不到文件。
- 教训：解包 EPUB 必须先修文件名——ZIP 条目未设 UTF-8 标志位（flag_bits & 0x800）时，Python zipfile 按 cp437 解出乱码名，需 `name.encode('cp437').decode('utf-8')` 修复；根因是打包端编码信息缺失，不修则按 manifest/spine 定位全部失准。
- 关键词：EPUB、zipfile、cp437、文件名乱码、flag_bits

### P-003 / 2026-09-03 / 清洗规则的三类误报陷阱：正常正文词、破折号字形、半角方括号
- 场景：删除论坛残留、规范标点、压缩状态栏等清洗操作时差点误伤正文。
- 教训：①"上传/基础上"是正常正文词，不能当论坛残留误删；②破折号正则必须用 `[—─]{2,}`——web 原文用的是 ──（U+2500 系）不是 ——；③半角方括号 `[ ]` 是心灵通讯/独白标记，不可删。根因：只看字形相似或关键词表面匹配，没对照原文字形与语义标记体系。

### P-004 / 2026-09-04 / 批量生成含特殊字符的文本别用 sed：直接 Write 逐个写
- 场景：批量生成 6 个 RP 知识域模板，用 sed -e 's/.../.../' 从模板派生，模板串含 `／`、`（）`、CJK 与斜杠组合。
- 教训：sed 表达式对未转义斜杠与特殊字符极脆，6 个文件里 1 个成 1 行残片、3 个部分缺失；根因是把「批量」误当成「该用 shell」的理由。**结构化文本批量生成直接用 Write 工具逐个写**（或 Python 脚本读模板写文件），sed 只适合纯 ASCII 单行替换。

### P-007 / 2026-09-08 / 沙盒实验的度量缓存必须随库状态递增版本号（pre≡post 假象）
- 场景：自演化沙盒 X2d 实验中，对同一库「批量写入前后」各测一次检索指标，两次读数完全相同——不是库没变，是度量函数的全局缓存 key 为 `(lib路径, rev)`，两次调用都传 rev=0，post 读到的是缓存的 pre 条目集。
- 教训：实验脚本里任何「读库→度量」的缓存，key 必须包含库内容版本（写操作后 rev+1），否则写后测量静默读旧数据，产出「干预无效」假象。根因：缓存设计时只考虑了「同状态重复度量要快」，没把「库已被自己写入」纳入失效条件——与报告失败 #7（id() 缓存串味）同族，都是缓存键不完整。识别信号：两次本应不同的测量**完全相等**。
- 详情：X2d pre≡post 假象 → rev 参数化 + 整库重建重跑后，真实数据显示批量写入使 default 参数 kw_recall5 从 0.4 跌到 0.2。全程见 大审查/衔尾蛇/reports/X2bcd_防作弊遗忘重组.md。
- 关键词：沙盒、缓存、rev、实验假象、度量、pre-post、写后失效
- 关联：[[PT-008]]（沙盒流水线规范已把「rev 随写递增」写进纪律）、[[PT-005]]（首跑抓出）
