### Q-001 · 统一写路径 `library_write`【P0｜架构｜1.5d】

**症状**：`engine shadow` / `guard --snapshot` / `guard --anchor` / `engine reflect` 写了 audit/ledger/文件树却不刷 Merkle 根 → `doctor` 报"根不一致"；`t_engine_lifecycle` 把不一致固化为预期。
**根因**："audit → ledger → root → state" 时序被手写 5 遍，漏 4 遍；且 `state.json` 全部为就地 read-modify-write，崩溃留半截 JSON。
**改法**：
① 新增原子写与统一事务：

```python
def _atomic_write_json(path: Path, obj) -> None:
    """Q-001：同盘临时文件 + os.replace——崩溃不留半截 JSON"""
    path.parent.mkdir(parents=True, exist_ok=True)
    tmp = path.with_name(path.name + ".tmp")
    tmp.write_text(json.dumps(obj, ensure_ascii=False, indent=1), encoding="utf-8")
    os.replace(tmp, path)
class _WriteTxn:
    __slots__ = ("lib", "_dirty")
    def __init__(self, lib: Path): self.lib = Path(lib); self._dirty = False
    def audit(self, text: str, prev_override: str = None) -> str:
        self._dirty = True
        return chain_append(self.lib / "audit", text, prev_override=prev_override)
    def ledger(self, action: str, detail: str):
        self._dirty = True
        _ledger_append(self.lib, action, detail)
@contextlib.contextmanager
def library_write(lib):
    """Q-001：统一写路径。块内经 tx.audit/tx.ledger 登记（Y-001 时序由结构保证），
    退出时统一刷根。state.json 不入根（D2），块内可安全写业务字段。"""
    lib = Path(lib)
    tx = _WriteTxn(lib)
    try:
        yield tx
    finally:
        if tx._dirty:
            st_path = lib / "state.json"
            if st_path.exists():
                st = json.loads(st_path.read_text(encoding="utf-8"))
                st["merkle_root"] = merkle_root(lib, exclude={"state.json"})
                _atomic_write_json(st_path, st)
```

② 五处改写（示意 append，其余同构）：

```python
        with library_write(lib) as tx:
            _atomic_write_json(epath, e)
            h = tx.audit(f"entry:{e['id']} → {dest.name}")
            tx.ledger("append", f"entry={e['id']} → {dest.name}")
            st_path = lib / "state.json"
            if st_path.exists():
```

③ **shadow 语义重新裁决**（本票的显式决策）：shadow 落 audit+ledger、根如实刷新；"未改状态"收窄为"memory 条目与业务状态字段（emotion/importance_accum）不变"。打印语改为：`shadow: 已记录（audit/ledger/根如实更新）；memory 条目与业务状态未变——公理G`。
④ `retire` / `wrapup` / `reflect` / `reflect-done` / `guard snapshot|anchor` / `migrate` 全部改走 `library_write`（migrate 用 `tx.audit(..., prev_override=prev)`）。install 首装流程保留 bespoke 结构，但 state 落盘统一走 `_atomic_write_json`。

### Q-003 · validate_entry 硬化【P0｜安全｜0.5d】

**症状**：① `id` 未校验字符集 → `"../../evil"` 可写穿 memory/，且 doctor 对账正则隐式依赖"id 无空白"（契约未声明）；② `importance`/`confidence`/日期无类型校验 → state 更新阶段崩溃，留下 entry+audit+ledger 已写、state 未写的**自造不一致**。
**改法**：

```python
_ID_RE = re.compile(r"[A-Za-z0-9][A-Za-z0-9._-]{0,63}")
_TS_RE = re.compile(r"^\d{4}-\d{2}-\d{2}")
def validate_entry(e: dict) -> list:
    errs = []
    for k in SCHEMA_V3:
        if k not in e: errs.append(f"缺字段 {k}")
    if "evidence" not in e and "source_event_id" not in e: errs.append("无证据锚(铁律2)")
    if not _ID_RE.fullmatch(str(e.get("id", ""))):
        errs.append("id 非法（[A-Za-z0-9][A-Za-z0-9._-]{0,63}）——防路径穿越与对账正则失配")
    for k in ("created_at",):
        v = e.get(k)
        if not isinstance(v, str) or not _TS_RE.match(v):
            errs.append(f"{k} 须为 YYYY-MM-DD 前缀字符串")
    imp = e.get("importance")
    if isinstance(imp, bool) or not isinstance(imp, int) or not (0 <= imp <= 10):
        errs.append("importance 须为 int(0..10)")
    if e.get("confidence") not in ("高", "中", "低"):
        errs.append("confidence 须为 高/中/低")
    v = e.get("validity")
    if not isinstance(v, dict):
        errs.append("validity 须为 dict")
    else:
        for tk in ("t_valid", "t_invalid"):
            if tk in v and (not isinstance(v[tk], str) or not _TS_RE.match(v[tk])):
                errs.append(f"validity.{tk} 须为日期前缀")
    for lk in ("keywords", "links"):
        if not isinstance(e.get(lk), list):
            errs.append(f"{lk} 须为 list")
    if re.search(SECRET_PATTERNS, json.dumps(e, ensure_ascii=False)):
        errs.append("疑似密钥(铁律5)")
    return errs
```

**次序调整**（`cmd_engine append`）：归一化前移——`e = entry_normalize(json.loads(text))` 之后才 `validate_entry(e)`，否则旧八字段条目在 `keywords` list 校验处误拒。
**验收**：新增测试覆盖：id=`../x` 拒、id 含空格拒、importance="9" 拒、confidence="S" 拒、created_at="不是日期" 拒；现有 `t_schema_rejects_missing_source`/`t_law5_secret_scan`/`t_engine_lifecycle` 全绿（现有测试条目 id 均合法，已核对）。

### Q-008 · 检索零命中过滤 + importance 降权【P1｜算法｜0.5d】

**症状**：`score = kw*3 + c + importance - 0.1*age` 中 importance 为**加法基线**——importance=9 的无关条目稳进 top-k，挤掉真实命中（`t_retrieve_keywords_boost` 的 hub 恰靠此缺陷入围）。另：`-0.1*age` 使 30 天以上记忆被完全压制，与"长期记忆"定位矛盾。
**改法**（`_rank_entries` 重写计分段，同时修复 Q-016.10 的双解析）：

```python
    raw = {}; scored = {}; bad_ts = []
    for f, e, age_days in entries:
        # 时间戳解析一次（原双解析修复）
        c = e["content"]
        kw_hit = sum(1 for w in q.split() if w in " ".join(e["keywords"]))
        c_hit = sum(1 for w in q.split() if w in c)
        if kw_hit: c_hit = max(c_hit, 1)
        raw[f.stem] = (e, age_days, c)
        if kw_hit or c_hit:   # Q-008：零命中不入围；importance 降为 0.1 权重 tie-break
            scored[f.stem] = (kw_hit * 3 + c_hit + 0.1 * e.get("importance", 0)
                              - 0.05 * min(age_days, 730), e, c)
    # [[links]] 一跳扩散：命中条目向未命中邻居传播 0.5×自身分
    for fid, (s, e, c) in list(scored.items()):
        for link in e.get("links", []):
            lid = str(link).strip("[]")
            if lid in raw and lid not in scored:
                e2, age2, c2 = raw[lid]
                scored[lid] = (s * 0.5 + 0.1 * e2.get("importance", 0)
                               - 0.05 * min(age2, 730), e2, c2)
```
