### E3 留出集门 —— 伪特征

| | 新鲜集效用 | 终局 `w_spur` |

### E16 Pareto 档案 —— 目标切换

先优化 A 再优化 B，切回 A 能拿回多少：

| 档案 | A 能力保留 |
|---|---|
| 单一最优 | 0.7188 |
| **Pareto** | **0.8125** |
| Pareto + 采样 12 | 0.7969 |

代价从 E41 的 0.0025 升到 **0.094**。

### E13 廉价筛选只淘汰 —— 廉价评估不精确

| 模式 | 相对起点 | 代数 |
|---|---|---|
| 全昂贵 | +0.0921 | 13 |
| **只淘汰（正确）** | **+0.1025** | 13 |
| 用于采纳（违规） | +0.0630 | 40 |

违规代价 0.04（E41 中 0.008）。**四条里代价最小的一条**——与 E33 一致：廉价筛选是 P2，取决于廉价评估精度。

### 结论：E41 的警告被完整验证

> **红线不能用"在我的测试里没差别"来否定。** 在平滑、无伪特征、目标不切换的世界里，四条红线的代价分别是 −0.06/+0.02/0.003/0.008（≈0）；在各自的危险环境里是 **0/12 失败、0.195、0.094、0.040**。

修正后的红线优先级（代价 × 危险出现概率）：

| 红线 | 危险环境代价 | 真实系统出现该危险的概率 | 优先级 |
|---|---|---|---|
| **margin 标定 + 监控** | 停摆（+0.000） | 高（标定极易出错） | **P0** |
| E7 宽松准入 | 0/12 到不了全局最优 | 中（取决于地形） | P1 |
| E3 留出集门 | 0.195 | 高（高维配置空间近乎必有伪特征） | P1 |
| E16 Pareto 档案 | 0.094 | 中（取决于目标是否切换） | P1 |
| E13 只淘汰 | 0.040 | 取决于廉价评估精度 | P2 |

## 二、E43 margin 自动标定：不如手工

既然 margin 标定错了是 P0 风险，能否自动标定？用空分布估计：
`margin = 1.645 × σ_Δ / √n`（单侧 95%）

| 模式 | 相对起点 | 平均 margin |
|---|---|---|
| **手工 0.01** | **+0.1525** | 0.0100 |
| 自动标定 | +0.0971 | **0.0437** |

**自动标定把 margin 定到 0.044（4 倍于最优值），损失 0.055。**

原因：σ_Δ 的估计包含了**变异本身的真实效应量**，而不只是噪声。当变异普遍带来真实改进时，σ 被高估 → margin 过大 → 挡掉真改进。

> **结论：统计形式的自标定在这里是错的。** 正确做法应该是用**配对重评估**（同一配置评估两次，测纯噪声），而非从变异的 Δ 分布反推。这一点值得后续单独做（本轮未能验证自标定的正确形式）。

实践建议：**margin 用手工粗标定（0.01–0.03）+ 监控采纳率**（见 E44），比自动标定更可靠。

## 三、E44 停摆监控器：有效（P0 的解法）

margin=0.15 是致命设置（E29b：零采纳）。加入监控器：**连续 5 代零采纳 → margin 减半**

| | 相对起点 | 终局 margin | 放宽次数 |
|---|---|---|---|
| 无监控 | **+0.0000** | 0.1500 | 0 |
| **有监控** | **+0.0558** | 0.0050 | 7.8 |

**监控器把"完全停摆"救回到 +0.056。**

它平均放宽 7.8 次，说明是**渐进摸索**到合适量级而非一步到位——但能持续工作。

> 这是 E41 定为 P0 的那个风险的可行缓解：**不需要标定得准，只要能检测到"卡住不动"并自动放宽**。这比 E43 的自动标定成功得多——因为它检测的是**结果**（采纳率=0），而不是**猜测参数**。

**一个通用原则浮现**：检测"系统没在动"比"预测该设多少"可靠。前者是观测，后者是建模。

## 四、E45 四态判别：发现一个真实 bug 模式

在 E12 的三态（收敛/卡住/漂移）基础上加入"任务分布切换"。

**第一次实现：42/56。** `drifted` 全被判成 `switched`，`switched` 全被判成 `converged`。

诊断后发现根因：

```
best = 0.850   ← 记录于旧地形
切换后：measure(1.0,1.0) = 0.65，但 0.65 < 0.850 → best 永不更新
→ 平台计数器一直累加（误以为"没有改进"）
→ 探针用陈旧的 best 做比较 → 全部判错
```

**这不是测试构造问题，是一个真实的 bug 模式**：

> **平台期检测不能拿历史最优分数当作当前天花板。** 世界一变，那个分数就过期了，系统会误判为"已收敛"而停止探索——**恰好在它最该继续探索的时候**。

**修正（探针 0：重测冠军）**：平台确认后，先用**当前标尺**重新评估冠军，若其分数显著低于记录值 → 环境变了；再用旧任务区分漂移与切换。

```
修正后：56/56（四类各 14/14）
```

判别协议（最终版）：

```
平台确认（连续 8 代无改进）
  → 探针0（重测冠军）：当前分数 << 记录分数 ？
        ├─ 是 → 旧任务上也掉 → 漂移（尺子变了）
        └─ 是 → 旧任务仍好   → 切换（任务分布换了）
  → 探针1（探索爆发）：随机 180 次能突破 → 卡住
  → 否则 → 收敛
```

## 五、E46 importance 冷启动：悲观最优

E32 证明实测优于自称，但新条目没有观测数据。比较五种初始化：

| 策略 | top-10 真实质量 |
|---|---|
| **悲观（新 = 0）** | **0.7651** |
| **略高于均值（0.55）** | **0.7651** |
| Thompson 采样 | 0.7446 |
| 乐观（新 = 1） | 0.5742 |
| UCB 上界 | 0.5742 |

**悲观初始化最优，乐观/UCB 最差（0.574 vs 0.765）。**

反直觉但可解释：老条目已经有充分观测（40 轮使用），其实测值是可靠的；新条目零观测，若给高初值会**挤掉已经验证过的优质老条目**。在"存量质量已经很高"的场景下，探索的收益小于挤占的损失。

> 但这有个重要前提：**老条目已被充分观测**。若整个库都是冷的（冷启动整体），结论可能反转。本实验未测该场景。

## 七、一个贯穿本轮的模式

E43 与 E44 的对比最有说服力：

| 方法 | 思路 | 结果 |
|---|---|---|
| E43 自动标定 | **建模**：预测 margin 该设多少 | 失败（−0.055） |
| E44 监控器 | **观测**：检测系统是否在动 | 成功（+0.056） |

E45 也是同一模式：修正前我在**猜**状态（用陈旧分数推断），修正后改为**重测**（直接观测当前值）。

**凡是"先建模再预测"的方案在本轮都失败，凡是"直接观测结果"的方案都成功。**

这与整个九轮的主线一致：v3 的 `guard` 走的是建模路线（预测什么算违规），能力式安全走的是观测/结构路线（让违规无法表达）。
