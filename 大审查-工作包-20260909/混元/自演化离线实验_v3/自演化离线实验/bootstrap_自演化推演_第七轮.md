# 自演化 · 第七轮推演

> 前六轮测的都是**独立机制**。本轮攻此前标记的最高价值未测领域：**机制之间的交互**，以及**两条从未验证过的工程主张**。
> 实验：`proto/evolve9.py`
> 结果：**1 个涌现问题（全套机制反而更差）、1 条建议被限定、1 条悬置五轮的主张被强力证实**

---

## 一、E29 端到端集成：出现了涌现问题

把前六轮所有机制组装起来，在**新鲜任务集**（从未参与任何选择）上测真实效用：

| 配置 | 相对起点 | 档案规模 | 重锚次数 |
|---|---|---|---|
| v3 单门 + 单档案 | +0.1150 | 1.0 | 0 |
| 两级门控 | +0.1119 | 1.0 | 0 |
| **+ Pareto 档案** | **+0.1260** | 22.4 | 0 |
| **+ 全套机制** | **+0.0525** | 17.0 | **3.1** |

**全套机制比"两级门控 + Pareto"差一倍（+0.053 vs +0.126）。**

这正是第六轮末尾预警的"工程失败往往发生在交互处"。逐个消融定位：

| Pareto | bootstrap | 轮换 | 廉价筛选 | 锚定 | 相对起点 |
|---|---|---|---|---|---|
| 0 | 0 | 0 | 0 | 0 | +0.1119 |
| **1** | 0 | 0 | 0 | 0 | **+0.1260** |
| 1 | **1** | 0 | 0 | 0 | **+0.0369** ← 元凶 |
| 1 | 0 | **1** | 0 | 0 | +0.1396 |
| 1 | 0 | 0 | **1** | 0 | +0.1181 |
| 1 | 0 | 0 | 0 | **1** | +0.1260 |
| 1 | 1 | 1 | 1 | 1 | +0.0525 |

**bootstrap 门控是唯一的负贡献项**（+0.126 → +0.037）。轮换反而略有助益，廉价筛选与锚定近似中性。

### 为什么 bootstrap 在这里是负贡献

E17 推荐 bootstrap 的理由是"固定 margin 在小样本下假阳性 0.42"。但那次对比的基准是 **margin=0.05**。本轮在同样操作点上系统比较：

| 噪声 | 门控 | margin | 相对起点 | 采纳次数 |
|---|---|---|---|---|
| 0.05 | 固定 | **0.01** | **+0.0931** | 2.9 |
| 0.05 | 固定 | 0.05 | +0.0756 | 1.0 |
| 0.05 | 固定 | **0.15** | **+0.0000** | **0.0** |
| 0.05 | bootstrap | — | +0.0806 | 1.0 |

**关键发现：margin=0.15 直接杀死演化（120 代 0 次采纳）。**

bootstrap 的优势是"不需要标定"，代价是"拒绝过多真改进"。当 margin 能被标定好时（0.01），固定 margin 反而更优。

> **修正 E17（限定适用条件）**：bootstrap 的优势成立的前提是 **margin 未标定**。若能通过 E17 的假阳性测量把 margin 标定到合适量级，固定 margin 可能更优。**两者都不是无条件最优**——真正不可接受的是 margin 过大（0.15 → 演化完全停摆）。

### 两个附带发现

1. **锚定审计在无漂移场景下误报 3.1 次**。E29 中 `w` 恒为 W0（无漂移），却触发了 3.1 次重锚。本实验中重锚是 no-op 所以无损失，但**真实场景中每次误报都要消耗一次人工裁决（成本 10）**。这提示阈值 0.90 在无漂移时的误报率需要单独测量——E14 只测了**有漂移时的检出率**，从未测**无漂移时的误报率**

2. **本操作点方差较大**：bootstrap 在两次结构相近的实现中分别得到 +0.037 与 +0.081。说明 8 个种子在此操作点处于边缘。涉及 bootstrap 的结论应视为**方向性提示**而非精确值

## 二、E32 记忆层核心主张被证实（悬置五轮）

第二轮我从"演化档案与记忆库结构同构"推出：**`importance` 应是被测量的量，而非条目自称的数字**，并指出这是 P1-6（重要度主导排序）的病根。**这个主张从未被验证过。**

本轮构造：条目有系统不可见的 `true_quality`；系统能观测到的只有"被检索出来后是否被真正采纳"。

| 排序依据 | top-10 条目真实质量 |
|---|---|
| **自称 importance** | **0.4949** |
| **实测采纳率** | **0.7110** |
| 两者各半 | 0.6869 |

**实测比自称高出 0.216（44%）。**

这是本轮最强的结果，因为它：
- 验证了一个**从架构对称性推出、而非从实验得出**的主张
- 直接指向 P1-6 的根治方案（v3 的 `importance` 就是条目自己声明的一个数字）
- 且"实测采纳率"的数据**系统本来就有**（检索后被采纳 = 有后续动作 = 账本可记录），无需新增采集成本

> 这条把第二轮的哲学推演变成了可执行的工程项：**把 `importance` 从输入字段改为派生字段**，由"被检索后是否真被采纳"累加而成。

## 三、E30 档案压缩：压缩不损能力，反而更好

宽松准入让档案膨胀（不压缩时峰值 103 条）。测各种压缩策略在**目标切换后**的能力保留：

| 策略 | A 能力保留 | 平均规模 | 峰值规模 |
|---|---|---|---|
| 不压缩 | 0.6406 | 53.9 | 103.1 |
| Pareto 前沿 | 0.7812 | 19.0 | 42.0 |
| 前沿 + 分叉点 | 0.7109 | 9.3 | 18.1 |
| 随机 12 条 | 0.6797 | 11.5 | 12.0 |
| **前沿 + 采样 12** | **0.7969** | **9.3** | **12.0** |

**"Pareto 前沿 + 随机采样至 12 条"同时最优：能力保留最高（0.797），规模最小（峰值 12）。**

压缩不仅不损害，反而**优于不压缩**（0.797 vs 0.641）。推测机制：过大的档案使父代采样退化为准随机游走，反而稀释了选择压力。

这给了第五轮"档案治理"建议一个正面证据——**压缩是收益项，不只是成本规避项**。

## 四、E33 廉价筛选：精度不足时不如不用

E13 推荐"廉价筛选只淘汰"，本轮校准容忍度并引入**系统性偏差**（而非纯噪声）：

| 容忍度 tol | 偏差 0.0 | 偏差 0.20 | 实际代数（偏差0） |
|---|---|---|---|
| 0.15 | +0.0663 | +0.0806 | 16.2 |
| **0.30** | **+0.0994** | +0.0663 | 13.4 |
| **0.60** | **+0.0994** | **+0.0994** | 12.0 |
| **1.00** | **+0.0994** | **+0.0994** | 12.0 |

**容忍度越大（= 筛选越松、越接近不筛选）结果越好。**

tol ≥ 0.60 时结果完全相同（+0.0994），说明此时筛选已不淘汰任何候选 —— 即**"不筛选"是本操作点的最优解**。

原因：廉价评估噪声 0.25，与真实改进量级相当。**当廉价评估的信噪比接近 1 时，它的淘汰决策基本是随机的**，剔除真改进的损失超过了节省预算的收益。

> **限定 E13**：廉价筛选的收益取决于**廉价评估的精度**。只有在 `噪声 << 效应量` 时才成立；否则应放宽或关闭。判断方法：测量廉价评估与昂贵评估的相关性，低于某阈值（本实验暗示约 0.5）时不要用。

顺带：系统性偏差（bias=0.20）的影响**小于**容忍度的影响，这印证了 E13 的核心论点（只淘汰时，偏差只影响淘汰谁，不会造成错误采纳）。

## 五、E31 留出集轮换：结论不成立（诚实记录）

| 轮换周期 | 自报提升 | 真实提升 | 膨胀 |
|---|---|---|---|
| 从不换 | 0.0741 | 0.0819 | **−0.0078** |
| 每 5 代 | 0.0819 | 0.0881 | −0.0063 |
| 每 15 代 | 0.0809 | 0.0805 | +0.0004 |
| 每 40 代 | 0.0663 | 0.0850 | −0.0187 |
| 自适应 | 0.1366 | 0.1131 | +0.0234 |

**E8 的"留出集膨胀 3.7 倍"在本实验中没有复现**——膨胀几乎为 0，甚至有负值。

可能原因：E8 用的是 12 条留出集跑 300 代（消耗强度 25 代/条），本实验 16 条跑 120 代（7.5 代/条），且任务池有限导致"新鲜集"其实部分重叠。

**结论：本实验未能确定最优轮换节奏，E8 的膨胀效应也未在此规模下复现。** 这是一个**未完成**的实验，不应写入红线。若要做实，需要更大的任务池与更长的演化。

## 七、方法论：一条越来越清晰的规律

把七轮的"被推翻/被限定"记录放在一起：

| 类型 | 例子 |
|---|---|
| 机制 A 优于 B | E17（bootstrap）→ 被限定：取决于 margin 标定 |
| 补救措施有效 | E23（层次化）→ 推翻；E13（廉价筛选）→ 被限定 |
| 补救措施有效 | E21（恢复解冻）→ 推翻；E10（元参数开放）→ 推翻 |
| 架构对称性推论 | E32（importance 实测）→ **证实** |

**凡是"观察到问题 → 设计补救 → 未独立验证"的建议，推翻率很高（约 5/7）。**
**凡是"从结构对称性推出、且能被直接测量"的主张，验证通过（1/1）。**

这提示一个实用准则：**在提出补救措施时，优先选择"可被直接测量的量"而非"新设计的启发式"**。E32 之所以成立，是因为"被采纳率"是一个本来就存在的可观测量；而层次化归并、近因加权都是新发明的启发式，各自带着未检验的隐含假设。

## 八、下一步

本轮暴露的最值得追的两件事：

1. **锚定审计的误报率从未测量**（E29 附带）。E14 只证明了"有漂移时能检出"，但一个在无漂移时也频繁误报的审计，成本上是否划算？这直接决定 E25 的预算结论
2. **E31 未完成时不应写入红线**——需要一个更大的任务池重做

另外 E29 的方差提示：**在本操作点上 8 个种子偏少**，涉及细微差异的比较（如 bootstrap vs margin）应提高到 20+ 种子或改用配对设计。
