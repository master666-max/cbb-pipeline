# 自演化 · 第二轮推演

> 承接《自演化架构设计方案》。上一轮验证了"自演化有效、作弊不可表达、双门防过拟合"。
> 本轮追问五个尚未回答的问题，全部用实验回答（含两个**否定性结果**），并据此修正架构。
> 实验：`proto/evolve4.py`

---

## 一、五个新实验

### E7 双门该用在哪一层 —— 本轮最重要的结果

**问题**：双门（配对比较 + 留出集）应当用于"候选能否进入档案"，还是只用于"能否晋升主线"？

构造欺骗性地形：起点 `(1,0)=0.50` 是局部最优，`(0,1)=0.90` 是全局最优，中间隔着低谷 `(1,1)=0.45`。任何单步改动都会先变差。

| 策略 | 终值均值 | 逃出局部最优 |
|---|---|---|
| **双门用于准入**（每步必须变好） | 0.500 | **0/20**（全部卡死，分布只有一个值 0.5） |
| **档案宽松准入 + 双门仅管晋升** | 0.900 | **20/20** |

**完美分离，无一例外。**

这是一个硬结论：**严格的门控使系统无法跨越适应度低谷**。配对比较 + margin 意味着每一步都必须改进，而任何需要"先退一步"的改进路径都被永久封死。

而 DGM 那套"开放式档案"的真正意义正在于此——它不是为了多样性而多样性，它是**让中性/小幅退化的中间态得以存活，从而保留跨越低谷的可能**。

> 修正：上一版方案把双门画成一个判定框，是错的。必须是**两级**。

### E8 留出集会污染

**问题**：长期用同一留出集做选择，会不会把它变成第二个训练集？

固定 12 条留出集，跑 300 代，另用一批**全新任务**测真实泛化：

| 代数 | 留出集提升 | 全新任务集提升 | 差距（= 膨胀） |
|---|---|---|---|
| 50 | 0.052 | 0.013 | 0.040 |
| 100 | 0.063 | 0.006 | 0.056 |
| 150 | **0.094** | **0.025** | **0.069** |
| 300 | 0.094 | 0.025 | 0.069 |

**系统自报的进步是真实进步的 3.7 倍。**

值得注意的是：它**没有失控**，在第 150 代后趋于平台——因为门控同时要求训练集改进，起到部分刹车作用。但膨胀是真实且持续的。

> 结论：留出集是被消耗的燃料，不是可反复使用的尺子。必须定期从储备池轮换。

### E5 代理失效（Goodhart）——修正后

上一版实验中代理指标不可剥削，导致结果无效。修正为"点击率"式代理（相关 +1、位置加成、吸睛加成 1.3/条），使"推吸睛但不相关内容"在代理上划算：

| 指标 | 结果 |
|---|---|
| 真目标变化 | **−0.2118**（12 个种子中 **7 个为负**） |
| 终局 `w_catchy` | 0.000 → **+0.833** |
| 人工审计（每 5 代抽 5 条） | 捕获 **7/12**，平均第 **21.4** 代 |

单种子轨迹（seed=1）：

```
代  1  真目标 +0.833  代理 1.341  w_catchy 0.00
代 24  真目标 +0.867  代理 1.538  w_catchy +0.50   ← 代理涨、吸睛权重被采纳
代 40  真目标 +0.867  代理 1.538  w_catchy +0.50
```

**系统在无人察觉的情况下把"吸睛"权重推到 0.83，而真目标在多数种子上退化。** 这正是现实中"以互动率为目标 → 内容质量下降"的微观复现。

审计机制有效，但**平均在第 21 代（40 代中的一半）才捕获**——审计频率直接决定损失上限。

### E4 标注效率：分歧采样（弱结果）

用"多个配置在同一任务上意见最不一致"来挑选值得标注的任务：

| 标注预算 | 随机 | 分歧采样 | 差 |
|---|---|---|---|
| 6 | 0.0337 | 0.0337 | +0.0000 |
| 10 | 0.0563 | 0.0694 | **+0.0132** |
| 16 | 0.0962 | 0.0969 | +0.0007 |
| 24 | 0.1025 | 0.1159 | **+0.0134** |

**结论：有小幅收益、从不损害，但不是解药。** 别指望它把标注量降一个数量级。冷启动的标注成本仍然要实打实地付。

### E6 结构演化（否定性结果）

加入离散结构基因（检索器选型 / 零命中过滤 / 一跳扩散）：

| 配置 | 留出集提升 | 为正的种子 |
|---|---|---|
| 仅标量参数 | +0.0500 | 6/12 |
| 标量 + 结构基因 | +0.0437 | 6/12 |

**结构基因没有带来收益，甚至略差。**

诚实解读：这个合成世界的"正确结构"就是 `hybrid`，切换到 `kw-only` / `content-only` 都是损害，所以可发现的结构性改进本就不存在。实验没有证明"结构演化无效"，它证明了：

> **结构演化的价值取决于世界是否真的有结构可发现**，而在缺乏结构信号时，门控能阻止结构性退步被采纳（6/12 为正，其余未退步）。

这对阶梯排序有意义：**S3（参数层）收益确定，S4（结构层）收益不确定**。

## 二、架构修正（基于实验）

### 修正 1 · 两级门控（E7）

```
变异 → 候选
   │
   ├─【档案准入】宽松：Δ > −tolerance 即入档（允许中性、允许小幅退化）
   │     档案 = 开放式探索空间，保留完整谱系
   │
   └─【主线晋升】严格：Δ(train) > margin AND Δ(held) > margin（配对比较）
         主线 = 唯一对外生效的配置
```

**理由**：准入严格 → 0/20 跨越低谷；准入宽松 + 晋升严格 → 20/20。

**推论**：档案会持续增长，需要治理（见修正 4）。

### 修正 2 · 留出集是消耗品（E8）

```
储备池（未标注/未使用）
   ├─→ 训练集（可反复使用）
   └─→ 留出集（被选择消耗）→ 定期轮换回储备池，换入新批次
   └─→ 审计集（极少触碰，只在定期审计时使用，用后立即归还储备池）
```

- 留出集**有预算**：每被使用 N 次即整批轮换
- 另设**审计集**，仅用于周期性人工/离线审计，绝不参与任何选择
- 对外报告的进步，以**审计集**为准，不以留出集为准

### 修正 3 · 人类的角色是"度量审计者"，不是"变更审批者"（E5）

这是本轮最大的观念转变。

I4 说"低风险变更不需要人类逐个批准"。E5 说明为什么：**批准变更是低效且无效的**——你批准的是系统声称会变好的东西，而它的"变好"是用代理指标衡量的，你批准时看不出问题。

**人类注意力应该花在审计度量本身**：

```
定期审计（抽样 N 条任务）：
  比对 代理指标 与 真人判断 的移动方向是否一致
  不一致 → 判定代理失效 → 冻结自动演化 → 重新校准
```

E5 显示：每 5 代抽 5 条，能捕获 7/12，平均第 21 代。提高频率即可压缩损失窗口。**这是可以用注意力预算直接购买的安全性**——与"审批每个变更"相比，性价比高几个数量级。

### 修正 4 · 档案治理

档案宽松准入意味着它会膨胀。治理策略：

- 保留 **Pareto 前沿**（在多目标上互不支配的配置）
- 保留 **谱系关键节点**（分叉点）
- 保留 **随机样本**（维持多样性）
- 其余移 `attic`（不删除）
- 档案本身纳入 Merkle / 事件流

### 修正 5 · 成本不对称 → 严谨度不对称

真实评测（LLM 调用）昂贵，不可能对每个候选跑全量。

```
候选 → 廉价筛选（高召回、低精度，只淘汰不采纳）→ 幸存者 → 昂贵门控（配对比较 + 留出集）
```

**关键**：廉价筛选器**只能淘汰，不能采纳**。淘汰错误只损失机会（可恢复），采纳错误造成退步（需回滚）。

> 这一条同时化解了"用代理指标会不会重蹈 E5 覆辙"的担忧：代理只用于**否决**，不用于**通过**。E5 的灾难恰恰来自代理被用于通过。

### 修正 6 · 阶梯排序调整（E6）

| 阶段 | 收益确定性 | 建议 |
|---|---|---|
| S3 参数层自演化 | **高**（实验 1/3 一致为正） | 优先做 |
| S4 结构层 | 中低（E6 无收益） | 延后，且需先确认世界有结构可发现 |
| S5 规则/提示词层 | 未知，风险最高 | 最后，且需全套护栏 |

## 三、更深的推演

### 3.1 演化档案 与 记忆库 是同一个机制

把两级门控（宽松准入 / 严格晋升）与 v4 的记忆分层对照：

| | 演化档案 | 记忆条目 |
|---|---|---|
| 准入 | 变异即入档（宽松） | `append` 即入库（宽松） |
| 晋升 | 双门（配对 + 留出） | **v3 缺失**：`importance ≥ 7` 直接进 longterm |
| 真值 | fold(事件) | fold(事件) |

**结构完全同构。** v3 已有 `intermediate` / `longterm` 两层，但**晋升没有任何门控**——`importance` 是条目自己声明的一个数字。

于是 P1-6（重要度主导排序）的病根浮出水面：**`importance` 是自称的，不是测出来的。**

修正方向：`importance` 应改为**被测量的量**——一条条目被检索出来后，是否被真正采纳（有后续动作、有账本记录），累加成其实测效用。晋升到 longterm 的判据不再是"声明 importance ≥ 7"，而是"在留出任务上证明过自己有用"。

> 这一改，检索排序、反思触发、条目生命周期三件事同时被同一套机制解决。

### 3.2 真正的事实源是「人类判断」，不是「规则」

E5 的教训推到底：效用函数是人对"什么叫更好"的压缩。写错它，系统就高效地优化错误目标——**这是设计层的 objective hacking，元层机制防不住**。

那什么防得住？

**存判断，不存公式。**

v3 的做法是存公式：`LAWS` 是 6 条中文字符串，`TUNABLES` 是 13 个数字。它们是**从判断里推导出的结论**，而判断本身丢了。所以一旦外界变化，无法重新推导，只能打补丁（这正是 v3.1→v3.8.1 一路 30 多个补丁的根源）。

正确的形态：

```
元层事实源 = 一组带签名的人类判断样本
            { (情境, A方案, B方案, 人判 A 优于 B, 理由, ts, 签名) , ... }

派生品（全部可重算）：
   效用函数权重 ← 从判断样本拟合
   铁律文本     ← 从判断样本归纳（渲染件）
   TUNABLES     ← 从判断样本标定
```

这直接呼应公理 A（单一事实源）——只是把"事实源"从"数据的单一存放处"升级为**"判断的单一存放处"**。规则是渲染产物，判断才是原料。这也让公理 B（文档即产物）第一次有了真正的生成器。

### 3.3 收敛后的三种状态，必须能区分

E8 显示演化会进入平台。但"平台"有三种可能：

| 状态 | 含义 | 应对 |
|---|---|---|
| **收敛** | 已找到该任务分布上的近似最优 | 停止，把算力投向别处 |
| **卡住** | 困在局部最优（E7 的 strict 情形） | 提高变异率、放宽档案准入、注入随机父代 |
| **世界变了** | 任务分布漂移，旧配置过时 | 刷新任务集、重标定效用函数 |

三者表现相同（留出集不再提升），应对完全相反。**必须设计区分手段**：

- 卡住：提高探索强度后如果立刻有突破 → 卡住
- 世界变了：在**旧任务**上性能不变、在**新采样的真实任务**上性能下降 → 分布漂移
- 收敛：两者都无变化，且档案 Pareto 前沿已稳定

**没有这个区分，系统在"世界变了"时会安静地持续退化，而所有内部指标都是绿的。**

### 3.4 元层的悖论

元层不可被自动修改（防 objective hacking）。但元层由人设定，人也会错。

出路不是"让人不犯错"，而是**让元层变更也走同一套证据纪律**：

- 元层变更需人侧签名（已有）
- 元层变更必须附带**新的判断样本**作为理由（不是"我觉得"，是"这里有一批新判断"）
- 元层变更后，全量重算所有派生品并对账（已有 `verify` 的雏形）
- 元层变更本身入事件流、入审计链

这样元层不是"不可变"，而是**变更成本极高且必须留据**。这比"绝对冻结"更现实——绝对冻结的系统无法适应世界变化，最终会被绕过。

## 四、修正后的完整架构

```
┌─ 元层（人侧签名，变更需附新判断样本）────────────────┐
│  判断样本库（事实源） · 效用函数 · 任务集 · K · margin │
│  · 铁律 · 审计频率 · 档案策略                          │
└───────────────────────┬───────────────────────────────┘
                        │ 派生（可重算）
┌─ 法层（系统自主演化）──┴──────────────────────────────┐
│  检索参数 · 阈值 · 结构开关 · 提示词 · 包状态机        │
│                                                        │
│   变异 →【廉价筛选：只能淘汰】→ 幸存者                 │
│            ↓                                           │
│        【档案准入：宽松，Δ > −tol】→ 档案（谱系完整）  │
│            ↓                                           │
│        【主线晋升：严格，配对+留出双门】→ 主线生效      │
└────────────────────────────────────────────────────────┘
                        │
┌─ 行层（自由写入）──────┴──────────────────────────────┐
│  记忆条目（宽松准入 / 实测效用晋升）· 情绪 · 索引       │
└────────────────────────────────────────────────────────┘

旁路：定期审计（抽 N 条）→ 比对代理 vs 真人判断 → 背离则冻结演化
      留出集轮换 · 收敛/卡住/漂移 三态判别
```

### 与 v3/v4 的对接

| 机制 | 角色 |
|---|---|
| 事件流 + `chain_tip` | 演化谱系的审计面与锚点 |
| git 后端 | 档案 = 分支/提交图；主线晋升 = merge；`-S` = 人侧签名 |
| 能力式边界 | 让"违反铁律的变异"不可表达 |
| `engine shadow` | 从"记日志"升级为"廉价筛选 + 影子执行" |
| `evals/` | 元层任务集（当前不可信，需重建） |
| 记忆 `importance` | 从"自称"改为"实测效用" |

## 五、新增红线

6. **档案准入必须宽松，晋升必须严格**——反之则系统无法跨越低谷（E7：0/20 vs 20/20）
7. **廉价筛选只能淘汰，不能采纳**——代理用于否决策安全，用于通过则灾难（E5）
8. **留出集是被消耗的燃料**——定期轮换，对外报告的进步以审计集为准（E8：膨胀 3.7×）
9. **人类注意力用于审计度量，而非审批变更**
10. **必须能区分收敛 / 卡住 / 世界漂移**——否则系统在世界变化时安静退化且全绿

---

## 六、一句话

上一轮证明了自演化**可行**；这一轮证明了它需要**两级门控、可轮换的尺子、以及一个只用于审计不用于审批的人类**。

而最深的一条是：**真正该被保存的不是规则，是判断**。v3 存了规则丢了判断，所以它只能用补丁追赶一个它无法重新推导的世界。
