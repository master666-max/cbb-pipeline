# 试点方案 · 本地 LLM-judge（Qwen3-8B @ ollama，5070Ti 12GB）

> 2026-09-10 · 前置发现与试点设计。全量实验（E1/E81 类）的预注册在本试点通过后另立。

## 〇、前置发现：世界必须先语义化

读桥接层发现：玩具世界条目 content = `"T0 K0 片段0"`（纯记号，无语义）。
**真 LLM judge 对它无法产生有意义的评分**——替换点不只是 `jscore`，世界的
文本载体本身要先换成真文本。这是接入工程的第一项，不是缺陷是发现：
玩具世界的"judge 可评性"从来不是免费假设。

## 一、世界语义化改造（管线搭建，一次性）

- 6 组 query（T0–T5）× 每组 10 条，共 60 条真实短文本（中文，~50–200 字）。
- **质量分档构造**：每条按构造标签生成——高档=切题、准确、可执行；中档=部分切题；
  低档=跑题/含糊/凑字。`true_quality` = 构造标签（0.1/0.5/0.9 三档），
  **不由任何 LLM 判断**，避免自测污染。
- 表象特征从文本真实提取：length=字符数归一、formatting=结构标记数、
  kw_density、has_citation——不再是随机数，LLM judge 才能真实感知"表象"。
- 生成器：ZCode 本人（一次性内容生成=管线工作；先于一切实验，无评分污染）。
- 生成产物：`semantic_world.json` + 构造依据记录。

## 二、judge 质量探针（不跑演化，先验 judge 本身；全部本地零成本）

| # | 探针 | 方法 | 通过标准 |
|---|---|---|---|
| P1 | 确定性 | 同 (query,列表) 评 2 次（temp=0） | 100% 逐字一致（缓存前提） |
| P2 | 辨别力 | 好/中/差条目列表各 30 个 query 配对评分 | 好显著 > 差（配对 t≥4） |
| P3 | JSON 服从 | 200 次调用 | ≥98% |
| P4 | 表象敏感性（E81 前哨） | "切题+冗长/花哨" vs "切题+简洁"列表对比 | 记录偏见方向与幅度（存在=特性非失败） |
| P5 | 吞吐 | 并发 20 路 × 200 调用 | 推算全实验 <12h |

## 三、硬件与算力结论（5070Ti Laptop 12GB 实测确认）

- Qwen3-8B Q4（~5GB）装入 12GB 后余 ~6GB 给 KV 缓存 → 并发 30–60 路
- 单实验 60 万次 fresh 调用 ≈ 2.4 亿 prefill token → **4–8 小时/实验，过夜跑**
- 电费 ~¥1/晚；32G 内存无压力
- 云费用归零；对比 DeepSeek flash API ≈ ¥150/实验——本地更省但慢，两者可混用（同 openai 兼容协议）

## 四、通过后才做的事

- 全量实验预注册（E1 类可行性 → E81 类偏见动力学，判据另锁）
- judge_adapter 加 `JUDGE_API_BASE=http://localhost:11434/v1` 即插即用

## 五、诚实声明

- 语义化世界的文本由 ZCode 生成：内容构造与实验假设同源的风险由"构造标签先于
  文本、文本不得自评质量"缓解；残余风险=文本风格与质量标签的相关性可能携带
  生成偏好，试点 P2/P4 会部分暴露它。
- Qwen3-8B 是 n=1 的 judge 样本：它的偏见参数不代表 LLM judge 总体，只代表
  "本地小模型当 judge"这个具体配置。
