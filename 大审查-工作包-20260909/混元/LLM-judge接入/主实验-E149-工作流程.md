## 1. 目标

最小闭环可行性：**LLM judge（M-Prometheus-14B）驱动法层参数演化**，

## 2. 预注册判据（2026-09-11 锁定，不得更改，只允许追加）

- 世界：`semantic_world.json`（60 条目 / 6 query 组 / 三档构造标签 18/24/18）
- 演化：24 代 × 4 子代；检索 top-4；每代 12 任务；margin=0.02、tol=0.04、cap=8（沿玩具参数）
- **canonical order 铁律**：任何 judge 调用前，检索列表按条目 id 排序（试点报告 §三的位置偏见）
- judge：M-Prometheus-14B（LM Studio, temp=0, max_tokens=512），解析兼容 JSON/[RESULT]
- **H1（可行性主判据）**：n=6 种子真值增益均值 > 0，且 ≥4/6 种子为正（符号检验 p≤0.34 一侧；
  本轮为试点，正 → 第 37 轮扩 n=44；null/负 → 按 34-35 轮框架归因后再定）
- H2（自报-真实差，E14 风格）：记录 judge 分数增益 − 真值增益，不设方向
- H3（工程）：LLM 调用缓存命中率 ≥80%；断点续跑验证一次（杀进程→重启→完成）
- 失败构造检查：任何 seed 真值增益与 judge 增益同时 ≈0 → 判构造/管线失效，不判机制无效

## 5. 失败模式与处置

| 症状 | 处置 |
|---|---|
| LLM 调用 404/模型不存在 | LM Studio 未加载该模型，重新加载；管线会如实记 None，**不许静默降级** |
| 解析失败率 >5% | 停跑，查模型输出样例（cache 里有 raw），改解析器后**清空对应 cache 条目重跑** |
| 全调用超时 | LM Studio 卡死，重启服务；缓存保住已完成工作 |
| 真值增益全 0 且 judge 增益全 0 | 按 §2 失败构造检查停跑归因 |
| 显存打架（两个推理服务同时用 GPU） | 一次只跑一个；8B 探针（ollama）与 14B（LM Studio）严格串行 |

# E150 增补（v1.1 · 2026-09-11）：抗 Goodhart 的 judge 接线

## 增补预注册（锁定）

- **E150a rubric 臂**：评分标准显式锚定——"只依据 ①主题相关性 ②内容正确性；
  长度/格式/排版/措辞风格一律不影响评分"，输出仍为 0-1。检验 rubric 锚定
  （盲评的真 LLM 形态）能否压缩自报-真实差。
- **E150b absolute 重跑臂**：与 E149 同 prompt、同种子，新增终局取证
  （持久化 main config + 6 个 query 的最终检索集）——E149 未持久化终局 config 的
  补课，同时提供同管线配对数。
- 两臂均 n=6 × 24 代 × 4 子代，种子 1-6，与 E149 按种子配对比较。
- 判据（锁定）：
  - H1：rubric 臂真值增益 − E149 真值增益（按种子配对）> 0 且 ≥3/6 种子改善
  - H2：rubric 臂自报-真实差 < E149 的 +0.3129（幅度记录，不设阈值）
  - H3：取证——终局 config 的检索集与 root 的差异可解释（哪些文本被顶上来）
  - 诚实条款：若 rubric 臂仍为负 → 显式标准也挡不住 Goodhart，归因升级到 judge 内部
    偏见（非指令可控面），负面清单 +1
- 判据锁定后不得更改。E149 的 res_e149.json 原样封存，不覆写。
