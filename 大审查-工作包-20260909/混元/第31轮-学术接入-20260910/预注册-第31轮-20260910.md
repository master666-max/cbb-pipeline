## 一、文献依据（设计输入）

| 方法 | 出处 | 本轮用法 |
|---|---|---|
| **ADWIN**（自适应窗口） | Bifet & Gavaldà, *Learning from Time-Changing Data with Adaptive Windowing*, KDD 2007 | 对审计真值流做变窗均值 cut：\|μ0−μ1\| ≥ ε_cut = sqrt((1/2m)·ln(4\|W\|/δ))，m=两段子窗长度的调和平均；只在 μ0>μ1（下降）时报 |
| **Page-Hinkley** | Page 1954；Hinkley 1971；数据流挖掘用法见 river/skmultiflow `PageHinkley`（δ, λ 双参数） | 累积偏离 + 最小值跟踪，报 PH_t − PH_min > λ |
| **CUSUM** | Page 1954；参数 (k, h) 按 ARL 标定（Minitab/质量控制文献标准做法） | S_t = max(0, S_{t−1} + (μ̂0 − x_t) − k)，μ̂0=扩张均值；报 S_t > h |
| DDM | Gama et al. 2004 | **预注册排除**：需要分类器错误率流，与本场景（真值读数流）不匹配 |

与本项目已有结论的接口：审计频率 ≫ 样本量（E97b）→ 本轮审计从每 5 代提到**每代**；
红线22（8–12 种子无差异不可信）→ n=44；红线25 → 必报触发次数。

## 二、E139 · 检测层比武（先跑）

**问题**：在相同的审计真值流上，文献检测器能否在受控误报下优于现行判据（一步落差
`x_t < x_{t−1} − 0.01`，即 kernel degrade_thr 的操作化）？

**数据流**：复用 evolve35.run 的演化循环（不改动同步包任何文件，仅 import），逐代审计
champion 真值读数（probe=4 任务，同 E135 的固定探针集）。场景 4 种：
`none`（对照）/ `drift`（第8代一次性重洗35%，同E135）/ `driftg`（渐进：第10/15/20代各重洗10%）
/ `corrupt`（第8代换差champion，同E135）。事件代 E0=8。

**阈值标定（防选择性报告）**：标定种子 1001–1020（20 条干净流，**不参与测试评估**）。
每个检测器的网格内选"干净流 FPR ≤ 10% 前提下最敏感"的档；平手取延迟更短。
ADWIN 按理论 δ 取档（保证是它的卖点，不参与 FPR 标定，但同样报告其 FPR）。

**测试**：种子 1–44 × 4 场景。基线参数 0.01 沿用 kernel，不标定。

**指标（锁定）**：
- 事件后命中 TPR（首个报警落在 [E0, 24] 的种子比例）
- 事件前误报 FPR（E0 前任一次报警的种子比例）
- 检测延迟 = 首报代 − E0（命中种子上的均值±se）
- 报告格式一律 均值±se (t, n)；检测器触发次数必报（红线25）

**成功判据（锁定）**：
- H1（渐进漂移 driftg）：存在文献检测器 TPR ≥ 1.5× 基线 且 FPR ≤ 10% → 文献接入有价值
- H0-预期（abrupt drift）：双方都应≈饱和（构造是阶跃大落差），仅作边界确认
- 延迟不劣于基线 +2 个审计点
- 若 H1 不成立：如实报告"文献检测器在本构造下无优势"，负面清单 +1

**实现纪律**：检测器先过合成流自测（常数流不报 / 阶跃下降必报 / 渐降必报 / 上升流不报）
才能上实验；全部标准库实现（无 pip）。

## 三、E140 · 动作层接线（在 E139 完成并冻结检测器选择后跑）

**问题**：把中选检测器接进 split 架构（停摆监控 + 审计二态判别，kernel 现形态），
动作收益是否为正？

**设计**：配对 n=44 × 4 场景 × 2 臂：
- `split`（基线：E135 split 逐字复刻，但审计改为逐代——两臂同频，公平）
- `split_cd`：基线全部逻辑不变，**仅新增**一条规则——CD 报警且当期未判退化时，
  提前重锚（btr/best = cur/main）。CD **不得覆盖** cur_best 二态判别的回退决定
  （corrupt 场景 CD 必然也报警，此时必须仍回退——这是安全性检查点）。

**判据（锁定）**：
- H2（driftg）：split_cd − split > 0，n=44 配对，显著（|t|≥2）
- H3（安全）：corrupt 与 none 场景 |Δ| < 0.03（检出限内），corrupt 场景回退次数不低于基线
- H4（drift）：不预设方向（提前重锚可能省代理、也可能丢适应），如实报
- 主报：真值增益 均值±se (t, n)；副报：回退/重锚/放宽次数

## 追加更正（2026-09-10，E140 出数后）

**E140-v1 判定为设计失败，其 null 结果无证据效力。** 原因：在逐代审计下，基线路径
每个审计点本就执行 `btr, best = cur, main`，预注册动作"提前重锚（btr/best = cur/main）"
与默认路径重合，CD 臂唯一差异是计数器 → 四场景 Δ 恒等于 0（bit 级）属于构造必然，
不是实验发现。归入设计失败记录（"过于整齐=bug 信号"的又一实例，本次败在判据设计层）。

**不做 v2** 的理由（结构性论证，E139 数据支撑）：CD 只观测冠军读数单通道，而
drift 与 corrupt 在该通道上**同样表现为读数下降**（E139：PH 在 corrupt 场景 TPR=0.93
——即 CD 把配置故障也当"世界变了"）。因此任何"CD 仲裁回退 vs 重锚"的接线都会在
corrupt 场景系统性翻车（错误否决本应回退的动作，损失 E133 的 +0.179 收益）；
区分二者必须测【历史最优在当前世界的读数】（kernel 二态判别），这不是信号强度问题，
是通道原理性不可辨识。CD 的动作价值退化为误报经济学，而本架构中假 `degraded` 的
代价近乎零（干净世界的假报警走重锚，无损害）——故动作层收益 ≈ 0 是**架构性质**，
不再是待检验假设。
