# 自演化 · 第十七轮推演（终局）

> 五轮循环要求的最后一轮。做**终局验证**：分级配置、防御代价、内部预警、最脆弱环节、复合灾难场景。
> 实验：`proto/evolve19.py`
> 结果：**1 个正面总账、1 个负面总账（复合场景 v4 更差）、1 个关于"自知之明"的否证**

---

## 一、E76 分级配置：极简版拿到 92% 的收益

| 配置 | 混合场景 | 收益占比 |
|---|---|---|
| v3 基线 | +0.1129 | — |
| **极简**（审计 + Pareto） | +0.1460 | **89%** |
| 核心（+ 留出集门） | +0.1523 | 99% |
| 完整（+ 停摆监控） | +0.1525 | 100% |

**每级相对 v3 的增量：极简 +0.033、+留出集门 +0.006、+监控 +0.0002。**

> **最小可行版本 = 锚定审计 + Pareto 档案**，两项就拿到 89% 的收益。留出集门与监控是"保险"（平时几乎零收益，出事时救命）。

这是 E66 结论的复现与确认（E66 也是阶段 3+4 贡献 85%）。**两次独立实验给出相同排序，可信度高。**

## 二、E77 防御代价：在良性环境下，护栏是免费的

这是本轮最重要的**正面**结果：

| 配置 | 良性环境 | vs v3 |
|---|---|---|
| v3 基线 | +0.1129 | — |
| 极简 | +0.1460 | **+0.0331** |
| 核心 | +0.1523 | **+0.0393** |
| **完整** | **+0.1525** | **+0.0396** |

**在没有任何危险的良性环境下，全套护栏不仅没有代价，反而提升了 35%。**

这推翻了一个常见担忧（"安全性会牺牲性能"）。原因是这些护栏**不是限制探索，而是改善探索**：
- Pareto 档案 → 保多样性（E16/E30）
- 留出集门 → 挡噪声（E52）
- 锚定审计 → 只在漂移时触发，平时零干预

> **安全性与性能在这里不冲突。** 唯一有代价的是"过度严格的门控"（E29b 的 margin、E54 的自适应收缩），而那些正是已被证伪的方案。

## 三、E79 最脆弱环节：Pareto 档案

留一法（每次移除一个机制）：

| 移除的 | 相对起点 | **损失** |
|---|---|---|
| 完整 | +0.1525 | — |
| audit | +0.1525 | **0.0000** |
| monitor | +0.1523 | 0.0003 |
| holdout | +0.1460 | 0.0065 |
| **pareto** | **+0.1150** | **0.0375** |

**Pareto 档案是唯一有实质损失的（0.0375），其余三者在混合场景下损失 ≈ 0。**

⚠️ **但这里有个重要提醒**：这个排序**只在"混合场景"下成立**，而混合场景中的危险是**漂移**（drift）——按理审计应该最重要才对，为什么移除 audit 损失为 0？

原因：混合场景中 `drift` 从 `gens//3` 开始，但**审计触发后只是把 `w` 重置为 W0，而下一代又被漂移拉回去**。在持续漂移下，重锚的效果被持续消耗。

> 这与 E69（锚定集不刷新 → −0.061）一致：**单次重锚在持续漂移下无效，必须配合锚定集刷新。**
>
> 所以"移除 audit 损失 0"**不代表审计不重要**，而是本场景的漂移是持续性的、审计频率相对不足。E67（drift 场景，护栏收益 0.145）与 E69 都证明审计在**瞬时/周期性**漂移下极为关键。

## 四、E78 内部指标预警：系统没有"自知之明"（否证）

无外部信号时，内部指标能否区分"正常"与"失败"？

| 失败类型 | 采纳次数 | 停滞代数 | 正常采纳 | 正常停滞 | **可区分？** |
|---|---|---|---|---|---|
| 正常 | 2.6 | 0.0 | 2.6 | 0.0 | — |
| drift | 2.9 | 0.0 | 2.6 | 0.0 | **否** |
| spur | 2.8 | 0.0 | | | **否** |
| deceptive | 2.5 | 0.0 | | | **否** |
| gold | 2.6 | 0.0 | | | **否** |
| **stop** | **0.0** | 0.0 | | | **是** |

**6 种失败里只有 1 种（完全停摆）能被内部指标识别。**

其余 4 种——漂移、伪特征、欺骗地形、金标噪声——**内部指标与正常运行时完全无法区分**（采纳次数 2.5–2.9 vs 正常 2.6，停滞代数全部为 0）。

### 这是全部 17 轮中最重要的否证

它直接回答了"自演化系统能否自己知道出问题了"：

> **不能。** 除了"完全卡死"这种极端情况，系统在运行指标上**看不出自己在失败**。漂移中的系统采纳更多（2.9 > 2.6）、自评更好（E14：自报 +1.50 而真实 −0.83）。

**这不是实现缺陷，是自指系统的结构性限制**——与 E14（系统塑造评判者）、E24/E47/E58（系统影响受审查程度）、E57（双门挡不住共同偏差源）完全同构。

> **唯一出路是外部参照**：锚定集（启用前采集）、人类签名（元层）、异质标注者。这三者是全部架构中仅有的外部性来源——本轮为这个论断提供了最直接的一条证据。

## 五、E80 复合灾难场景：v4 反而更差（负面总账）

四种危险**同时**出现（漂移 + 伪特征 + 欺骗地形 + 20% 金标噪声）：

| 配置 | 相对起点 |
|---|---|
| v3 基线 | **−0.1053** |
| **v4 完整** | **−0.2608** |

**在复合灾难下，v4 比 v3 更差（−0.26 vs −0.11）。**

### 为什么

回顾 E63 的单一场景：v4 在 5/6 场景更优。但复合场景下反转。可能机制：

1. **宽容准入（`tol=0.04`）在伪特征 + 金标噪声下放大了过拟合** —— E63 的 spur 场景已显示 v4 略差（−0.029），E67 也发现按总量拒绝会误伤。伪特征与噪声叠加时，宽松准入引入了更多垃圾
2. **Pareto 档案在欺骗地形下保留了"诱饵"配置** —— E55 发现欺骗地形下严格准入（tol=0）反而更好（+0.104 vs −0.062）
3. **两种效应叠加**：档案里堆满了"在噪声+伪特征下看起来好"的诱饵

### 如何解读这个结果

⚠️ 首先要说明：**这个场景刻意极端**（四种危险同时拉满），不代表真实情况。但它揭示了一个真实风险：

> **护栏之间存在负交互。** 每个护栏单独测试都是正收益（E67），但组合起来在特定场景下会相互放大。

**已确认的负交互对：**
- 宽松准入（E7）× 伪特征（E3）：准入越松，伪特征越容易进档案（E63 spur 场景 −0.029）
- Pareto 档案（E16）× 欺骗地形（E55）：档案保留诱饵（E55 严格准入更好）

### 可行的缓解（未测）

1. **危险感知的自适应**：用 E45 的四态判别先判断环境类型，再选择 `tol`（诱饵地形用小 tol，低谷地形用大 tol）。但这又是一个"自适应机制"，而 E54 已证明自适应有风险
2. **降低复合概率**：务实的做法是**确保危险不同时发生**——例如先修复金标质量再开启演化
3. **接受这个边界**：明确写入文档"本架构在 ≥3 种危险同时出现时不可靠"

## 六、十七轮的最终答案

### 6.1 该做什么

| 优先级 | 机制 | 收益 | 代价（良性环境） |
|---|---|---|---|
| **1** | 锚定审计 + 重锚 | 0.145（漂移场景） | **0（+0.033）** |
| **2** | Pareto 档案（cap=8） | 0.038–0.075 | **0（+0.033）** |
| 3 | 留出集门（简单二元） | 0–0.15（看场景） | +0.006 |
| 4 | 停摆监控 | 防唯一灾难 | +0.0002 |

**前两项 = 89% 收益，且零代价。这是实施的最小可行集。**

### 6.2 不该做什么（12 条被证伪）

层次化归并 · 近因加权 · 剔除矛盾样本 · 1/5 自适应步长 · 简单恢复解冻 · 回滚 · 元参数开放 · Δ分布自标定 margin · 跨库迁移 · 多岛迁移 · **按成分拒绝（本轮新增）** · 逐参数独立调优

### 6.3 三条不可能性

| 不可能性 | 证据 |
|---|---|
| **系统无法自知失败** | E78：6 种失败只识别出 1 种；E14：自报 +1.50 / 真实 −0.83 |
| **系统无法被自己的数据检验** | E57 双门挡不住共同偏差；E47/E58 规避审计；E24 剥削 margin |
| **自主性有注意力门槛** | E64：预算 <150 时终局恒为负；价格超线性 |

### 6.4 唯一可靠的三个外部性来源

1. **启用前采集的锚定集**（且必须刷新，E69）
2. **人类签名的元层**（制度兜底，与审计互为备份，E70）
3. **异质标注者**（把相关噪声变回独立噪声，E57）

### 6.5 回到第一条公理

> **不追求不犯错，追求犯错可查可回。**

- "不犯错"做不到：E80 复合场景下 v4 也失败；E78 系统甚至不知道自己在失败
- "可查"依赖外部参照：E34 阈值 0.85、E57 异质标注者、E69 锚定刷新
- "可回"靠重锚不靠回滚：E26 有效、E27 无效

十七轮推演从"让会修改自己的系统安全演化"出发，最终证明了：**这个问题的答案不在系统内部，而在系统与外部参照的关系中。**
