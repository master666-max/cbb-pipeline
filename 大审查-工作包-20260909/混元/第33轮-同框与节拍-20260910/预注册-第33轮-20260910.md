## 一、E143 · strict_cd + CUSUM + 轮换探针 三者同框

前两轮结论各自成立但从未同框：CD 重启治愈 strict（E141，PH+固定探针）、
CUSUM 在轮换下近乎免疫而 PH 误报升到 0.20（E142）。本轮组合：

- 臂：strict / strict_cd(CUSUM, k=0.0025 h=0.05, E139 冻结, 报警后重置) / reanchor
- 世界：none / drift / driftg / corrupt × n=44；探针**轮换**（Random(4242+g)）；audit 每 2 代
- 判据（锁定）：
  - H1：drift 场景 strict_cd − strict > 0 且 |t|≥2（治愈在轮换下存活）
  - H2：none 场景 strict_cd ≥ strict − 0.03（预期 ~11% 假重启无害——重启=放宽基线）
  - H3：corrupt 场景 strict_cd ≥ strict − 0.03（修复抢跑沉默是否在轮换噪声下保持）
  - driftg：探索性，无方向承诺（记录即可）

## 二、E144 · 修复延迟是否重开 corrupt 边界（节拍巧合检验）

第32轮 corrupt 零损失依赖"回退在一个审计间隔内修复读数"。本实验把修复延迟变成
架构参数：strict_slow = strict 但回退要求 streak ≥ 3（退化持续 3 个审计=6 代才修复）。
若 CD 在修复前的持续下跌中积累到报警 → 重启替代回退 → 故障未被修复 → 边界重开。

- 臂：strict_slow / strict_slow_cd(CUSUM 同上)；对照 strict 取自 E141 存档
  （同种子/世界/节拍/固定探针，直接可比）
- 世界：corrupt（主）/ drift / none × n=44；探针固定（隔离架构问题与轮换噪声）
- 判据（锁定）：
  - H4：corrupt 场景 strict_slow_cd − strict_slow < 0（边界重开；**若不重开则更好**
    ——CD 重启对延迟修复的架构也安全）
  - H5（探索性）：drift 场景 strict_slow_cd vs strict_slow 无方向承诺
  - 附带记录：每个 seed 的 CD 首报代 vs 实际修复代（赛跑的直接观测）
