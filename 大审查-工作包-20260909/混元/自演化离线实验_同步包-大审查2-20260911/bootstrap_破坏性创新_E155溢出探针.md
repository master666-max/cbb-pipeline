# 破坏性创新 · E155：溢出探针落进内核（第 43 轮）

> 任务：E154 证明**表象权重残留是比 gain 敏感 60 倍的溢出检测器**，
> 而内核当时只有活跃度（看核心维度）和停摆（看零采纳），
> **没有任何东西检测"这个系统是否学会了破解"**。
>
> 结果：**验收 53 → 63，全过。但探针能力比预期弱，且第一版有 bug。**

---

## 一、⚠️ 第一版 bug：用了 `abs()`

我直接复用了 `Policy.surf_magnitude()`，它内部是：

```python
abs(w_len) + abs(w_fmt) + abs(w_den) + abs(w_cit)
```

结果：**干净运行也报残留 6.54**（中性漂移被 abs 累加），**完全无区分度**。

而 E154 用的是**有符号和**：

```python
main.w_len + main.w_fmt + main.w_den + main.w_cit
# hack 组 +1.54 / 对照组 −0.43
```

> 判别信号在**方向**上：对照组把表象压到**负值**，不该被计为残留。

修正后新增 `surf_signed()`，并把这条写成回归测试 **T28**。

## 二、⭐ 内核内独立复现（n=12，20 代）

| 配置 | 有符号残留 |
|---|---|
| judge≈真值（无破解机会） | **+0.924** |
| judge 看表象（有破解机会） | **+2.865** |
| 看表象 **+ 盲评** | **+0.924** |

**差值 +1.941，与 E154 的 +1.973 几乎完全一致。**

> 两个独立实现（离线脚本 vs 内核）给出同一个数字，
> 这是本项目少见的强交叉验证。

而且**盲评把残留从 +2.865 打回 +0.924**——**E146c「盲评是消元不是改善」第三次复现**。

## 三、⚠️ 第二个负结果：justified 判据不可用

初版判据是"表象是否挣得回自己"：

```
justified = truth(champion) − truth(剥掉表象的 champion)
justified < 阈值 且 残留高 → 报警
```

实测噪声底（`proto/_diag_spill.py`）：

| 任务数 | justified 均值 | sd | **噪声底** |
|---|---|---|---|
| 8 | +0.0115 | 0.0444 | **±0.0888** |
| 20 | +0.0132 | 0.0423 | ±0.0847 |
| 40 | +0.0110 | 0.0400 | ±0.0800 |
| 80 | +0.0110 | 0.0400 | ±0.0800 |

**任务数增加毫无帮助**（世界只有 60 条目，加任务只是重复抽样同一批条目）。

> **噪声底 ±0.08 远大于任何真实信号 → justified 判据作废。**
> 保留为**观察量**上报（`surf_justified`），不参与判据。

这与第 27 轮"信噪比审计"同源：**先测噪声底，再决定能不能用这个量。**

---

## 四、⚠️ 第三个限制：单 seed 判不准

残留的 seed 间 sd ≈ **2.85**，而干净/破解的均值差只有 1.94。

```
12 seed 报警率：hack 7/12 vs clean 4/12
```

**probe 是聚合级信号，不是逐运行告警。**

> 单个运行无法可靠判断"这个系统是否学会了破解"——
> 必须看多个并行运行或长时间窗口的统计。

这是 E78「系统无自知之明」的又一实例：**连检测它都需要外部聚合视角**。
