# 自演化架构设计方案

> **目标定位**：自演化（系统能自主改进自己，且改进本身可审计、可测量、可回滚）是最高目标，不是可选项。
> 本文修正上一轮"先别做愿景 C"的判断，并给出可落地的架构与冷启动路径。
> 所有结论基于三个可运行原型的实测数据（`proto/evolve.py` / `evolve2.py` / `evolve3.py` / `proto/bs3v4.py`）。

---

## 零、先认错：上一轮的判断错在哪

上一轮我说："自动演化前置依赖不成立，因为 eval 判别力有问题（P1-6：检索排序与查询无关，recall@5 虚高），基准不可信时开自动演化等于给目标漂移开绿灯。"

**这个判断把"依赖未满足"当成了"不该做"。**

- 前半句对：eval 确实不可信
- 后半句错：eval 不可信是**可以修复的工程问题**，而且**自演化机制本身正是发现这类缺陷的最强手段**

实证：本次实验中，演化循环在无人指导的情况下把 `w_imp` 从 `1.0` 调到 `−0.5`——**这正是我做了整轮代码审查才找到的 P1-6**。系统自动发现了它需要 25 代 × 75 次评估。

**结论修正**：不是"eval 可信才能自演化"，而是**"有了自演化，eval 才有被持续校正的可能"**。两者是共生关系，不是先后关系。

## 一、可行性已验证：三个实验

### 实验 1 · 自演化真的能变好吗

以 **v3 默认配置作为起点（genesis）**，只让它变异自己的检索参数，元层（K=5、评测协议、任务集）冻结。

```
8 个随机种子，25 代 × 3 变异：
  留出集: 0.0328 → 0.8141   (均值 +0.78)
  为正的种子: 8/8

单种子细看（seed=1）：
  起点 v3 默认: w_kw=3.0, w_content=1.0, w_imp=1.0, w_age=0.1, filter_zero=0
  演化后      : w_kw=4.5, w_content=1.0, w_imp=0.5, w_age=0.1, filter_zero=1
  留出集: 0.0862 → 0.7663 (+0.68)
```

它自己找到了两个改进：**降低重要度权重**（P1-6）、**开启零命中过滤**（我列的 BUG-006 修复项）。

### 实验 2 · 作弊能刷分吗

注入"把重要度权重拉满"的贪婪变异：

```
w_imp=10  : 训练集 -0.6200  留出集 -0.6800
w_imp=100 : 训练集 -0.6163  留出集 -0.6838
```

**无法刷分**。原因不是检测更聪明，而是**结构性的**：`K=5` 和评测协议都在元层固定，堆权重改变不了"只有 5 个结果"这个事实。

> 这是最重要的设计教训：**防作弊靠结构约束，不靠更聪明的检测**。v3 的 `guard` 之所以能被绕过（patch 形态 / 删除 / 改内容不改名），正是因为它走的是检测路线。

### 实验 3 · 门控是必需的吗（关键实验）

构造一个**可被利用的伪相关**：真信号只有 60% 可靠；伪特征 `spur` 在训练集上 100% 指向金标、**在留出集上方向反转**。

| 训练任务数 | 有门控·留出集 | 无门控·留出集 | 无门控·训练集 | 有门控采纳伪特征 | 无门控采纳伪特征 |
|---|---|---|---|---|---|
| 12 | **+0.0819** | +0.0194 | +0.1806 | 0/12 | 1/12 |
| 20 | **+0.0962** | −0.0000 | +0.1708 | 0/12 | 2/12 |
| 40 | **+0.0781** | **−0.0521** | +0.1667 | 0/12 | 3/12 |

**这就是 reward hacking 的完整复现**：无门控系统在训练集上报告 +0.167 的"巨大进步"，实际留出集 **−0.052（倒退）**。它找到了一条刷高历史指标的捷径，而非真正变好。

而**双门（配对比较 + 留出集）在 12 个种子中 0 次采纳伪特征**。

> 注：前两版实验（evolve.py / evolve2.py）我没能造出这个差异——世界太干净、伪信号太弱、每组条目数 < K 导致金标必然被召回。**第三版才构造成功**。这本身说明：过拟合需要特定条件才会发生，但一旦发生，没有门控就是灾难。

## 二、架构：三层 + 演化循环

### 2.1 三层模型（核心：方向性约束）

| 层 | 内容 | 谁能改 | 变更方式 |
|---|---|---|---|
| **元层 Meta** | 评测协议、任务集、效用函数、显著性阈值、K、档案策略、铁律 | **仅人侧签名** | git 保护 + 全量重算对账 |
| **法层 Law** | 检索参数、阈值、启发式、提示词、包状态机、档位定义 | **系统自主演化** | 变异 + 双门选择 |
| **行层 Action** | 记忆条目、情绪、索引 | 自由写入 | 事后可审计 |

**关键：变更只能向上申请，不能向下修改。**
法层永远改不了元层——**系统无法修改评判自己的尺子**。这一条结构性消灭了 objective hacking（`CHARTER_L8` 里点名的风险）。

### 2.2 演化循环（DGM 式）

```
  档案 Archive（谱系完整，可回滚到任意祖先）
     │  采样父代（70% 取 top3，30% 随机 —— 保持多样性，避免局部最优）
     ▼
  变异 → 候选配置
     │
     ▼
  影子执行（git 分支 / shadow，不改主线）
     │
     ▼
  配对比较：同一批任务、同一随机种子，逐任务求 Δutility
     │
     ▼
  双门判定：Δ(train) > margin  AND  Δ(held-out) > margin
     │                                    │
   否 → 丢弃（留档，不作废）              是 → 入档案 → 推广主线 → 记账 + 入链
```

三个不可省略的设计：

1. **配对比较（paired）而非绝对分**——同任务对比，消除"任务难度"混淆。方差比独立比较小一个量级
2. **留出集门**——实验 3 证明这是防过拟合的唯一有效手段
3. **档案多样性采样**——只从最优变异会卡在局部最优（DGM 的关键创新：开放式探索）

### 2.3 与既有设计的对接

| 已有机制 | 在自演化架构中的角色 |
|---|---|
| `chain_append` / 事件流 | 演化谱系的审计面（每次变异 = 一个事件） |
| `chain_tip` 三元组 | 元层锚点，防谱系被截断 |
| `git` 后端 | 影子分支 = 变异沙盒；revert = 回滚；`-S` = 人侧签名 |
| `engine shadow` | 从"记一行日志"升级为"真正执行并测量" |
| `evals/golden_queries.json` | 元层任务集（当前不可信，需重建） |
| 慢车道 | 元层变更的门禁（复用现有逻辑） |
| 能力式边界 | 让"违反铁律的变异"不可表达 |

## 三、冷启动阶梯：从今天到自演化

最大的现实障碍不是架构，是**没有任务集**。v3 现在的 `evals/golden_queries.json` 判别力已被证明有问题（P1-6）。

所以路径是**先积累燃料，再点火**：

| 阶段 | 做什么 | 产出 | 风险 |
|---|---|---|---|
| **S0 影子期** | 系统照常跑，记录每次检索了什么、哪些被真正采纳、任务结果如何。**不做任何自动变更** | 真实任务轨迹库 | 无 |
| **S1 建任务集** | 从轨迹中提取 N 个可复现任务（≥50，含留出集），标注金标 | `evals/tasks.json`（元层，人侧签名） | 标注质量决定上限 |
| **S2 离线回放** | 只用历史配置回放评测，验证评测协议本身稳定（同一配置重复跑，分数波动 < 阈值） | 评测协议可信度报告 | 无（只读） |
| **S3 参数层自演化** | 开放法层的数值参数（权重、阈值）自动演化，双门控 | 自动调参，且每次进步都有留出集证明 | 低（可回滚） |
| **S4 结构层自演化** | 开放结构变更（是否启用过滤、检索器选型），人抽样裁决 10% | 结构性改进 | 中 |
| **S5 规则/提示词层** | 开放提示词与启发式演化，**元层仍冻结** | 接近完整自演化 | 高，需全套护栏 |

**S0–S2 不需要任何自动变更，可以立刻开始**——这也是最容易被忽略的一点：冷启动期做的事（记录轨迹）本来就该做，不管要不要自演化。

### 效用函数怎么定（这是全系统最关键的一行）

实验里的目标函数：`命中金标 +1，每掺入 1 条无关条目 −0.15`

对真实系统，建议的起点：

```
utility = w_task · 任务成功率
        − w_noise · (检索出的条目中被实际采纳的比例倒数)
        − w_cost  · (token / 步数)
```

**警告**：效用函数定义了"什么叫做更好"。写错它，系统就会高效地优化错误的目标——这是**设计层的 objective hacking，元层机制防不住**。所以效用函数属于元层，变更需人侧签名。

## 四、红线（不可让渡）

1. **元层不可被自动修改**——系统永远不能改评判自己的尺子
2. **自演化不能修改"自演化能否发生"的规则**——否则可能自我关闭监督
3. **任何自动采纳必须可回滚**——档案保留完整谱系（实验验证：12/12 种子"可回滚=True"）
4. **效用函数变更 = 元层变更 = 人侧签名**
5. **能力声明不得强于实际能力**（公理 G）——不声称防住了③档

## 五、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 任务集不具代表性 | 演化出的策略过拟合到任务分布 | 任务集持续扩充；定期人工注入新分布任务；留出集滚动更新 |
| 效用函数写错 | 系统高效优化错误目标 | 元层锁定 + 人侧签名；多目标冲突项相互制衡（成功率 vs 噪声 vs 成本） |
| 递归自我改进失控 | 改掉"改进过程"本身 | 元层硬约束；改进算子本身属于元层 |
| 谱系膨胀 | 档案无限增长 | 定期 `compact`（保留 Pareto 前沿 + 随机样本，不删除，移 attic） |
| 过拟合（实验 3） | 报告进步、实际倒退 | **双门**；margin 随样本量自适应 |

## 六、与前述方案的关系

自演化**不替代**事件溯源 / git 后端 / 能力式边界，而是**建立在它们之上**：

```
能力式边界（违规不可表达）     ← 保证演化不会越界
      ↓
git 后端（分支=影子，revert=回滚，-S=人侧签名）  ← 提供演化的沙盒与安全网
      ↓
事件溯源（谱系 = 事件流）      ← 提供演化的记忆与归因
      ↓
自演化循环（变异-配对比较-双门-档案）  ← 最上层，真正让系统自己变好
```

**实施顺序**（与前述工单集合并后）：

```
CP0 冷启动数据：S0 影子期 + S1 任务集 + S2 离线回放      ← 可立刻开始，零风险
CP1 安全底座：chain_tip + 能力式边界 + git 后端
CP2 结构重构：事件溯源 + 分层 + UoW
CP3 自演化 S3：参数层自动演化（双门 + 档案）
CP4 自演化 S4/S5：结构层、规则层，人抽样裁决
```

---

## 七、一句话

自演化不是"先把一切做对才敢碰的奢侈品"，而是**发现问题能力最强的那套机制本身**——实验里它用 75 次评估自动找到了我做整轮代码审查才发现的同款缺陷。

真正的前置条件只有一个：**有一把可信的尺子**。而那把尺子（效用函数 + 任务集）属于元层，由人签字、系统碰不到。

有了它，就可以点火。
