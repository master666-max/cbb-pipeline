# MEM-EVOLVE-SANDBOX · agent 记忆库自演化引擎沙盒实验设计

> 目标：在受控沙盒里**用可运行的原型**论证「记忆库自演化引擎」的架构可行性与边界条件，而不是纸上推演。
> 被测对象：`bootstrap_v3.py`（v3.8.1，2415 行）的真实记忆内核 + 一套外接的自演化引擎（法层）。
> 依据：`自演化推演_实验总报告-14轮后.md` 的 66 个实验结论与本仓库对源码的静态/动态复核。
> 日期：2026-09-08

---

## 0. 一句话总览

把 `bootstrap_v3.py` 的**行层**（记忆条目/审计链/账本/根）当作不可改的事实层，把它的**法层**（检索权重、热度预算、TTL、重组方式、importance 口径）参数化为「基因」，在其上跑一个带两级门控 + 开放式档案 + 锚定审计的演化循环；用**静态记忆库**与**若干消融臂**作对照，在五种已知地形上量化「存储 / 更新 / 遗忘 / 重组」四项能力与四项成本。

**本实验不试图证明"自演化一定更好"**，而是给出一张可判定的表：在什么条件下值得演化、哪些护栏是必需的、哪些"听起来合理"的设计是无效的。

## 1. 实验目标与假设

### 1.1 主目标（G）

- **G1 有效性**：自演化能否在**冻结审计集**上带来可泛化的净收益（而非只在训练集/留出集上好看）。
- **G2 安全性**：在无护栏时是否会自信地走错（reward hacking / 评判者漂移），护栏能否阻止。
- **G3 一致性**：自演化过程是否破坏记忆库自身的审计面（五态对账 / 哈希链 / 根 / 铁律）。
- **G4 成本**：演化收益相对注意力预算与计算开销是否划算；是否存在"低于阈值反而有害"的门槛。

### 1.2 假设与零假设（全部预注册，见 §8.3）

| # | 假设（H₁） | 零假设（H₀） | 对应报告实验 | 判据（冻结审计集 ΔU） |
|---|---|---|---|---|
| **H1 存储/检索** | 自演化能自动发现 v3 检索参数的缺陷，ΔU ≥ +0.10 | ΔU ≤ 0 | E1 | clean 地形 two-tier − static |
| **H2 更新** | importance 由"自称"改为"实测采纳率"能提升 top-10 条目真实质量 ≥ +15% | 无差异 | E32 | `run.py importance` |
| **H3 遗忘** | 目标/策略切换后，Pareto 档案能保留旧目标能力（不低于切换前） | 单一最优同样能保留 | E16 | `run.py forget` |
| **H4 重组** | 层次化归并**不优于**平铺（否定性假设） | 层次化更优 | E28 | `run.py reorg` |
| **H5 防过拟合** | 伪特征地形下：无门控 ΔU < 0，两级门控 ΔU ≥ 0 | 门控无作用 | E3/E7 | pseudo 地形 none vs two-tier |
| **H6 跨低谷** | 欺骗地形下：严格准入 0/N 逃出，两级门控 ≥ 8/N 逃出 | 无差异 | E7 | deceptive 地形 escaped 计数 |
| **H7 漂移可见** 〔判据已按实测修正，见 §9.4〕 | 无锚定出现**峰值后回撤**（漂移把已获得的收益吃掉一部分）；加锚定后回撤显著降低（配对 bootstrap 下界 > 0），且 α=0 时零误报 | 锚定无作用 | E14/E34 | drift 地形 ±anchor，α 扫描 |
| **H8 成本门槛** | 注意力预算 < B\* 时终局 ΔU ≤ 0；存在超线性门槛 | 线性、无门槛 | E64 | `run.py budget` 曲线形状 |
| **H9 一致性** | v3 在并发写下丢更新 > 0；截断攻击在**无外部锚点**时检不出、有人侧抄录时可检出 | v3 自洽 | §2.3/P0-4 | `run.py consistency` |
| **H10 演化≠搜索** | 同等评估预算下，演化显著优于随机搜索 | 二者等价 | （本设计新增对照 G5） | clean 地形 two-tier − random |

> **H4 / H7 是否定性/条件性假设**，必须按预注册口径如实报告，不得事后改判据。

### 1.3 非目标（Out of scope）

- 不评估 LLM 合成质量（反思/摘要的语义好坏）——沙盒里没有 LLM，演化的只有可计算参数。
- 不评估真实用户记忆库上的效果（无金标，无法算 recall）。
- 不做跨库迁移（E18 已给出负面结论，需先建立分布相似度度量）。

## 4. 沙盒架构（三层边界）

```
┌──────────────────────────────────────────────────────────┐
│ 锚定层（人侧，不可触碰）                                   │
│   W0 初心效用权重 / 40 条锚定判断样本 / 冻结审计集          │
└──────────────────────────────────────────────────────────┘
                  ↑ 方向性约束：只能向上申请，不能向下修改
┌──────────────────────────────────────────────────────────┐
│ 元层（人侧签名，系统不可达，实验期间冻结）                  │
│   K=5 / 评测协议 / 任务集 / 效用权重 W / margin / tol       │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ 法层（自演化引擎可自主修改）— genome.py 的 12 个基因        │
│   w_kw w_content w_imp w_age filter_zero link_spread      │
│   importance_source hot_budget ttl_days max_age_days      │
│   merge_mode longterm_cut                                 │
│   变异 → 廉价筛选(仅 reject) → 宽松准入档案 → 双门晋升      │
└──────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────┐
│ 行层（真实 bootstrap_v3 语义，自由写入）                    │
│   memory/ audit/ ledger/ state.json evals/                │
│   采纳日志（反馈）→ measured importance                    │
└──────────────────────────────────────────────────────────┘
```

**四项能力 ↔ 基因 ↔ 源码** 的对应（这是"存储/更新/遗忘/重组"四个词在本实验里的操作化定义）：

| 能力 | 操作化定义 | 可演化基因 | 源码依据 |
|---|---|---|---|
| **存储** | 条目写入、冷热/长短分层、容量约束 | `longterm_cut` `hot_budget` | `cmd_engine append` L927 分层；`index_hot_budget` |
| **更新** | importance 的口径与刷新 | `importance_source`（self / measured） | `wrapup`→`reflect` 链；E32 |
| **遗忘** | TTL 出仓 + 生存期闸门 + 热度逐出 | `ttl_days` `max_age_days` `hot_budget` | `retire` L1075（移 attic，铁律1） |
| **重组** | 链接扩散强度 + 归并方式 | `link_spread` `merge_mode` | `_rank_entries` L908；E28 |

## 5. 实验步骤

### Phase 0 · 门禁（不通过不得开跑）

```bash
py -3.14 harness/run.py selftest
```

两道硬门禁：

1. **等价性门禁**：把世界条目落到真实库，跑真实 `_rank_entries`，与参数化内核 `kernel.score_all` 在默认基因下**逐条同分**对比。
   > 必要性：演化循环需要上万次评估，真实函数每次都 `rglob` + 读盘，IO 会主导测量；重实现必须被证明同构。
   > 实测：`checked=1020, mismatch=0, passed=True`
2. **冲突存在性门禁**：`(recall@5, −cost_norm)` 的 Pareto 前沿必须 ≥2 点。
   > 必要性：报告「实验设计失败 #4」——目标不冲突时，比较选择策略/档案策略毫无意义。
   > 实测：前沿 5 点；`hot=20` → recall .375/cost .047；`hot=400` → recall .925/cost .877（真实权衡成立）

### Phase 1 · 一致性基线与架构判据（C1–C5）

```bash
py -3.14 harness/run.py consistency --procs 12
py -3.14 harness/run.py concurrency --procs 12
```

| 探针 | 操作 | 预跑实测 |
|---|---|---|
| C1 五态对账 | 干净库跑真实 `doctor` | `五态 全一致 = True` |
| C3-a 截断（完整回滚） | 去掉尾部 k 个事件的记忆条目+审计行+账本行，重算根并写回 `state.json` | `detected_internal = **False**`，`detected_by_human_anchor = True` |
| C3-b 截断（仅删审计行） | 只删审计链尾部 | `detected_internal = **True**`（集合差能抓到） |
| C4 并发写 | 12 进程并发 `append(importance=5)` | v3 丢失 **23.8%**（210→160）；v4 事件溯源 **0%** |
| C5 铁律 2/5 | `validate_entry` 注入空 `source_event_id` / `sk-` 密钥 | 铁律 2 **未拦截**（空串绕过，复现 P0-2）；铁律 5 拦截正常 |
| R1 Merkle 伸缩 | 50/100/200/400 条目全树重算 | 0.021 / 0.038 / 0.073 / 0.140 s → **线性 O(n)** |
| G 自测诚实性 | `render_quickref(0)` vs `(999)` | 输出随 n 变化（`depends_on_n=True`） |

> 修正报告的一处结论：截断攻击在**有人侧抄录**时 v3 也能检出（根变了），v4 同样。二者的真正差距在**并发**（RMW vs 事件重放）与工程成本，不在"能否检出截断"。

### Phase 2 · 主实验：五地形 × 六对照臂

```bash
# 干净地形
py -3.14 harness/run.py evolve --terrain clean   --cfgs static none strict-admit two-tier two-tier+anchor random --seeds 24 --gens 60
# 伪特征（reward hacking）
py -3.14 harness/run.py evolve --terrain pseudo  --cfgs static none two-tier --seeds 24 --gens 60
# 欺骗地形（适应度低谷）— 必须隔离基因，否则其他维度收益会淹没目标效应
py -3.14 harness/run.py evolve --terrain deceptive --cfgs strict-admit two-tier --seeds 24 --gens 60 --genes w_kw filter_zero
# 目标切换
py -3.14 harness/run.py evolve --terrain switch  --cfgs static two-tier --seeds 24 --gens 60
# 评判者漂移（α 扫描）——阈值**必须先标定**，再扫 α
py -3.14 harness/run.py calibrate --alphas 0.0 0.10 --seeds 8 --gens 40
$env:ANCHOR_THRESHOLD='<标定值>'
py -3.14 harness/run.py sweep --alphas 0.0 0.05 0.10 0.20 0.30 --seeds 12 --gens 40
py -3.14 harness/run.py sweep-show       # 紧凑表 + 配对 bootstrap 检验
```

**五种地形的构造与用途**

| 地形 | 构造 | 要检验的东西 |
|---|---|---|
| `clean` | 无伪特征、无低谷 | 有效性上界（H1/H10） |
| `pseudo` | 伪特征 `xpf` **独占正文通道**，训练集金标与 xpf 同向、留出/审计集**反转** | 门控能否防过拟合（H5） |
| `deceptive` | 关键词通道做成检索中立（只放噪声），地形项使 `(w_kw≥4 且 filter_zero=1)` 才是全局最优，且**任何单步都先变差** | 两级门控能否跨低谷（H6） |
| `switch` | 第 30 代目标权重从「召回优先」切到「排序优先」 | 灾难性遗忘（H3） |
| `drift` | 评判者权重被系统当前输出锚定 `w ← (1−α)w + α·dir(feats(主线))` | 漂移可见性（H7） |

### Phase 5 · 消融（定位"哪条护栏在赚钱"）

按 `--cfgs` 逐条叠加：`none` → `+廉价筛选` → `+留出集门` → `+Pareto 档案` → `+锚定审计` → `+停摆监控`。
判据：以 `static` 为 0 点，报告每项的**边际 ΔU**（报告 E66：档案与锚定审计贡献约 85%）。

## 6. 评估指标

四类共 20 项。**自报值与实测值必须分列**，禁止用被测系统的自报值下结论（报告 E8/E32）。

### A. 检索准确率（效果）

| 指标 | 定义 | 采集点 |
|---|---|---|
| `recall@5` | 金标条目出现在 top-5 的查询占比 | 训练 / 留出（轮换）/ **审计（冻结）** 三处分别报 |
| `MRR` | 首个金标名次倒数的均值 | 同上 |
| `ΔU_audit` | **主指标**：冻结审计集上终局效用 − 起点效用 | 每 run 一次 |
| `top10_true_quality` | 按 importance 取 top-10 的**真实质量**均值 | H2 专项 |

### B. 记忆一致性（安全）

| 指标 | 定义 | 来源 |
|---|---|---|
| C1 五态对账一致率 | memory/audit/ledger/链/state 五项差异全空 | 真实 `doctor` |
| C2 哈希链连续率 | 逐行重算 `line_hash` + 跨月续接 | 真实 `doctor` |
| C3-a 截断检出（内部） | 完整回滚后无任何内部信号报警 | 探针 |
| C3-b 截断检出（人侧锚点） | 与人侧抄录的 Merkle 根 / chain_tip 比对 | 探针 |
| C4 并发写丢失率 | `1 − 实测accum / 期望accum` | 12 进程并发 |
| C5 铁律拦截率 | 铁律 2（空证据锚）/ 铁律 5（密钥）是否被 `validate_entry` 拒绝 | 探针 |

### C. 演化效率

| 指标 | 定义 |
|---|---|
| `evals` | 达到终局所消耗的评估次数（= 注意力成本的代理） |
| `adoptions / gens` | 采纳率；连续 0 采纳 = 停摆（E44 监控器输入） |
| `escaped` | 是否逃出局部最优（欺骗地形专用，H6 判据） |
| `front_size` / `pool_size` | Pareto 前沿与变异池规模（多样性） |
| `gens_to_target` | 达到目标 ΔU 所需代数（H8 效率口径） |

### D. 资源开销

| 指标 | 定义 | 预跑实测 |
|---|---|---|
| `merkle_seconds(n)` | Merkle 全树重算随条目数的曲线 | 线性，400 条目 0.14s |
| `wall_seconds` | 单 run 墙钟 | 25 代 × 300 条目 ≈ 10–16 s |
| `storage_bytes` | 活跃条目序列化字节数 | 每代记录 |
| `cost_norm` | 扫描面占全库比例（检索成本的效用内项） | 0.05–0.88 |
| `attention_budget` | 初始判断样本 40 + 每代裁决 1 + 每 10 代审计 5 | `metrics.max_gens` |

## 7. 对照组设置

| 臂 | 配置 | 目的 | 期望 |
|---|---|---|---|
| **G0** `static` | v3 默认参数，**不演化** | 绝对基线（ΔU ≡ 0 by construction） | 0 |
| **G1** `none` | 每代取训练集最优直接晋升，**无门控** | 检验"没有护栏会怎样" | clean 好、pseudo/drift **灾难** |
| **G2** `strict-admit` | 每步必须在训练集上变好，无档案 | E7 反例：严格准入跨不过低谷 | deceptive **0/N 逃出** |
| **G3** `two-tier` | 宽松准入 + 双门晋升 + 开放式档案 | 目标架构 | 全地形最稳 |
| **G4** `two-tier+anchor` | G3 + 锚定审计（阈值 0.85） | 漂移专用 | drift 地形下避免转负 |
| **G5** `random` | **同等评估预算**的随机搜索 | 判别"演化"是否只是"搜索" | 应显著差于 G3 |
| **G6** `v4core` | 事件溯源内核 | 架构替换的收益/成本 | 并发 0% 丢失 |

**消融维度**（在 G3 上逐项开关）：`--archive single|pareto`、廉价筛选、留出集轮换 `--rotate`、`--genes <子集>`（隔离实验）。

> **方法论硬要求**：验证一条护栏前，必须先构造它所防范的危险。在 clean 地形下"违反某条红线也没差别"**不构成否定该红线的证据**（报告 E41 的方法论警告）。

## 8. 数据采集与分析

### 8.1 采集

- 每个 run 产出 `runs/<name>/log_s<seed>_<cfg>.json`（逐代 JSONL 化的 list）+ 汇总 `summary.json`。
- 逐代字段：`gen / adopted / rejected_by_cheap / u_train / u_hold(真实) / u_audit / u_perceived / front / pool / frozen / anchor{agreement,drifted} / stall_margin / genome / bytes / sec`。
- **原始日志与派生指标分离**：只写原始量，聚合在分析阶段做，避免"采集中就把结论算死"。

### 8.2 分析

1. **配对比较**：同地形、同种子、同代数下逐对照臂配对，报告 Δ 的均值 ± 标准差、正号种子数。
2. **显著性**：配对 bootstrap（1000 次重采样）的 **95% 置信下界**；判据严格写成 `下界 > max(0, margin)`（红线 15，否则 margin 为负时判据被架空）。
3. **主指标固定为冻结审计集的 ΔU**；留出集只用于门控，不作为对外结论（红线 11）。
4. **地形分层汇报**：禁止跨地形求平均后下单一结论（报告 E63 显示各场景符号可相反）。
5. **否定性结果同等对待**：H4/H7 若无差异，按预注册口径报"未获证实"，不做 HARKing。

### 8.3 预注册（开跑前完成，写入 `runs/prereg.md`）

- 假设与判据：§1.2 表格原样落地；
- 样本量：每格 **24 种子 × 60 代**（预跑 6–12 种子已足够看出分离度）；
- 排除规则：仅当 run 崩溃/超时才排除，且必须记录；**不得因"结果不好"排除种子**；
- 停止规则：达到 24 种子即停，不做"再跑 5 个种子看看能不能显著"（peeking）。

### 9.4 H7 判定：drift 地形 α 扫描（12 种子 × 40 代，阈值已标定为 0.95）

| α | two-tier ΔU / 峰值 / **回撤** / 自报−真实 | +anchor ΔU / **回撤** / 自报−真实 / 冻结 |
|---|---|---|
| **0.00** | +0.5408 / 0.721 / **0.0009** / +0.000 | +0.5408 / **0.0009** / +0.000 / **0/12** |
| 0.05 | +0.5175 / 0.728 / **0.0315** / +0.165 | +0.5351 / **0.0102** / +0.144 / 11/12 |
| 0.10 | +0.4969 / 0.716 / **0.0396** / +0.228 | +0.5166 / **0.0156** / +0.184 / 11/12 |
| 0.20 | +0.4961 / 0.710 / **0.0346** / +0.238 | +0.5188 / **0.0089** / +0.199 / 12/12 |
| 0.30 | +0.5006 / 0.710 / **0.0301** / +0.231 | +0.5120 / **0.0157** / +0.205 / 12/12 |

配对 bootstrap（`two-tier − two-tier+anchor`，同种子，判据 = 下界 > 0）：

| α | ΔU 差（下界） | **回撤差（下界）** | 回撤差为正的种子 |
|---|---|---|---|
| 0.00 | +0.0000（+0.0000） | +0.0000（+0.0000） | 0/12 |
| 0.05 | −0.0177（−0.0285） | **+0.0213（+0.0122）** | 8/12 |
| 0.10 | −0.0197（−0.0369） | **+0.0239（+0.0076）** | 10/12 |
| 0.20 | −0.0227（−0.0349） | **+0.0257（+0.0156）** | 9/12 |
| 0.30 | −0.0114（−0.0181） | **+0.0144（+0.0100）** | 9/12 |

**结论：H7 成立（有条件）。**

1. **漂移确实有害，但形态是"回撤"不是"转负"**：本世界里检索 headroom 大于漂移造成的损失，所以终局 ΔU 始终为正；漂移的可观测伤害是**先涨到峰值再被吃掉一部分**（回撤 0.030–0.040），而 α=0 时回撤 ≈ 0.0009 —— 回撤确实由漂移引起。H7 的原判据"ΔU 显著下降/转负"不成立，**已按实测修正为峰值后回撤**（与报告"十四轮里推翻自己 14 次"同构，属于开跑后的判据修正，如实记录）。
2. **自报−真实缺口**随 α 单调上升并饱和（0 → 0.165 → 0.228 → 0.238 → 0.231），E14 的"自报 +1.50 真实 −0.83"现象复现。
3. **锚定有效且统计显著**：回撤从 0.030–0.040 降到 0.009–0.016（降 60–75%），四个 α 的配对 bootstrap 下界均 > 0。
4. **冻结只是"停下"，不是"变好"**：冻结后自报−真实缺口仍残留 +0.14~+0.21。这与报告 E26/E27 一致——真正解决问题的是**重锚**（重新采集人类判断），不是冻结/回滚。本沙盒未实现重锚，列为后续工作。

### 9.2 Go / No-Go 判据

| 能力 | Go（可行） | 边界（有条件可行） | No-Go（不可行） |
|---|---|---|---|
| **存储/检索** | ΔU_audit ≥ +0.10 且 ≥ 20/24 正 | 0 < ΔU < 0.10 | ΔU ≤ 0 或正号种子 < 12/24 |
| **更新** | top-10 真实质量 +≥15% | +5%~15% | ≤ +5%（E32 不成立） |
| **遗忘（防灾难性遗忘）** | Pareto 保留旧目标能力 ≥ 起点且 > 单一最优 | 与单一最优持平 | Pareto 反而更差 |
| **重组** | （预期否定）层次化不优于平铺 → 记为"归并降维无效，改用减少目标数" | — | — |
| **防过拟合** | pseudo 下 none < 0 ≤ two-tier | 两者皆 ≥ 0（说明伪特征构造失败，需重做地形） | two-tier < 0 |
| **跨低谷** | deceptive 下 strict 0/N、two-tier ≥ 8/N | 2–7/N | two-tier ≤ 1/N |
| **漂移可见** | α=0 零误报 **且** α≥0.05 回撤差的配对 bootstrap 下界 > 0 | 只满足其一 | 两条都不满足 |
| **成本** | 预算 ≥ 300 时 ΔU > 0 且存在明显门槛 | 线性收益但无门槛 | 任何预算下 ΔU ≤ 0 |
| **一致性** | 并发丢更新 > 0 被复现；截断在双口径下结论明确 | — | — |

### 9.3 决策含义

- **全部 Go** → 自演化引擎可进入工程实现；建议实施顺序按 E66：`停摆监控 → 留出集门 → Pareto 档案 → 锚定审计 + 重锚`（后两项贡献约 85%）。
- **存储 Go 但安全项 No-Go** → 只能做**参数自适应**（离线标定 + 上线冻结），不能做在线自演化。
- **一致性 No-Go（演化破坏审计面）** → 必须先把底座换成事件溯源内核（G6 已验证并发 0% 丢失）再谈自演化。

## 10. 已知限制与未验证项

1. **地形是合成的**。`deceptive` 的低谷由**显式塑形项**构造（效用里加了人侧定义的地形项），不是自然涌现；它的价值在于"已知结构的判别力校验"，不代表真实库存在同构低谷。
2. **没有 LLM**。反思/摘要的语义质量、提示词演化均未纳入；本实验只演化可计算参数。
3. **注意力成本是建模值**（初始 40 条判断 + 每代 1 次裁决 + 每 10 代 5 次审计），不是真实人类实验。H8 的**曲线形状**可信，绝对阈值不可外推。
4. **锚定审计的零误报是"无标注噪声"下的上界**。本沙盒中 α=0 时一致率**恒等于 1.000**（同一批查询、同一份规范化库状态、同一批基因组，无任何采样噪声），因此"零误报阈值"是乐观值。真实系统存在标注噪声与采样噪声，必须按 E52/E57 注入**独立噪声**与**相关噪声**后重新标定；E57 已证明双门挡不住相关噪声。
5. **漂移只在第 15 代之后注入**（`drift_start=15`）。这是为了让漂移发生在检索 headroom 被消耗之后，否则漂移伤害会被 headroom 掩盖（实测 α=0.20 且 drift_start=0 时两组完全持平，测不出任何东西）。代价是：本实验不覆盖"系统边吃 headroom 边被带偏"的早期漂移形态。
6. **重锚未实现**。冻结能止损（回撤降 60–75%）但不能消除自报−真实缺口（残留 +0.14~+0.21）；报告 E26 指出真正有效的是重锚，本沙盒未做，列为后续工作。
5. **真实库未接入**：`install`/`absorb`/`guard` 全链路只在临时目录里跑，未对用户的真实记忆库做过任何写操作。
6. `_rank_entries` 的重实现依赖等价性门禁（1020 对 0 失配）；若后续修改 `bootstrap_v3.py`，**必须重跑 `selftest`**，否则后续所有数据作废。

## 11. 开跑后发现并修掉的三个陷阱（方法论产出）

这三个都是"看起来在测 A，实际在测 B"型错误。**每一条都曾让 H7 完全没有分离度**，且都不会报错。

### 11.1 锚定阈值未标定 → 无漂移时 11/12 误报并冻结

直接套用报告 E34 的 0.85：α=0（**完全没有漂移**）时一致率最低 0.583，11/12 个 run 被判漂移并冻结演化，
终局 ΔU 从 +0.5408 掉到 +0.4142，**净损失 0.127**。护栏本身变成了伤害源。
修法：加 `calibrate` 子命令，先在零漂移基线上测一致率分布，再定阈值（本沙盒标定为 0.95）。
修后 α=0 与 two-tier **逐位相同**（0/12 冻结，差值 0.0000）。

> 与报告 E34 同构（阈值 0.95 → 92% 误报，降到 0.85 才零误报）。**阈值是世界的函数，不是常数。**

### 11.2 锚定审计测到的是"库状态漂移"，不是"权重漂移"

标注用**全新库**打分，审计用**演化中的活库**打分——热层/attic/采纳日志都不同，
成对序被状态差异翻转，与权重是否漂移无关。实测 α=0 与 α=0.10 的一致率分布**几乎完全重叠**
（min 0.583 vs 0.500），分离度为零。
修法：审计必须在与标注**完全相同的规范化库状态**上打分（`scorer` 内部新建 `Library` 并 `apply(g)`），
使唯一变量是效用权重。修后 α=0 一致率恒为 1.000，α=0.10 的 min 0.500 / 中位数 0.917。

### 11.3 `time.strptime` 被调用 246 万次，占 60% 墙钟

`age_days` 对每个条目、每个查询都重新解析一次日期字符串。cProfile：`age_days`→`_ts`→`strptime`
累计 25s / 42s，单个 10 代 anchor run 要 20s，α 扫描因此慢到不可用。
修法：`_ts` 加 `functools.lru_cache` + 预计算关键词/正文文本块 + 把扫描面占比的计算移出查询循环。
**加速 7.5×**（anchor run 20.1s → 2.7s，锚定集构造 2.40s → 0.40s）。
等价性门禁在优化后重跑仍为 1020 对 0 失配，确认是纯性能改动、未改语义。
