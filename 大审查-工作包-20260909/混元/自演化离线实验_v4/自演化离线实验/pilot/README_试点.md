# 自演化试点 · 部署指南（你的环境里跑）

> 你选了**真实试点**，但我不部署在本地。
> 所以交付物是：**一套能丢进你环境的最小探针 + 一个在你环境里跑的离线分析器**。
> 你只需接入 3 行，跑一段时间，把分析器输出贴回来，我据此设计 S1。

```
pilot/
├── pilot.py     探针（标准库，零依赖，零行为改变）
├── analyze.py   离线分析器（本地跑，不联网）
└── README_试点.md
```

## 一、为什么先做"影子期"而不是直接开演化

| 依据 | 结论 |
|---|---|
| **E64** | 注意力预算 <150 时，自演化**终局恒为负**——跑完不如不跑，而内部指标全绿 |
| **E17** | n=10 时假阳性率 **42%**，小样本下一半"改进"是纯噪声 |
| **E105** | 把预算全投在审计上是**负收益**（−0.030） |
| **E32** | 重要性应当**实测**（被检索后是否被采纳），系统本就有这个数据 → **零标注成本** |

**影子期只记录、不改任何行为，风险为零，今天就能开始。**

## 二、接入（三步）

### 第 1 步：放文件

把 `pilot.py` 拷到你的项目里。标准库，无依赖。

### 第 2 步：包住你的检索函数

```python
from pilot import Pilot
P = Pilot("/var/log/traces.jsonl")     # 路径自选

# 你的检索函数，行为完全不变
wrapped = P.wrap(
    my_retrieve,
    id_of  = lambda x: x["id"],                      # 条目标识
    feat_of= lambda x: {"kw": x["kw_score"],         # ★ 关键：把排序用得到的特征记下来
                        "recency": x["age_days"],
                        "importance": x["importance"]},
)
results = wrapped(query)      # 用法与原来一致
```

### 第 3 步：在"真的被采纳了"的地方调一次

```python
# 用户点了 / 下游用了 / 你确认它有效时
P.adopt(chosen_item["id"])
```

**这是全部工作量。** `wrap` 内部 try/except 包住，记录失败绝不影响业务。

### 手工模式（如果 wrap 不方便）

```python
P.log(query="...", candidates=[{"id": "a", "feat": {...}}, ...], adopted_id="a")
```

## 三、采集多久？

**经验值：至少 200 条轨迹，理想 1000+。**

分析器会自己算统计功效（Q1）——它会告诉你"检出 10% 的改进需要多少条"，
以及当前够不够。**不够就继续攒，别急着开演化。**

## 四、跑分析

```bash
python3 pilot/analyze.py /var/log/traces.jsonl              # 打印报告
python3 pilot/analyze.py /var/log/traces.jsonl -r out.md    # 存成文件
```

输出四问：

| 问 | 对应实验 | 不达标意味着什么 |
|---|---|---|
| Q1 采纳信号够强吗 | E17 | 样本不足 → 继续攒 |
| Q2 实测重要性 | E32 | 条目间是否有真差异 |
| Q3 反事实回放能改进吗 | E3/E8 | **留出集收益才算数** |
| Q4 预算够吗 | E64 | <150 恒为负 |

## 五、已做的端到端验证

我用模拟环境跑通了整条链路（600 / 1200 条轨迹）：

**场景 A · 关键特征没被记录**（采纳取决于 `qual`，但只记了 `imp`/`fmt`）

```
MRR 基线 0.4718 → 调优后 0.4448   留出集收益 −0.0270
结论：⏸ 继续影子期，优先补特征
```

**场景 B · 特征记录完整**（把 `qual` 也记上）

```
MRR 基线 0.7115 → 调优后 1.0000   留出集收益 +0.2885
```

**这个对照本身就是一条重要结论**：分析器能正确区分"特征不足"和"确实可改进"。
**如果你那边跑出来是负收益，八成是特征没记全，而不是自演化没用。**

## 六、隐私

- 默认 **开启脱敏**：query 与 item id 都过 SHA-256（`salt` 可自定义）
- 只记 `id` + 你显式给的数值特征，**不记内容原文**
- 单文件上限 200MB，超出自动停止写入
- 分析器**纯本地**，不联网、不上传

需要原样保留 id 便于排查时：`Pilot(path, anonymize=False)`。

---

## 七、把什么贴回来给我

只需要**分析器的输出**（Markdown 全文）。它不含任何业务数据。

如果 Q3 是负收益，额外告诉我：
1. 你的排序目前用哪些信号（这就是候选特征清单）
2. 有没有"这个结果真的有用"的反馈信号（采纳/点击/采纳后无回退）

我据此设计：
- 判断集采集方案（EV-03，用**最大差异采样**，E20 证明比"最不确定"采样省 40%）
- 效用函数拟合（EV-04）
- 是否值得进入 S1 的 go/no-go

## 八、红线（接错了会白干）

| ❌ 不要 | 原因 |
|---|---|
| 只记排序结果、不记特征 | 无法做反事实回放，Q3 必然无收益 |
| 用 judge/模型打分代替真实采纳 | E81：judge 可被操纵时锚定审计**零触发** |
| 样本 <200 就开演化 | E64：预算不足终局恒为负 |
| 让被演化的系统自己生成评测题 | E82：自生成任务集 −0.022 |
| 用同一批数据既调参又验收 | E8：留出集会被消耗，必须轮换 |
