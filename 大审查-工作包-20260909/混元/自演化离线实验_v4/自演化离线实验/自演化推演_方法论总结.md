# 自演化推演 · 经验、教训与方法论

> 二十四轮、115 个实验、21 次实验设计失败、22 次自我推翻的完整沉淀。
> 本文不重复实验数据（见 `自演化推演_实验总报告.md`），只讲**可迁移的东西**：
> 什么做对了、什么做错了、错在哪一层、以及如何避免重犯。

---

# 零、一句话总结

> **证伪比证实容易，所以负面清单比收益数字更稳健；
> 直觉在这类问题上准确率约一半，所以每个"听起来合理"的方案都必须独立验证——
> 包括验证"补救措施本身"是否有效。**

# 第一部分 · 经验：什么真的有效

## 1.1 三个配对原则（最重要的产出）

所有真正有效的机制**都是配对的**。单独任一侧，无效甚至有害。

| 探索侧 | 筛选侧 | 证据 | 单侧后果 |
|---|---|---|---|
| 宽松准入（tol>0） | 双门晋升（margin） | E7：严格准入 **0/20** 逃出局部最优，宽松准入 **20/20** | 严格准入卡死在 0.500 |
| **大幅度变异** | **真值审计** | E110：单独大幅度 **−0.048**，配审计 **+0.162** | 大幅度跑飞 / 审计干扰搜索 |
| 档案多样性 | 留出集门 | E16/E30 | 单一最优导致灾难性遗忘 |
| **写入（数据空间）** | **整理（数据空间）** | E119/E120/E123 | 单独写入 **−0.055**；配对后 **+0.018**；**整理也是审计生效的前提** |

**第四个配对跨空间**：数据空间也需要自己的"探索 × 筛选"（写入 × 整理）。
只在一个空间里配对，污染会从另一个空间进来。

**这是可以迁移到任何自演化系统设计的核心结构：**
`性能 = 探索力 × 筛选力的配对质量`，不是两者之和。

## 1.2 有效机制清单（按边际收益排序）

| 机制 | 边际 | 前提 | 依据 |
|---|---|---|---|
| **真值审计**（配大幅度） | **+0.162** | 必须配大幅度 | E110 |
| 锚定审计 + 重锚 | +0.104 | 锚定集必须刷新 | E66/E67/E69 |
| **大幅度变异** | +0.097（1.0→2.0） | 必须配审计 + 盲评 | E106/E110 |
| Pareto 档案 | +0.077 | cap≥8 | E66/E72 |
| 判断集刷新 | +0.051 | 每 5 代 | E102/E110 |
| 盲评 | +0.029 | 结构性，一次性 | E110 |
| 停摆监控 | 0.000（平时） | 保险 | E110 |

**注意最后两行的反直觉之处**（见 1.3）。

## 1.3 边际收益 ≠ 重要性（本轮最值钱的认知修正）

| 机制 | 边际收益 | 实际地位 |
|---|---|---|
| 盲评 | **仅 +0.023** | **地基**：审计 100% 失效时，大幅度仍 +0.116（E111）；让伪装自然失效（E98） |
| 停摆监控 | **0.000** | **保险**：平时零收益，margin 出错时是唯一救命机制（E44/E96） |

> **评估一个机制，不能只看边际收益，还要看它是不是别人的前提。**
>
> 盲评像地基——本身不提供使用面积，但没有它上面什么都盖不起来。
> 我据此"不必把盲评做到极致"的判断是对的（E100：天花板仅 +0.081），
> 但"边际小所以优先级低"的推论是错的。

**同理**：E96 发现"有监控时 margin 取值几乎不重要"——这让前几轮关于 margin 标定的争论**大幅贬值**。
**加一个能纠错的监控，胜过精确标定一个参数。**

## 1.4 有效的方案 vs 无效的方案（模式识别）

翻遍 24 轮，**有效的方案几乎全是"测量/利用已有可观测量"**：

| 有效 | 做法 |
|---|---|
| E32 | 用"被检索后是否被采纳"实测 importance（零新增成本，+44%） |
| E44 | 检测"采纳率 = 0"这个**绝对状态** |
| E50 | 测廉价筛选的精度再决定开关 |
| E73 | 固定混合算子（覆盖离散 + 连续） |
| E113 | 按回退次数（绝对状态）双向调整 |

**无效的几乎全是"让机制更聪明的改良"**——见 2.1 的 17 条清单。

> **一句话**：不要发明新启发式，去测量已经在那里但没人看的东西。

# 第三部分 · 方法论：可复用的原则

## 3.1 实验设计原则（从 21 次失败中学到的）

### 原则 1：结果"过于整齐"时，先怀疑实现

| 案例 | 症状 | 真相 |
|---|---|---|
| F-18（E91） | 展示权重恒为 **0.000** | 变异用 `w * x`，起点为 0 永远锁死 |
| F-20（E95） | cap 三档结果**完全相同** | Pareto 被写成 `arch[-cap:]`，参数完全惰性 |
| E24 首版 | 与 `frozen` 结果完全一致 | 漏设 `meta=True`，margin 根本没演化 |

> **"太干净的结果"是最强的 bug 信号。** 真实系统有噪声，整齐意味着某个变量没动。

### 原则 2：先验证"它所防范的危险确实存在"，再评估一条红线

E41 是典型失败：注入红线违规后，"违反 E7"**反而更好 +0.0625**。
原因不是红线错了，而是**测试环境里那四条红线所防范的危险根本不存在**。

> **不能用"在我的测试里没差别"否定一条红线。**

### 原则 3：验证补救措施本身，而不只是验证问题存在

十七次推翻里，至少 6 次是这种模式：

```
观察到一个现象 → 提出听起来合理的补救 → 从未独立验证补救本身
```

这正是我第一轮批评 v3 的模式（"先写 2400 行，再补公理"）——**我自己重复了它。**

### 原则 4：检查算子的隐含假设

E86 → E88 的反转：我以为在测"维度"，实际测的是"单点变异算子 + 维度"。
换成协调变异后结论完全反转。

> **测一个参数之前，先问：这个结果还依赖哪些我没在看的默认设置？**
> E104 发现变异幅度（被忽略 24 轮的默认参数）收益 +0.097 —— 超过大多数精心设计的新机制。

### 原则 5：标度量纲必须可比

E89 表象分为负、真值在 [0,1]，绝对阈值判断全部退化为"永远判否"，
导致 correctness 虚假地高达 93%。修正（sigmoid 映射）后降到 74%。

### 原则 6：消除基线率假象

E89 报告"低污染下正确性判断几乎不受损（97.8%）"——
其实是绝对阈值下多数判断为"否"造成的。平衡样本后 **97.8% → 74%**。

### 原则 7：信噪比低时，换度量比加种子数更有效

E9 用"演化终值"衡量，达成率在 −473%~137% 乱跳；改用排序相关 τ 后立刻清晰。

### 原则 8：要测"系统保有什么"，不要测"系统当前输出什么"

E16 首次测"最终配置的 A 值"，三种模式结果相同（都选 argmax B）。
改测"档案里是否保留 A 方向的最优配置"后才看到差异（0.81 vs 0.72）。

## 3.2 工程原则

### 原则 9：能力式 > 检测式

不是"检测到违规就拒绝"，而是**让违规代码写不出来**。

| 红线 | 能力式实现 |
|---|---|
| 廉价筛选不得采纳 | `cheap_screen() -> "reject" \| "unknown"`，**没有 accept** |
| 系统不得改元层 | 元层目录只读挂载 |
| 锚定集不得衰减 | 类型上无写入方法 |

> 这解释了为什么 P1-5 那类问题"不是被修好，是不再存在"。

### 原则 10：监控比标定重要

E96：有停摆监控时，margin 从 0.005 到 0.05 **几乎无差异**。
E44：监控检测**绝对状态**（采纳率=0），而不是相对目标值。

### 原则 11：自适应可以成功，但要满足三个条件

| E54（失败） | E113（成功 +0.025） |
|---|---|
| **单向**收缩 | **双向**（可升可降） |
| 相对目标（成功率） | **绝对状态**（回退次数） |
| 收缩到下限 0.30 饿死自己 | **有边界** 0.5–4.0 |

### 原则 12c：judge 可排序，不可判定

| 实验 | judge 的角色 | 结果 |
|---|---|---|
| E81 | 锚定集判断来源 | **零触发** |
| E122 | 整理标准裁判 | +0.005（真值 +0.064，**13 倍**） |
| E119 | 审计回退（错层） | **负收益 −0.067** |

> **judge 可用于"生成候选排序"（错了下一轮还能纠正）；
> 不得用于"最终判定"（错了直接改变系统状态）。**

### 原则 12d：间接路径的退化压力天然更弱

E81（自我美化）直接改检索权重 → 展示权重 **2.195**。
E121（自写入）改数据需经"写入→被检索→影响评分" → writalloc 停在 **0.52–0.59**。

> **评估风险时看路径长度**：直接影响评分的通道最危险，间接通道压力被稀释。

### 原则 12b：防御必须与污染同维度（跨空间污染）

三次独立出现：

| 实验 | 防线 | 污染从哪进来 | 结果 |
|---|---|---|---|
| E81 | 配置空间锚定 | 观测通道 | 零触发 |
| E84 | 配置空间探针 | 探针分布 | −75% |
| **E119** | **配置空间审计** | **数据空间** | **−0.067** |

> **任何单空间的防御体系都会被跨空间污染绕过。**

### 原则 12：外部参照必须独立于观测通道

E81：锚定集的判断来自同一个被污染的 judge → **零次触发**。
E85：直接通道操纵下 **膨胀 349×**，真值审计只压到 133×（管得住"选哪个"，管不住"怎么报告"）。

> **若外部参照是通过同一个有缺陷的观测通道获得的，它不构成外部性。**

### 原则 13：审计频率 >> 样本量

E97b：样本量 2 就达到 +0.059；省下的预算应提高频率。
E84：探针集被污染时，高频审计反而更差（回退翻倍）——**所以探针要轮换**。

### 原则 14：复合失配是常态，不是异常

六次独立出现：E60 / E66 / E80 / E87 / E93 / **E115**。

> **不要假设"各项改进可加"。** 每次叠加都要重新验证。

## 3.3 认知原则

### 原则 15：记录你错在哪里，而不只是对在哪里

负面清单（17 条）比收益数字更稳健，因为**证伪比证实容易**。

### 原则 16：区分"边际收益"与"结构必要性"

见 1.3。盲评边际 +0.023，但它是地基。

### 原则 17：被忽略的默认参数，往往比精心设计的新机制更重要

变异幅度被忽略 24 轮，扫描后 +0.097。

# 第五部分 · 检查清单（用于新项目）

设计自演化系统时，逐条核对：

**结构上**
- [ ] 探索侧与筛选侧是否**配对**？（不是只加强一侧）
- [ ] 三层（元/法/行）是否隔离？系统能否修改评判自己的尺子？
- [ ] 哪些约束是**能力式**（写不出来）而非检测式？

**观测上**
- [ ] 外部参照是否**独立于**演化所用的观测通道？
- [ ] judge 的分数是否**永不对外报告**？
- [ ] 探针/锚定集是否**外部固定且定期轮换**？
- [ ] **防御是否与污染同维度**？（配置空间的审计挡不住数据空间的污染）
- [ ] 数据空间是否有自己的"写入 × 整理"配对？
- [ ] judge 是否被用在**最终判定**位置上？（应只用于排序）
- [ ] 审计/盲评的**前提机制**是否已就位？（整理 / 盲评）

**防御层次**
- [ ] 第 0 层（结构性，如盲评）是否就位？——它是其他机制的前提
- [ ] 第 1 层（探索力，如大幅度）是否与第 2 层配对？
- [ ] 第 2 层（周期性审计）是否**不可预知**？

**验证上**
- [ ] 是否验证了"补救措施本身"有效，而不只是"问题存在"？
- [ ] 注入红线违规时，测试环境是否**真的包含**该红线所防范的危险？
- [ ] 结果是否"过于整齐"？（如果是，先怀疑实现）
- [ ] 度量是否有**基线率假象 / 标度失配**？
- [ ] 叠加多个改进后是否**重新验证**？（复合失配已出现 6 次）

**失败准备**
- [ ] 是否有负面清单，记录哪些方案已被证伪？
- [ ] 是否记录了自我推翻？（直觉准确率约 50%）
- [ ] 注意力预算是否足够？（judge 可被操纵时门槛约 300）
