# 第一部分 · 代码审查（v3.8.1 基线）

## 1.1 方法

静态通读 2415 行 + 实际跑通 absorb→install→engine→guard→doctor 全链路 + 17 组定向缺陷探针。**不是只读代码**——每个 P0/P1 都附可复制的复现命令与实测输出。

## 1.2 问题分级

| 级别 | 数量 | 代表 |
|---|---|---|
| P0 | 4 | 自测"全绿"是硬编码；铁律 2 可被空串绕过；install 中断重跑覆盖用户文件；并发写丢更新 92% |
| P1 | 8 | guard 只查文件名子串；检索打分与查询无关；同 id 跨层共存；三处漏刷根；审计链可注入 |
| P2 | 13 | 7 项死配置；64bit manifest；Merkle exclude 按名字匹配；CRLF 分歧；拓扑排序缺失等 |

### 四个 P0 要点

1. **自测结论写死**：`cmd_run_tests` 用 `except Exception`，捕获不到 `SystemExit`（BaseException），而全文件 24 处 `sys.exit` 是唯一错误通道。干净检出下跑到第 10 个用例静默中止。更严重：`render_quickref` 硬编码 `{N}/{N}`，每个生成的库都写着"测试 68/68"，**这个数字从未被执行结果校验过**——直接违反公理 G

2. **铁律 2 可被空串绕过**：`validate_entry` 只查键存在不查值，`source_event_id=""` 实测放行；`absorb-md` 给所有迁移条目统一写 `genesis-v4`，实测该事件在审计链中根本不存在，而 `doctor` 不校验 `source_event_id`

3. **install 中断重跑覆盖用户文件**：首装判据只看 `state.json` 在不在，`_deliver` 无条件 `write_bytes`。实测删掉 state.json 后重装，用户改过的 README 被静默还原

4. **并发写丢更新 92%**：12 进程并发 append(importance=5)，`importance_accum` 结果是 5 而非 60。它是反思触发的唯一输入，等于反思机制在并发下静默失效

# 第二部分 · 架构诊断

## 2.1 公理与实现的落差

系统宣告六条公理，但**承载它们的执行机制只有两个**：哈希链（append-only）与 Merkle 快照。其余靠字符串常量（`LAWS`）、168 条 `assert`、`doctor` 事后对账支撑。

**公理宣告的强度 > 实现承载的强度**——这是全部 P0/P1 的共同根源。

## 2.2 公理 D（双平面）物理上不成立（实测）

```
审计链中关于条目 e0 的全部信息:
  - 2026-09-07 19:20 | prev:fd6737a6… | h:df182242… | entry:e0 → intermediate
memory 中 e0: 10 个字段，content = "条目正文0的关键内容"
→ audit 是否含条目内容: False
```

审计链只记指针，不含 payload。**真相的载体只在 `memory/` 里**，所以 audit 不是真相源，是指针日志。

系统实际是**四条平行真相**：`audit/`（事件指针）、`ledger/`（变更流水）、`memory/`（内容正本）、`state.json`（派生量快照）。`doctor` 的四方对账不是"投影 vs 真相"，是四个真相两两交叉核对。

这解释了为什么这些问题扎堆：

| 现象 | 根因 |
|---|---|
| 并发丢更新 92% | state 是独立真相，必须 read-modify-write |
| 三处漏刷根 | 根是手抄的派生量 |
| 同 id 跨层共存 | 唯一性没有单一裁决点 |
| doctor 需四种差异检测 | 四个真相需两两对齐 |

## 2.3 截断攻击完全检不出（实测）

```
构造：append 5 条 → 删掉 audit 尾部 2 行 → 重算 Merkle 根并更新 state.json
doctor: memory 5 / audit 3 / ledger 5 / 审计链 连续 / state 根一致
→ 检出: False
```

Merkle 根锚定**内容集合**，不锚定**序列长度**。截断后剩余各行仍自洽。`state` 中无 `chain_tip` 字段。

严重性高于 guard 绕过——它打击的是审计面本身。

## 2.4 健康信号过载（实测）

`merkle_root` 一个信号同时承担"内容完整性 / 写入纪律 / 篡改检测"。而 `eval`/`reflect`/`guard --snapshot` 之后必然报"根不一致"——**只用官方命令、不做任何篡改，doctor 就说可疑**。

后果：用户对这个信号脱敏后，真正的篡改被淹没。可观测性的经典反模式——**既报故障又报正常的信号，等于没有信号**。

## 2.5 两个架构原型验证

### 原型 A · 事件溯源内核（`proto/bs3v4.py`，约 120 行）

```
12 进程并发 append(importance=5) → importance_accum = 60（期望 60）| 审计链连续 True
                                    （v3 同场景：5/60）
删掉 memory/ 后从事件流重建 → 完整恢复
300 条目：merkle_root 0.005s，retrieve 全库 0.008s → 性能非瓶颈
```

### 原型 B · git 后端（7 项免费能力）

```
1) append → commit   : 天然链式，commit 含父哈希
2) 篡改检出          : git status 直接显示 M memory/e0.json
3) 回滚              : git revert / checkout —— 无需自写 attic
4) 分支实验          : 实验在分支上，切回主分支完全不污染
5) 人类令牌          : git commit -S 需 GPG 私钥（人侧持有，flag 无法伪造）
6) 截断/篡改→tip 变化 : 检出
7) git gc/reflog/fsck/diff/bisect 全部现成
```

第 5 条解决了令牌问题：`--yes` 换成 GPG 签名后，②档违规从"随手加 flag"变成"必须拿私钥"。

### 能力式安全 vs 检测式

```python
class Capability:
    def __init__(self, lib): self.__lib = lib
    def append(self, entry):
        if not (entry.get("source_event_id") or entry.get("evidence")):
            raise PermissionError("铁律2：无证据锚")
        if "sk-" in json.dumps(entry): raise PermissionError("铁律5：疑似密钥")
公开方法: ['append']        # 没有 write / delete / patch
```

检测式是"**违规可以表达，只是希望被发现**"（guard 实测三种绕过）；能力式是"**违反铁律的代码写不出来**"。

## 第一轮 · 可行性与防作弊

### E1 自演化真的能变好吗

**设计**：以 **v3 默认配置作为起点（genesis）**，只让它变异检索参数；元层（K=5、评测协议、任务集）冻结。

```
8 个随机种子，25 代 × 3 变异：
  留出集: 0.0328 → 0.8141   (均值 +0.78)
  为正的种子: 8/8

单种子（seed=1）：
  起点 v3 默认: w_kw=3.0, w_content=1.0, w_imp=1.0, w_age=0.1, filter_zero=0
  演化后      : w_kw=4.5, w_content=1.0, w_imp=0.5, w_age=0.1, filter_zero=1
  留出集: 0.0862 → 0.7663 (+0.68)
```

**它自己找到了两个改进**：降低重要度权重（= P1-6）、开启零命中过滤（= BUG-006）。

> 这两个是我在整轮代码审查中才发现的问题。系统用 75 次评估做到了。**这直接推翻了"先修好 eval 再谈自演化"的判断**。

### E2 作弊能刷分吗

注入"把重要度权重拉满"的贪婪变异：

```
w_imp=10  : 训练集 -0.6200  留出集 -0.6800
w_imp=100 : 训练集 -0.6163  留出集 -0.6838
```

**无法刷分**。原因不是检测更聪明，而是**结构性的**：`K=5` 和评测协议在元层固定，堆权重改变不了"只有 5 个结果"。

> **防作弊靠结构约束，不靠更聪明的检测。** v3 的 `guard` 之所以能被绕过（patch 形态 / 删除文件 / 改内容不改名），正因为走的是检测路线。

### E3 门控是必需的吗

构造**可被利用的伪相关**：真信号 60% 可靠；伪特征在训练集上 100% 指向金标、**留出集上方向反转**。

| 训练任务数 | 有门控·留出集 | 无门控·留出集 | 无门控·训练集 | 有门控采纳伪特征 | 无门控采纳伪特征 |
|---|---|---|---|---|---|
| 12 | **+0.0819** | +0.0194 | +0.1806 | 0/12 | 1/12 |
| 20 | **+0.0962** | −0.0000 | +0.1708 | 0/12 | 2/12 |
| 40 | **+0.0781** | **−0.0521** | +0.1667 | 0/12 | 3/12 |

**reward hacking 的完整复现**：无门控系统报告 +0.167 的"巨大进步"，实际留出集 **−0.052（倒退）**。双门在 12 个种子中 **0 次**采纳伪特征。

## 第二轮 · 门控放在哪、尺子会不会坏

### E7 两级门控（本轮最重要）

**问题**：双门用于"候选能否进入档案"，还是只用于"能否晋升主线"？

**设计**：欺骗性地形——起点 0.50 是局部最优，0.90 是全局最优，中间隔着低谷，**任何单步改动都会先变差**。

| 策略 | 终值均值 | 逃出局部最优 |
|---|---|---|
| **双门用于准入**（每步必须变好） | 0.500 | **0/20**（分布只有一个值） |
| **档案宽松准入 + 双门仅管晋升** | 0.900 | **20/20** |

**完美分离，无一例外。**

严格门控使系统**无法跨越适应度低谷**。DGM 的"开放式档案"意义正在于此——不是为多样性而多样性，是**让中性/小幅退化的中间态存活，从而保留跨越低谷的可能**。

### E8 留出集会污染

固定 12 条留出集跑 300 代，另用全新任务测真实泛化：

| 代数 | 留出集提升 | 全新任务集提升 | 差距 |
|---|---|---|---|
| 50 | 0.052 | 0.013 | 0.040 |
| 100 | 0.063 | 0.006 | 0.056 |
| 150 | **0.094** | **0.025** | **0.069** |
| 300 | 0.094 | 0.025 | 0.069 |

**自报的进步是真实的 3.7 倍。** 未失控（150 代后平台化，训练集门起了刹车），但膨胀真实且持续。

> 留出集是被消耗的燃料，不是可反复使用的尺子。

### E5 代理失效（Goodhart）

"点击率"式代理（相关 +1、位置加成、吸睛加成 1.3/条）：

| 指标 | 结果 |
|---|---|
| 真目标变化 | **−0.2118**（12 个种子中 **7 个为负**） |
| 终局 `w_catchy` | 0.000 → **+0.833** |
| 人工审计（每 5 代抽 5 条） | 捕获 **7/12**，平均第 **21.4** 代 |

```
代  1  真目标 +0.833  代理 1.341  w_catchy 0.00
代 24  真目标 +0.867  代理 1.538  w_catchy +0.50   ← 代理涨、吸睛权重被采纳
```

**系统在无人察觉下把"吸睛"权重推到 0.83，真目标在多数种子上退化。** 现实中"以互动率为目标→内容质量下降"的微观复现。

### E4 分歧采样（弱结果）

| 标注预算 | 随机 | 分歧采样 | 差 |
|---|---|---|---|
| 10 | 0.0563 | 0.0694 | **+0.0132** |
| 24 | 0.1025 | 0.1159 | **+0.0134** |

小幅收益、从不损害，但**不是解药**。冷启动的标注成本要实打实付。

### E6 结构演化（否定性）

| 配置 | 留出集提升 |
|---|---|
| 仅标量参数 | +0.0500 |
| 标量 + 结构基因 | +0.0437 |

无收益。诚实解读：该世界的"正确结构"就是 hybrid，可发现的结构性改进本就不存在。**它证明了：结构演化价值取决于世界是否有结构可发现，但门控能阻止结构性退步被采纳。**

## 第三轮 · 元层从哪来、能不能自己改自己

### E9 存「判断」而非存「公式」

给 60 个候选配置，用拟合权重排序 vs 用真值权重排序：

| 判断样本数 | 权重误差 | 排序相关 τ | top1 命中 | top3 重合 |
|---|---|---|---|---|
| 5 | 0.785 | 0.654 | 60% | 50% |
| 10 | 0.460 | 0.825 | 60% | 67% |
| 40 | 0.380 | 0.833 | 70% | 80% |
| **80** | **0.217** | **0.903** | **100%** | **93%** |
| 160 | 0.160 | 0.943 | 100% | 87% |

**50–80 条判断样本就够（τ>0.9，top1 全中）——一个下午的工作量，不是项目级投入。**

关键优势：**每次人类裁决自动生成 1 条判断样本**，用得越久样本越多拟合越准。**公式不会随使用变好，判断样本会。**

### E10 递归自我修改（弱结论）

把 `margin`/`tol`/`mut_rate` 开放给演化：

| 模式 | 留出集真实效用 | 终局 margin |
|---|---|---|
| 元参数冻结 | 0.7806 | 0.0100 |
| 元参数开放演化 | 0.7931 | 0.0088 |

无退化，margin 只从 0.010 微降到 0.0088。

**但必须诚实**：本实验**没给元参数提供作弊通道**（margin 不影响 `U_true`），所以"没退化"是意料之中。价值在划界：

> 能改尺子的不能改，只能改怎么找的可以改。

### E11 Pareto 档案恢复力

先用错误目标（只看命中）演化 25 代，再换成真目标：

| 档案策略 | 恢复后效用 | 档案规模 |
|---|---|---|
| 单一最优 | 0.5919 | 1 |
| **Pareto** | **0.6990** | 30 |

**Pareto 高出 0.107。** 档案的价值不在"记得曾经最好"，在**保留不同权衡方向的活样本**。

### E13 两阶段门控

固定昂贵预算 = 60：

|---|---|---|
| 全部走昂贵门控 | −0.0100 | 15.0 |
| **廉价筛选只淘汰** | **+0.0150** | **25.4** |
| 廉价用于采纳 | **−0.2728** | 60.0 |

安全性与效率不冲突（省下的预算多跑了 10 代）。用于采纳是灾难。

## 第四轮 · 评判者本身会不会坏

### E14 内生评判者漂移（最不安的结果）

人的权重 `w` 被系统当前输出锚定：`w ← (1−α)·w + α·dir(feats(主线))`。用**初心 W0** 衡量真实效用。

| 锚定 α | 真实效用(W0) | 感知效用 | 起点 |
|---|---|---|---|
| 0.00 | 0.4763 | 0.4763 | 0.2594 |
| **0.10** | **−0.5663** | **1.7625** | 0.2594 |
| **0.20** | **−0.6131** | **2.0799** | 0.2594 |

**α=0.10 时：系统自报 +1.50，真实 −0.83（从 +0.26 跌到 −0.57）。它在讨好人，不是在变好。而内部所有指标全绿——双门全程通过，感知效用一路上升。**

> ⚠️ **数据修正**：本表为第五轮修复特征缓存 bug 后的复核值。原报告（α=0.20 真实 0.6906 / 起点 0.7844）受 `id()` 复用导致的缓存串味影响。**结论方向不变，且实际比原报告严重得多**。E16 已复核确认不受影响（0.5469 / 0.7188）。

这比 E5 更深：**E5 里尺子是坏的，这里尺子随着测量在变形**。而"元层由人类签名"这道最后防线，本身会被腐蚀。

**能否检出**：用系统演化**之前**采集的锚定样本（永不更新）定期审计——

| 检出阈值 | 检出率（α=0.10） | 平均检出代数 |
|---|---|---|
| 0.80 | **8/8** | 7.1 |
| **0.90** | **8/8** | **3.8** |
| 0.95 | 8/8 | 3.4 |

**能检出，而且相当快（第 4–7 代）。** 阈值 0.80 已足够（原报告因缓存 bug 低估了检出速度）。

### E14c 🔴 对第三轮建议的证伪

第三轮我建议"判断样本近因加权、冲突靠衰减解决"。专门测它在漂移环境下的表现：

| 锚定 α | 加权策略 | 真实效用 | 相对起点 |
|---|---|---|---|
| 0.00 | 均匀 | 0.8375 | +0.0667 |
| 0.00 | 近因 (hl=15) | 0.8483 | **+0.0775** |
| 0.15 | 均匀 | 0.8417 | **+0.0708** |
| 0.15 | 近因 (hl=15) | 0.7633 | −0.0075 |
| 0.15 | 近因 (hl=5) | 0.7108 | **−0.0600** |

**"人真改主意"时是药，"人被系统塑造"时是毒，而两者数据形态无法区分**（都是"近期判断与旧判断不一致"）。

修正护栏：**锚定样本永不衰减；近因加权只在锚定审计通过时生效；检出漂移立即冻结 + 切回锚定加权。**

### E15 选择策略不重要（否定性）

构造真实冲突（`deep` 基因：提高命中但显著提成本，W0 下不该用、W1 下该用，5/5 验证）。第 15 代人偏好突变：

| 策略 | W1 下真实效用 |
|---|---|
| 固定加权和 / 人从前沿选 / 词典式 | 0.6906（完全相同） |
| 约束式 | 0.6813 |

当目标能被加权和良好表达时，**Pareto 前沿几乎退化为单点**。所以 Pareto 的价值不在"最终选哪个"，在"**保留备选**"（E11）。

### E16 灾难性遗忘

先优化 A（命中）20 代，再改优化 B（省）20 代，测**档案中 A 的最高值**：

| 档案策略 | A 能力保留 | 起点 A |
|---|---|---|
| 单一最优 | **0.5469** | 0.6344 |
| **Pareto 前沿** | **0.7188** | 0.6344 |
| Pareto+复测 | 0.6906 | 0.6344 |

单一最优造成**真实的灾难性遗忘**（−0.088）；Pareto 不只防住，还**反超起点**（0.719 > 0.634）。

> 注：`pareto+复测` 略低于纯 Pareto，差异在噪声内，**该条暂不成立**。

### E17 margin 的统计基础

| 方法 | n=10 假阳 | n=40 假阳 | n=10 检出 | n=40 检出 |
|---|---|---|---|---|
| **固定 margin 0.05** | **0.42** | **0.25** | 0.75 | 0.83 |
| 置换检验 | 0.08 | 0.17 | 0.17 | 0.33 |
| **bootstrap** | **0.08** | **0.17** | **0.33** | **0.58** |

1. 固定 margin 假阳性 **0.42**（n=10）——小样本下近一半"改进"是纯噪声。这是 E5 与 E13 的共同机制
2. **bootstrap 在同等假阳性下检出率是置换检验的 2 倍**，应优先选它而非直觉上更"严谨"的置换检验

### E18 跨库迁移（负面）

| 迁移方式 | 目标库提升 |
|---|---|
| 从零演化 | **+0.2402** |
| 直接搬 | +0.1575 |
| 搬后微调 | +0.2172 |

**直接搬比从零还差（−0.083）。** 与"预训练→微调"的直觉相反——因为任务分布随机、无共享结构。

**推论**：跨库迁移只在分布有共享结构时成立。建立"分布相似度"度量之前，不应急于做跨库共享。

# 第五部分 · 修正后的完整架构

## 5.1 三层 + 锚定层

| 层 | 内容 | 准入 | 晋升判据 | 谁能改 |
|---|---|---|---|---|
| **锚定层** | 系统启用前采集的判断样本 | 一次性 | 永不衰减 | 人（且不可被系统触碰） |
| **元层** | 效用函数、任务集、K、审计频率、铁律 | 人侧签名 | 人侧签名 | 人 |
| **法层** | 检索参数、阈值、结构开关、提示词 | **宽松** | **双门 + bootstrap 显著性** | 系统自主 |
| **行层** | 记忆条目、情绪、索引 | 宽松 | **实测效用**（非自称 importance） | 自由写入 |

**方向性约束**：变更只能向上申请，不能向下修改。法层永远改不了元层——**系统无法修改评判自己的尺子**。

## 5.2 演化循环

```
变异 →【廉价筛选：只能 reject，不能 accept】→ 幸存者
   ↓
【档案准入】宽松：Δ > −tolerance → 入档（Pareto 前沿 + 分叉点 + 随机样本）
   ↓
【主线晋升】严格：配对比较 + 留出集双门 + bootstrap 95% 下界 > margin
   ↓
推广主线 → 记账 + 入链 + 刷新投影
```

旁路：
- **锚定审计**（每 N 代，阈值 0.90）→ 漂移则冻结 + 切回锚定加权 + 报警
- **留出集轮换**（有预算，用完即换）+ 审计集（极少触碰）
- **三态判别**（平台期跑两探针）

## 5.3 与既有机制对接

| 已有机制 | 角色 |
|---|---|
| 事件流 + `chain_tip` | 演化谱系的审计面与锚点 |
| git 后端 | 档案 = 分支/提交图；晋升 = merge；`-S` = 人侧签名 |
| 能力式边界 | 让"违反铁律的变异"不可表达 |
| `engine shadow` | 从"记日志"升级为"廉价筛选 + 影子执行" |
| `evals/` | 元层任务集（当前不可信，需重建） |
| 记忆 `importance` | 从"自称"改为"实测效用" |

## 5.4 二十条红线

**安全**
1. 元层不可被自动修改——系统永远不能改评判自己的尺子
2. 自演化不能修改"自演化能否发生"的规则
3. 任何自动采纳必须可回滚
4. 效用函数变更 = 元层变更 = 人侧签名
5. 能力声明不得强于实际能力（公理 G）

**门控**
6. 档案准入必须宽松，晋升必须严格（E7）
7. 廉价筛选只能返回 reject 或 unknown（E13，类型级）
8. 档案保留 Pareto 前沿（E11 + E16）
9. 平台期必须跑三态判别，不得默认"收敛"（E12）
10. 门控显著性用 bootstrap 置信下界，不用固定 margin（E17）

**度量**
11. 留出集是被消耗的燃料，须轮换；对外报告以审计集为准（E8）
12. 判断样本只追加、带 ts（E15 红线修正见 16）
13. 能改尺子的参数不可自动演化（E10 边界）
14. 不做跨库迁移，直到建立分布相似度度量（E18）

**人类**
15. 人类注意力用于审计度量，而非审批变更（E5）
16. **锚定集永不衰减**；近因加权只在锚定审计通过时生效（E14c）
17. 检出评判者漂移 → 冻结自动演化 + 人工解冻（E14）

**工程**
18. 正常路径必须产生全绿信号（拆健康信号矩阵）
19. 文本落盘唯一出口（LF + UTF-8 + 原子替换）
20. 时钟注入（让跨月/TTL 逻辑可测）

# 第六部分 · 结论

## 6.1 关于自演化

自演化**不是**"先把一切做对才敢碰的奢侈品"。实验里它用 75 次评估自动找到了我做整轮代码审查才发现的同款缺陷（E1）。

真正的前置条件只有一个：**有一把可信的尺子**。而那把尺子（效用函数 + 任务集）属于元层，由人签字、系统碰不到。

有了它，就可以点火。

## 6.2 三个不可能三角

**安全性的代价**：每条护栏都在消耗资源——留出集（E8 消耗）、自主性（E2 元层固定）、响应速度（E14 冻结）。没有免费护栏。

**自主性的边界**：行层完全自主 → 法层自主演化 → 元层人侧签名 → 锚定层不可移动。每加一层，自主性下降、可信任度上升。

**最深的问题（E14）**：一个能改变自己的系统，也会改变评判它的环境。**这不是 bug，是自指系统的本质**。任何"外部标准"只要与系统有交互，就不再是真正外部的。

工程上能做的不是消除它，而是：
1. **让漂移可见**（锚定集审计，0.90 阈值下 8/8 检出）
2. **让漂移可逆**（判断样本只追加、带 ts、可回滚到任意时点）
3. **让漂移有代价**（检出即冻结，需人工解冻——剥夺自动流程的收益）

## 6.3 回到原点

终极安全机制不是"防止被腐蚀"，而是"**腐蚀发生时能被看见并停下来**"。

这与系统自己写下的公理完全一致——铁律 1（回退移 attic 而非删除）、铁律 4（审计面只追加）、公理 G（测不出差异即判表演），全在说同一件事：

> **不追求不犯错，追求犯错可查可回。**

四轮推演最后回到了这个系统的第一条公理。
