## 结论（对演化引擎的含义）

1. **并发丢更新**：引擎若多进程演化（多主线并发写），importance_accum（反思触发输入）会静默少计 → 反思/衰减机制在并发下失真。本系列引擎单进程顺序写不受影响；但真实部署需原子读-改-写或事件溯源内核（总报告原型 A bs3v4 的修复：12 进程=60）。**建议**：沙盒演化驱动器保持单写者 + state 更新加锁或并入 append-only ledger。
2. **截断攻击的密码学静默**：Merkle 根锚定"内容集合"而非"序列长度"——删审计尾行后剩余各行自洽、根一致。doctor 只能看到表面计数差。对自演化架构的含义：**完整性断言不能只依赖链/根**；建议在 state 增加 chain_tip（长度锚定）或在 doctor 增加"审计行数 ≥ 条目数"的派生断言（总报告修正方向），并把引擎的"审计证据"（真值采样）与链完整性解耦——本系列引擎的审计走独立真值通道（E81 已证有效），不因链静默而失效，但"篡改可查"承诺需要 chain_tip 类修复才成立。
3. 套件价值：两条已复现的 P0 可作为回归测试常驻（out_r1_3/results_r1_3.json），防止未来引擎改造在不知不觉中引入同类缺陷。
