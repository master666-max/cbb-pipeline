# 记忆库自演化引擎 · 沙盒实验设计方案（V2）

> 一句话定位：在只依赖标准库、离线、确定性的沙盒里，让真实的 bootstrap_v3.py（v3.8.1）记忆库代码路径承载「存储 / 更新 / 遗忘 / 重组」全部底层操作，在其外驱动一个自演化引擎（固定混合变异算子 → 档案宽松准入 → 主线严格晋升 → Pareto 档案 → 真值抽样审计），用 static / bare(无门控) / gated(报告修正架构) 三臂对照与消融，检验该架构能否在不破坏记忆一致性的前提下系统性地提升检索效用，并诚实地报告自己。
> 依据资产：《自演化推演_实验总报告17轮后.md》（80 实验 + 3 架构原型 + 19 次设计失败 + 15 次自我推翻）、《bootstrap_自演化落地工单集.md》（EV-01~21）、《bootstrap_A轮_实验世界升级.md》（E81~E83）、《bootstrap_v3.py》源码（2415 行）、run_sandbox.py（V1 骨架，本设计为其 V2 升级）。
> 前置实测：env_check.py 已在 Python 3.14.7 + bootstrap_v3 VERSION=3.8.1 上跑通全部真实代码路径（见 4.3 与 env_check.out.txt）。

## 0. 为什么需要 V2：V1 骨架与任务要求之间的缺口

run_sandbox.py（V1）只做了一件事：在静态条目集上演化检索参数（w_kw/w_content/w_imp/w_age/filter_zero），对照 static/ungated/gated。它对「记忆库自演化」的覆盖不完整，与本次任务要求的四能力（存储 / 更新 / 遗忘 / 重组）存在 4 个缺口：

| 缺口 | V1 现状 | V2 必须补上 |
|---|---|---|
| G1 遗忘 | 无条目生命周期；retire/attic 路径只对 seed=1 库做过一次一致性检查 | 场景注入「事实过期/被取代」，测 TTL 出仓、防泄漏（过期事实不得被召回） |
| G2 更新 | 库是静态的；append 同 id 拒绝、t_invalid、supersede 语义从未被当作演化对象 | 演化世界引入版本流：新事实取代旧事实、冲突、纠正；引擎按 append-only 语义提案更新 |
| G3 重组 | 检索参数之外无可演化结构 | 引入 links 嫁接 / keywords 改写 / 跨条目反思合并（R-xxx）等「行层算子」，并测其只在存在可发现结构的场景有价值（E6 的诚实解读） |
| G4 评判通道 | gold 直接用 importance 或隐藏 rv，judge 看到的就是真值（A 轮已指出这是致命干净） | spur-surface 场景让「引擎能看见的表面特征」与「真值」错位，检验锚定审计 vs 真值抽样的差异（E81/E81c） |

V2 的实验对象也因此从「检索器参数」升级为完整的记忆库自演化引擎：法层（参数/开关）+ 行层（条目级算子）都开放给引擎提案，但全部经真实 v3 公开函数落盘，元层（K、任务集、真值审计、铁律）冻结在人侧。

## 1. 背景与设计前提（从源码与报告中提炼的 12 条事实）

实验设计的每条都对应源码行号或报告实验号，避免纸面推演：

| # | 事实 | 出处（源码/报告） |

| S1 | 条目 schema 十字段：id/created_at/updated_at/content/keywords/links/source_event_id/importance/confidence/validity；validity.t_invalid 置位即「失效不删除不参与检索」 | SCHEMA_V3 L106；_rank_entries L890 |
| S2 | 写入按 importance 分流：importance>=7 → memory/longterm，否则 intermediate（V2 实测确认） | cmd_engine append L927 |
| S3 | 同 id 拒绝覆盖（铁律 1：永不删除/覆盖；「更新」没有 in-place API）——库内更新语义只能是 append 新版本 + links + 旧条失效 | L930-932；LAWS L98 |
| S4 | 检索打分硬编码：kw_hit×3 + c_hit + importance − 0.1×age_days，links 一跳扩散 ×0.5；K=5；eval=recall@5+MRR 基线 | _rank_entries L906-914；cmd_engine eval L949-971 |

| S8 | guard 守卫 BASELINE_BLACKLIST 文件名段；变异触及即否决；能力式边界优于检测式 | L1102-1141；报告 2.5 |
| S9 | 自演化有效性已被证实：留出集 0.033→0.814、8/8 正，且自发现 w_imp 应降、filter_zero 应开（=人工审查发现的同款缺陷） | E1 |
| S10 | 两级门控决定性：准入严格 → 0/20 逃不出局部最优；档案宽松 + 晋升严格 → 20/20；廉价筛选返回值只能 reject/unknown | E7/E13 |
| S11 | 护栏一错即灾难、其余是保险：margin 过大→停摆；Pareto 防灾难性遗忘（0.719 vs 0.547）；留出集是消耗性燃料需轮换；锚定集永不衰减；锚定审计阈值 0.85（零误报）；judge 只看到表象时锚定审计 0 次触发，唯一有效是周期性真值抽样 | E3/E8/E16/E14c/E34/E81/E81c |
| S12 | 三条不可能性 + 边界：系统无法自知失败；无法被自己的数据检验；自主性有注意力门槛（预算<150 恒为负）；≥3 种危险同时出现时全套护栏也不可靠（E80） | 报告第五部分 D |

架构前提（本实验接受、并把它当作被测对象而非信仰）：
- A1 四层权限：锚定层（人，只读且永不衰减）> 元层（人签名）> 法层（系统自由演化）> 行层（系统自由写，但经真实 API）。
- A2 引擎只能经 v3 公开函数（append/retire/reflect 素材 + eval/retrieve 读）作用于库；任何「更新」= append 新条目 + 旧条失效，无 in-place 改写。凡是需要 in-place 的「更新」诉求，本设计明确把它作为被测缺陷记录（见 H6b）。
- A3 检索层用 _rank_entries 的显式参数化同构 retrieve_top(cfg)，默认参数必须通过 parity 门与真实 _rank_entries 一致（5.1 P0）；库内容与写路径 100% 走真实 b3 代码。
- A4 沙盒中「真值」= 世界生成器隐藏的 rv（随场景按需漂移）；「judge 可见面」= 条目表面特征；两类通道物理分离（EV-19/20 硬约束）。
- A5 反思合成（R-xxx）在沙盒中用确定性规则聚合器模拟（离线、可复现），不调用任何 LLM。

## 2. 实验目标与假设

### 2.1 总目标
在可复现沙盒中回答三个问题：
1. 架构可行性：报告修正架构（S10/S11）驱动的自演化记忆库，是否在不破坏记忆一致性的前提下，于干净/过期/重复漂移/表象错位/目标切换场景中稳定优于静态库？
2. 机制必要性：两级门控、Pareto 档案、真值抽样审计各自贡献多少？裸演化为何必须上护栏？（用负对照量化「没护栏时它自信地走错且指标全绿」）
3. 边界诚实性：注意力门槛、复合危险（≥3）、judge 通道被表象污染时系统表现如何？把「做不到」写进判据而不是假装能做到。

### 2.2 假设表（每条都可被单场景、可量化检验）

| 假设 | 内容 | 主场景 | 判据（阈值） | 依据锚点 |
|---|---|---|---|---|
| H1 | gated 自演化 > static 静态库：审计真值集上的检索效用 ΔU_audit 显著为正 | clean/stale/dup-drift/spur-surface/switch | 每场景 ≥70% 种子为正（12 种子配对），bootstrap 95% CI 下界 > 0；净增益 ≥ +0.02（recall 单位） | E1/E40/E63（修正架构均值 +0.0526） |
| H2 | 裸演化（bare）自我报告膨胀：训练集收益 ≥ 3× 真值收益；存在种子真值倒退 | spur-surface/clean | gap = ΔU_train/ΔU_truth ≥ 2.0；≥1/12 种子 ΔU_truth<0 而 ΔU_train>0 | E3（+0.167 vs −0.052）、E8（3.7×） |
| H3 | Pareto 档案防灾难性遗忘：目标切换后，阶段 A 的旧能力保留率显著高于 bare/static 单一最优 | switch | gated 的 A-能力保留 ≥ 起点×1.05；bare < 起点×0.95 | E16（0.719 vs 0.547） |
| H4 | 实测 importance 优于自称 importance：按实测采纳率排序的 top-10 真实质量 ≥ 自称排序 ×1.2 | spur-surface | top-10 命中金标占比提升 ≥ +20% | E32（+44%）、EV-14 验收线 |
| H5 | 真值抽样审计优于「仅锚定审计」：judge 只看表象时，仅锚定审计 0 次触发且真值退化；叠加真值抽样后真值收益回升 | spur-surface | noAudit vs withTruthAudit 的 ΔU_truth 差 ≥ +0.03；审计触发只在真退化时发生 | E81（触发 0.0）、E81c（+0.024→+0.090） |
| H6 | 一致性不变量全程成立：写路径走真实 b3 代码 → 哈希链连续、五态对账零错位、无覆盖、attic 无删除、铁律零违例 | 全部（gated 与 static 同时断言） | 每次检查点 chain_bad=0、set_mismatch=0、no-overwrite=0；eval 后根不一致单独计数（S7 已知现象，不计入违例） | S2-S6；红线 1/25/26 |
| H6b | 裸演化的非法更新被能力边界挡下：引擎若绕过 API 直接改写条目字段 → append 同 id 拒绝/写入失败计数 > 0，证明「违反铁律的变异不可表达」的必要性 | clean（注入恶意算子） | 所有 in-place 改写尝试 100% 被拒；gated 引擎自身 0 次尝试 | 报告 2.5、E24 |
| H7 | 重组算子收益是场景依赖的：links/keywords/合并只在「存在可发现结构」（dup-drift）场景带来净增益；在无结构场景无增益也不损害 | dup-drift vs clean | dup-drift 中 gated+行层 ≥ gated(仅法层)（Δ≥+0.02）；clean 中 |Δ| 在噪声内（E6 否定性结论的复现带） | E6、E60 |
| H8 | 注意力预算存在门槛：效用/成本随预算增长先负后正，存在阈值 B*；预算 < B* 时演化净负 | clean（预算扫描） | 拟合出 B* 区间；B < B* 端均值 < static 基线 | E64（<150 恒为负）、E22/E25 |
| H9 | 复合危险边界：≥3 种危险同现时，修正架构也不可靠（净效用可转负）——如实记录为已知边界 | composite(stale+spur+switch) | 记录 ΔU_truth 分布与崩溃比例；不做「修好它」的承诺，只写边界 | E80（−0.26 vs −0.11） |
| H10 | 漂移可检出、干净零误报：judge 漂移注入后 ≤6 代检出；干净环境连续 30 代零误报（阈值 0.85） | drift-probe | 检出 ≤6 代 / 10 种子；FP=0 / 30 代 | E34/E38/E14（3.8-7.1 代检出） |

对照组的总对比：static（静态记忆库）是零假设；bare 证明「演化本身不够」；gated 是主张的架构；消融臂回答「哪条护栏值钱」（对应落地工单 EV-09/10/11/12/19 的取舍）。

## 3. 被测对象：自演化引擎架构（与 bootstrap_v3.py 的接线图）

### 3.1 四层 + 演算位置映射

| 层 | 内容 | 存放 | 谁可改 | 实验中的「物体」 |
|---|---|---|---|---|
| 锚定层 | 真值审计查询（独立于 judge 通道）、铁律、K=5 | anchors.jsonl（沙盒内只读）+ 世界生成器 | 人（=世界脚本，启动前固定） | 见 4.2 audit_q |
| 元层 | 效用函数（=真值 rv 上的 recall）、任务集定义、AUDIT_EVERY、阈值 | world 快照 + 常量区 | 冻结（脚本常量） | SCENE/SEED 之外的全部常量 |
| 法层 | 检索基因：w_kw/w_content/w_imp/w_age/filter_zero/links_gain/use_imp(自称或实测) | 引擎主线的 cfg | 系统（经两级门控） | cfg 值 |
| 行层 | 条目级算子：append 新条目(合并/纠正)、links 嫁接、keywords 改写、失效标记提案、R-xxx 反思合并 | 真实库 memory/ | 系统（仅经 b3 公开函数） | 算子序列（ops log） |

方向性约束（红线 1/4/6）：法层/行层变异永远不能写锚定层与元层；引擎进程对 anchors.jsonl 与评测协议只有读权限（沙盒内以独立目录 + 校验实现）。

### 3.2 演化循环（=报告 5.2 + A 轮修正的落地形态）

每代 g（世界时间推进一个 step，新事件按场景剧本注入）：

1. 提案：固定混合算子 ×3（约 10% 翻转离散基因 filter_zero/links_gain；其余对 w_* 单参数 ×(1±0.3) 缩放；无自适应步长——E54 已证伪 1/5 规则）。
2. 档案准入（宽松）：Δ > −tol（tol=0.04），只看 train 集；准入只淘汰不采纳（廉价筛选函数无 accept 返回值——E13）。
3. Pareto 档案：对 (train, hold) 双目标取 Pareto 前沿；超 cap=8 时随机采样至 8（E11/E16/E30/E72）。
4. 主线晋升（严格）：档案中首个满足 Δtrain>margin 且 Δhold>margin 的候选上位（E7 的「宽松准入+严格晋升」）；margin 初始 0.02。
5. 停摆监控：连续 5 代零采纳 → margin×0.5（下界 0.005）并记日志（E44，P0 中的 P0）。
6. 真值抽样审计（每 AUDIT_EVERY=3 代）：从审计查询池抽 8 条全新查询（用完即弃，不参与任何训练决策——E8 污染防线），以独立于 judge 的真值 rv 计 util；相对上一检查点跌幅 > REVERT_THR=0.03 → 回退到上一检查点主线 + margin×0.7 + rollback++（E81c 的轻量实现）。
7. 行层算子（仅 gated+行层 臂 / dup-drift 场景）：引擎基于轨迹（traces）提案 links 嫁接/keywords 改写/R-合并，只生成新条目或只读提案，不 in-place 改文件；提案同样过两级门控（用其落盘后对 train/hold 的效用增益计）。
8. 记账：每代把基因、各集 util、档案规模、margin、采纳/回退事件写入轨迹 TSV（值语义，杜绝按对象 id 缓存——报告教训 7）。

> 引擎不知道世界剧本（哪些条目会过期、主题会切换）；它只能通过检索结果与审计真值间接感知——这正是要论证的自演化可行性形态。

### 5.1 P0 parity 门（检索层可信基座）
1. 实现 retrieve_top(entries, q, cfg, k)：逐行转写 _rank_entries（L899-914）的计分公式与 links 扩散，把三个硬编码常数提为 cfg 键：w_kw=3.0, w_content=1.0, w_imp=1.0, w_age=0.1，另加 filter_zero（kw/c 双零 → -inf）与 links_gain=0.5。
2. parity 脚本：建 5 个随机真实库（lib_bridge.materialize），每库跑 20 条查询；对默认 cfg，比较 retrieve_top 与 b3._rank_entries 的 top-5 集合一致率；不一致即修，禁止带病前进。
3. 记录 parity 报告进 out_v2/parity.json（一致性、最大分差、断点条目）。

### 5.2 P1 世界生成器（world_gen.py）
统一条目模型（字段与 v3 schema 对齐，另含隐藏域）：

~~~text
Entry = {id, created_at, updated_at, content, keywords, links,
         source_event_id:"genesis", importance(名义), confidence:1.0,
         validity:{t_invalid?},        # v3 可见字段，真实入库
         _rv, _topic, _spur, _birth_gen, _obsolete_gen, _group  # 世界隐藏真值}
~~~

内容词法：topic 语义词 t0a..t5d + 噪声词；keywords 含 topic 主词。查询池按主题构造；每查询金标 = 该主题下当前代有效的 _rv 最高 K_GOLD=3 条。通道分离：
- judge 通道（train/hold 用）：计分能看到的 = 词面 + 名义 importance + 表面词（spur 场景含 SPUR/格式词）——模拟「LLM-as-judge 看到文本」。
- 真值通道（audit 用，独立抽取）：金标 = _rv，与表面词无关——对应 EV-19「人直接判断有没有用」。

场景剧本（每代注入事件流）：
- clean：无事件；rv 稳定；名义≈rv+ε。
- stale（遗忘压）：t0/t1 主题条目按剧本在某代起失效（世界侧把 validity.t_invalid 写入新注入事件的创建时刻；真实库 retire 用 Clock 前进验证 TTL），同时注入「纠错版」新条目（同 _group，links 指向旧 id）→ 测遗忘与更新。
- dup-drift（重复-重组）：同一 _group 事实由 3 个「写入者」以不同词面多次入库（真重复）；金标组给 _group 首领；正确做法是把它们合并/链接 → 测重组。
- spur-surface（表象错位）：名义 importance 与 rv 反向错位（spur 条 30%）；表面词 SPUR 高频但零信息；judge 通道优化会把权重导向表面 → 测 H2/H4/H5。
- switch（目标切换）：前 2/3 代优化 t0/t1，后 1/3 优化 t2/t3（judge 查询集切换）→ 测 H3 灾难性遗忘。
- composite：stale + spur + switch 同时 → H9 边界。
- drift-probe（专供 H10）：小规模，锚定审计的「人」权重 w 被系统当前输出逐步带偏（α 锚定）→ 检验只靠锚定审计能否检出。

世界快照按代序列化（事件、真值、查询池 seed 派生），保证 replay 与独立分析可重放。

### 5.3 P2 主实验（static / bare / gated × 场景 × seeds）
每 (scene, seed)：
1. world = build_world(scene, seed)；anchors.jsonl（只读）由世界在启动时生成（真值审计查询预抽样、运行期不追加）。
2. static 臂：主线 cfg 恒为默认；生命周期照默认策略跑（stale 场景下到 TTL 才 retire——即「只遗忘、不演化」）；不提案任何行层算子。
3. bare 臂：单主线、无档案/无门控：每代取 train 上 Δ>0 的候选直接上位（margin=0，无审计）——复现 E3「无门控」。
4. gated 臂：按 3.2 全流程（含真值抽样审计）。
5. 每 5 代一个检查点：check_integrity（真实库路径）+ 轨迹落盘；每 10 代 materialize 一份影子真实库并跑真实 b3 doctor/retire（Clock 注入验证 TTL），把真实路径输出与引擎内一致性快照对账。
6. 终局：每条查询在「从未被训练决策引用过的剩余审计池」上测终局效用（防 E8 污染：训练/晋升用的 hold 每 10 代轮换一次，审计池只出不进）。

运行档位：quick = seeds 4 × gens 12；full = seeds 12 × gens 40。预估（env_check 实测 append 单条约 <10ms；纯 util 计分 O(N×Q)）：full 主矩阵约 20-60 分钟/场景×3臂，P3/P4 另计；全部带 --quick 冒烟先行。

### 5.4 P3 消融与算子探针（在 gated 上逐项开关）

| 臂 | 改动 | 检验 |
|---|---|---|
| gated-noPareto | 档案=单最优 | H3 的 Pareto 贡献 |
| gated-noAudit | 关真值抽样审计 | H5/H1 的审计贡献（spur 场景必测） |
| gated-marginHigh | margin=0.15（E29b 致死量） | 停摆监控是否 ≤10 代救回 |
| gated-recency | 锚定/审计判断按近因加权（hl=15） | E14c 毒药对照：漂移下应显著劣于均匀 |
| gated-impDerived | 引擎把 importance 当派生量（按 traces 实测采纳率归一）参与计分 | H4 |
| gated+row-ops | 开行层算子（仅 dup-drift/clean 两场景跑） | H7 |

消融共享同一运行帧（每代三臂可复用同一批候选的 eval 结果——按 (scene,seed,gen,cfg-值,query) 值语义缓存，杜绝报告教训 7 的 id() 缓存 bug）。

### 5.5 P4 边界探针
- 预算曲线（H8/E64）：把「可调用的 eval 次数/代」当作预算 B，扫 B ∈ {10,40,80,150,300}，画终局效用 vs B；拟合门槛 B*。
- 复合危险（H9/E80）：composite 场景 × seeds 3 × {static,bare,gated}，如实记录分布；若 gated 也净负，写边界、不修（E80 的诚实输出）。
- judge-drift 检出（H10/E14/E38）：drift-probe 场景，注入 α∈{0.10,0.20}，测：仅锚定审计的触发率；阈值 0.85 的检出代数；干净 30 代误报数。
- 恶意算子注入（H6b）：写一个「绕过 API 直接 edit memory/*.json 字段」的作弊臂，断言 100% 被真实 b3 写路径拒绝（同 id）或破坏一致性后被 check_integrity/doctor 检出——量化「能力式边界的必要性」。

### 5.6 P5 真实路径抽查
每场景取 seed=1 的 gated 终局库：b3 doctor、eval、retire（Clock 前进 +90d）、b3.merkle_root 与 state.json 对账、guard snapshot/anchor 对账（人侧表 = 世界脚本生成的锚定文件）——把 H6 断言钉在真实代码输出上而非引擎模拟器。

### 5.7 P6 分析（独立进程，读盘不读内存）
analysis/analyze.py 读 out_v2/ 下全部 rows/traj/checkpoints → 输出：逐场景三臂均值表、配对 Δ 分布、sign-test k/12、Wilcoxon p、bootstrap 95% CI、轨迹曲线图、检查点一致性热图、预算曲线拟合。运行器与分析器分离，杜绝「用同一份带 bug 缓存跑出太漂亮的数」（报告教训 8）。

## 8. 数据采集与分析方法

### 8.1 产物 schema（全部 JSON/TSV，UTF-8，值语义）
- rows_{scene}.json：每臂每种子一行 → {scene, seed, arm, final_cfg, u_train/u_hold/u_audit(终局未用池), adopts, dips, rollbacks, arch_size, eval_units, sec, per-checkpoint 摘要}。
- traj_{scene}_{seed}_{arm}.tsv：每代一行 → gen, cfg 全基因(值), u_train/u_hold/u_audit_thisgen, margin, arch_size, stall, events(adopt/rollback/relax/audit_dip), ops(行层)。
- checkpoints/{...}.json：chain_bad/set_mismatch/merkle/attic 计数/库体积/铁律违例/traces 统计。
- integrity_real/{scene}_seed1_gated_end.json：P5 真实 doctor/eval/retire 输出。
- manifest.json：脚本、python 版本、b3.VERSION、seeds、gens、场景、每臂参数字典、文件指纹——复现第一道闸。
- anchors.jsonl（每个 (scene,seed) 一份，运行期只读校验：哈希比对，防引擎越权）。

### 8.2 统计协议（先写死在 analysis 里再跑数，避免后验挑方法）
1. 主判据：配对 sign-test（正种子数 k/12）+ Wilcoxon signed-rank（n=12，α=0.05 双侧）+ bootstrap 10^4 次 95% CI 下界（红线 15：CI 下界 > 0 才算「显著为正」，不用固定 margin 当显著）。
2. 诚实度：H2 用 per-seed gap 分布（中位数、P25），自报与真值均在同一条轨迹上测，消除采样偏差。
3. 污染控制：hold 每 10 代轮换重抽；audit 池只出（每检查点抽 8 弃 8）不入；终局报告用「从未参与任何决策」的独立池。
4. 误报统计：干净场景把「审计触发」当 FP 计；漂移场景把「≤6 代内触发」当 TP 计；报告混淆矩阵而非单一检出率（E34 教训：0.95 阈值「检出 8/8」是几乎永远报警下的空话）。
5. 报告纪律：先出「阴性/证伪表」，再出「支持表」；每条结论注明支撑实验与效应量，禁止用均值掩盖分布（报告第四部分方法论）。

### 8.3 分析方法
- 主表：场景×臂 的 u_audit 均值±std + 相对 static 的配对 Δ（含 CI）。
- 归因：消融差分（gated − gated-noX）得每条护栏的边际贡献；与报告 EV-09~12 的预期量级对照。
- 曲线：traj 平滑曲线（代 vs u_audit）按臂叠画；平台判别用报告 E12/E45 的「重测冠军」规则防误判。
- 预算曲线：u vs B 拟合（分段线性/幂律），报告拐点 B*。
- 一致性热图：检查点 × 指标 的绿/红矩阵（绿=零违例），直接把 H6 断言画成图。

### 9.2 可行性判据（验收清单——报告写完逐条勾选）
自演化引擎「架构设计可行」当且仅当：

- [ ] F1 H1 通过：≥3/5 场景（含 stale、spur）70% 种子为正且 CI 下界 > 0；
- [ ] F2 H2 确认门控必要性：gap ≥ 2×（否则「裸演化」也诚实，架构需重新论证）；
- [ ] F3 H3/H4 通过：遗忘防护与 importance 实测化拿到报告量级（±30% 容差）；
- [ ] F4 H5 通过：真值抽样审计在 spur 上带来 ≥ +0.03 净增益且审计只在真退化时触发；
- [ ] F5 H6 全程零违例（含 P5 真实 doctor 抽查）：即自演化引擎在存储/更新/遗忘/重组四能力上与记忆一致性不冲突；
- [ ] F6 H8 门槛被量化：运营策略可写死「预算 < B* 禁止开启演化」（E64 落成策略）；
- [ ] F7 H9 边界被如实写入（不因难看不通过，因不诚实不通过）；
- [ ] F8 可复现：固定 seed + manifest 在第二台机器跑出 headline 数字差 ≤ ±0.005（单线程确定性、无网络）。

判据的判据：如果 F1/F5/F8 通过而 F2 不通过，说明门控冗余 → 架构应简化；如果 F4 不通过而 F1 通过，说明场景没造出「judge 只看表象」的压力 → 先修场景（报告教训 3：判别器没错是构造不成立），不得用改判据来通过。

| 检索器 replica 与真实代码漂移 | P0 parity 门 + P5 真实抽查双保险 | 报告「先修好 eval 再谈」教训 |

| 近因加权毒药 | 锚定/审计判断均匀加权；recency 只作为毒药对照臂 | E14c |
| 缓存串味（id() 复用） | 全程值语义缓存 + 运行/分析分离 | 教训 7/8 |
| 结果太漂亮 | 先跑 quick + 先写阴性表；怀疑优先于庆祝 | 教训 8 |
| 门控阈值拍脑袋 | 阈值全部来自报告（0.85/0.04/0.02…）并在 manifest 登记 | E34/E55/E17 |
| judge 通道同源 | 真值与 judge 通道物理分离（A4）；审计不读任何引擎可优化量 | E81/EV-19/20 |
| 报告里混口径 | 每个指标标注采集方法（真实 b3 or 引擎统计），不一致时以真实输出为准 | 公理 G |
| 注意力预算超支 | EV-16 账本化，预算 < B* 自动禁止 | E64/E22 |

三条不可能性在实验中的位置：系统无法自知失败（H9/E78：我们不设计「自查」，依赖外部真值审计）；系统无法被自己的数据检验（A4 通道分离 + H5 复现 E81 的零触发）；自主性有注意力门槛（H8 量化 B*）。实验的目标不是「证明没有边界」，而是把边界测出来并写成可执行策略——这本身就是可行性论证的一部分。
