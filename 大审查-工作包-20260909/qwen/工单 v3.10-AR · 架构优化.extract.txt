# 工单 v3.10-AR · 架构优化（进化式重构）

| 字段 | 内容 |
|---|---|
| **工单编号** | `v3.10-AR` |
| **性质** | 执行类工单（代码变更 + 测试资产） |
| **标的** | `bootstrap_v3.py` 现有单文件架构 |
| **宗旨** | **修房子不搬家**：不改外部行为、不改交付形态、不破坏锚点连续性，只补结构强制面 |
| **前置** | `v3.9-1` 缺陷工单的 P0-00（可运行基线）完成 |
| **总工作量** | 约 8.5 人日（含测试与回归） |
| **状态** | 待排期 |

## 1. 范围声明

- **做**：统一写路径、不变式执法层、异常模型、锚点分层、操作注册、索引、增量 Merkle 与 schema 版本化。
- **不做**：重写存储格式、变更库布局、更换交付形态（这些归 v4.0-RF 探讨）。
- **铁约束**：任一 AR 项完成后，既有 `run-tests` 必须零回归；审计链不得分叉；人侧已抄录的锚点不得失效。

## 2. 工作项清单

### AR-01｜统一写路径：`LibraryTx` 事务抽象
| 维度 | 内容 |
|---|---|
| 证据 | 刷根靠各操作自觉：`append/wrapup/retire/reflect-done/build` 手写，`guard/shadow/reflect` 全漏；「账本先于根」靠注释维持 |
| 方案 | 唯一写入口 `LibraryTx`：暂存改动 → 退出时按固定顺序落盘（写条目 → `chain_append` → `_ledger_append` → 重算根 → 原子写 `state.json`） |
| 验收 | ① 除 `LibraryTx` 外无任何代码直接写 `state.json`（可 grep 审计）；② 新测试：对每个写操作跑完即 `doctor` 五态全一致；③ 既有测试零回归 |
| 量 / 依赖 | M（1 人日）／依赖 P0-00 |

### AR-02｜不变式执法层：`INVARIANTS` 注册表
| 维度 | 内容 |
|---|---|
| 证据 | 铁律是散文，执法散且不全——铁律1 唯一性只查单目录（跨层可重复）；铁律4 只验自哈希不验同文件相邻链接（重算哈希即可逃检） |
| 方案 | 六铁律逐条建模为可执行谓词，注册于 `INVARIANTS`，在 `LibraryTx` 提交边界统一运行；`doctor` 复用同一套谓词——「什么叫一致」全系统单点定义 |
| 验收 | ① 六条铁律各有谓词（铁律3/6 可为静态扫描谓词）；② 「跨层重复 id」「重算哈希断链」两个攻击用例先红后绿；③ 代码评审确认 doctor 与写面共用谓词、无第二份判断逻辑 |
| 量 / 依赖 | M（1.5 人日）／依赖 AR-01 |

### AR-03｜领域异常层级，废除 `sys.exit` 控制流
| 维度 | 内容 |
|---|---|
| 证据 | `resolve/detect_cycle/cmd_engine/cmd_install` 用 `sys.exit` 抛错；`cmd_absorb_md` 甚至 `except SystemExit` 后字符串匹配「已存在」——错误语义耦合在报错措辞上 |
| 方案 | `BootstrapError` 层级：`ValidationError / DuplicateIdError / IntegrityError / GateError / NotFoundError`；库函数只 raise，**仅 CLI 边界**映射退出码；退出码表渲染进 `spec.md` |
| 验收 | ① `cli.py`（主入口块）之外零 `sys.exit`（可 grep）；② `absorb-md` 改为捕获 `DuplicateIdError`；③ 退出码表入库 |
| 量 / 依赖 | S（0.5 人日）／无依赖，建议最先做 |

### AR-04｜身份锚分层：复合锚点
| 维度 | 内容 |
|---|---|
| 证据 | 整文件 sha256 为包锚，但文件混装代码+题录+参数+测试：加一篇题录或加一个测试即全锚变动，所有库的 `package_sha256` 失配；`len(TESTS)` 注入渲染件还会级联改库根 |
| 方案 | `package_anchor = H(code_hash, registry_digest, tunables_digest, schema_digest)`；`REGISTRY/TUNABLES` 外置 `bootstrap_data/sources/` 各自独立哈希；测试计数移出渲染面 |
| 验收 | ① 新增一条题录后 `code_hash` 不变、仅 `registry_digest` 变；② 锚定表能表述「哪一层变了」；③ 锚点口径变更有慢车道裁决记录且 `spec.md` 同步 |
| 量 / 依赖 | M（1 人日 + 裁决等待）／⚠️ 触碰公理 E 措辞，**须人类令牌**；可与 AR-05/06 并行 |

### AR-05｜操作注册 + 读写面声明
| 维度 | 内容 |
|---|---|
| 证据 | `cmd_engine` 是 ~10 分支的 `if/elif` 巨链；「哪些操作该刷根」靠记忆 |
| 方案 | 沿用 `@t` 自注册惯用法：`@engine_op("retrieve", writes=False)`；分发器 ≤30 行；`writes=False` 的操作在结构上不可能触碰 `state.json` |
| 验收 | ① 新增操作 = 新增一个函数 + 一行注册；② 读操作零写面（静态可查）；③ 既有测试零回归 |
| 量 / 依赖 | M（1 人日）／依赖 AR-01 |

### AR-06｜持久化检索索引
| 维度 | 内容 |
|---|---|
| 证据 | `_rank_entries` 每次查询全量 `rglob` + 子串匹配，O(N×长度)；`index_hot_budget` 只是登记 |
| 方案 | 库内增量倒排索引（stdlib 实现），在 `LibraryTx` 提交时更新；`retrieve/eval` 走索引；全量扫描降级为 `doctor` 的对账手段 |
| 验收 | ① 索引结果与全量扫描**逐条一致**（双跑比对断言入测试）；② `doctor` 新增「索引↔条目」一致性态；③ 既有评测 `recall@5/MRR` 数值不变 |
| 量 / 依赖 | L（1.5 人日）／依赖 AR-01 |

### AR-07｜增量 Merkle + schema 版本化
| 维度 | 内容 |
|---|---|
| 证据 | `merkle_root` 每次写全树重算（Y-010 已登记）；manifest 用截 16 hex、根用全 256bit，口径不一；条目与 `state.json` 无版本号，schema 演进无迁移面 |
| 方案 | 目录级子树哈希缓存，写后只重算受影响路径；统一哈希口径；条目加 `schema_version`、state 加 `state_schema_version`，配迁移注册表 |
| 验收 | ① 单条目写入的哈希计算量可计量且显著低于全树（埋点断言）；② 一次 schema 升级演练：migrator + 测试；③ 根数值口径变更须一次性人侧重抄录并留痕 |
| 量 / 依赖 | L（1.5 人日）／依赖 AR-01 |

## 4. Definition of Done

1. AR-01~07 全部落地，各项验收标准逐条通过。
2. `run-tests` 全绿，且新增「攻击用例集」（跨层重复、重算断链、劣化重放）长期保留。
3. 审计链零分叉；人侧锚点零失效（AR-04 的口径变更除外，且已完成裁决与重抄录）。
4. `spec.md` 更新：退出码表、不变式清单、单写者声明。

## 5. 风险

- **AR-04 触碰公理 E**：锚点语义变更属宪章级，必须慢车道；裁决未过则该项挂起，不阻塞其余。
- **AR-07 根口径变更**：涉及一次人侧重抄录，须与用户对账窗口对齐。
- **与 v4.0-RF 的关系**：若重构立项，AR-05/06/07 可能被吸收；**但 AR-01/02/03 与其攻击测试资产永远不浪费**——它们是 v4 行为等价验证的基准。建议无论如何先做这三条。
