## 1. 变异闭环六段 → 结构化执法点（本工单核心）

现状：闭环的「执法」大多靠注释与约定。本工单把每一段的执法点**固定到代码结构上**。

| 段    | 当前形态                                         | 结构化执法点                          | 代码落点                                        |
| ---- | -------------------------------------------- | ------------------------------- | ------------------------------------------- |
| ① 提出 | `mutations/candidates/` 裸文件，**不是事件**         | 变异提出=账本事件，带溯源（谁提出/依据宪章哪条）       | `_ledger_append` 新增 `mutation-proposed` 事件型 |
| ② 验证 | `guard --diff` 黑名单（文件名子串）+ run_tests/lint    | 黑名单**锚定化**；三守卫豁免且入根             | `cmd_guard` + `BASELINE_BLACKLIST`          |
| ③ 仲裁 | 宪章要求人类令牌，但**只拦 install/redeliver**，应用变异无结构门禁 | 应用变异=受门禁的提交；判据**不可见**（人侧）       | 提交边界 + `GateError`                          |
| ④ 应用 | agent 直接写文件，**可能忘刷根**                        | 唯一写路径：不变式前置→落盘→链追加→刷根→原子写 state | 写路径抽象（见 v3.10-AR/AR-01）                     |
| ⑤ 锚定 | `guard snapshot/anchor`，**不刷根→误报/漏报**        | 锚定操作刷根；锚定表抄录人侧                  | `cmd_guard`（P2-02 修复后）                      |
| ⑥ 回退 | attic + `ESCAPE_POD`（铁律1）                    | 回退=移 attic+登记，**永不删除**，可逆可追责    | `retire`/attic                              |

## 2. 工作项：五道保证 + 一条红线

### `EVO-01` · 提出可审计 —— 变异生命周期入账

- **落点**：`_ledger_append`；新增命令面 `mutation propose/apply/rollback` 事件型。
- **缺口**：变异从提出到应用**全程无事件**，演化史不可审计。
- **修复**：`mutation-proposed / mutation-verified / mutation-accepted / mutation-applied / mutation-rolledback` 五类事件入 `ledger/changes.jsonl` + 审计链，每条带溯源。
- **攻击用例** `t_evo_mutation_lifecycle_logged`：走一遍完整变异流程，断言五类事件齐全且可回放。

### `EVO-02` · 评测面不可变 —— 基准豁免 + 棘轮单调

- **落点**：`BASELINE_BLACKLIST`、`cmd_engine("eval")`。
- **缺口**：棘轮覆写基线（P1-03）；黑名单按文件名子串、且 `glob("*")` 若失效则 guard 全盲。
- **修复**：
  
  ```python
  # eval 劣化分支——冻结基线，绝不覆写
  if degrade:
      (lib/"evals"/"baseline-rejected.json").write_text(json.dumps(base, ...))
      _ledger_append(lib, "eval-degraded", f"recall@5={base['recall@5']} 被拒")
      sys.exit(2)
  else:
      (lib/"evals"/"baseline.json").write_text(json.dumps(base, ...))
  ```
  
  黑名单文件哈希入根锚定；先写单测确认 `glob` 在目标环境有效。
- **攻击用例** `t_evo_ratchet_monotonic`：预置 `recall@5=1.0` → 制造劣化 → 断言①`exit 2` ②`baseline.json` 仍为 1.0 ③紧接第二次 eval 仍报劣化。

### `EVO-03` · 仲裁必强制 —— 慢车道令牌在写面校验

- **落点**：提交边界（新增 `GateError`，见 v3.10-AR/AR-03）。
- **缺口**：应用变异这一刻**无结构门禁**，令牌只是宪章措辞。
- **修复**：`mutation apply` 必须携带有效人类令牌，提交边界校验；无令牌 → `GateError` 拒绝。charter gate（M-003）留痕入审计链。
- **攻击用例** `t_evo_apply_requires_token`：无令牌应用变异 → 提交被拒，库状态零变化。

### `EVO-04` · 判据不可见 —— 防 objective hacking 核心

- **落点**：`bootstrap_data/`（人侧）、`SOP_GUARD`、`CHARTER_L8` 第2/4条。
- **缺口**：不可见是**宪章声明**，无机制保证判据细则不泄漏进变异引擎可见域。
- **修复**：验收判据细则**只存人侧** `bootstrap_data/`，变异引擎仅接收 pass/fail；`guard snapshot` 把判据哈希纳入锚定；SOP「不可见条款」被改写/移除即报警（宪章第4条落地为可检测）。
- **攻击用例** `t_evo_criteria_invisible`：断言判据细则不出现在任何变异引擎可读路径；篡改 `SOP_GUARD` 不可见条款 → 报警触发。

### `EVO-05` · 应用事务化 + 回退非销毁

- **落点**：唯一写路径（v3.10-AR/AR-01）；`retire`/attic。
- **缺口**：应用变异靠手工写文件，刷根靠自觉（P2-02 同源）；回退路径未与变异绑定。
- **修复**：`mutation apply` 走事务（不变式前置→落盘→`chain_append`→刷根→原子写 state）；`mutation rollback` = 移 attic + 登记账本，**永不删除**。
- **攻击用例** `t_evo_apply_refreshes_root`：应用变异后 `state.merkle_root` 与重算一致；`t_evo_rollback_to_attic`：回退后原文件在 `attic/` 且账本留痕，库中无删除痕迹。

### `EVO-06`（红线）· 不变式层高于一切

- **落点**：新增 `INVARIANTS` 注册表，提交边界执法，`doctor` 复用（v3.10-AR/AR-02）。
- **缺口**：铁律是散文；`validate_entry` 只管铁律2/5；铁律1 唯一性漏跨层、铁律3/4/6 写入面无谓词。
- **修复**：
  
  ```python
  INVARIANTS = {
    "L1-唯一id":   lambda e, lib: not _id_exists_anywhere(lib, e["id"]),   # 全库含 attic
    "L4-链连续":   lambda lib: ChainVerifier(lib).fully_linked(),           # 含相邻链接
    "L5-无密钥":   validate_no_secret, ...
  }
  def check_pre_commit(e, lib):
      for name, pred in INVARIANTS.items():
          if not pred(e, lib): raise IntegrityError(f"违反不变式 {name}")
  ```
- **攻击用例** `t_evo_invariant_overrides_tests`：构造一个**过全部测试、但违反铁律1（覆盖写）**的变异 → 提交边界拒绝。这是「测试有盲区、仲裁会出错、但不变式是结构」的终极证明。
