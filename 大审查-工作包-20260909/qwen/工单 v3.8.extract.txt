## 0. 执行摘要

本次审计在逻辑层挖出 **3 个 P1 硬伤**，共同主题是：**系统用文档与测试宣称的三条核心保证——“审计链连续（铁律4）”“写入不覆盖（铁律1）”“劣化不得合入（宪章）”——在代码里都没有被真正强制**。对应测试存在，但测的是“相邻能力”，给出了假信心。

另有 **1 个 P0 阻断**：交付的 `.py` 本身无法通过语法检查（含多处词法断裂、`__`/`*` 丢失、未注释的中文行、制表符分隔线）。**在拿到可编译基线前，任何逻辑修复都无法被验证**，故列为预备工单的第一道闸。

## 1. P0 · 阻断项（先于一切）

### `v3.9-1/P0-00` 交付件不可编译：恢复可运行基线
- **严重度**：P0（阻断）
- **现象**：文件无法 `py_compile`，`run-tests` 无法启动。
- **定位（已观察到的具体损坏点）**：
  1. `REGISTRY = {` 紧随的裸行 `status: verified=… | absorb-pending=…` —— 既非注释也非合法键值。
  2. 多处应为 `#` 注释的中文说明行裸露：`v3.2/C-013：…`、`v3.2/C-006：…`、`v3 语义模块名 →…`、`v3 特色包语义名 →…`、`v3.1/V-008：…`、`v3.1/V-009：…`、`内容体（数据，非代码）：…`、`v3.7/L-008(D1)：…`。
  3. 多处 `────` 制表分隔线直接出现在代码区。
  4. `self_hash()` 中 `Path(file)` → `file` 未定义（应为 `__file__`）。
  5. 主入口 `if name == " main ":` → `name` 未定义（应为 `if __name__ == "__main__":`）。
  6. `_deliver()` 中 `body_text.enc ode("utf-8")` → 词断裂（应为 `.encode`）。
  7. doctor 分支 `c hain_bad = []` → 非法标识符（应为 `chain_bad`）。
  8. `t_verify_offline_honest` 中 `urllib.request.urlopen = real_urlope n`（应为 `real_urlopen`）。
  9. `t_reinstall_without_data` 中 `cmd_ install(...)`（应为 `cmd_install`）。
  10. 多个正则的 `(.*)` 被写成 `(. )`、`\|` 被写成裸 `|`（见 doctor 行解析、`_parse` 字段解析）——裸 `|` 在正则里是“或”，**会改变匹配语义**。
  11. 通配符丢失：`rglob(" .json ")`、`glob("lifelog-.md ")`（应为 `"*.json"` / `"lifelog-*.md"`）——现状匹配不到任何文件。
  12. `cmd_engine(op, lib, text=" ", k=5)` 默认 `text` 为**单个空格**而非空串——导致 `eval`/`retrieve` 走 CLI 默认分支时 `Path(" ")` 判定为真，直接 `评测集不存在` 退出。
- **判定**：以上多数是**导出/转录损伤**，但在拿到干净源之前无法区分“转录噪声”与“真实缺陷”。
- **整改动作**：
  1. 重新导出**无损源文件**（保留 `#`、`__`、`*`、`\|`、`.` 等符号）。
  2. `python -m py_compile bootstrap_v3.py` 通过。
  3. `python -X utf8 bootstrap_v3.py run-tests` 建立**全绿基线**并存档输出。
- **验收标准（DoD）**：`py_compile` 0 错误；`run-tests` 输出 `N/N` 全绿；基线日志入库。
- **预估**：S（0.5–1 人时，取决于能否直接拿到干净源）。

&gt; ⚠️ **排期约束**：P1–P3 的所有“复现/验收”均以 P0-00 完成为前提。若某条缺陷在干净源下消失，则降级为“转录噪声”并关闭。

## 2. P1 · 核心不变式被击穿

### `v3.9-1/P1-01` doctor 审计链：**同文件内** prev→h 链接从未校验（铁律4 名不副实）
- **严重度**：P1｜**位置**：`cmd_engine()` → `op=="doctor"` 的链校验循环
- **现象 / 复现**：
  现有校验只做两件事：① 每行自哈希 `line_hash(prev, text) == h`；② 跨月首行 `prev == 上月尾哈希`。**它从不检查“本行 `prev` 是否等于上一行 `h`”（同一文件内）**。
  构造攻击：取合法三行链
  ```
  L1: prev:genesis h:H1 text1      (H1=H("",text1))
  L2: prev:H1      h:H2 text2      (H2=H(H1,text2))
  L3: prev:H2      h:H3 text3      (H3=H(H2,text3))
  ```
  篡改 `text2→text2'` 并**重算** `H2'=H(H1,text2')`、回写 L2 的 `h`。此时：
  - L1/L2/L3 各自自哈希全部通过；
  - 但 `L3.prev(=H2) ≠ L2.h(=H2')`，链已断——**doctor 仍报“审计链连续”**。
- **根因**：链校验缺“相邻行链接”这一环；自哈希只保证“行内自洽”，不保证“行间连续”。
- **影响**：铁律4“行哈希链连续”实际未被强制；审计面防篡改宣称失效。现有 `t_doctor_chain_check` 只篡改文本（破坏自哈希）被测出，**没有覆盖“重算哈希后断链”**，给出假信心。
- **修复建议**：遍历时维护 `expected_prev`；对每行断言 `prev == expected_prev`（首行/跨月行取上一文件尾哈希），随后 `expected_prev = h`。把“自哈希”与“链接”作为两条独立检查。
- **需补测试**：构造上述“重算 H2' 断链”用例，断言 doctor 报 `断链` 且定位到行号。
- **验收标准**：新用例下 doctor 必须报断链；原 `t_doctor_chain_check`、`t_cross_month_real`、`t_doctor_crossmonth_and_state` 保持通过。
- **预估**：M（1–2 人时，含测试）。

### `v3.9-1/P1-02` append 重复 id 检查**仅限单一层**，跨层/跨 attic 可写入同 id（违反铁律1）
- **严重度**：P1｜**位置**：`cmd_engine()` → `op=="append"`
- **现象 / 复现**：
  ```
  dest = memory/longterm  if importance&gt;=7  else memory/intermediate
  epath = dest / f"{id}.json"
  if epath.exists(): 拒绝
  ```
  重复检查只看**目标层目录**。先 `append id=X importance=1`（落 `intermediate/X.json`），再 `append id=X importance=8`（目标变为 `longterm/X.json`，不存在）→ **放行**。同一 id 同时存在于两层。
- **根因**：唯一性约束的作用域被写成了“目标层”，而非“全库”。
- **影响**：违反铁律1/唯一 id 不变式。`_rank_entries`、`doctor` 均以 `f.stem` 建集合，重复 stem 会互相覆盖/去重，导致检索结果不可预期、doctor 三方对账误报。现有 `t_append_rejects_dup_id` 两次用相同 importance（同层），**恰好避开跨层洞**。
- **修复建议**：写入前对 `memory/**/{id}.json`（含 `attic/`）做全库存在性检查；命中即拒。更新语义走显式裁决（铁律1 已要求）。
- **需补测试**：同 id、先 `importance=1` 后 `importance=8`，断言第二次被拒；再补“attic 已有同 id 时拒绝/或按裁决放行”的用例并固化预期。
- **验收标准**：跨层重复 append 必拒；原同层用例不回归。
- **预估**：S（1 人时，含测试）。

### `v3.9-1/P1-03` eval 劣化基线被**无条件覆写**，质量棘轮失效（“劣化不得合入”可被绕过）
- **严重度**：P1｜**位置**：`cmd_engine()` → `op=="eval"`
- **现象 / 复现**：
  ```
  if 旧基线存在 and 新recall &lt; 旧recall*0.95: degrade="…宪章警告…"
  baseline.json 写入(新结果)      # 无条件覆写
  if degrade: sys.exit(2)
  ```
  检出劣化后**仍把更差的新值写为基线**，然后才 `exit(2)`。下一次 eval 以“已劣化的值”为基线 → 不再触发 → **绿**。劣化只在第一次被报警，随后被永久接受。
- **根因**：控制流顺序错误——“写基线”应先受“是否劣化”门禁；劣化分支不应固化新基线。
- **影响**：宪章“劣化超 5% 不得合入”实际只拦一次；质量棘轮（ratchet）断裂。`t_eval_degradation` 只断言“本次 exit 2”，**未断言基线未被污染**，假阴性。
- **修复建议**：`degrade` 为真时**跳过基线写入**（或另存 `baseline-rejected.json` 留证），保持旧基线不变；仅在不劣化时更新基线。
- **需补测试**：预置 `recall=1.0` 基线 → 制造劣化 → 断言 ① `exit 2`；② `baseline.json` 仍为 `1.0`（未被覆写）；③ 紧接第二次 eval 仍报劣化。
- **验收标准**：连续两次劣化 eval 均 `exit 2`；基线不被劣化值覆盖。
- **预估**：S（1 人时，含测试）。

## 3. P2 · 正常路径下的状态不一致 / 数据误处置

### `v3.9-1/P2-01` retire 重复扫描 attic，二次运行自移/重复记账
- **位置**：`cmd_engine()` → `op=="retire"`
- **现象**：`for f in (lib/"memory").rglob("*.json")` **包含 attic 子目录**。已入仓条目 `t_invalid` 仍在、账龄仍超 TTL → 每次 retire 都被再次处理，`shutil.move(attic/x.json → attic/x.json)` 自移；并向审计链/账本**重复追加** `retire` 记录，污染审计面。另 `dest` 仅取 `f.name`，跨层同名（叠加 P1-02）有碰撞风险。
- **修复建议**：扫描时排除 `memory/attic`；`dest` 保留层级来源或先做同名冲突检测。
- **需补测试**：连续两次 `retire`，断言审计链 `retire` 记录不重复、无异常、attic 不被二次搬移。
- **预估**：S–M。

### `v3.9-1/P2-02` guard 快照/锚定写库后不刷 Merkle 根 → 其后 doctor 报“根不一致”
- **位置**：`cmd_guard()`（snapshot 与 anchor 分支）
- **现象**：`--snapshot` 在库内写 `anchor_snapshot.json` 并 `_ledger_append`；`--anchor` 也 `_ledger_append`。二者都**改变了参与 Merkle 的文件**，但都不回写 `state.merkle_root`。随后 `doctor`/`install 校验` 必报“根不一致”。
- **修复建议**：两分支末尾刷新并回写 `state.merkle_root`；**或**将 `anchor_snapshot.json` 纳入 `merkle_root(exclude=…)` 的排除集（与 `state.json` 同级）。二选一并写明口径。
- **需补测试**：`guard --snapshot` 后 `doctor` 应报“根一致”。
- **预估**：S。

### `v3.9-1/P2-03` absorb 镜像删除：曾被吸收、本轮超限(&gt;512KB)的文件被误移入 removed
- **位置**：`cmd_absorb()` 的 skip 与镜像删除段
- **现象**：`&gt;512KB` 的文件被 `continue` 跳过、**不进 `hit_keys`**。若该文件此前已被吸收（在 `bodies` 中），本轮因不在 `hit_keys` 而被镜像删除逻辑移入 `removed`——文件仍在源树，却被判“已消失”。
- **触发条件**：文件由小变大越过 512KB（边界场景，但会造成静默数据丢失）。
- **修复建议**：对被 `skipped` 的文件，其既有 `bodies` 条目应**保留原状**（不进 `hit_keys` 也不触发镜像删除），或在镜像删除前剔除 `skipped` 集合。
- **需补测试**：构造“先以小文件吸收→改大→再 absorb”，断言其仍在原槽、未入 `removed`。
- **预估**：S。

### `v3.9-1/P2-04` chain_append：上一文件末行非法时静默以空/genesis 重启链（链分叉风险）
- **位置**：`chain_append()`
- **现象**：跨月取 `prev` 依赖对 `files[-1]` 末行 `h:([0-9a-f]{64})` 的正则；若末行**非法规整**（无 64-hex `h`），`prev` 落回空串，新月份首行以 `prev:genesis` 起始——**链被静默重启而非报错**。
- **影响**：与铁律4“链连续”冲突；异常上游数据会导致无声分叉。
- **修复建议**：末行解析失败时 `sys.exit`/抛出明确错误（除非显式 `prev_override` 用于 migrate），禁止静默兜底。
- **需补测试**：构造末行无 `h:` 的上月文件，再跨月追加，断言报错而非生成 `genesis` 行。
- **预估**：S。

## 4. P3 · 健壮性 / 边界 / 耦合 / 风格（登记在册）

| 编号 | 位置 | 问题 | 建议 |
|---|---|---|---|
| `P3-01` | `eval` | 空评测集 `n=0` → `hits/n`、`rr/n` **除零** | `n==0` 时提前友好退出 |
| `P3-02` | `resolve()` | `dep not in order` 恒假（`order` 是层级名），为死代码；依赖满足**依赖 `adds` 层内顺序**，脆弱 | 改为“先全量收集再校验”，去除顺序耦合 |
| `P3-03` | retrieve/eval/doctor/retire | 以 `f.stem` 充当 id，与 `e["id"]` 强耦合；文件名≠id 时错配/误报 | 统一改用 `e["id"]`，或在校验层强制 `stem==id` |
| `P3-04` | `cmd_migrate()` | 空链尾行 `splitlines()[-1]` 触发 `IndexError`；`glob and any(glob)` 冗余（生成器恒真） | 加空判；简化为单次 `any(glob)` |
| `P3-05` | `cmd_absorb()` | `removed` 键用 `f"{slot}__{key}"`，去重判断却用裸 `key`，格式不一致 → 去重失效（潜在残留/重复） | 统一键格式后再比较 |
| `P3-06` | CLI | `--hash` 标志定义后**无任何分支使用**（主流程恒打印自哈希） | 落实 `--hash` 语义或移除 |
| `P3-07` | `cmd_build()` | `out` 与 `lib` 不同且均给定时，`spec/速查/citations` 落 `out`、`AGENTS/README` 落 `lib`，**落点分裂** | 明确单一落点或校验 `out==lib` |
| `P3-08` | install 校验模式 | 升级 `VERSION` 后重装，渲染件因含版本号被误报“渲染件被改” | 属设计取舍；建议提示走 `build-docs --lib` 而非报警 |
| `P3-09` | `reflect`/`wrapup` | 直接读 `state.json`，缺失即崩（doctor 有兜底，此二者无） | 补存在性防御，统一友好退出 |
| `P3-10` | 模块级 | `DEPS` 定义于 `resolve/detect_cycle` 之后（前向引用，运行期无碍，风格隐患） | 上移定义顺序 |
